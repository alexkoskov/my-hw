# Task 2: Admin alerts E031-E033

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Расширяем `admin_alerts.py` тремя новыми builder-функциями для t-hunted-парсера, который появится в Task 1 (Wave 1, параллельно с этой задачей). Парсер `t_hunted_source.fetch_t_hunted_article` имеет три различимых failure-режима, по которым оператору нужно получать различимый сигнал в админ-чат:

1. **E031** — `alert_t_hunted_host_rejected(link)` — SSRF allowlist отверг URL (хост не `t-hunted.blogspot.com`).
2. **E032** — `alert_t_hunted_fetch_error(link, error)` — HTTP/сетевая ошибка при загрузке статьи.
3. **E033** — `alert_t_hunted_no_body(link)` — парсер не нашёл блок `<div class="post-body">` / `.entry-content`.

Выбор паттерна — три отдельных алерта вместо одного агрегатора (см. tech-spec Decision 3): источник низковолюменный (~2 поста/день), и оператору важно сразу понимать, что именно сломалось, без перепроверки `journalctl`. Подход 1:1 повторяет lamley E025-E028 (минус `_too_large`, так как Blogger не отдаёт огромные страницы).

Коды E031-E033 — следующие свободные после E030 (`alert_orangetrack_summary_header`) согласно code-research §A.5. E029 пропущен сознательно: это был «зарезервированный» зазор; реюзить его не будем, чтобы хронология последовательна была.

Это атомарная задача, не зависит от Task 1: парсер ещё не будет звать эти builder'ы в момент мерджа Task 2, но они должны существовать к моменту мерджа Task 1.

## What to do

   - `alert_t_hunted_fetch_error(link: str, error: str) -> str` с кодом `[E032]` — текст в стиле E027, severity 🟡, содержит ссылку и текст ошибки.
   - `alert_t_hunted_no_body(link: str) -> str` с кодом `[E033]` — текст в стиле E028, severity 🟡, содержит ссылку и упоминание "не найдено тело" / селектора `.post-body` или `.entry-content`.

## Details

**Files:**
- `admin_alerts.py` — текущее состояние: три блока source-fetcher-алертов (Mattel E020-E024, Lamley E025-E028, Orangetrack E030, см. строки 202-326). Lamley использует один builder на каждый failure-mode + предваряет каждый блоком `# ---------------------------------------------------------------------------` с описанием кода. Применить ту же структуру. Добавить три новые функции между концом lamley-блока (строка 317) и заголовочным комментарием E030 (строка 320). E030 должен остаться **последним** в файле (он — outlier-агрегатор, см. code-research §A.5 «Insertion ordering rationale»).
- `tests/test_admin_alerts.py` — текущее состояние: класс `TestAdminAlerts` (line 23) содержит тесты E001-E030 одной плоской последовательностью. Lamley-тесты (E025-E028) на строках 183-205, E030 на 207-214, `test_all_alerts_have_unique_codes` на 216-249. Добавить три новых теста перед `test_e030_orangetrack_summary_header`. Расширить `all_messages`-список (line 219+) тремя новыми вызовами — порядок: после `alert_lamley_no_body("x")` (line 241), перед `alert_orangetrack_summary_header(1)` (line 242).

**Dependencies:**
- Task 1 (parser) и Task 2 — обе в Wave 1, не зависят друг от друга.
- Не вводит новых пакетов; ничего из `requirements.txt` не трогаем.
- Не трогает SQLite, env vars, deploy plumbing.

**Edge cases:**
- Аргумент `error: str` в `alert_t_hunted_fetch_error` может содержать длинные traceback'и — но это уже забота вызывающего кода (парсер должен подавать `error_type` / краткое сообщение, как делает lamley в `alert_lamley_fetch_error`). На уровне builder'а — простой f-string, без обрезки.
- Аргумент `link` уже валидирован выше по стеку (SSRF allowlist в парсере) — но это не повод не выводить его в текст алерта, оператору нужно увидеть, какой именно URL не прошёл проверку (как в E025).
- Никакого `_redact_text` внутри builder'ов — `send_admin_notification` сам редактит payload (см. docstring файла, строки 1-20).

**Implementation hints:**
- Скопировать структуру `alert_lamley_host_rejected` (line 271-280) → подставить `[E031]`, «t-hunted», «t-hunted-парсера». Аналогично для E032 (с lamley E027) и E033 (с lamley E028).
- В E033 (`alert_t_hunted_no_body`) упомянуть селектор `<div class="post-body">` (а не `.entry-content` как в lamley) — это первичный селектор t-hunted-парсера, оператору этого якоря достаточно для триажа.
- Severity для всех трёх — `🟡` (warning, не critical): провал одной статьи не валит источник целиком, бот пропустит и пойдёт дальше — точно как у lamley.
- Сохранить структуру «заголовок\n\nПричина:\n\nЧто сделать:» — на этих подстроках висят интеграционные тесты других файлов (см. docstring `admin_alerts.py`).
