## Description

Подключить t-hunted как четвёртый источник на уровне конфигурации и фильтра boilerplate. Две независимые правки в одном таске, потому что обе тривиальны и тематически связаны (приём нового источника с португальским контентом):

1. **`feeds.json`** — добавить RSS-URL `https://t-hunted.blogspot.com/feeds/posts/default?alt=rss` четвёртой записью (4/5 entries, под текущим софт-лимитом). После мерджа `news_bot._fetch_rss_entries` начнёт читать ленту t-hunted каждый тик через существующий универсальный feedparser-путь — никакого нового кода не требуется.
2. **`boilerplate_filter.py`** — добавить блок из 10 `^`-якорных PT-регэкспов в конец `_BOILERPLATE_PATTERNS` (после существующего RU-блока). Покрывает Blogger-артефакты португальской локали (Compartilhar, Marcadores, Postado por, Assinar, Postagens mais antigas и т.д.), которые попадают в `paragraphs` при скрейпе шаблона Blogger. Защита — глобально применённые `^`-якорные регэкспы с уже действующей длинной отсечкой `_MAX_BOILERPLATE_LEN = 120` (Decision 4 — повторяет RU-precedent 2026-05-08, без per-language тегирования).

Wave 2 параллельно с Task 3 (news_bot wiring), Task 5 (тесты регистра), Task 6 (deploy plumbing). Функциональной зависимости от Wave 1 нет: feeds.json читается универсальным `_fetch_rss_entries`, а PT-патерны применяются `is_boilerplate` независимо от парсера. Парсер `t_hunted_source.py` (Task 1) вызовет `filter_boilerplate` уже с готовыми PT-паттернами после merge waves.

**Edge cases:**

- `^postagem$` (точное равенство строке без хвоста) vs `^postagem\b` (с word boundary) — выбираем `^postagem$` для минимизации FP: «postagem nova foi publicada» (реальная проза, начинается с postagem) не должна фильтроваться. Если в первых публикациях обнаружатся варианты «Postagem anterior», добавим отдельный паттерн как follow-up.
- `coment[áa]rio` — учитывает обе кодировки (UTF-8 normalized NFC `á` U+00E1 vs decomposed `a` + `́`). На практике Blogger отдаёт NFC; добавили `a` как fallback на случай нормализации фидпарсером.
- `^p[aá]gina` — аналогично, «Página» vs «Pagina» (если ASCII-фолбэк).
- `Leia mais` vs `Ler mais` — code-research §4.D помечает риск FP для `^ler\s+mais$`. Берём только `^leia\s+mais$` (короче список FP-кандидатов, Blogger использует именно «Leia mais»).
- 120-char длинная отсечка — все PT-патерны имеют префиксы 10-30 char, под безопасным потолком (см. code-research §4.C).
- RSS-URL для смок-проверки требует сетевого доступа. Если CI/локальная среда без интернета — это ожидаемо (skip smoke вручную с пометкой); pytest-юнит-тесты от сети не зависят.

**Implementation hints:**

- Шаблон для PT-блока — точная копия RU-блока (line 132-157 в boilerplate_filter.py): такой же блок-комментарий, такие же одиночные `re.compile(..., re.I)` записи, разделённые пустыми строками только при логической группировке (UI-метки vs nav-ссылки).
- Шаблон для `test_portuguese_patterns_filtered` — копия `test_russian_patterns_filtered` (line 94-95) с другим списком `@pytest.mark.parametrize`. Тот же `assert is_boilerplate(text) is True, f"expected boilerplate: {text!r}"`.
- Шаблон для ReDoS-теста — копия `test_redos_safety_long_buy_pattern` (line 185-195), но параметризованная по списку adversarial-входов (по одному на PT-паттерн). Используем `time.monotonic()` без `signal.alarm` (signal.alarm не работает на Windows-CI; monotonic+threshold — кросс-платформенно).
- JSON-правка `feeds.json` — ручная (4-строчный массив), либо через `python -c "import json; ..."` (но проще руками с сохранением форматирования соседних записей: 4 пробела отступ).
- При запуске smoke-команды `feedparser.parse(...)` — Blogger отдаёт Atom-feed по дефолту, поэтому URL содержит `?alt=rss` (форсим RSS). feedparser handles это нативно (Decision rationale + code-research §1).
