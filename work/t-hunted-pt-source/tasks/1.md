# Task 1: New parser module + unit tests

## Description

Создаём новый модуль-парсер `t_hunted_source.py` — четвёртый источник новостей для бота, парсит статьи с Blogger-блога `t-hunted.blogspot.com`. Структурно это «обрезанная» копия `lamley_source.py`: тот же контракт `fetch_*_article(link, session, notifier) -> dict | None`, тот же паттерн SSRF-allowlist, тот же flat-walk HTML-экстракшен через BeautifulSoup, но без всей Cloudflare/WAF/throttle-машинерии (Blogger её не требует) — итоговый размер ~150 LOC вместо лэмливских 380.

Парсер ходит на статью по HTTPS с allowlist'ом ровно одного хоста `t-hunted.blogspot.com` (строгое exact-match, без glob — это hard SSRF-гейт; диспатчер в `news_bot.py` использует permissive substring-check `'blogspot.com' in domain`, и именно эта функция отвечает за безопасность). Возвращает `{title, subtitle, paragraphs, images}` или `None` на любую ошибку (host-rejected / fetch-error / no-body). На каждый отказ дёргает `notifier` коллбек с alert-сообщением — конкретные builder'ы `alert_t_hunted_host_rejected/_fetch_error/_no_body` появятся в Task 2 (E031-E033), но контракт notifier'а уже определяем здесь.

Параллельно создаём companion-тестфайл `tests/test_t_hunted_source.py` с двумя классами: `TestFetchTHuntedArticle` (6 методов: базовый парс, HTTP-ошибка, missing body, image-limit, image-dedup для Blogger-суффиксов, порядок boilerplate-фильтра ДО subtitle-lift) и `TestHostAllowlist` (8 методов: allow t-hunted, reject других blogspot-сабдоменов, reject произвольных хостов, reject не-http схем, проверка notifier на rejected host, userinfo-атака, suffix-host-атака, subdomain-варианты). Всего ~14 методов. Все тесты — на mock'нутый `session.get`, без реальных HTTP-вызовов.

Это Wave 1 (foundation) — задача независимая (depends_on=[]), параллельно с ней идёт Task 2 (admin alerts). На её выходных артефактах строится Wave 2: Task 3 (`news_bot.py` wiring) импортирует этот модуль и роутит в него blogspot URL'ы в диспатчере `fetch_full_article`.

### Edge cases

- **Title-only пост** (нет реальных параграфов, только Blogger-футер «Marcadores: ...») → после `filter_boilerplate()` `paragraphs == []` → `subtitle = ""`, `paragraphs = []`. Caller в `news_bot.py:1764` отбросит entry по `not article.get('paragraphs')`. Корректное поведение.
- **HTML с `<h1>` БЕЗ `class="entry-title"`** — fallback цепочка title: `find("h3", class_="post-title") or find("h1", class_="entry-title") or find("h1")`. Если ни один не найден → `title = ""`. Caller отбросит entry.
- **Body найден, но в нём 0 `<p>/<li>/<h2-4>/<blockquote>`** (теоретически возможно если пост — одна большая `<div>` без структуры) → `paragraphs = []`, `subtitle = ""`. Caller отбросит entry. Notifier НЕ дёргается (no-body alert триггерится только при отсутствии body-обёртки, а не пустой content).
- **`<img>` теги с `data-src` вместо `src`** — игнорируем (фильтр `if not src.startswith("http")` отсеет). Blogger обычно использует прямой `src`, не lazy-loading.
- **Userinfo в URL (`http://t-hunted.blogspot.com@evil.com/x`)** — `urlparse(...).hostname` корректно возвращает `'evil.com'`, наш exact-match отвергает. Подтверждается тестом `test_rejects_userinfo_attack`.
- **Schema без слэшей (`https:t-hunted.blogspot.com/x`)** — `urlparse` может вернуть пустой hostname. Hard-reject через exact-match (None или '' не в `_ALLOWED_HOSTS`).
- **Очень большой response (>2MB)** — hard cap `_MAX_BYTES`, возвращаем `None` с WARN, БЕЗ alert (Blogger таких не отдаёт, это defensive).
- **Network timeout** — `requests.RequestException` ловится, `notifier(alert_t_hunted_fetch_error(...))` вызван, `None` возвращён.
- **`session=None`** (вызов без передачи session) — создаём свою через `requests.Session()`. Поведение идентично lamley.

### Implementation hints

- **Не копировать WAF-машинерию.** `lamley_source.py:80-330` — это retry-after / cool-down / blacklist / curl_cffi импersonation — НИЧЕГО из этого в `t_hunted_source.py` быть НЕ должно. Blogger не Cloudflared. Если соблазн «оставлю на всякий случай» — отвергнуть. Размер файла ~150 LOC vs lamley 380 — это by design.
- **Image dedup — главное отличие от lamley.** Lamley использует `src.split("?", 1)[0]` (стрипает query-params типа `?resize=1024`). Blogger хранит размер в path: `https://...googleusercontent.com/img/abc/=s1600/photo.jpg`. Поэтому: `base = re.sub(r'=s\d+(-c)?$', '', src.split("?", 1)[0])`. Регекс пишем с anchor `$` на конце — отрезает только trailing размер-маркер. Тест `test_image_dedup_strips_blogger_size_suffix` это закрепляет.
- **Порядок `filter_boilerplate` → subtitle-lift КРИТИЧЕН.** Если перепутать (сначала subtitle, потом filter) — на title-only постах Blogger-футер «Marcadores: ...» попадёт в subtitle, потому что filter применится уже после лифтинга. Тест `test_boilerplate_filter_applied_before_subtitle_lift` это закрепляет — он специально подсовывает «Marcadores: ...» как первый non-title параграф.
- **SSRF allowlist — exact match, точка.** `('t-hunted.blogspot.com',)` — tuple с одним элементом. НЕ glob `*.blogspot.com`, НЕ endswith, НЕ regex. Любая «гибкость» открывает дверь для `evil.t-hunted.blogspot.com.attacker.example`. Тесты `test_rejects_suffix_host_attack` и `test_rejects_subdomain_variants` это закрепляют.
- **Используй `parsed.hostname`, НЕ `parsed.netloc`.** `parsed.netloc` для `http://t-hunted.blogspot.com@evil.com/x` вернёт `'t-hunted.blogspot.com@evil.com'` — split на `:` сюда не поможет. `parsed.hostname` корректно вытащит `'evil.com'`.
- **User-Agent — простой.** `'Mozilla/5.0 (compatible; HotWheelsNewsBot/1.0)'` — Blogger не требует Chrome-импersonation. Этого достаточно, чтобы не быть auto-rejected как bot (некоторые CDN режут `python-requests/X.Y` дефолт).
- **Logger setup:** `logger = logging.getLogger(__name__)` — стандартный паттерн проекта. НЕ конфигурируем хендлеры локально (это глобальная ответственность `news_bot.py`).
- **Reference fixtures из code-research §C.1:**
  - SAMPLE_HTML с «Caça ao tesouro Pop Culture 2026» как title.
  - PT-параграфы «Mais um lançamento que vai agitar a galera dos colecionadores.» и «Os modelos chegam em packs de seis.»
  - Дубль-картинки `=s1600/photo1.jpg` и `=s640/photo1.jpg` (один файл, два размера) + `=s1600/photo2.jpg` (другой файл).
  - Хвост «Compartilhar no Facebook» и «Marcadores: Pop Culture, 2026» — должны быть отфильтрованы.
- **Тест-фикстура для image-limit:** генерируй HTML программно — `''.join(f'<img src="https://blogger.googleusercontent.com/img/{i}/=s1600/x.jpg" />' for i in range(15))` — 15 уникальных хостов, чтобы дедуп не схлопывал. Ассерт: `len(out['images']) == 10`.
- **Помни про монки-патч `admin_alerts.alert_t_hunted_*`** в conftest или setup методах класса. Без него `pytest tests/test_t_hunted_source.py` упадёт с `AttributeError: module 'admin_alerts' has no attribute 'alert_t_hunted_host_rejected'` до тех пор, пока Task 2 не смержен.
