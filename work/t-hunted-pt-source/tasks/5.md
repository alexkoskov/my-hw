## Description

Эта задача — тесты-обёртка вокруг wiring-правок из Task 3 (`news_bot.py`: `NETLOC_TO_SOURCE`, `SOURCE_HASHTAG_OVERRIDE`, `_source_hashtag`, dispatcher branch). Цель: зафиксировать на уровне юнит-тестов три инварианта, которые легко регрессируют при будущих правках:

1. **Реестр источников** (`NETLOC_TO_SOURCE` + `_resolve_source_name`) знает про `t-hunted.blogspot.com` и резолвит его в `'t-hunted'`. Существующие locked-set тесты (`test_has_exactly_the_five_keys`, `test_values_are_only_the_three_source_names`) были привязаны к старым размерам множеств — обе нуждаются в обновлении ассертов и переименовании (текущие имена становятся ложью после добавления 5-го ключа netloc и 4-го уникального source_name).
2. **Канальный хэштег** — `send_telegraph_teaser` для t-hunted URL выдаёт ровно строку `#thunted #news` (Decision 2: `SOURCE_HASHTAG_OVERRIDE`). Это закрывает R1 (Telegram отбрасывает дефисы в хэштегах) и R2 (наивный `parts[-2]` дал бы `#blogspot`).
3. **Dispatcher routing** — `fetch_full_article` при доменах с `blogspot.com` вызывает именно `t_hunted_source.fetch_t_hunted_article(link, …)`, а на незнакомых доменах возвращает `None`. Это юнит-уровневая защита от ошибочного порядка веток в if-цепочке (Risk: подмена ветки при будущей правке dispatcher'а).

Тесты — это **deliverable** (задача чисто тестовая, продакшн-кода она не трогает). После Task 3 wiring в `news_bot.py` уже на месте; здесь мы пишем тесты, которые без Task 3 падали бы.

NOTE: `tests/test_ux_guidelines_structure.py` создаётся в Task 7 (Wave 3), не здесь — его ассерты бьют по правкам в `ux-guidelines.md`, которые приходят в Task 7.

**Edge cases:**
- **Locked-set test rename.** Существующие имена методов (`test_has_exactly_the_five_keys`, `test_values_are_only_the_three_source_names`) после правок становятся ложью о содержимом. Обязательно переименовать — иначе будущий читатель запутается, и тесты-документация перестанут говорить правду.
- **mock-target path.** В `news_bot.py` t-hunted импортируется как `import t_hunted_source`, и dispatcher вызывает `t_hunted_source.fetch_t_hunted_article(...)`. Patch должен указывать на `news_bot.t_hunted_source.fetch_t_hunted_article` (где модуль используется) — это канонический "patch where it's used" паттерн.
- **Уникальность хэштега `#thunted`.** Telegram-парсер хэштегов — `[a-zA-Z0-9_]+`. `'thunted'` валидно (нет дефиса). Если кто-то в будущем поменяет на `'t-hunted'` в `SOURCE_HASHTAG_OVERRIDE`, наш ассерт `'#thunted #news'` сразу заметит.
- **Не дублировать существующие тесты.** Не пишите аналог `test_autoevolution`/`test_lamley` для t-hunted в полном объёме — `test_t_hunted_hashtag` достаточно. И не дублируйте `test_strips_www_prefix` — он source-agnostic.
- **`test_fetch_full_article_unknown_domain_returns_none`** не должен ассертить warning лог — это implementation detail (текущий код делает `logger.warning(f"No source handler for domain: {domain}")`, но это может меняться).

**Implementation hints:**
- `@patch('news_bot.t_hunted_source.fetch_t_hunted_article')` — самый чистый способ. Декоратор передаст `MagicMock` первым позиционным аргументом в test-метод после `self`.
- Если хочется pytest-style без `unittest.TestCase` — используйте `monkeypatch.setattr(news_bot.t_hunted_source, 'fetch_t_hunted_article', mock_fn)`.
- В Тесте 2 (unknown domain) минималистичный вариант — один ассерт `assert news_bot.fetch_full_article({'link': 'https://example.com/x'}) is None`. Если хочется hard guarantee — мок всех 5 fetchers, проверка `.called == False` у каждого.
- В `test_telegram.py` существующий стиль — `unittest.TestCase` с `self.assertEqual`. Соблюдайте этот стиль для нового теста (не смешивайте pytest `assert` и `self.assertEqual` в одном классе).
- В `test_sources_registry.py` стиль — pytest plain `assert`. Сохраняйте.
