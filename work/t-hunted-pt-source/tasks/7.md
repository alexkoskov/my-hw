## Description

`.claude/skills/project-knowledge/references/ux-guidelines.md` — это runtime system-prompt для каждого LLM-движка транскреации (Claude / OpenRouter / Gemini / OpenAI). Файл читается через `_llm_common._build_system_prompt` (`_llm_common.py:114`) и доставляется на сервер в составе deploy-bundle. Любая правка немедленно меняет тон и поведение канала на следующем cron-тике.

В рамках фичи `t-hunted-pt-source` мы добавляем четвёртый источник `t-hunted.blogspot.com` — Blogger-блог про Hot Wheels на бразильском португальском. Чтобы LLM не отбрасывал PT-вход и не калькировал коллекционерский жаргон, нужны три точечные правки в каноническом промпте + новый структурный тест-файл, фиксирующий эти правки от регрессии.

Правки **content-anchored** (анкер по содержанию, не по номеру строки), потому что номера строк дрейфуют между правками промпта в других фичах. Блок-цитата (system-prompt body, строки 20-41 на момент `f7bf56c`) — инвариант (см. строку 132 файла: «Any edit to this file must preserve the prompt text verbatim inside the blockquote»). Меняем **только** одно прилагательное внутри блок-цитаты (вход EN → EN/PT) и добавляем секции **вне** блок-цитаты.

Структурные тесты гарантируют, что правки не откатятся случайным merge'ем и переживут будущие refactor-правки промпта.

## Details

**Files:**
- `.claude/skills/project-knowledge/references/ux-guidelines.md` — **читается LLM как system prompt на каждом cron-тике после deploy**, поэтому правки чувствительны к точности. Сейчас файл содержит:
  - L1-3: header + ссылка на runtime entry-point `_llm_common.py:114`
  - L5-14: «Scope» таблица (где применяется guide)
  - L16-41: `## The system prompt` — содержит **блок-цитату** (`> ...` строки 20-41), которую LLM получает как свой role-prompt. Здесь живёт правка (a).
  - L43-59: «Operational checklist» (archived hw_review path)
  - L61-72: «Length + structure» (allowed-drops rule)
  - L74-103: `## Per-source style notes` с 3 под-блоками. После Mattel-блока (заканчивается на L102) — точка вставки для правки (b).
  - L104+: `## Red flags ...` — перед ним точка вставки для правки (c).
  - L132 (последняя строка файла): инвариант — «Any edit to this file must preserve the prompt text verbatim inside the blockquote.» **Соблюсти.**
- `tests/test_ux_guidelines_structure.py` (новый) — 4 функции `def test_*`. Использовать `pathlib.Path(__file__).resolve().parent.parent / '.claude' / 'skills' / 'project-knowledge' / 'references' / 'ux-guidelines.md'` либо аналогичный absolute-anchor. Не дублировать содержимое файла в тесте — все assertions работают через `Path.read_text(encoding='utf-8')` + substring/regex проверки.

**Dependencies:** нет (Task 7 не зависит от других Wave 3 / Wave 1-2 задач — `ux-guidelines.md` правки полностью изолированы; LLM-pipeline-runtime подхватит изменения после deploy без code-changes в `_llm_common.py` / `*_transcreation.py`).

**Edge cases:**
- **Блок-цитата невредима.** Если случайно тронуть любой другой `> ...` строки кроме widened sentence — это нарушит invariant L132 и сломает production LLM prompt. Регрессия будет тихая (LLM запросы продолжат идти, но качество просядет). Code-review должен это поймать.
- **Эмодзи U+1F7E4 (🟤 brown circle).** Скопировать как есть — UTF-8 4-byte sequence. Если IDE/редактор подменит на похожий-но-не-тот символ (например U+25CF black circle), тест `test_t_hunted_style_block_present` упадёт. Проверить hex-дамп при сомнениях.
- **Markdown table pipes.** Все 14 строк глоссария + header + separator должны иметь одинаковое количество `|` (5 — для 4 колонок). Один сдвинувшийся pipe ломает render.
- **TDD-светофор «красный → зелёный».** Сначала написать тесты, прогнать, **убедиться, что все 4 падают** (по правильным причинам — отсутствуют целевые строки/секции/слова). Потом править файл. Потом снова прогнать — должны позеленеть. Это защита от тестов, написанных под уже-сделанные правки и потому всегда зелёных.
- **PT диакритика в глоссарии.** Слова `Edição`, `Coleção`, `Série`, `Lançamento`, `Página` содержат `ç` / `ã` / `é` / `á` — UTF-8 multi-byte. Сохранять как есть.
- **`[TBD operator]` маркеры.** Оператор сам уточнит описания после первых 5-10 публикаций (Decision 5 / user-spec AC7 deferral). Заполнять их prosецифично сейчас — преждевременная оптимизация и ставит реалистично-выглядящие, но недостоверные характеристики канала.

**Implementation hints:**
- Структурные тесты должны быть **content-anchored**, не **line-anchored**. Никаких `assert lines[22] == '...'`. Использовать `'## Glossary — PT/EN/RU' in content` или regex по содержанию.
- Для подсчёта строк таблицы глоссария: split content на секции по `## `, найти секцию `Glossary`, внутри её содержимого посчитать строки, которые матчат `^\|.*\|.*\|.*\|.*\|$` (4 pipe-разделителя для 4 колонок), вычесть header (1) и separator (`|---|---|...`) (1). Получить `>= 10` — тест проходит. 14 entries в нашем плане → assertion с большим запасом.
- Для проверки «sentence has both ‘английский’ and ‘португальский’»: найти в файле абзац, начинающийся с «Твоя единственная задача» (это уникальный anchor по всему файлу), взять текст до следующей пустой строки или до конца `> ...` блока, проверить substring-присутствие обоих слов (case-insensitive). Это устойчиво к любой будущей формулировке внутри блок-цитаты, если она сохраняет оба языковых упоминания.
- **Canonical wording для widened sentence (НЕ менять, mirrors tech-spec Decision 5 verbatim):** `входящий текст (английский или португальский)` — это **noun form** («текст» — существительное), не adjective form. Структурный тест пропустит любой вариант, в котором встречаются оба слова, но семантически правильная и согласованная с tech-spec формулировка — **только эта одна**. Если будущий редактор увидит alternative wording в code-research.md (§5.A "англоязычный или португалоязычный", §A.4 другая форма) — это draft-варианты, **canonical = noun form в скобках**.
- Тест-файл — самый короткий из всех в Task 7's deliverables: один `Path.read_text` + 4 функции, ~50 LOC. Не нагружать abstractions.
- При вставке `### 🟤 t-hunted` блока следить за пустыми строками между подзаголовками — Markdown требует пустую строку перед `### `-заголовком, иначе он отрендерится в одной строке с предыдущим параграфом.
- При вставке таблицы глоссария: header row → separator row (`|---|---|---|---|`) → 14 data rows. Опциональная пустая строка перед таблицей.
- **Сначала запустить `pytest tests/test_ux_guidelines_structure.py -v` ДО правки `ux-guidelines.md`** — это проверит, что тесты падают по корректным причинам (TDD red), а не из-за синтаксической ошибки в самом тесте.

Основной deliverable — Markdown-промпт, читаемый LLM как role-prompt. Решения о формулировках («friend at a bar» vs «expert collector»), о деривации поля для per-source-блока, о точной формулировке «PT-EN-RU глоссарий vs PT/EN/RU словарь» — это работа с промптом, не с алгоритмами.
