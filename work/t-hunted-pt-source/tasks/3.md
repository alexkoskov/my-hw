## Description

Wires the new `t_hunted_source` parser (built in Task 1) into the existing `news_bot.py` infrastructure through five atomic, narrowly-scoped edits. This is the integration seam that makes a t-hunted RSS entry actually flow through the pipeline: import the module, register the netloc → `source_name='t-hunted'` mapping so `_resolve_source_name` stamps incoming entries correctly, dispatch blogspot URLs to the new parser inside `fetch_full_article`, route the Telegram channel hashtag through a new `SOURCE_HASHTAG_OVERRIDE` map so the post emits `#thunted` (and not the default `#blogspot` that the naive netloc-second-level logic would produce), and add the cosmetic `SOURCE_EMOJI` / `SOURCE_LABEL` entries that the archived `hw_review` CLI consumes (Decision 7 — implementation hygiene to keep the dicts symmetric across all 4 sources).

The edits are mechanical and isolated — no new logic beyond a single dict lookup; the hard SSRF gate lives inside `t_hunted_source._is_allowed_t_hunted_url` (Task 1), not here.

## What to do

1. **Import the new parser module.** Add `import t_hunted_source` to the source-module import cluster near the top of `news_bot.py` (currently lines 34-37, sibling to `mattel_news_source` / `autoevolution_source` / `lamley_source` / `orangetrack_source`). Place the new import after `import orangetrack_source` (line 37) and before `import telegraph_publisher` (line 38) to preserve the existing visual grouping of first-party source modules.

2. **Register the netloc → source_name mapping.** Add the entry `'t-hunted.blogspot.com': 't-hunted',` to the `NETLOC_TO_SOURCE` dict literal (currently lines 823-831). Insert it after the `corporate.mattel.com` entry (line 828) and before the `orangetrackdiecast.com` entry (line 829) so the visual grouping by source is preserved. Do NOT add a `www.t-hunted.blogspot.com` variant — Blogger 301-redirects bare-form, so no traffic legitimately arrives with the `www.` prefix.

3. **Introduce `SOURCE_HASHTAG_OVERRIDE` constant.** Immediately after the `NETLOC_TO_SOURCE` dict literal (line 831, before `_resolve_source_name` at line 834), define a new module-level constant:
   - Name: `SOURCE_HASHTAG_OVERRIDE`
   - Type: `Dict[str, str]` mapping netloc → full hashtag string (including `#` prefix and dash-stripped)
   - Seed entry: `'t-hunted.blogspot.com': '#thunted'`
   - Include a docstring/comment explaining the purpose (per code-research §F): defaults from `_source_hashtag` lift the TLD-stripped `parts[-2]`; this map handles outliers where `parts[-2]` is the hoster (`blogspot`) instead of the brand. Also note that Telegram hashtag rules accept only `[a-zA-Z0-9_]` so dashes are stripped at definition time, not by Telegram's parser.

4. **Patch `_source_hashtag` to consult the override map.** Modify `_source_hashtag` (currently lines 799-808) so it consults `SOURCE_HASHTAG_OVERRIDE` AFTER stripping the `www.` prefix and BEFORE falling through to the existing `parts[-2]` TLD-strip logic. The override is keyed on the normalised (www-stripped, lowercased) netloc and returns the dict value as-is. Existing sources (autoevolution / lamley / mattel) do not appear in the override map → fall through to the unchanged legacy branch → emit `#autoevolution` / `#lamleygroup` / `#mattel` byte-identically to current behaviour (Decision 2: no regression to other sources). Update the docstring to mention the override-first lookup.

5. **Add the dispatcher branch in `fetch_full_article`.** Inside the try-block at `fetch_full_article` (currently lines 1405-1444), add a new conditional branch routing blogspot URLs to the new parser. CRITICAL detail (per tech-spec): this dispatcher is an **if / return** chain, NOT an if/elif chain — each matched branch returns directly, so ordering vs. existing branches is independent (no fall-through). Place the new branch after the `autoevolution.com` branch (line 1438-1439) and before the closing `except Exception` (line 1440). Condition: `if 'blogspot.com' in domain:` — intentionally permissive substring check matching the existing convention (security gate lives in `t_hunted_source._is_allowed_t_hunted_url`, called via Task 1's parser). Body: `return t_hunted_source.fetch_t_hunted_article(link, notifier=send_admin_notification)` — mirrors the lamley call shape verbatim.

6. **Add archived-consumer dicts entries (Decision 7).** Append `'t-hunted': '\U0001F7E4',  # brown circle` to `SOURCE_EMOJI` (currently lines 857-862) and `'t-hunted': 'T-Hunted',` to `SOURCE_LABEL` (currently lines 863-868). These dicts are consumed only by the archived `hw_review.py` CLI (per code-research §1.A) — the entries keep the dicts symmetric across all 4 sources. `'T-Hunted'` mirrors the source's own capitalisation convention. The brown circle `🟤` (U+1F7E4) is the only unused warm-colour circle in the existing palette and is visually distinct from the orange `🟠` (autoevolution) / purple `🟣` (mattel) / green `🟢` (lamley) / blue `🔵` (orangetrack).

7. **Smoke-verify locally.** Run the Verify-smoke command (below) to confirm imports resolve, the override is consulted, and the resolver returns `'t-hunted'`.

**Dependencies:**

- No new pip packages; no new env vars; no SQLite migration

**Edge cases:**
- Hashtag spec: Telegram accepts `[a-zA-Z0-9_]` in hashtags but NOT `-`. The override map stores the already-normalised string `'#thunted'` (dash stripped at definition time, not at render time). This avoids a runtime regex / replace and keeps the override value WYSIWYG against what subscribers see.
- The dispatcher condition `'blogspot.com' in domain` is intentionally a permissive substring match — matches `t-hunted.blogspot.com`, `www.t-hunted.blogspot.com` (if it ever appears), and any future blogspot subdomain we might add. Security relies on `_is_allowed_t_hunted_url` inside the parser (Task 1's SSRF gate) — exact-match allowlist on `('t-hunted.blogspot.com',)`. Do NOT widen the dispatcher to `endswith` semantics or tighten the allowlist to a glob — the layering is deliberate (per code-research §1.C, §3.H).
- Override-map lookup must happen on the NORMALISED netloc (after `www.` stripping, lowercase). Otherwise a URL like `https://WWW.T-HUNTED.BLOGSPOT.COM/foo` would miss the override and fall through to `#blogspot`. Mirror the existing `netloc.startswith('www.')` strip ordering in `_source_hashtag`.
- The `\U0001F7E4` brown circle emoji literal must be inside a string literal (not as a raw glyph in source) for consistency with the existing entries (lines 858-861 all use `\U0001F7E0` / `\U0001F7E3` / `\U0001F7E2` / `\U0001F535` escape form).
- `SOURCE_HASHTAG_OVERRIDE` keys are netlocs (matching the `_source_hashtag` lookup), NOT source_names (`'t-hunted'`). Don't conflate with `NETLOC_TO_SOURCE` — they're parallel maps keyed on the same kind of value, but the override returns a hashtag string while NETLOC_TO_SOURCE returns an internal source_name.

**Implementation hints:**
- Edits are small; a careful sequence is: (1) write all 5 hunks; (2) run `python -c "import news_bot"` to catch SyntaxError / NameError; (3) run the Verify-smoke one-liner; (4) run `pytest tests/test_telegram.py tests/test_sources_registry.py -v` to catch regressions in existing sources.
- Tech-spec §Decisions Decision 2 is the canonical reference for the override-map shape and the rationale for preferring it over a `netloc.endswith('.blogspot.com')` special-case inside `_source_hashtag`.
- Tech-spec §Decisions Decision 7 is the canonical reference for the brown circle + `'T-Hunted'` label choices and why we add them despite the entries being consumed only by archived code (symmetry / future-proofing).
- The dispatcher is an if/return chain (each matched condition returns directly) — verified at code-research §A.1 and visible at `news_bot.py:1416, 1434, 1436, 1438`. There is no fall-through risk between branches, so the placement after `autoevolution.com` is positional convenience, not semantic.
- The existing comment block at `news_bot.py:819-822` notes "Kept intentionally separate from `_source_hashtag`" — that comment refers to the `NETLOC_TO_SOURCE` ↔ admin-ping vocabulary separation (e.g. `lamley` internally vs `#lamleygroup` in channel). The new `SOURCE_HASHTAG_OVERRIDE` keeps this principle intact: it's a separate map from `NETLOC_TO_SOURCE`, only consulted by `_source_hashtag`, only when the default would produce wrong output. Update or extend the comment block as needed for clarity.
