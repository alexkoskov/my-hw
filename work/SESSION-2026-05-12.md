## Two fixes shipped

### 1. mattel-anchor-count-tolerance (XS-size, write-code shortcut)

**Symptom.** `mattel_news_source - ERROR - [E021] 🔴 Mattel: парсер не
нашёл данные на странице` on every cron tick, with `Детали:
article2.entries not found`. Mattel listing fetch returned `[]`; bot
otherwise healthy — RSS sources still working.

**Root cause.** Mattel changed the live listing payload on 2026-05.
The literal anchor `_ARTICLE2_ANCHOR = '"article2":{"entries":['` no
longer matches because Mattel interpolates a `"count":440,` field
between the opening brace and the entries key. Curl-verified live at
2026-05-12 ~13:30 МСК: JSON-unescaped flight push #45 (963 KB) carries
`"article2":{"count":440,"entries":[{"body":"$63",...`.

**Fix.** Replace the literal anchor with a regex that permits up to 5
simple scalar-valued prefix pairs (number or short string) before the
`"entries":[` key:

```python
_ARTICLE2_ANCHOR_RE = re.compile(
    r'"article2"\s*:\s*\{'
    r'(?:"\w+"\s*:\s*(?:\d+|"[^"]*")\s*,\s*){0,5}'
    r'"entries"\s*:\s*\['
)
```

Updated `_find_entries_slice` to `re.search` + `match.end()-1` for the
array start. `_extract_listing_entries` uses regex `.search()` instead
of substring `in` test. Synthetic fixtures (`_make_flight_listing`)
gain an optional `count_field` parameter; the no-prefix form keeps
matching because `{0,5}` accepts zero repeats — existing tests stay
green.

Headroom: if Mattel adds another simple key like `"version":"v2",`,
the regex absorbs it without another emergency patch.

**Tests.** 1 new in `tests/test_mattel_news_source.py`:
`test_extracts_entries_when_article2_has_count_prefix` — exercises the
new live shape via the updated fixture. Fixture builder fix in
`tests/fixtures/mattel_flight_builder.py`.

**Verification.** Live `curl` against `corporate.mattel.com/news` +
stdlib regex sanity-check (no pytest in codespace) returned the
expected 6 entries (zero HW-relevant today — orthogonal to the bug).
Post-deploy test-instance log at 2026-05-12 14:03 МСК:
`Mattel news: 0 Hot Wheels entries found` — no error, no admin ping.

**Commit.** `c6405da` (squashed into `75b0edb` on main via PR #6).

### 2. orangetrack-checklist-url-slug-filter (XS-size, write-code shortcut)

**Symptom.** Prod silent at 10:00 МСК 2026-05-12. Plan-of-day ping:
1 article queued, slot 10:01. At 10:01:05 МСК:

```
[fallback] Claude per-article failure for .../hot-wheels-basics-2026-j-case-contents-checklist-for-mainline/:
ClaudeTranscreationError: OpenRouter response paragraphs appear to be
English — translation likely skipped (Cyrillic letter share below 30%)
— slot strike (next slot retries this row)
[slot 1/1] publish failed
[job] done. Published 0, carry-over 0, queue size now 1.
```

Only one slot for the day; no retry budget; channel dark.

**Why test posted but prod didn't.** Same code, same article, different
LLM stochastic output. Test's morning attempt returned `output_tokens
=700`, Cyrillic share above 30%, EN-leak guard passed, published.
Prod returned `output_tokens=561`, Cyrillic share below 30%, EN-leak
guard tripped. Lottery — not a code divergence between instances.
Lucky test draw masked the underlying issue.

**Root cause.** Orangetrack publishes a recurring URL pattern
`/hot-wheels-basics-{year}-{letter}-case-contents-checklist-for-mainline/`
(J today, H/G earlier in 2026, will continue with K, L...). Body is
typically ~4000 chars (well above the 500-char `_CHECKLIST_BODY_TEXT_
FLOOR` from 2026-05-08), but ~80% of those chars are proper nouns
(car model names + manufacturer codes). The LLM correctly leaves
proper nouns in English; the result fails the EN-leak guard. The
existing title+body filter (`_is_text_only_checklist`) catches the
title-says-checklist-AND-body-empty case but not the
title-says-checklist-AND-body-padded-with-car-names case.

**Fix.** Add URL-slug trigger A to `_is_text_only_checklist`,
independent of body length:

```python
_CHECKLIST_URL_RE = re.compile(r'case-contents-checklist', re.IGNORECASE)

def _is_text_only_checklist(entry, article):
    link = entry.get('link') or ''
    if _CHECKLIST_URL_RE.search(link):
        return True
    # ... unchanged title + body check (now labelled trigger B)
```

Pattern is narrow: exactly the substring `case-contents-checklist`.
Doesn't catch `case-report` URLs (e.g. team-transport-K which shipped
successfully on 2026-05-06 — it has real editorial content). Doesn't
catch other source domains since the pattern is orangetrack-specific.

**Tests.** 3 new in `tests/test_relevance_filter.py`:
- `test_orangetrack_case_contents_checklist_slug_dropped_regardless_of_body`
  — prod regression with 4000-char body
- `test_orangetrack_h_case_contents_checklist_also_dropped`
  — mixed-case URL coverage
- `test_case_report_slug_is_not_caught_by_url_trigger`
  — negative: `case-report` stays in

9-case stdlib-only sanity-check ran locally (positive + negative +
edge); all 9 passed. CI on push to dev was green (CI #91, CI #92).

**Commit.** `768dbbd` (squashed into `75b0edb` on main via PR #6).

## Operator-side actions

### Cleaned zombie row in prod pending_articles

The failing J Case Checklist was staged on prod with `attempt_count=1`
before the fix landed. The new URL-slug filter operates at fetch-time
(step b3 in `job()`), so an already-staged row goes untouched. Without
manual cleanup the row would have absorbed slot 1 on 2026-05-13 and
2026-05-14 (strike 2 and 3) before reaching `failed_articles` — and
potentially blocked two more silent days if no other fresh articles
appeared.

SQL run on prod VPS (`hwbot@148.135.207.54`, `/home/hwbot/bot/news.db`)
BEFORE the prod deploy:

```sql
BEGIN IMMEDIATE;
INSERT OR IGNORE INTO processed_news (link, title, pub_date, processed_at)
  SELECT link, title, pub_date, datetime('now')
  FROM pending_articles
  WHERE link LIKE '%j-case-contents-checklist%';
DELETE FROM pending_articles
  WHERE link LIKE '%j-case-contents-checklist%';
COMMIT;
```

Result: 1 row moved, `pending_articles` empty, `processed_news` entry
at `2026-05-12 11:18:52`. The dedup machinery will treat the link as
already-handled — won't re-fetch even though it stays in the RSS feed.

## Decisions across the session

- **Single PR for both fixes** (#6) — both surgical, regression-tested,
  zero state-divergence risk. Title bundles both: «fix: Mattel anchor
  + orangetrack case-contents-checklist filter».
- **Squash-merge** vs regular merge — collapses the 2 dev commits into
  1 main commit (`75b0edb`) for clean main history. `dev` reset to
  main after, per standard post-squash hygiene.
- **Full test → confirm → prod pipeline** — not direct main hotfix.
  Both fixes had observable test-instance evidence (Mattel:
  `Mattel news: 0 Hot Wheels entries found` at 14:03 МСК; filter:
  logic spot-checked, no live case-contents-checklist URL in test
  feed today to exercise live).
- **Filter is narrow, not broad** — only `case-contents-checklist`
  substring. Considered `case-report` inclusion but rejected: those
  posts have real editorial content (verified by team-transport-K
  which shipped 2026-05-06). If a future pattern emerges, extend
  `_CHECKLIST_URL_RE` then.
- **Pre-commit bypass with `--no-verify`** — codespace lacks pip /
  pre-commit; explicit operator approval obtained before each commit.
  CI on dev branch ran the same checks unconditionally.
