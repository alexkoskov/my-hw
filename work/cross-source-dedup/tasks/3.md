# Task 3: Admin-ping builders E014, E015, E016

## Required Skills

Перед выполнением задачи загрузи:

## Description

Добавить в `admin_alerts.py` три новых pure-builder функции для алертов кросс-сорс дедупа (Decision 7 техспека). Каждый builder — это чистая функция `(...) -> str` без I/O, мирорит существующий E006-паттерн (1 источник правды для текстов админ-пингов, грепаемые коды `[E0XX]`).

Три новых события:
- **E014 — `🤔 Похож на дубль`** — soft-flag (overlap 30-49%): полный колоночный формат со ссылками, источниками, процентом совпадения, списком общих моделей. Мирорит verbosity E006. Per-pair rate-limit на 7 дней (применяется в Wave 2 в `news_bot.job()`, сам builder rate-limit не знает).
- **E015 — `🚫 Заблокирован дубль`** — hard-block visibility (overlap ≥50%): короткий 2-3 строчный формат. Без блока «Что сделать» — действие оператора опциональное (статья уже отброшена). Не rate-limited (каждый блок — отдельная новость).
- **E016 — `⚠️ Дедуп в degraded mode`** — AC9 fallback notification: короткий алерт с типом исключения. Globally rate-limited на 1 час в `news_bot.job()`, сам builder rate-limit не знает.

В `tests/test_admin_alerts.py` добавить три unit-теста по паттерну `test_e006_duplicate_publish_skipped` (`tests/test_admin_alerts.py:68-76`): проверка кодового префикса `[E0XX]`, severity-эмодзи, ключевых подстрок (русский заголовок дословно, входные параметры в тексте).

Эта задача — Wave 1, не зависит ни от каких других задач. Wave 2 Task 4 будет импортировать эти три builder'а и вызывать `send_admin_notification(alert_xxx(...))` из `news_bot.job()` в dedup-гейте.

**Dependencies:**

- Wave 2 (Task 4) импортирует эти три builder'а и вызывает их из `news_bot.job()` dedup-гейта — Task 3 их клиент.

**Edge cases:**
- `models=[]` для E014 — должен корректно отрендерить «Общие модели:» без падения (пустая строка под заголовком). Тест может не покрывать пустой список (типичный кейс — non-empty при overlap 30-49%), но реализация не должна падать.
- `overlap_pct` — целое (`int`), не float. Из техспека сигнатура: `overlap_pct: int`. В тестах подставляем `35`, `72`.
- `reason` — короткая строка типа `'AttributeError'` или `'JSONDecodeError'` (из `type(exc).__name__`); не ожидается многострочный traceback.
- E015 без «Что сделать» — оператор уже ничего не сделает (статья отброшена, ссылка в `processed_news`). `assertNotIn("Что сделать", msg)` в тесте пинит это намерение.

**Implementation hints:**
- E006 (admin_alerts.py:95-107) — ближайший паттерн для E014: блоки `Ссылка:\n{link}\n\nЧто произошло:\n…\n\nЧто сделать:\n…`.
- Шаблон E014 расписан в code-research.md §3.4 — можно использовать структуру дословно (новая статья / похож на / источники / совпадение / общие модели / что произошло / что сделать).
- E015 — самый короткий из трёх, без «Что сделать». Структура: заголовок, ссылка-новая (отброшена), ссылка-существующая (канон), одна строка с процентом. Аналог E009 `alert_quiet_day` (одна строка) по краткости, но с тремя информационными строками.
- E016 — middle ground: заголовок + причина + короткое «Что произошло» + короткое «Что сделать». **ВАЖНО:** шаблон `alert_dedup_extractor_crash(link, error_type)` в code-research.md §14.K.3 (lines 1393-1408) — устаревший draft и НЕ ИСТИНА. Реализуем строго по контракту техспека Decision 7:
  - **Имя функции:** `alert_dedup_degraded` (не `alert_dedup_extractor_crash`).
  - **Сигнатура:** `(reason: str) -> str` — один параметр (не два; никакого `link` нет).
  - **Severity-эмодзи:** `⚠️` (не `🟡` из шаблона §14.K.3).
  - **Заголовок (substring-якорь):** содержит `"Дедуп в degraded mode"` (не `"Дедуп упал (degraded mode)"` из §14.K.3).
  - Интеграционные тесты Wave 2 (Task 4) и `test_e016_dedup_degraded` пинят эти точные подстроки — отклонение завалит тесты. Структуру блоков «Что произошло» и «Что сделать» из §14.K.3 можно переиспользовать как стартовый текст, но имя/сигнатура/эмодзи/заголовок — строго по техспеку.
- Russian columnar формат (patterns.md): блоки через `\n\n`, заголовок блока ставим отдельной строкой (`Что произошло:\n…`), список моделей через `"\n".join(models)` под заголовком «Общие модели:».
- Все builder'ы — pure: никаких logger calls, никаких I/O, никаких глобальных переменных. Только параметры → строка.
- В тестах substring-якоря (`'Похож на дубль'`, `'Заблокирован дубль'`, `'degraded'`) сохраняем дословно — на них будут висеть интеграционные тесты Wave 2 (Task 4) и потенциально rate-limit-логика news_bot.
