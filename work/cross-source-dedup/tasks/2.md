# Task 2: Schema migration + repo helpers + rate-limit helpers

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Подготовить хранилище данных для cross-source dedup-фичи: добавить колонку `model_fingerprint TEXT` на обе таблицы (`pending_articles` + `published_articles`) идемпотентной миграцией, расширить `insert_pending` под новое поле (backward-compatible), добавить 3 query/write-хелпера для чтения окна и записи fingerprint в published, и 4 хелпера-обёртки над `bot_state` для rate-limit (per-pair soft-flag 7 дней + global degraded-mode 1 час). Все запросы — только через `?`-параметризацию (соблюдаем `TestSqlAudit::test_parameterized_queries_only` из существующих тестов). Schema-pin тесты обновляются под новую форму обеих таблиц.

Эта задача — фундамент Wave 1: без миграции и хелперов Task 4 (wire dedup gate в `news_bot.job()`) и Task 5 (backfill script) не смогут писать/читать fingerprint и rate-limit-стейт. Task 1 (model_extractor) и Task 3 (admin alerts) от этой задачи не зависят и идут параллельно.

## What to do

1. **Расширить миграцию в `init_schema`** (`pending_articles_repo.py:185-194`) — добавить в существующий `for ddl in (...)` блок две новые DDL-строки: `ALTER TABLE pending_articles ADD COLUMN model_fingerprint TEXT` и `ALTER TABLE published_articles ADD COLUMN model_fingerprint TEXT`. Тот же `try/except sqlite3.OperationalError` гарантирует идемпотентность (Decision 11). Двойной вызов `init_schema(conn)` не должен бросать.
2. **Зарегистрировать новую JSON-колонку в `_PENDING_JSON_COLS`** — добавить `'model_fingerprint'` в существующий tuple (`pending_articles_repo.py:118`). Это включает автоматическую десериализацию dict-формы `{"strict":[...], "brands":[...]}` через `_row_to_dict` при чтении.
3. **Расширить `insert_pending(entry)`** — добавить в INSERT statement колонку `model_fingerprint` и в VALUES — `_dumps(entry.get('model_fingerprint'))`. NULL-preserving семантика (см. Decision 5: NULL = «не обработано»; `{"strict":[],"brands":[]}` = «обработано, брендов нет»). Существующие callers без поля `model_fingerprint` получают NULL — это и есть backward-compat.
4. **Добавить 3 новых query/write-хелпера** в публичный API модуля (под существующими `Reads` / `Transactional moves` секциями):
   - `list_recent_pending_fingerprints(conn, days=7) -> list[dict]` — SELECT link, source_name, title, model_fingerprint FROM pending_articles WHERE fetched_at >= datetime('now', ? || ' days'). Параметр окна через `?`-плейсхолдер (значение `-{days}`). Десериализует `model_fingerprint` JSON в dict.
   - `list_recent_published_fingerprints(conn, days=7) -> list[dict]` — то же на `published_articles` (published_at вместо fetched_at).
   - `update_published_fingerprint(conn, link, fingerprint) -> None` — UPDATE published_articles SET model_fingerprint=? WHERE link=?. Используется backfill-скриптом (Task 5). `fingerprint` сериализуется через `_dumps`.
   Все три функции принимают `conn` явно (не `_connect()` внутри) — это согласовано с tech-spec §Interfaces и нужно для backfill-скрипта, который держит свою долгую транзакцию.
5. **Добавить 4 rate-limit хелпера**, работающие через существующую таблицу `bot_state` (key/value), мимикрирующие паттерн `outage_state.py`:
   - `is_pair_rate_limited(conn, new_link, existing_link, window_days=7) -> bool` — читает `bot_state[softflag_pair:{new}\n{existing}]`, парсит ISO-8601 timestamp, возвращает True если разница `now - last_ping < window_days`. Корректно обрабатывает отсутствие ключа (False), некорректное значение (False + logger.warning, не падать).
   - `mark_pair_pinged(conn, new_link, existing_link) -> None` — UPSERT (`INSERT OR REPLACE`) ключа `softflag_pair:{new}\n{existing}` со значением `datetime.now(timezone.utc).isoformat()`.
   - `is_dedup_degraded_rate_limited(conn, window_hours=1) -> bool` — то же для ключа `dedup_degraded_last_pinged_at`, окно по часам.
   - `mark_dedup_degraded_pinged(conn) -> None` — UPSERT ключа `dedup_degraded_last_pinged_at`.
   Ключ pair использует `\n` как сепаратор (не `:` / `/` — они встречаются в links). Decision 6 фиксирует форму.
6. **Обновить schema-pin тесты:**
   - `tests/test_pending_articles_repo.py::EXPECTED_PENDING` — добавить `'model_fingerprint'` (type TEXT, nullable, no default).
   - `tests/test_pending_articles_repo.py::EXPECTED_PUBLISHED` — то же добавление.
   - `tests/test_migration.py::EXPECTED_PENDING_COLUMNS` — добавить `model_fingerprint`. Если в файле есть `EXPECTED_PUBLISHED_COLUMNS` — обновить и его.
7. **Добавить unit-тесты для 7 новых хелперов** (см. tech-spec §Testing Strategy → unit tests):
   - SQL parametrization — все новые запросы используют только `?`-плейсхолдеры. Покрывается существующим `TestSqlAudit::test_parameterized_queries_only` — нужно убедиться что зелёный.
   - Recent-window filtering — для каждого `list_recent_*`: засеять N строк (половина внутри 7-дневного окна, половина старше), убедиться что возвращается только in-window subset.
   - Rate-limit window expiry — 3-шаг: `mark_pair_pinged(...)` → `is_pair_rate_limited(...) == True` сразу → fast-forward >1h / >7d (через прямой UPDATE строки `bot_state` со старым timestamp) → `is_pair_rate_limited(...) == False`. Аналогично для `is_dedup_degraded_rate_limited`.
   - Independent pair tracking — `mark_pair_pinged(A, B)` не делает `is_pair_rate_limited(C, D) == True`. Pair ключи независимы.
   - JSON-column roundtrip — `insert_pending` с `model_fingerprint={"strict": ["toyota 4runner"], "brands": ["toyota"]}` → `get_pending(link)['model_fingerprint']` возвращает тот же dict (НЕ str). Это пинит `_PENDING_JSON_COLS` от типографских опечаток.
   - Backward-compat — `insert_pending` без поля `model_fingerprint` в `entry` работает как раньше, NULL-значение в БД, не бросает.
   - Migration idempotency — двойной вызов `init_schema(conn)` не бросает; покрывается также через `tests/test_migration.py`.

**Dependencies:** нет (Wave 1, `depends_on=[]`). Tasks 4 и 5 зависят от результата этой задачи.

**Edge cases:**
- Двойной вызов `init_schema` на уже мигрированной БД — `sqlite3.OperationalError` ловится и подавляется существующим `except` блоком (тот же паттерн что для `telegraph_url`-миграции).
- `entry` без поля `model_fingerprint` в `insert_pending` — `entry.get('model_fingerprint')` → None → `_dumps(None)` → None → NULL в БД (backward-compat для существующих callers до Task 4).
- Pair-rate-limit ключ должен использовать `\n` как сепаратор (links содержат `:` и `/`, что иначе ломало бы парсинг или вводило двусмысленность). Decision 6 явно фиксирует это.
- `bot_state` value с corrupted timestamp (manual edit, миграция между форматами) — `_parse_dt`-аналог должен возвращать None + logger.warning, а функция `is_pair_rate_limited` должна интерпретировать None как «нет последнего ping» → False (не блокируем). Паттерн один-в-один с `outage_state.py:160-172`.
- `list_recent_*` функции принимают `conn` явно (не открывают свой) — backfill-скрипт (Task 5) хочет держать одну долгую транзакцию. Согласовано с tech-spec §Interfaces.
- 7-дневное окно через SQL `datetime('now', ? || ' days')` с параметром-строкой `'-7'` — тот же паттерн, что в `list_pending_stale` (`pending_articles_repo.py:443-444`).
- Distinct empty fingerprint vs NULL: NULL = «не обработано/не attempted»; `{"strict":[],"brands":[]}` = «обработано, брендов нет». Tasks 4 и 5 используют это различие — наш `_PENDING_JSON_COLS` должен корректно различать (NULL → None, `'{"strict":[],"brands":[]}'` → dict, не пустая строка).

**Implementation hints:**
- Миграция: вместо нового `for ddl in (...)` блока — добавить две новые DDL-строки в существующий tuple (`pending_articles_repo.py:185-188`). Минимальная diff-площадь.
- Rate-limit хелперы: вынести `_KEY_SOFTFLAG_PAIR_PREFIX = 'softflag_pair:'` и `_KEY_DEDUP_DEGRADED = 'dedup_degraded_last_pinged_at'` как module-level constants для тестируемости.
- Для timestamp используйте `datetime.now(timezone.utc).isoformat()` (tz-aware, как в `outage_state._serialise_dt`). Парсинг — `datetime.fromisoformat(raw)`. Сравнение окна — `now - last < timedelta(days=window_days)` / `timedelta(hours=window_hours)`.
- Тесты на window-expiry: проще всего через прямой `INSERT INTO bot_state` (или UPDATE после `mark_*`) со старым timestamp вместо patch `datetime.now` — короче и нагляднее, и согласуется с паттерном тестов `outage_state`.
- Тесты на `list_recent_*` window: вместо timestamp-mock использовать `conn.execute("UPDATE ... SET fetched_at=?", (old_iso,))` — прямое смещение даты строки. Это короче, чем фричить часы.
- JSON-roundtrip тест: `entry = {..., 'model_fingerprint': {'strict': ['toyota 4runner'], 'brands': ['toyota']}}` → `insert_pending(entry)` → `result = get_pending(entry['link'])` → `assert result['model_fingerprint'] == entry['model_fingerprint']` и `assert isinstance(result['model_fingerprint'], dict)`. Второй ассерт критичен — ловит опечатку в `_PENDING_JSON_COLS`.
- Не вводить новые внешние зависимости (tech-spec AC). Stdlib только (`json`, `sqlite3`, `datetime` уже импортированы в `pending_articles_repo.py` или будут добавлены).
- Имена ключей, форматы значений и тестовый паттерн полностью cohere с `outage_state.py` — копировать, не изобретать.
