## Description

Финальный шаг доставки фичи cross-source dedup на прод. Деплой делает оператор локально через `./deploy.sh` (SCP-based bundle на VPS `hwbot@148.135.207.54:/home/hwbot/bot/`). Никакого нового кода в этой задаче не пишется — задача организационная: подготовить deploy-бандл (убедиться что `deploy.sh` FILES list содержит новые top-level файлы), сообщить оператору команду запуска и шаги пост-деплой верификации схемы.

Контекст почему это важно: `news_bot.py` импортирует `model_extractor` при старте; если файл не попал в FILES list — первый же тик крона на прод-VPS упадёт с `ImportError` (без сигнала из CI). Аналогично, `backfill_fingerprints.py` нужен оператору на VPS для закрытия cold-start окна (7 дней без исторических fingerprints) — без него фича работает, но первую неделю не блокирует дубли.

Миграция схемы (ALTER TABLE для `model_fingerprint TEXT` на `pending_articles` и `published_articles`) применяется автоматически на первом тике крона через `init_db()` (Decision 11 — `try/except sqlite3.OperationalError`). Ручных шагов на VPS оператору не требуется кроме SCP и (опционально, в Task 11) запуска backfill.

Альтернативный путь — push в `main` → GitHub Actions (`deploy.yml`). Этот путь тоже должен работать после Task 5 (Task 5 уже обновил `deploy.sh` FILES list; GitHub Actions workflow `deploy.yml` использует точно такой же FILES list, поэтому INVARIANT из `deployment.md` соблюдён). Но оператор предпочитает локальный `./deploy.sh` (см. memory `feedback_operator_prod_ops.md` — оператор управляет прод-операциями, Claude готовит, оператор применяет).

```bash

git checkout dev
git pull
# (опционально) проверить тесты
python3 -m pytest tests/ -q
# Деплой (env vars обязательны!):
SSH_HOST=hwbot@148.135.207.54 DEPLOY_PATH=/home/hwbot/bot ./deploy.sh
# (SCP всех FILES, потом pip install --user -r requirements.txt на VPS)
# Restart сервиса вручную после SCP:
ssh hwbot@148.135.207.54 "sudo systemctl restart news_bot.service"
```

Путь B — GitHub Actions (если оператор предпочтёт автомат):

**Edge cases:**
- Первый тик после деплоя падает с `ImportError: No module named 'model_extractor'` → значит файл не попал на VPS. Проверить через `ssh hwbot@... "ls /home/hwbot/bot/model_extractor.py"`. Если файла нет — пересобрать `deploy.sh` FILES list и перезапустить деплой.
- `sqlite3 ... ".schema"` показывает таблицу без `model_fingerprint` после первого тика → значит `init_db()` не отработал ALTER. Маловероятно (try/except sqlite3.OperationalError у нас на ALTER), но если случилось — посмотреть `journalctl -u news_bot.service` за момент рестарта, искать SQL exception. Workaround — ALTER вручную:
  ```bash
  ssh hwbot@148.135.207.54 "sqlite3 /home/hwbot/bot/news.db 'ALTER TABLE pending_articles ADD COLUMN model_fingerprint TEXT; ALTER TABLE published_articles ADD COLUMN model_fingerprint TEXT;'"
  ```
- Если оператор предпочитает Путь B (GitHub Actions через main) — изменения должны быть смёрджены `dev → main` через `git merge` (default fast-forward ОК).
- Если в момент деплоя SQLite база заблокирована тиком крона (Pre-Deploy Checklist: «Any currently running `news_bot.py` process stopped before file copy») — `systemctl stop news_bot.service` ДО SCP не требуется (cron-driven, не daemon), но если оператор видит «Text file busy» — попросить дождаться окончания тика и повторить.

**Implementation hints:**
- Перед тем как сказать оператору «деплой готов к запуску», запустить локальный pre-flight: `bash -n deploy.sh && for f in model_extractor.py backfill_fingerprints.py news_bot.py pending_articles_repo.py admin_alerts.py; do [ -f "$f" ] || echo "MISSING $f"; done`. Все пять MUST exist (новые + изменённые).
- В сообщении оператору указать конкретное окно деплоя — желательно вне 10:00 МСК ±15 мин (cron tick window), чтобы не словить SQLite lock.
- После деплоя посоветовать оператору не запускать сразу `backfill_fingerprints.py` (это Task 11) — сначала дождаться первого тика крона чтобы убедиться что миграция отработала и `news_bot.service` не падает.
- Помнить про memory `feedback_operator_prod_ops.md`: SSH сам не делать, секреты не печатать, готовить — оператор применяет.
