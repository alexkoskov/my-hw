## Description

Cold-start filler. The dedup gate added in Task 4 compares each new article against fingerprints from the last 7 days of `pending_articles` + `published_articles`. На момент деплоя `published_articles.model_fingerprint` пустой у всех исторических строк — гейт ничего не найдёт и не заблокирует первые ~неделю настоящих кросс-источниковых дублей. Этот one-shot скрипт закрывает разрыв: один раз после деплоя (плюс возможные повторы) ре-скачивает HTML опубликованных статей за окно `--days N` (по умолчанию 14), пропускает через `model_extractor.extract_fingerprint`, и записывает результат в новую колонку `model_fingerprint` через `update_published_fingerprint` (helper из Task 2).

Идемпотентность — единственный критерий «закончил»: канонический маркер «не обработано» — `model_fingerprint IS NULL`. Computed-empty `{"strict":[],"brands":[]}` — это терминальное состояние (статья без брендов, либо удалена из источника), повторно не трогать. Исключение при fetch (Cloudflare 403, network timeout) — оставляет NULL для retry на следующем запуске.

Скрипт следует форме `hw_review.py` (Decision 10): `argparse`, top-level CLI, `main(argv=None) -> int`, `if __name__ == '__main__': sys.exit(main())`. Convention: `import news_bot` в самом верху файла (до `logging.basicConfig()` в `main()`) — `_TokenRedactingFilter` устанавливается безусловно на import news_bot (news_bot.py:344), так что технически порядок не ломает редакцию; держим конвенцию, совпадающую с `hw_review.py`, для консистентности и future-proofing на случай, если import-side-effect news_bot или порядок basicConfig изменятся.

Параллельно обновляется `deploy.sh` FILES list — добавляются оба новых top-level файла (`model_extractor.py` из Task 1 и `backfill_fingerprints.py`). Без этого первый cron-tick на VPS упадёт с `ImportError: No module named 'model_extractor'`, потому что `news_bot.py` импортирует его при старте.

## What to do

1. **Create `backfill_fingerprints.py`** at repo root (рядом с `hw_review.py`, `news_bot.py`).
   - Docstring: что делает скрипт, когда запускать, контракт идемпотентности (NULL vs computed-empty).
   - **Import order — конвенция:** `import news_bot` на верху файла, до `logging.basicConfig(...)` в `main()`. `_TokenRedactingFilter` ставится безусловно при import news_bot (news_bot.py:344), поэтому фильтр прикрепится в любом случае — порядок здесь про консистентность с `hw_review.py` и future-proofing (если когда-нибудь изменится либо side-effect news_bot, либо порядок наших вызовов, мы не словим регрессию).
   - argparse `_build_parser()`:
     - `--days N` — int, default 14. Кламп в `[1, 90]` (защита от опечатки `--days 9000`). Реализовать через `type=` custom callable, который raise'ит `argparse.ArgumentTypeError` если вне диапазона.
     - `--dry-run` — store_true. Вычислять fingerprints, но не вызывать `update_published_fingerprint`.
     - `--verbose` — store_true. `logging.DEBUG` вместо `INFO`.
   - `main(argv=None) -> int`:
     - Парсит args, открывает sqlite connection (через тот же путь, что использует `news_bot` — обычно `news.db` в CWD или env var; проверь как `hw_review.py` это делает).
     - Вызывает `init_schema(conn)` для гарантии что миграция применена (на dev-машине могла не запускаться).
     - SELECT `link`, `source_name`, `title` FROM `published_articles` WHERE `published_at >= datetime('now', ? || ' days')` AND `model_fingerprint IS NULL` (binding для days через `?`, не f-string).
     - Per row: вызвать `backfill_one(row, dry_run=args.dry_run)` (helper ниже), aggregate в counters.
     - 1-секундная `time.sleep(1)` между fetches (rate-limit defense vs Cloudflare).
     - В конце — print summary (см. Details).
     - Return 0.
   - `backfill_one(row, *, dry_run) -> str` (возвращает `'updated' | 'skipped' | 'empty-fp' | 'error'`):
     - Если `row.get('model_fingerprint') is not None`: return `'skipped'` (защита от race — SELECT отсёк, но повторно проверяем).
     - Построить `entry_stub = {'link': row['link'], 'source_name': row['source_name'], 'title': row.get('title') or '', 'published': ''}`.
     - `try: article = news_bot.fetch_full_article(entry_stub)`. На исключение → log via `logger.error("backfill failed for %s: %s", link, exc)`, return `'error'`. **NULL остаётся** — на retry.
     - Если `article is None` или `not article.get('paragraphs')`: `fp = {"strict": [], "brands": []}`. Если не dry_run — `repo.update_published_fingerprint(conn, link, fp)`. Return `'empty-fp'`.
     - Иначе: `fp = model_extractor.extract_fingerprint(article)`. Если не dry_run — `repo.update_published_fingerprint(conn, link, fp)`. Return `'updated'`.
   - `if __name__ == '__main__': sys.exit(main())`.

3. **Create `tests/test_backfill_fingerprints.py`** — pytest-style, mirror структуры `tests/test_hw_review.py`:
   - Use `tmp_path` + in-memory или file sqlite to seed `published_articles` rows.
   - Helper: `_seed_published(conn, link, published_at, model_fingerprint=None)` — INSERT row напрямую.
   - **TDD anchors:**
     - `test_idempotency_second_run_processed_zero` — seed N rows, fp=NULL. Run main(). Run main() второй раз. Assert второй run возвращает 0 и summary `Processed: 0`.
     - `test_days_window_honored` — seed 2 rows: одна published_at = now, одна published_at = `datetime('now', '-30 days')`. Run main(['--days', '7']). Assert обработана только свежая (vary, mock fetch чтобы вернуть paragraphs).
     - `test_dry_run_writes_nothing` — seed 1 row. Run main(['--dry-run']). Assert `SELECT model_fingerprint FROM published_articles WHERE link=?` всё ещё NULL.
     - `test_fetch_exception_leaves_null` — seed 1 row, monkeypatch `news_bot.fetch_full_article` чтобы raise ConnectionError. Run main(). Assert fp всё ещё NULL, counter `Errors: 1`.
     - `test_fetch_empty_stores_computed_empty` — seed 1 row, monkeypatch fetch чтобы вернуть `None`. Run main(). Assert fp в БД = `'{"strict": [], "brands": []}'` (или equivalent dict через `_row_to_dict`), counter `Empty fp: 1`.
     - `test_summary_structure` — после успешного run capture stdout (через `capsys`), assert содержит `Window:`, `Processed:`, `Skipped:`, `Empty fp:`, `Errors:`, `Duration:`.
     - `test_days_clamp_rejects_out_of_range` — `main(['--days', '0'])` → SystemExit (argparse exit code 2). Same for `--days 100`.
   - Mock policy: `news_bot.fetch_full_article` мокаем через `monkeypatch.setattr`. `model_extractor.extract_fingerprint` НЕ мокаем — пусть работает на синтетических articles (это integration-flavored, дешевле чем мок).

## Details

**Files:**
- `backfill_fingerprints.py` (NEW, top-level) — argparse CLI + `main(argv=None) -> int` + `backfill_one(row, *, dry_run)` helper. Imports: `argparse`, `json`, `logging`, `sqlite3`, `sys`, `time`, `news_bot` (ПЕРЕД logging.basicConfig), `model_extractor`, `pending_articles_repo as repo`.
- `deploy.sh` (MODIFY) — добавить `"model_extractor.py"` и `"backfill_fingerprints.py"` в FILES array. Текущее состояние: FILES contains 22 entries (news_bot.py, sources, repos, llm-engines, configs); deploy.sh — flat `scp` без `-r`, top-level Python модули копируются как есть.
- `tests/test_backfill_fingerprints.py` (NEW) — 7 тестов по TDD anchor-списку. Pattern: pytest functions, `monkeypatch` для mock `news_bot.fetch_full_article`, `tmp_path` для sqlite, `capsys` для summary capture.

**Dependencies (other tasks):**
- Task 1 — `model_extractor.extract_fingerprint` должен существовать.
- Task 2 — `pending_articles_repo.update_published_fingerprint(conn, link, fingerprint)` должен существовать; схема `published_articles.model_fingerprint TEXT` применена в `init_schema`.

**Edge cases:**
- `--days 0` / `--days 91` / `--days -1` — argparse rejects via `type=` callable (SystemExit 2 + clean usage message).
- DB пустая или ноль NULL-rows в окне — SELECT возвращает empty list, скрипт сразу печатает summary с `Processed: 0`, exits 0.
- `fetch_full_article` возвращает dict без ключа `paragraphs` — обработать как «empty» (computed-empty, terminal).
- `fetch_full_article` возвращает dict с `paragraphs=[]` (пустой list) — тоже «empty», computed-empty.
- `extract_fingerprint` возвращает `{"strict": [], "brands": []}` на статью БЕЗ ошибки (industry news, retrospective) — это валидный «empty fp» путь, считается как `'empty-fp'` для summary; записывается в БД (терминальное состояние).
- Прерывание скрипта (Ctrl-C) посреди работы — следующий run видит NULL у необработанных, продолжает. Никаких commit'ов по batch'ам не требуется (per-row update — каждая `update_published_fingerprint` сама commit'ит, см. Task 2 contract).
- `time.sleep(1)` — НЕ применять перед первой строкой (избежать лишней секунды для одиночного row); применять между итерациями.

**Implementation hints:**
- Эталон формы — `hw_review.py:759-829` (parser + dispatch + main). У нас проще: один subcommand нет нужды, dispatch не нужен — `main` напрямую делает работу.
- Сжатие SELECT row → entry_stub: `published_articles` хранит `link`, `title`, `source_name`, `published_at`; `fetch_full_article` ждёт минимум `link` (для роутинга по domain) и для autoevolution — пустой `published` тоже работает (проверь в Task 4 при чтении кода).
- Counter pattern: один `dict` `counters = {'scanned': 0, 'updated': 0, 'skipped': 0, 'empty_fp': 0, 'errors': 0}`, инкременты по результату `backfill_one`.
- Duration: `start = time.monotonic()` в начале `main`, `elapsed = time.monotonic() - start` в конце, формат `f"{int(elapsed // 60)}m {int(elapsed % 60)}s"`.
- Logging vs print для summary: print() — это контракт оператора по user-spec; logger.info() — для прогресса. Не смешивать.
- DB path — посмотреть как `hw_review.py` получает connection (`repo.connect()` или прямой sqlite3.connect, или env var). Использовать тот же способ для консистентности.
- НЕ использовать `Exception` как блок над `fetch_full_article` слишком широко — только над одним вызовом, чтобы не проглатывать баги в `extract_fingerprint` или `update_published_fingerprint` (это были бы баги нашей реализации, должны падать с traceback).
- На `--verbose` логировать каждую обработанную строку: `logger.debug("[%d/%d] %s -> %s", i, total, link, verdict)`.

**Import-order convention (NOT a security blocker):**
- `import news_bot` поставить в самом верху файла, до `logging.basicConfig()` в `main()`. Реальная причина — консистентность с `hw_review.py` и future-proofing, НЕ риск утечки токенов: `_TokenRedactingFilter` устанавливается безусловно на import news_bot (news_bot.py:344 прикрепляет фильтр к root-логгеру в module-level коде), поэтому порядок import vs basicConfig фактически не влияет на редакцию — фильтр прикреплён, как только модуль импортирован, независимо от того, успели ли мы вызвать basicConfig к этому моменту. Мы держим эту конвенцию, чтобы (а) код выглядел как `hw_review.py`, и (б) если в будущем кто-то изменит side-effect news_bot (например, перенесёт установку фильтра под условие) ИЛИ изменит порядок наших вызовов, мы не получим тихую регрессию защиты.
