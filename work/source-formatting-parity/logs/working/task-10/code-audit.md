**Проблема.** Функция дропает блок, у которого текст стал пустым, только для типов
`('paragraph', 'lead', 'heading')`. `list_item` в списке нет. Тремя десятками строк
ниже, в той же цепочке (`news_bot.py:3454`), соседний RU-фильтр бойлерплейта
перечисляет **все четыре** типа — то есть два фильтра, стоящие подряд, работают по
разным спискам типов.

**Проверено эмпирически, не выведено рассуждением:**

```
вход:  [{list_item, "(follow me on Instagram @diecast215)"},
        {paragraph,  "(follow me on Instagram @diecast215)"}]
после _strip_plugs_in_blocks: [{"type":"list_item","text":"","runs":[]}]   ← абзац дропнут, буллет выжил
после RU-фильтра бойлерплейта: тот же блок (is_boilerplate("") == False)
после рендера:  {"tag":"p","children":["• ",""]}                          ← <p>• </p> на странице
```

**Влияние.** Пустой буллет на странице Telegraph. Класс — «тихий ущерб»: ни лога, ни
пинга, ни падения; видно только глазами при чтении статьи. Сдвига счётчика блоков
здесь уже не будет — этап пост-переводный, спаривание к этому моменту закончено.

**Честная оговорка.** Триггер на реальных данных НЕ измерен: в корпусе t-hunted нет ни
одного `list_item` (отмечено в отчёте Task 9), а среди orangetrack-фикстур со списками
нет такого, где элемент целиком состоит из авторского плага. По правилу оператора от
2026-08-06 это делает риск **выведенным, а не измеренным**, и оператор вправе оставить
находку наблюдением. Аргумент в пользу правки: это не новая страховка, а приведение
существующего фильтра в соответствие с его же соседом тремя строками ниже — одно слово.

**Дефект не внесён Tasks 1–9** — `_strip_plugs_in_blocks` написана раньше, фича её не
трогала. Но контракт блоков — периметр этого аудита, а Phase 2 удваивает экспозицию.

**Фикс:** добавить `'list_item'` в кортеж на `news_bot.py:1409`. Тест: элемент списка,
целиком состоящий из плага, не доходит до узлов Telegraph.

#### major-2 — политика «типы, соответствующие абзацу» перепечатана четырьмя литералами

**Файлы:** `t_hunted_source.py:97`, `t_hunted_source.py:329`,
`orangetrack_source.py:365` — против источника истины `_llm_common.py:216`

**Проблема.** Инвариант выравнивания — «одна строка плоского `paragraphs` на каждый
патчабельный блок» — задан в четырёх независимых местах:

```
_llm_common.py:216        ("lead", "paragraph", "heading", "list_item")   ← истина
t_hunted_source.py:97     ("lead", "paragraph", "heading", "list_item")   ← перепечатка
t_hunted_source.py:329       ("paragraph", "heading", "list_item")        ← литерал без lead
orangetrack_source.py:365    ("paragraph", "heading", "list_item")        ← литерал без lead
```

Причём `news_bot._blocks_if_aligned` поступил ПРАВИЛЬНО и её докстринг прямо
объясняет почему: «THE COUNT COMES FROM `_llm_common._PATCHED_TEXT_BLOCK_TYPES` — the
tuple both sides of the pairing actually read. A literal retyped here would be exactly
the kind of drifted copy this guard is meant to catch» (`news_bot.py:2977-2979`). Оба
парсера сделали ровно то, что этот докстринг запрещает.

**Влияние — конкретный, а не абстрактный отказ.** Третий и четвёртый литералы не
просто «копия» — они уже сейчас логически расходятся с истиной: `lead` в них не
входит. Сегодня это безвредно только потому, что `dom_blocks` тип `lead` не эмитит.
Как только он появится (или в `_llm_common` добавят пятый патчабельный тип, например
`quote`) — плоский список окажется короче числа патчабельных блоков на каждой статье,
`_blocks_if_aligned` начнёт срабатывать **на 100 % публикаций** и молча выключит фичу.
Это ровно тот сценарий «всегда срабатывающего сторожа», против которого Task 8
написала половину своих тестов; наружу он выходит только строкой WARNING в логе.

**Влияние на главный вопрос аудита.** Экстракция убрала дублирование обходчика, но
оставила нетронутым дублирование контракта выравнивания — на том самом контуре, где
у проекта уже была авария 2026-05-06.

**Фикс:** опубликовать один кортеж (в `dom_blocks` или реэкспортом из `_llm_common`)
и читать его в обоих парсерах вместо трёх литералов; вывод плоского списка выразить
как «патчабельные типы» единообразно. Тест: производный список типов в парсерах
совпадает с `_llm_common._PATCHED_TEXT_BLOCK_TYPES` (anti-drift, как в четырёх
движках).
