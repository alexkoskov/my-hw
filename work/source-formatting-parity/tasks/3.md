# Task 3: `list_item` как патчабельный тип блока во всех четырёх движках

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Закрывает **AC3** (вторая половина: «элементы списка не переводятся повторно вторым запросом к LLM») по **Decision 7** техспека.

**Механика бага — проверено в коде 2026-08-05:**

Общий кортеж в `_llm_common.py:204` уже содержит `list_item`:

```
_PATCHED_TEXT_BLOCK_TYPES = ("lead", "paragraph", "heading", "list_item")
```

А у каждого из четырёх движков — **своя локальная копия БЕЗ `list_item`**:

| Файл | Строка | Текущее значение |
|------|--------|------------------|
| `claude_transcreation.py` | 162 | `("lead", "paragraph", "heading")` |
| `gemini_transcreation.py` | 133 | `("lead", "paragraph", "heading")` |
| `openai_transcreation.py` | 132 | `("lead", "paragraph", "heading")` |
| `openrouter_transcreation.py` | 220 | `("lead", "paragraph", "heading")` |

Расхождение даёт двойной перевод на **варианте B** (главный ответ LLM вернул `blocks: null`, движок подставляет оригинальные EN-блоки):

1. Все четыре движка импортируют `_patch_text_with_ru_paragraphs` из `_llm_common` (claude `:65`, gemini `:44`, openai `:43`, openrouter `:55`). Эта функция работает по **общему** кортежу, поэтому текст `list_item`-блоков **уже заполняется русским** из главного ответа (`_llm_common.py:564`).
2. Сразу следом движок зовёт **свой локальный** `_translate_block_strings(...)` с дефолтным `skip_patched_text=True` (claude `:455`, gemini `:406`, openai `:399`, openrouter `:509`). Тот сверяется с **локальным** кортежем — `list_item` в нём нет — и поэтому **не пропускает** уже русский текст, а отправляет его во второй запрос к LLM.
3. Итог: уже переведённый пункт списка переводится повторно RU→RU. Это лишние токены и потеря качества/стиля на каждом длинном блочном материале — ровно то, что AC3 запрещает.

Правка тривиальна (четыре кортежа), но **ценность задачи в тестах**. Урок репозитория: копия, разъехавшаяся с общим оригиналом, — это в точности тот механизм, которым выжил баг классификатора gemini. Ветка `_translate_block_strings` физически продублирована в каждом из четырёх модулей, поэтому **тест на один движок ничего не доказывает про остальные три**. Каждому движку нужен свой тест.

Тестовая база сейчас однобока: `_translate_block_strings` / `skip_patched_text` покрыты **только** в `tests/test_openrouter_transcreation.py` (класс `TestVariantBPlus`, тесты на `:464` и `:490`). В `test_claude_transcreation.py`, `test_gemini_transcreation.py`, `test_openai_transcreation.py` — **ноль** упоминаний этих символов.

**Про номера строк в техспеке.** Decision 7 называет claude `:159`, gemini `:132`, openai `:129`, openrouter `:217` и общий кортеж на `_llm_common.py:115`. Эти номера **устарели** — файлы с тех пор сдвинулись. Актуальные номера — в таблице выше; сверяйся с кодом, а не с техспеком.

## What to do

1. **Добавить `list_item` в локальный кортеж каждого из четырёх движков** — `claude_transcreation.py`, `gemini_transcreation.py`, `openai_transcreation.py`, `openrouter_transcreation.py`. Результат должен совпадать с `_llm_common._PATCHED_TEXT_BLOCK_TYPES` — то есть `("lead", "paragraph", "heading", "list_item")`.

2. **Обновить комментарий/докстринг там, где типы перечислены словами.** В `openrouter_transcreation.py` это `#:`-комментарий над кортежем (`:216-219`) и докстринг `_translate_block_strings` (`:239-245`, фраза «lead / paragraph / heading»). Иначе документация разъедется с кодом и следующий читатель поверит докстрингу.

3. **Написать по два теста в каждом из четырёх файлов тестов движков** (итого восемь). Имя каждого теста обязано содержать подстроку `list_item` — от этого зависит smoke-проверка:
   - **Поведенческий:** блок `list_item` с уже русским текстом + блок `image` с английским `caption`. После `_translate_block_strings(blocks, client, "m")` (дефолтный `skip_patched_text=True`) текст `list_item` не изменился, `caption` переведён, а в теле запроса к API русский текст пункта **отсутствует**.
   - **Анти-дрейф:** локальный `_PATCHED_TEXT_BLOCK_TYPES` движка равен `_llm_common._PATCHED_TEXT_BLOCK_TYPES`. Это и есть гард против повторения истории с копией, которая разъехалась.

4. **Проверить, что smoke-селектор реально что-то собирает.** `pytest -k` при нуле собранных тестов выходит с кодом 0 — «зелёный» прогон ничего не доказывает. Смотри на строку `N passed`, а не на exit code.

5. **Прогнать полный набор** — правка расширяет условие пропуска, поэтому теоретически может задеть существующие тесты варианта B+.

## TDD Anchor

Пишем → запускаем → убеждаемся, что падают → правим кортежи → убеждаемся, что проходят. Поведенческие тесты обязаны падать ДО правки — если тест зелёный на неизменённом коде, он ничего не проверяет.

**Почему по тесту на каждый движок, а не один общий.** `_translate_block_strings` продублирован в четырёх модулях: у каждого свой SDK-вызов, свой способ собрать `user_msg` и свой кортеж. Тест на openrouter не исполнит ни строки кода claude. Именно так уцелел баг классификатора gemini — правка легла в один модуль, тест доказал её там же, а три остальные копии остались с багом. Восемь тестов ниже — прямая плата за это.

Поведенческие (падают до правки):

- `tests/test_claude_transcreation.py::test_list_item_text_skipped_by_second_pass` — блок `list_item` с уже русским текстом + блок `image` с EN-`caption`; `_translate_block_strings` возвращает текст пункта нетронутым, `caption` переведённым, и русский текст пункта не попал в `client.messages.create(...)`.

## Details

**Files:**

- `claude_transcreation.py` — кортеж на `:162`, добавить `"list_item"`. Используется на `:191` в `_translate_block_strings`, вызывается из варианта B на `:455`. Комментария над кортежем нет — можно добавить однострочный `#:` по образцу openrouter.
- `gemini_transcreation.py` — кортеж `:133`. Докстринг `_translate_block_strings` (`:144-147`) отсылает к openrouter («See `openrouter_transcreation._translate_block_strings` for full doc»), поэтому здесь достаточно правки кортежа — но именно поэтому докстринг openrouter обязан быть верным.
- `openai_transcreation.py` — кортеж `:132`; та же отсылка к openrouter в докстринге (`:144-147`).
- `openrouter_transcreation.py` — кортеж `:220` плюс **два текстовых места**: `#:`-комментарий `:216-219` и абзац докстринга `:239-245` со словами «lead / paragraph / heading». Этот докстринг — единственный полный, на него ссылаются три остальных движка.
- Четыре файла тестов — по два новых теста в каждый, плюс один негативный контроль в openrouter. Существующие тесты не редактируем.

**Dependencies:** зависимостей от других задач нет (`depends_on: []`), новых пакетов нет, схема БД не меняется. Всё нужное уже в `requirements-dev.txt`.

**Edge cases:**

- **Конфликт с Task 4 по `_llm_common.py`.** Task 4 (та же волна 1) модифицирует `_llm_common.py`. Эта задача его **только читает**. Заманчиво «заодно» поправить устаревший докстринг `_patch_text_with_ru_paragraphs` (`:538-539` — там написано «lead / paragraph / heading», хотя общий кортеж уже содержит `list_item`), но не делай этого: получится конфликт слияния внутри одной волны. Запиши наблюдение в `decisions.md` как out-of-scope находку.
- **Тест на одном лишь `list_item`-блоке ничего не проверит.** При `skip_patched_text=True` и единственном блоке `list_item` список `items` окажется пустым, функция уйдёт в ранний `return blocks` (`claude_transcreation.py:197-198` и аналоги) и API вообще не вызовется — ассерт «текста нет в теле запроса» пройдёт вакуумно. Поэтому в блоках обязан быть ещё и `image` с EN-`caption`: тогда вызов реально происходит и его тело можно осмотреть.
- **Число переводов в моке должно совпасть с числом отправленных строк.** При несовпадении срабатывает ветка count mismatch, функция возвращает блоки нетронутыми — и тест снова пройдёт вакуумно, «доказав» скип по неверной причине. Мок с одним `image`-caption возвращает ровно одну строку: `{"translations": ["RU cap"]}`.
- **Существующие тесты варианта B+ не должны сломаться.** Просмотрены: в `tests/test_openrouter_transcreation.py` используются блоки типов `image`, `video` и `{"type": "p"}`. Ни один из них не `list_item`, `"p"` в кортеж не входит — расширение кортежа их не задевает. Но убедиться нужно прогоном, а не рассуждением.
- **`news_bot.py:3345` уже перечисляет `list_item`** в своём наборе типов — правка кортежей движков приводит их в соответствие с уже существующим поведением на стороне бота, а не вводит новое.

**Implementation hints:**

- Четыре файла тестов написаны **в двух разных стилях**, и переписывать их под один не нужно:
  - `tests/test_claude_transcreation.py` — pytest-стиль, функции + фикстуры, голый `assert`. Клиент строится хелпером `_make_mock_client(response_text)` (`:102-113`) под форму anthropic SDK (`response.content[0].text`). Новые тесты — обычные функции модульного уровня, **без** класса.
  - `tests/test_gemini_transcreation.py`, `test_openai_transcreation.py`, `test_openrouter_transcreation.py` — `unittest.TestCase` с `self.assertEqual`, хелперы `_make_response(text)` + `_make_client_returning(response_or_exc)`. В gemini и openai класса `TestVariantBPlus` пока нет — создай его по образцу openrouter (`:323`).
- Тело запроса читается у каждого движка по-своему — ещё одна причина, почему один общий тест невозможен:
  - claude: `client.messages.create.call_args.kwargs["messages"][0]["content"]` (system идёт отдельным kwarg `system=`); текст пользователя начинается с преамбулы «Translate these numbered English blog captions…» — `claude_transcreation.py:201-204`, в отличие от остальных трёх, где отправляется голый нумерованный список;
  - gemini: `client.models.generate_content.call_args.kwargs["contents"]`;
  - openai / openrouter: `client.chat.completions.create.call_args.kwargs["messages"][1]["content"]`.
- Эталон для копирования — `tests/test_openrouter_transcreation.py:464-488` (`test_skip_patched_text_default_skips_paragraph_block_text`). Там уже есть нужная форма: блоки, мок на одну строку перевода, ассерты «текст не тронут» + `assertNotIn` по телу запроса. Меняется только тип блока — `paragraph` → `list_item`.
- Русский текст в фикстуре бери узнаваемым (например, `"Уже переведённый пункт списка."`), чтобы `assertNotIn` бил точно и не совпал случайно с преамбулой запроса.
- Анти-дрейф-тест пиши через импорт `_llm_common` и сравнение кортежей целиком (`==`), а не через `assertIn("list_item", ...)`: сравнение с общим источником поймает и обратное расхождение — если завтра тип добавят в `_llm_common`, а в движки забудут.
- Правка кода — четыре строки. Если после неё поведенческие тесты зелёные, а до неё были зелёными тоже, тест написан неправильно — вернись к нему.
