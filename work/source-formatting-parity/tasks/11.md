# Task 11: Security Audit

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:security-auditor` — [.claude/skills/security-auditor/SKILL.md](../../../.claude/skills/security-auditor/SKILL.md) — методология анализа по OWASP Top 10. Файлы фичи лежат под `my-hw/`, поэтому используется scoped-скилл `my-hw:security-auditor`, а не глобальный.

## Description

Целостный security-аудит ВСЕЙ Phase 1 фичи `source-formatting-parity` — не одного файла, а
всей цепочки, написанной и изменённой в Task 1–9. OWASP Top 10 по периметру фичи плюс
**четыре именованные угрозы**, которые эта фича создаёт или переоткрывает, плюс
перепроверка одного операторского решения, принятого против рекомендации security-ревью.

Задача — только анализ. Код и тесты не меняются. Результат — audit-отчёт: вердикт
(PASS / PASS-WITH-NOTES / FAIL) + находки, каждая с severity, `файл:строка`, **конкретным
сценарием эксплуатации** и рекомендацией. Закрытую угрозу фиксировать явно как проверенный
инвариант — молчание в отчёте неотличимо от «не смотрел». Critical/Major — это
fix-before-deploy: правки вносит fixer, которого запускает lead этапа (feature-execution),
сам аудит не чинит.

### Почему этой фиче нужен отдельный security-аудит

До фичи три парсера **уничтожали разметку**: из недоверенного HTML доезжал плоский текст.
Фича снимает эту случайную защиту. Теперь враждебная разметка источника доходит до
регекспов общего модуля, до `iframe src` и `img src` в узлах Telegra.ph, до тела запроса к
LLM и до предпросмотра, который открывается в браузере под `file://` — origin, которому
браузер доверяет сильно. Каждый гейт, который orangetrack держал приватно у себя, обязан
теперь держаться для **всех** источников: экстракция раздаёт не только механизм, но и его
дыры, если их не закрыть в общем месте.

**Граница доверия.** HTML статьи-источника и ответ LLM — UNTRUSTED. Полный поток:
`fetch` (cap 2 MB t-hunted / 5 MB orangetrack) → BeautifulSoup → `dom_blocks` (регекспы,
host-гейт видео, выбор `src` картинки, ключ дедупа) → `blocks` + `runs` → JSON в SQLite
(`insert_pending`) → `_encode_format_markers` в тело запроса LLM → ответ LLM →
`_decode_format_markers` → узлы `telegraph_publisher` → страница Telegra.ph; отдельной
веткой те же узлы идут в `preview_renderer` → HTML под `file://`.

У проекта здесь есть **история находок по доступности**, и она не абстрактная: Task 4
существует ровно потому, что `_encode_format_markers` (`_llm_common.py:217`) сканирует
`text.find`-ом на каждый ран **без всякой границы**. Сегодня этот цикл свободен по
случайности — у autoevolution раны несут только `href` и не несут `formats`, поэтому каждая
итерация коротко замыкается. Фича эту случайность убирает. В пределах 2 MB фетча t-hunted
~200k однобуквенных жирных спанов дают ~4·10¹⁰ сравнений символов: десятки минут — часы на
однопроцессном боте, рестарт которого запрещён 10:00–20:00 МСК, причём **все три слота
публикации внутри этого окна**. Существующие границы (`_MAX_TEXT_FOR_RUNS = 100_000`,
`_MAX_RUNS_PER_BLOCK = 100`, `telegraph_publisher.py:157-158`) закрывают только путь
РЕНДЕРА — путь запроса они не видят.

### Четыре именованные угрозы

Это не абстрактный «пройтись по OWASP» — по каждой из четырёх нужен явный вердикт с
доказательством в коде. Полные формулировки проверок — в Details.

1. **Контракт ограниченных квантификаторов** — каждый регексп, добавленный или изменённый
   этой фичей. Не «в целом безопасно», а перечень: файл, имя паттерна, вердикт.
2. **Host-гейт видео ДО регекспа, для каждого источника** — хост проверяется ПЕРВЫМ, так
   что враждебный embed-URL до регекспа не доходит в принципе.
3. **Валидация схемы `img src` в публикаторе** (Task 6) — централизованно, а не доверием к
   пикеру каждого источника, и **в согласии** с уже существующим allowlist'ом
   `preview_renderer`, а не как вторая, разъезжающаяся политика.
4. **Граница на request-пути** (Task 4) вместе с её контрактом деградации: за границей —
   снять раны и отправить плоский текст; никогда не ошибка, никогда не потерянная статья,
   никогда не обрезанная статья.

### Решение «флаг по умолчанию ВКЛЮЧЁН» — перепроверить, но не перерешать

Флаг включён по умолчанию **против рекомендации security-ревью** (opt-in). Это осознанное
решение оператора от 2026-07-30, записанное в tech-spec § Risks вместе с аргументом
ревьюера: pre-deploy E2E невозможен, Decision 3b глушит каждый режим отказа, а выключение
требует рестарта, запрещённого в течение публикационного дня — значит выключатель не
успевает дать ту митигацию, которую ему приписывают.

Что делает аудит: **перепроверяет, изменилось ли за время Task 1–9 что-нибудь, что меняет
эту калькуляцию риска** — появилась ли новая поверхность атаки (Task 6 отдаёт `src` в
узлы, Task 7 гонит враждебный HTML через общий обходчик), стало ли наблюдаемее (WARNING
страховки Task 8), сузился ли радиус (Phase 1 = только t-hunted). Вывод — один абзац в
отчёте: «риск не изменился» либо «изменился так-то, оператору стоит знать это до деплоя».
Чего аудит НЕ делает: не переигрывает решение молча и не заводит находку «дефолт должен
быть OFF» как Critical — это решение оператора, а не дефект кода. Новый аргумент, если он
есть, адресуется оператору явно.

**Границы аудита.** Качество кода и межкомпонентная согласованность — периметр Task 10;
качество тестов — периметр Task 12. При пересечении достаточно одной строки со ссылкой на
смежный аудит. Phase 1 = t-hunted: `lamley_source.py` и `autoevolution_source.py` меняться
не должны — но их **читать надо**, потому что именно autoevolution несёт эталонные примеры
обеих дыр (регексп видео без host-гейта, `startswith("http")` вместо проверки схемы), и
именно они не должны были переехать в общий модуль.

## What to do

1. Собрать фактический периметр: `git diff --stat` по фиче + прочитать все
   созданные/изменённые исходники (Context Files → Code files) как единую цепочку. Читать
   **реальное состояние файлов**, а не tech-spec как «как должно быть»; расхождение спека с
   кодом — само по себе находка, но сверяться с [decisions.md](../decisions.md): агенты
   Task 1–9 могли зафиксировать легитимное отклонение.

2. **Угроза 1 — контракт ограниченных квантификаторов.** Составить ПОЛНЫЙ перечень
   регекспов, которые фича добавила или изменила (`dom_blocks.py`, `t_hunted_source.py`,
   `_llm_common.py`, `feature_flags.py`, `telegraph_publisher.py`, `preview_renderer.py`),
   и по каждому дать вердикт: только ограниченные квантификаторы (`{1,3}`, `{0,N}`), нет
   `+`/`*`/`.*` в позициях, допускающих катастрофический бэктрекинг, нет вложенных
   неограниченных групп. Отдельно проверить, что проверка пунктуации в эвристике заголовка
   сделана через `str.endswith`, а НЕ регекспом (прямое требование Decision 8 и AC
   tech-spec). Подкрепить хотя бы одной эмпирической пробой по времени, как это делал аудит
   `dedup-model-series`.

3. **Угроза 2 — host-гейт видео ДО регекспа, для каждого источника.** Проверить в коде, что
   гейт живёт внутри `dom_blocks`, хосты приходят как ДАННЫЕ, сравнение идёт по
   `urlparse(...).hostname` в нижнем регистре на ТОЧНОЕ вхождение в кортеж, и стоит ДО
   ID-регекспа — то есть враждебный URL до регекспа не доходит вовсе. Прогнать по коду
   список атакующих строк из Details и убедиться, что ни один путь (t-hunted, orangetrack,
   а также любой вызов эмиттера видео мимо `dom_blocks`) гейт не обходит.

4. **Угроза 3 — валидация схемы `src` в публикаторе.** Проверить, что проверка стоит
   ЦЕНТРАЛЬНО в `telegraph_publisher._build_content_from_blocks` (и hero, и картинки в теле,
   и `iframe src` видео-блока), а не отдана на доверие пикеру источника; что политика
   **совпадает** с уже существующим allowlist'ом `preview_renderer._SAFE_URL_RE`
   (`^https?://`, IGNORECASE) и не заведена как вторая, независимая; что невалидный блок
   отбрасывается, а не роняет публикацию (fail-open). Отдельно — что кап картинок
   (Decision 5) и отбраковка по схеме не конфликтуют так, что отброшенный блок всё равно
   съедает единицу лимита.

5. **Угроза 4 — граница на request-пути и её контракт деградации.** Проверить, что граница
   в `_encode_format_markers` стоит ДО цикла `text.find`-ов (ранний выход), а не внутри
   него; что за границей раны снимаются и уходит плоский текст; что статья при этом
   **цела** — не обрезана, не потеряна, исключения нет, пинга оператору нет, есть один
   WARNING; что имена и значения границ не разъехались с парс-таймовыми границами
   `dom_blocks` и рендер-таймовыми `telegraph_publisher.py:157-158`; что граница осталась
   РЕСУРСНОЙ и не превратилась в запрещённый AC7 редакторский порог «слишком много
   жирного». Подкрепить пробой на патологическом входе (см. Verification Steps).

6. **Перепроверка риска «дефолт ON».** Пройти по аргументу security-ревью из tech-spec
   § Risks пункт за пунктом и сверить с тем, что реально построено в Task 1–9. Записать в
   отчёт один абзац: изменилась калькуляция риска или нет, и если изменилась — что именно
   оператору стоит знать до деплоя. Не заводить сам дефолт как находку.

7. **Общий OWASP-проход по периметру фичи.** Трейс недоверенных данных от входа до выхода
   с проверкой каждой границы: инъекция в узлы Telegra.ph и в HTML предпросмотра (A03),
   небезопасный дизайн деградаций (A04), конфигурация — новый env-флаг и три деплой-манифеста
   (A05), новые зависимости — их не должно быть (A06), целостность данных — корпус фикстур
   и golden (A08), логирование — что попадает в `docker logs` (A09).

8. **Корпус HTML-фикстур (Task 1) как отдельный объект проверки.** 14 реальных страниц
   сторонних сайтов заезжают в репозиторий: проверить отсутствие в них секретов, cookie,
   токенов в URL и персональных данных; что `.dockerignore` действительно исключает
   `tests` (строка есть — подтвердить, что она не сломана и корпус не едет в прод-образ);
   что pre-commit (`gitleaks`, `check-added-large-files --maxkb=1000`) не обходили через
   `--no-verify`.

9. **Наблюдаемость без утечки.** Проверить, что WARNING страховки (Task 8) и WARNING
   границы (Task 4) не выливают в лог тело статьи целиком и не содержат секретов, и что ни
   один путь деградации этой фичи не зовёт `send_admin_notification` (Decision 3b) — то
   есть недоверенный текст в Telegram не уезжает вовсе.

10. Оформить audit-отчёт по формату из Details, сохранить его в
    `work/source-formatting-parity/logs/working/task-11/security-audit.md`, добавить ссылку
    в `decisions.md` и вернуть путь к отчёту.

### Угроза 1 — контракт ограниченных квантификаторов (Decision 8 + AC tech-spec)

Требование проекта уже записано в `patterns.md`: ограниченные квантификаторы, никаких
вложенных жадных групп, `^`-якорь там, где паттерн абзац-скоупный. Эталон дисциплины в
репозитории — `model_extractor._MODEL_AFTER_BRAND_RE` (полностью `{1,3}`/`{0,24}`).

Что проверять конкретно:

- **Перечислить все регекспы фичи поимённо.** Дешёвый способ собрать список:
  `grep -n "re.compile" dom_blocks.py t_hunted_source.py _llm_common.py feature_flags.py telegraph_publisher.py preview_renderer.py`
  плюс инлайновые `re.sub`/`re.search` без компиляции — их grep по `re.compile` не найдёт,
  искать отдельно.
- **Унаследованные паттерны — тоже периметр**, если они переехали в общий модуль. Два
  конкретных кандидата: `orangetrack._YOUTUBE_ID_RE:88` содержит `([A-Za-z0-9_-]{6,})` —
  квантификатор с открытым верхом; `t_hunted._BLOGGER_SIZE_SUFFIX_RE:64` — `=s\d+(-c)?(?:/|$)`
  с неограниченным `\d+`. Ни один из них не даёт катастрофического бэктрекинга (простые
  классы символов без вложенности), но если фича переносит их в `dom_blocks`, вердикт по
  ним нужен явный, с обоснованием «почему это не находка», а не умолчанием. Верхняя
  граница (`{6,64}`, `{1,12}`) — дешёвая рекомендация уровня Minor.
- **Антиэталон рядом:** `autoevolution.YOUTUBE_ID_RE:33` — `([A-Za-z0-9_-]+)`. Если этот
  паттерн (а не orangetrack'овский) оказался в общем модуле — это регресс дисциплины,
  занести как находку.
- **Пунктуация заголовка — `str.endswith`, не регексп.** Прямое требование Decision 8 и
  отдельная строка в tech-spec § Acceptance Criteria. Проверять по коду эвристики
  `looks_like_heading` в `dom_blocks.py`.
- Границы применения: регексп, работающий по НЕограниченному входу (тело статьи до 2 MB),
  строже чем регексп по `src` (короткая строка). Severity калибровать по этому.

### Угроза 2 — host-гейт ДО регекспа, для каждого источника

Эталон уже написан и прокомментирован в доноре: `orangetrack._video_embed_url:138-169` —
`urlparse` → `parsed.hostname.lower()` → проверка вхождения в кортеж `_YOUTUBE_HOSTS:52-60`
→ и только потом ID-регексп. Docstring там прямо называет закрываемую дыру: «autoevolution's
regex-only path has this gap; we close it here». Decision 1 сделал видео-шов **данными**
именно чтобы эту дыру нельзя было инъектировать обратно.

Что проверять:

- Гейт физически внутри `dom_blocks`, а не в парсере; парсер передаёт только кортеж хостов
  и имя провайдера. Инъекция callable вместо данных — Major как минимум: она возвращает
  ровно ту дыру, ради закрытия которой шов сделан данными.
- Порядок: `hostname`-проверка **до** любого `search`/`match` по URL. Регексп, вызванный
  первым и лишь потом отфильтрованный по хосту, формально даёт тот же результат, но
  нарушает контракт «до регекспа не доходит вовсе» — заносить как находку с пометкой, что
  это защита от ReDoS, а не только от подмены.
- Сравнение — точное вхождение в кортеж, **не** `in`, `endswith` или подстрока. В файле уже
  есть исторический комментарий про ровно эту ошибку (`_ALLOWED_HOSTS:45-47`:
  `orangetrackdiecast.com.attacker.example` проходил `in`-проверку).
- Берётся `hostname`, а не `netloc`: `netloc` несёт порт и userinfo.
- Vimeo-хосты добавлены (Decision 1) — и добавлены как ДАННЫЕ, а не как второй регексп.
- Атакующие строки для прогона (ожидание — `None`/не обёрнуто на каждой):
  `https://evil.example/youtube.com/embed/abc123`,
  `https://youtube.com.evil.example/embed/abc`,
  `https://evil.example/?x=youtu.be/abc123`,
  `//youtube.com/embed/abc` (scheme-relative),
  `https://user:pass@youtube.com@evil.example/embed/abc`,
  `https://YOUTUBE.COM/embed/abc` (регистр — должно как раз ПРОЙТИ, если `lower()` на месте),
  `javascript:/*youtube.com/embed/x*/alert(1)`.
- Что происходит при отказе гейта: возврат `None` и блок не эмитится. Эмиссия сырого URL в
  `iframe src` «на всякий случай» — Critical (Telegra.ph отдаёт iframe читателю).

### Угроза 3 — валидация схемы `src` в публикаторе (Task 6, Decision 5)

Tech-spec § Risks формулирует мотив: пикер autoevolution использует `startswith("http")` —
`httpx://evil/x.jpg` проходит, — а его галерейный путь проверки схемы не делает вовсе.
Публикатор объявлен «единственной точкой отсечки» (Decision 5), значит проверка обязана
жить там.

Что проверять:

- **Централизованность.** Проверка стоит в `_build_content_from_blocks` и покрывает ВСЕ
  места, где `src` доезжает до узла: hero-картинку (`:400-410` до фичи), картинки в теле
  (`:421-449`), и `iframe src` видео-блока. Видео легко забыть — риск-строка tech-spec
  говорит только про картинки, но iframe опаснее.
- **Согласие с предпросмотром, а не вторая политика.** `preview_renderer` уже реализует
  `_SAFE_URL_RE = ^https?://` (IGNORECASE) плюс allowlist тегов и CSP. Если публикатор
  завёл собственный набор схем (например, разрешил `mailto:` для `img`, или наоборот
  запретил `http://`, оставив только `https://`), две политики разъедутся — а разъехавшаяся
  политика означает, что предпросмотр перестаёт быть честной проверкой того, что уедет в
  публикацию. Расхождение = находка, даже если каждая политика по отдельности безопасна.
  Ориентир «как в этом файле уже делают»: `telegraph_publisher._is_same_site:127-153` —
  `urlparse`, `scheme.lower() not in ("http","https")`, broad-except с логом.
- **Формы, которые обязаны отсекаться:** `javascript:`, `data:`, `file:`, `vbscript:`,
  scheme-relative `//evil/x.jpg`, относительный путь `/img/x.jpg`, `httpx://evil/x.jpg`,
  пробел в начале (` javascript:…`), `HTTPS://` (должно проходить).
- **Fail-open.** Невалидный блок отбрасывается, публикация продолжается; исключение наружу
  — нарушение Ограничения user-spec «fail-open обязателен».
- **Взаимодействие с капом.** Кап Decision 5 отсекает картинки после N. Проверить, что
  отброшенная по схеме картинка не «съедает» единицу капа и что hero сохраняется, даже если
  первая картинка отбракована (иначе Instant View теряет превью — не security-находка, но
  честный Minor рядом).

### Угроза 4 — граница на request-пути и контракт деградации (Task 4, Decision 8)

Контракт дословно: **за границей — снять runs и отправить плоский текст. Никогда не
обрезать статью, никогда не ошибка, никогда не потерянная статья.** Пинга нет (Decision 3b),
WARNING один.

Что проверять:

- Граница стоит **до** цикла по ранам в `_encode_format_markers:217` (ранний выход), а не
  внутри него: проверка внутри цикла оставляет квадратичную работу до момента срабатывания.
- Обе величины: длина текста и число ранов. Одной мало — 200k однобуквенных ранов дают
  небольшой текст и огромный цикл.
- Имена и значения зеркалят рендер-путь (`_MAX_TEXT_FOR_RUNS = 100_000`,
  `_MAX_RUNS_PER_BLOCK = 100`, `telegraph_publisher.py:157-158`, применение `:283-289`).
  Три набора границ (parse в `dom_blocks`, request в `_llm_common`, render в
  `telegraph_publisher`) допустимы и осмысленны, но не должны молча разъезжаться в именах
  или порядке величин — молчаливое расхождение это будущая дыра, а не сегодняшняя.
- Результат за границей: `out == text` (текст ЦЕЛ, раны сняты). Обрезание текста —
  нарушение контракта и потеря контента, заносить как Major.
- Граница ресурсная, а не редакторская: она не должна давать эффект «слишком много жирного
  → выкинуть форматирование у нормальных статей», что запрещено AC7. Проверить порядок
  величин на реальных статьях корпуса (десятки ранов, не сотни).
- Второй конец пути — `_decode_format_markers` и `_BOLD_MARKER_RE` (`[^*\n]+?`,
  non-greedy, без вложенности): подтвердить, что ответ LLM (тоже недоверенный) не может
  раздуть работу декодера.

### Общий OWASP-проход — что здесь реально применимо

Не переписывать список OWASP целиком; закрыть применимое и явно отметить неприменимое.

- **A03 Injection.** Единственный настоящий выход — HTML: узлы Telegra.ph (структура —
  словари, не конкатенация строк) и предпросмотр (`html.escape(..., quote=True)` +
  allowlist тегов + allowlist имён атрибутов + CSP). Проверить, что Task 6 не завёл
  строковую сборку HTML вместо словарей узлов. SQL: `blocks` — opaque JSON через
  `?`-плейсхолдер, тело SQL статическое; подтвердить, что это не изменилось.
- **A04 Insecure design.** Декодированный из `**` ран приходит из ответа LLM — недоверенного
  канала; проверить, что он идёт тем же путём экранирования, что и текст источника.
- **A05 Misconfiguration.** Новый env-флаг: чтение на import-time, отсутствие секретов в
  `.env.example`, наличие обоих новых модулей во всех трёх FILES-манифестах (незалистенный
  модуль = ImportError-crashloop на боте — availability-дефект, уже случавшийся в проекте).
- **A06 Vulnerable components.** Новых пакетов быть не должно (tech-spec § Dependencies) —
  подтвердить по `requirements*.txt`.
- **A08 Integrity.** Golden-файл и корпус: подтвердить, что golden не редактировался
  (`git log`/`git diff` по пути) — это гейт целостности, а не только тест.
- **A09 Logging.** См. пункт 9 «What to do». Логи уходят в `docker logs` на хосте; тело
  статьи в WARNING — не утечка секрета, но шум и потенциальная PII из источника; секреты в
  логах — Critical.
- **A01/A02/A07/A10** — вероятнее всего неприменимы (нет аутентификации, нет новых
  крипто-операций, нет исходящих запросов по URL из статьи: картинки и iframe тянет клиент
  Telegra.ph, не бот). Именно так и записать: «неприменимо, потому что …», в одну строку
  на пункт.

### Edge cases для проверки

- `blocks` пустой/`None` → публикация падает обратно на `_build_content` (плоский текст),
  а не роняет тик.
- Статья, где вся разметка враждебная (каждый абзац — `<a href="javascript:…">`): раны с
  `href` доезжают до `_render_paragraph_with_runs`; проверить, что off-domain и небезопасные
  схемы отсекаются там, где отсекались до фичи.
- Картинка, чей `src` валиден, но ведёт на хост с гигантским файлом — не наш риск (тянет
  клиент), но отметить одной строкой, чтобы не выглядело пропуском.
- Патологический вход одновременно с включённой эвристикой заголовка: раны сняты границей
  → абзац перестаёт быть «целиком жирным» → заголовком не становится. Decision 8 это
  описывает как ожидаемое; подтвердить, что так и есть, и что это не даёт дешёвого способа
  подавить структуру статьи (косметика, Informational).
- Флаг выключен: у orangetrack блоки остаются. Значит «выключить фичу» НЕ означает
  «выключить блочный путь целиком» — проверить, что все четыре гейта работают и в
  флаг-off состоянии, потому что orangetrack по ним по-прежнему ходит.
