# Task 2: Subject-aware pair rule and capped backstop

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Change the broad-pair decision contour so E014 requires the pair's canonical series in both effective titles, while keeping distinctive blocking, candidate precedence, the overlap safety net, deferral semantics, and fail-open behavior intact. This is the core precision fix measured by Task 1's corpus.

## What to do

- Compute and reuse one effective original title for the new article at the dedup gate and persistence boundary.
- Extend `_pair_rule_verdict()` to qualify broad pairs against both title-series sets, keep scanning after rejections and qualified flags, and return bounded internal suppression diagnostics.
- Extend `_check_cross_source_dedup()` to carry the diagnostics and downgrade only a backstop block reached after a subject rejection to `overlap_capped` flag.
- Preserve distinctive precedence, legacy fingerprint skips, the series toggle, the unchanged backstop thresholds, and the enclosing E016 fail-open path.
- Activate the 24-pair acceptance target and add unit/integration coverage for state and arrival-order symmetry.

## Acceptance Criteria

- [x] A broad pair qualifies only when its canonical series is extracted from both effective original titles; article bodies are not used for subject qualification.
- [x] At least one qualified series is sufficient and only qualified pairs are returned for E014 rendering.
- [x] Rejected candidates do not terminate scanning; later qualified broad and distinctive candidates retain precedence.
- [x] A subject-rejected broad contour still reaches the unchanged seven-day backstop, whose hard block alone becomes a soft `overlap_capped` result.
- [x] `decision == 'flag'` remains the sole trigger for the existing 24-hour `publish_after` value.
- [x] The corpus target is 3/3 true duplicates flagged and at most 1/21 false pairs flagged.
- [x] Toggle-off, malformed/legacy fingerprints, distinctive E015, rate-limit/token state, and E016 fail-open contracts remain unchanged.
- [x] No schema, fingerprint key, backfill, dependency, or runtime network call is introduced.

## Details

**Files:** `news_bot.py` currently returns two values from `_pair_rule_verdict()` and `_check_cross_source_dedup()` and computes the persistence title later; the feature changes that contour. `tests/test_dedup_broad_precision.py` activates the oracle; `tests/test_integration.py` pins queue/processed state; `tests/test_model_extractor.py` pins existing canonical extraction behavior.

**Dependencies:** Task 1 supplies the accepted corpus. Reuse `model_extractor.extract_series()` and existing candidate projections; add no packages.

**Edge cases:** Empty/missing titles, malformed pair strings, a candidate without `pairs`, several shared broad series with only one qualified, rejected-before-distinctive ordering, rounded 50% display, and exceptions during title extraction/result handling.

**Implementation hints:** Keep decision helpers pure; extract the new-side title series once; preserve `_pair_match()` compatibility keys; represent cap provenance explicitly instead of inferring it from rounded overlap; leave `_set_overlap_backstop_verdict()` thresholds and filtering untouched.
