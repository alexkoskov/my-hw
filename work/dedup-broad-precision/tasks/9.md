# Task 9: Manual production deployment

## Required Skills

Before starting, load:
- `/skill:deploy-pipeline` — [SKILL.md](../../../.claude/skills/deploy-pipeline/SKILL.md)

## Description

Release the approved, green build through the repository's manual production procedure. Deployment is a separately authorized operational action and must preserve a known-good rollback target, the database volume and runtime configuration. It may run at any time.

## What to do

- Obtain explicit deployment authorization after existing review evidence and CI are green on the promoted commit.
- Record the current known-good rollback commit without environment details; time of day does not gate deployment.
- Follow the existing manual pull/rebuild procedure without changing runtime configuration or database state.
- Verify the service starts cleanly, expected review listener state is unchanged, and no startup/schema/E016 regression appears.
- Roll back immediately through the documented route if the startup gate fails and write a sanitized deployment report.

## Acceptance Criteria

- [x] Deployment starts only after explicit user authorization, existing review evidence and green CI.
- [x] The release preserves the existing database volume/configuration; it may occur at any time.
- [x] The service is running after rebuild with no startup, schema, E016, duplicate poller or configuration regression.
- [x] A known-good rollback target is recorded; no rollback was needed because every startup gate passed.
- [x] `deploy-report.json` contains only sanitized outcome and commit metadata, no commands with coordinates, raw logs, tokens or private identifiers.

### Smoke

- Repeat the documented container status and bounded startup-log checks → the deployed process is healthy without triggering a tick or injecting an article.

### User
