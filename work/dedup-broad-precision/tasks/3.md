# Task 3: E014 reasons, suppression logs, and funnel telemetry

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Make the operator contour accurately explain each soft-flag reason and expose how often the new title rule suppresses noisy comparisons. Diagnostics must remain bounded and secret-safe and must not alter dropped totals, review buttons, or alert rate limiting.

## What to do

- Add explicit `broad_subject`, `overlap`, and `overlap_capped` E014 rendering while preserving the existing review keyboard contract.
- Emit one bounded, redacted, single-line log record for each rejected candidate comparison and remove misleading pair-overlap percentages from broad logs.
- Increment `dedup_subject_suppressed` once per affected new article and render it in both E008/E009 funnel formats without adding it to dropped counts.
- Extend alert, integration, and token-leak tests across reason text, telemetry units, malformed values, rate limiting, and hostile external title/link shapes.

## TDD Anchor

- `tests/test_admin_alerts.py::test_e014_reason_variants_are_truthful` — parametrically verifies the three reasons, qualified-series naming, unchanged action text/buttons, and absence of false 50% claims.
- `tests/test_admin_alerts.py::test_funnel_renders_subject_suppression_without_counting_a_drop` — verifies both daily ping formats for zero, non-zero, and malformed counts.
- `tests/test_integration.py::test_subject_rejection_diagnostics_and_article_unit_telemetry` — logs every rejected candidate but increments the funnel exactly once for the new article and emits no broad percentage.
- `tests/test_no_token_leak_in_logs.py::test_dedup_suppression_log_is_bounded_redacted_and_single_line` — verifies control characters, URL credentials/query data, secret-shaped text, and long titles cannot forge or leak through logs.
- `tests/test_integration.py::test_e014_reason_wiring_preserves_rate_limit_and_review_token_contract` — verifies reason data changes neither per-pair alert throttling nor keyboard token/callback behavior.

## Acceptance Criteria

- [ ] `broad_subject` names only qualified series and contains no overlap-percent claim.
- [ ] `overlap` retains the existing below-block-threshold explanation.
- [ ] `overlap_capped` states that raw block similarity was reached but title evidence prevented automatic blocking.
- [ ] Every subject-rejected candidate has one bounded, redacted, single-line diagnostic record; broad and suppression logs contain no pair-overlap percentage.
- [ ] E008 and E009 show one suppression count per affected new article and do not add it to the dropped total.
- [ ] Review-button labels, callback grammar, token kind, per-pair rate limiting, and E015 text/side effects remain unchanged.

## Details

**Files:** `admin_alerts.py` currently renders one generic E014 and two funnel formats; `news_bot.py` logs all flags with overlap and has no suppression counter; the three named test modules own presentation, state and log-safety assertions.

**Dependencies:** Task 2 supplies explicit match reasons and suppression records. Reuse the existing secret-redaction and safe-link patterns.

**Edge cases:** Several rejected candidates for one article, a rejected candidate followed by a real flag, rate-limited E014, missing reason for legacy callers, malformed funnel values, control characters, credential-bearing URLs, and very long titles.

**Implementation hints:** Keep alert arguments keyword-only for new data; preserve legacy defaults for direct callers; count at article scope in `job()`; sanitize before interpolation rather than after a formatted log line is built.
