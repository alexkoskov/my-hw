# Task 7: Feature test audit

## Required Skills

Before starting, load:

## Description

Perform a read-only audit of the corpus and test suite to ensure the feature is protected by meaningful behavior and state assertions rather than mock counts or fragmented examples.

## What to do

- Map user-spec and tech-spec criteria to the final focused and integration tests.
- Review corpus provenance, label integrity, scorer fidelity, boundary cases and resistance to overfitting.
- Inspect assertions for final queue/processed state, alert text, diagnostic safety, distinctive precedence, toggle behavior and E016 fail-open behavior.
- Identify redundant/fragmented tests, missing reverse boundaries, false-positive assertions and untested direct callers.
- Write only `work/dedup-broad-precision/logs/audit/test-audit.json`.

## Acceptance Criteria

- [ ] Every acceptance criterion has at least one concrete test or an explicit justified observational check.
- [ ] Corpus score tests execute the real decision code and validate labels, not a duplicate implementation.
- [ ] Integration assertions inspect persisted state and rendered output where behavior crosses components.
- [ ] Findings include severity, evidence and a concrete improvement; the report is valid JSON.

## Details

**Dependencies:** Task 4 means production logic, tests and docs are stable enough for a final audit. Findings are fixed before Task 8.
