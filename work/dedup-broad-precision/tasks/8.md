# Task 8: Pre-deploy acceptance QA

## Required Skills

Before starting, load:
- `/skill:pre-deploy-qa` — [SKILL.md](../../../.claude/skills/pre-deploy-qa/SKILL.md)

## Description

Run the complete release gate after all feature audits and fixes. This task turns the approved requirements into traceable evidence and must block deployment if any irreversible-block, precision, lifecycle, diagnostic or fail-open contract is not proven.

## What to do

- Resolve every open code, security and test audit finding or record a blocking QA result.
- Map every user and technical acceptance criterion to a test, command, artifact inspection or explicit post-deploy observation.
- Run focused suites, the full repository suite, JSON validation, scoped pre-commit hooks and diff checks over the final change set.
- Inspect the corpus, logs, docs and Git diff for secrets, private data, migrations, new dependencies or unintended runtime/config changes.
- Write `work/dedup-broad-precision/logs/working/pre-deploy-qa-report.json` with exact commands, outcomes and deployment readiness.

## Acceptance Criteria

- [ ] All three feature audit reports are approved and all blocking findings are resolved.
- [ ] The 24-pair target, distinctive E015, defer invariant, reason text, suppression telemetry and E016 fail-open criteria have concrete passing evidence.
- [ ] Focused and full pytest suites pass from the final tree.
- [ ] Both corpus JSON files and `.project-progress.json` validate; scoped pre-commit and `git diff --check` pass.
- [ ] The report marks deployment ready only when every pre-deploy criterion is green and contains no sensitive data.

## Verification Steps

### Automated

- `venv/bin/python -m pytest tests/test_dedup_broad_precision.py tests/test_model_extractor.py tests/test_admin_alerts.py tests/test_no_token_leak_in_logs.py tests/test_integration.py -q` → focused feature contour passes.
- `venv/bin/python -m pytest -q` → full repository suite passes.
- `python3 -m json.tool tests/fixtures/dedup_broad_precision.json` and `python3 -m json.tool .project-progress.json` → planning and corpus JSON are valid.
- `pre-commit run --files <changed-files>` → every scoped hook passes without unrelated rewrites.
- `git diff --check` → no whitespace errors.

## Details

**Files:** Reads the complete final change set and three audit reports; writes only `work/dedup-broad-precision/logs/working/pre-deploy-qa-report.json` unless an explicit fix task is created.

**Dependencies:** Tasks 5, 6 and 7 must finish. Deployment remains separately authorized and must not begin from this task.

**Edge cases:** A green docs-only CI skip, tests run before the final fix, hook rewrites of evidence, an unresolved non-critical finding that affects acceptance, and observational criteria incorrectly claimed as locally verified.

**Implementation hints:** Record exact final commit/tree evidence; keep post-deploy-only checks explicitly pending rather than marking them passed; run pre-commit only on changed files.
