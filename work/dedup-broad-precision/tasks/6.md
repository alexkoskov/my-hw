# Task 6: Feature security audit

## Required Skills

Before starting, load:
- `/skill:security-auditor` — [SKILL.md](../../../.claude/skills/security-auditor/SKILL.md)

## Description

Perform a read-only security audit of the finished feature, with special attention to irreversible false blocks, external-input diagnostics, production-corpus hygiene, and unchanged review authorization/token boundaries.

## What to do

- Audit fail-open and irreversible-action boundaries across pair qualification, backstop capping, E015 and queue staging.
- Inspect title/link logging for control-character injection, credential/query leakage, secret-shaped values and unbounded data.
- Inspect the committed corpus and integrity checks for private or operational data exposure.
- Verify malformed fingerprints, SQLite access, alert rate limits, token kinds, callback grammar and admin authorization remain safe.
- Write only `work/dedup-broad-precision/logs/audit/security-audit.json`.

## Acceptance Criteria

- [ ] The audit covers every external-input and irreversible-state boundary introduced or touched by the feature.
- [ ] Corpus fields and values are checked for secret, credential, operator, database-row and server-coordinate leakage.
- [ ] Review tokens and callback authorization are proven unchanged or any regression is a blocking finding.
- [ ] Findings include severity, concrete evidence and remediation; the JSON contains no sensitive values.
