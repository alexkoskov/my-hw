# Task 1: Production corpus and scoring harness

## Required Skills

Before starting, load:
- `/skill:code-writing` — [SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Create the sanitized 24-pair production regression oracle before changing the dedup rule. The corpus and its scorer make the precision target reproducible while proving that no operational or private data enters the repository.

## What to do

- Record provenance and sanitization rules in `work/dedup-broad-precision/corpus-raw/README.md`.
- Materialize exactly 24 recoverable labelled pairs in the raw evidence JSON, then derive the stable test fixture from that evidence.
- Add fixture-integrity tests and a deterministic scorer that calls the real pair-rule contour without a database or network.
- Record the current-rule baseline separately from the target assertion that Task 2 will activate.

## TDD Anchor

- `tests/test_dedup_broad_precision.py::test_production_corpus_integrity` — validates exact label counts, required public fields, supported fingerprint shapes, unique pair identifiers, and the absence of prohibited or secret-shaped fields.
- `tests/test_dedup_broad_precision.py::test_current_pair_rule_corpus_baseline` — runs all 24 labels through the real pair rule and emits a deterministic baseline without database, network, or production state access.

## Acceptance Criteria

- [x] The corpus contains exactly 24 pairs: 3 `dupe` and 21 `not_a_dupe`.
- [x] Each article side contains only a public identifier, original title, source name, and existing fingerprint object.
- [x] The integrity test rejects tokens, chat/operator identifiers, credentials, server coordinates, raw database rows, and unexpected fields.
- [x] The scorer uses production decision code and produces stable labelled counts offline.
- [x] Raw evidence provenance and the fixture derivation are documented and reviewable.

## Details

**Files:** `work/dedup-broad-precision/corpus-raw/README.md` and `dedup-pairs.json` are new sanitized evidence artifacts; `tests/fixtures/dedup_broad_precision.json` is the stable test input; `tests/test_dedup_broad_precision.py` owns integrity and scoring behavior.

**Dependencies:** Requires the operator-mediated read-only export described by blocker B-002. Adds no package or runtime resource.

**Edge cases:** Duplicate article IDs, malformed fingerprints, unknown labels, hidden extra fields, credential-shaped strings, empty titles, and non-deterministic ordering must fail fixture integrity.

**Implementation hints:** Reuse the shape conventions in `tests/fixtures/cross_source_dedup_pairs.py`; keep raw evidence under the existing pre-commit evidence exclusion; isolate current baseline from Task 2's future target assertion.
