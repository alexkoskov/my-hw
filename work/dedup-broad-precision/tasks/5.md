# Task 5: Feature code audit

## Required Skills

Before starting, load:
- `/skill:code-reviewing` — [SKILL.md](../../../.claude/skills/code-reviewing/SKILL.md)

## Description

Perform a read-only holistic code-quality audit after implementation and documentation are complete. The audit must catch cross-component drift that task-level reviews may miss and produce a machine-readable decision artifact.

## What to do

- Review the final decision helpers, job wiring, alert builders, tests, corpus and Project Knowledge against both approved specs.
- Check complexity, duplicated policy, error boundaries, reason consistency, state transitions, compatibility keys, and preservation of existing dedup invariants.
- Classify every finding with evidence and a concrete fix, or explicitly approve with no findings.
- Write only `work/dedup-broad-precision/logs/audit/code-audit.json`; do not modify implementation files.

## Acceptance Criteria

- [ ] Every modified production and test contour is covered by the audit.
- [ ] The report checks effective-title reuse, scan precedence, cap provenance, deferral invariant, reason propagation, and fail-open handling.
- [ ] Findings include severity, exact file/function evidence, and an actionable fix.
- [ ] The report is valid JSON and contains no raw secrets, private data, or production coordinates.

**Dependencies:** Task 4 closes implementation documentation. Any audit finding is handed back for a separate fix and re-review before Task 8.
