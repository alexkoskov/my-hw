## Variant B+ in production (validated)

Logs at 12:29 / 13:09 / 13:49 МСК today show all three autoevolution publishes hit the variant B+ path (model `openai/gpt-5.4-mini-20260317` returned `blocks: null` for each). Outcomes:
- Slot 1 (33 blocks): second-pass count mismatch (32 expected, 31 returned) → kept EN captions ([news_bot logs]).
- Slot 2 (18 blocks): second-pass success — 18/18 RU.
- Slot 3 (27 blocks): second-pass success — 27/27 RU.

So 2/3 articles got fully Russian captions; 1/3 fell back to EN — which was the explicit safety contract.

## Schedule window fix

Cron tick was at 10:00 МСК but slots were computed with `compute_publish_slots(N, now)` *without* the `window_start`/`window_end` kwargs. The function defaulted to `WINDOW_START = time(13, 0)`, silently shrinking the daily window from 10h to 7h (≤ 11 slots). Fixed by passing the kwargs explicitly. Regression-guarded.

## Lamley WAF mitigations (sequence)

The fresh server IP got 5 consecutive 429s per cron tick — Lamley's Cloudflare-like WAF was profiling. Mitigation in stages:
1. Browser-style headers — `Accept`, `Accept-Language`, `Sec-Ch-Ua-*`, `Sec-Fetch-*`, etc. UA bumped Chrome 120 → Chrome 131. May or may not be enough on its own.
2. `curl_cffi.requests` with `impersonate="chrome131"` — matches a real Chrome TLS handshake byte-for-byte. Cloudflare also fingerprints JA3, so plain `requests` was getting flagged before headers were even read. Tests inject `session=MagicMock()` and bypass this entirely.

If 429s persist after deploy, next steps: residential proxy or RSS-only-with-teaser fallback (Lamley RSS only carries 1-sentence summary, not full content).

## Operations

### Sudoers NOPASSWD (one-time install on VPS, as root)

`/etc/sudoers.d/news_bot` (mode 0440 — anything else and sudo silently ignores the file):

```
hwbot ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart news_bot.service, /usr/bin/systemctl status news_bot.service, /usr/bin/journalctl -u news_bot.service
```

Required for the deploy workflow's restart step. Without it, the SSH step fails with "terminal is required to read the password".

### Backup script (one-time install)

`/home/hwbot/bot/backup_db.sh` (reference copy in repo at `scripts/backup_db.sh`). Daily at 02:00 server time via hwbot's user crontab. Rotates 7-day window. Outputs to `/home/hwbot/backup/news_<DATE>.db`.

Crontab install snippet (idempotent):
```bash
( crontab -l 2>/dev/null | grep -v 'backup_db.sh' ; \
  echo '0 2 * * * /home/hwbot/bot/backup_db.sh' ) | crontab -
```

### Migration recovery (codespace → server)

When the bot moved from the codespace to VPS, the codespace's `news.db` (5 entries in `processed_news`) was NOT migrated. Server's empty `processed_news` made it re-publish ~5 URLs that were already in the channel from the codespace-fetcher era.

Recovered 2026-04-29 by merging codespace's `processed_news` into server's via `INSERT OR IGNORE` over SSH stdin, then `DELETE FROM pending_articles WHERE link IN (SELECT link FROM processed_news)`. 3 future dupes prevented; 2 already happened (visible in channel as repeats from April).
