# Task 2: Keyboard builder + reply_markup forwarding

## Required Skills

## Description

Строим две «кирпичика» фичи dedup-review-buttons, которые дальше (Wave 2, Task 3)
соберут вместе на E014-сайте отправки:

1. **Клавиатура.** Чистый билдер `admin_alerts.build_dedup_review_keyboard(token)`,
   который возвращает `InlineKeyboardMarkup` с двумя инлайн-кнопками —
   «🚫 Не публиковать» и «👍 Оставить». `callback_data` кодируется по грамматике
   из Decision 3: `dd:c:<token>` (cancel) и `dd:k:<token>` (keep). Токен —
   короткий (`secrets.token_urlsafe(9)`, ~12 символов), поэтому `callback_data`
   укладывается в лимит Telegram 64 байта (сам URL статьи — PK `pending_articles`
   — в лимит не влез бы). Функция чистая, без I/O, полностью юнит-тестируема.

2. **Проброс клавиатуры.** В `news_bot.send_admin_notification` добавляем
   **keyword-only** параметр `reply_markup=None` и прокидываем его в
   `bot.send_message`. Keyword-only — обязательное требование: все существующие
   вызывающие передают `message` позиционно, а `max_attempts` уже keyword-only;
   новый параметр после `*` гарантирует, что ни один существующий тест/вызов не
   сломается, а `reply_markup=None` по умолчанию делает вызов байт-в-байт таким
   же, как сегодня.

Эта задача даёт только *возможности*. Минтинг токена, `put_review_token`,
и фактический проброс `reply_markup` в E014-пинг — это **Task 3** (Wave 2), не
здесь. Слушатель нажатий и логика решения — Task 4/5.

**Dependencies:**
- Зависит от задач: нет (Wave 1, `depends_on: []`).
- Пакеты: новых нет. `python-telegram-bot==21.10` уже даёт `InlineKeyboardButton`/`InlineKeyboardMarkup` (tech-spec Dependencies).

**Edge cases:**
- Порядок кнопок: cancel (`dd:c`) обязан идти ПЕРЕД keep (`dd:k`) — смоук и тест сравнивают плоский список `['dd:c:t','dd:k:t']`. Плоский обход `for r in kb.inline_keyboard for b in r` сохраняет порядок независимо от того, одна строка из двух кнопок или две строки по одной.
- `reply_markup=None` по умолчанию = дефолт PTB `send_message` (нет клавиатуры) → полная обратная совместимость. Существующие тесты `TestAdminNotifyRedaction` ассертят только `kwargs["text"]`, поэтому лишний kwarg `reply_markup=None` их не ломает.
- Эмодзи — часть видимого текста кнопки (`text`), в `callback_data` эмодзи нет.
- Keyword-only: сегодня у функции нет второго позиционного параметра (после `message` идёт `*`), поэтому позиционная передача клавиатуры уже даёт `TypeError` — тест это фиксирует как контракт.

**Implementation hints:**
- `callback_data` каждой кнопки — её префикс из грамматики Decision 3, склеенный с токеном (точные значения см. в What to do п.2 и TDD Anchor). Никакой валидации/экранирования токена в билдере не нужно — токен генерируется на стороне отправителя (Task 3) как `secrets.token_urlsafe(9)` (url-safe алфавит).
- Не добавляй в `news_bot.py` неиспользуемый импорт `InlineKeyboardMarkup` — `send_admin_notification` работает с уже готовым объектом (иначе code-reviewer отметит мёртвый импорт).
- Держи `build_dedup_review_keyboard` чистой (str → InlineKeyboardMarkup), без обращения к БД/сети — это упрощает юнит-тест и соответствует стилю модуля `admin_alerts` (все билдеры чистые).
