# User Spec: multiple-rss-feeds

## Что делаем
Добавляем поддержку нескольких RSS-лент в существующего бота Hot Wheels News. Бот будет обрабатывать до 5 RSS-лент из разных источников новостей Hot Wheels, агрегировать новости, переводить, суммировать и публиковать в Telegram-канал.

## Зачем
Одна RSS-лента ограничивает охват новостей. Энтузиасты Hot Wheels хотят получать новости из нескольких источников, чтобы не пропускать важные анонсы. Фича решает проблему ограниченного охвата и повышает ценность бота для подписчиков.

## Как должно работать
1. Пользователь добавляет до 5 RSS-URL в конфигурационный файл (или переменные окружения).
2. Бот при каждом запуске (раз в день) проверяет все ленты на новые статьи.
3. Для каждой новой статьи бот извлекает заголовок, текст, изображения.
4. Бот переводит заголовок и текст с английского на русский.
5. Бот создаёт краткое изложение (3-5 предложений) переведённого текста.
6. Бот отправляет в Telegram-канал пост с заголовком, картинкой и кратким содержанием.
7. Ссылка на статью сохраняется в SQLite базу данных, чтобы избежать дублирования.

## Критерии приёмки
- [ ] Бот корректно парсит все добавленные RSS-ленты и извлекает новые статьи.
- [ ] Дубликаты определяются по ссылке и не публикуются повторно.
- [ ] Каждая новая статья переводится на русский язык (заголовок и текст).
- [ ] Для каждой статьи создаётся краткое изложение (3-5 предложений).
- [ ] Пост с переводом, картинкой и кратким содержанием публикуется в Telegram-канал.
- [ ] Ошибки парсинга/перевода/отправки логируются, но не останавливают обработку остальных лент.
- [ ] Конфигурация лент может быть изменена без изменения кода (через файл или переменные окружения).

## Ограничения
- **Количество лент:** не более 5 (ограничение по производительности и времени выполнения).
- **Частота обновления:** раз в день (суточный интервал, как у текущего бота).
- **Ограничения Telegram:** длина сообщения до 4096 символов, размер изображения до 5 МБ, количество изображений в одном посте — одно.
- **Технические ограничения:** RSS-ленты должны быть валидными и доступными, перевод зависит от доступности Google Translate API.

## Риски
- **Риск 1:** Одна из RSS-лент может стать недоступной, что приведёт к ошибке парсинга и остановке обработки остальных лент. **Митигация:** Добавить обработку исключений для каждой ленты независимо, логировать ошибку и продолжать обработку других лент.
- **Риск 2:** Google Translate API может временно недоступен или ограничен по частоте запросов. **Митигация:** Использовать fallback — оставлять текст на английском, если перевод не удался, с записью в лог.
- **Риск 3:** Увеличение времени выполнения из-за множества лент может превысить допустимые лимиты (например, cron-таска). **Митигация:** Установить таймауты на каждую ленту, ограничить количество одновременно обрабатываемых статей (например, не более 10 новых статей за запуск).

## Технические решения
- Мы решили хранить конфигурацию RSS-лент в JSON-файле `feeds.json`, потому что это гибко и не требует перезапуска бота при изменении списка.
- Мы решили не создавать отдельную таблицу для каждой ленты в БД, потому что deduplication работает по ссылке глобально.
- Мы решили не добавлять веб-интерфейс для управления лентами, потому что это выходит за рамки MVP и увеличивает сложность.

## Тестирование

**Unit-тесты:** делаются всегда, не обсуждаются.

**Интеграционные тесты:** делаем — причина: нужно проверить парсинг RSS, работу с базой данных, вызовы внешних API (Google Translate, Telegram) в изолированном окружении с моками.

**E2E тесты:** не делаем — причина: E2E-тесты требуют реальных RSS-лент и Telegram-бота, что сложно автоматизировать и поддерживать; достаточно ручной проверки после деплоя.

## Как проверить

### Агент проверяет

| Шаг | Инструмент | Ожидаемый результат |
|-----|-----------|-------------------|
| 1. Запустить бота с тестовыми RSS-лентами (mock) | bash, python | В логах видно, что бот обработал все ленты, нашёл новые статьи, перевёл и отправил mock-сообщение. |
| 2. Проверить, что ссылки добавлены в БД | sqlite3, bash | В таблице `processed_news` появились новые записи с корректными ссылками. |
| 3. Проверить обработку ошибок (недоступная RSS) | bash, python | Бот логирует ошибку, но продолжает работу с остальными лентами. |

### Пользователь проверяет
- После деплоя добавить реальные RSS-ленты в конфигурацию и убедиться, что посты появляются в Telegram-канале с переводом и картинкой.
- Проверить, что дубликаты не публикуются (добавить уже обработанную ранее статью).
- Убедиться, что лог ошибок (если есть) доступен для диагностики.
