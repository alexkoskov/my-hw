# Session 2026-06-24 — filter by source brand label (fix Matchbox false positive)

Operator: a published post "🚗 Ещё фото машинок из серии Moving Parts 2026" was
NOT Hot Wheels. The 2026-06-23 filter fix had added `'moving parts'` to the
HW-series title guesses — but **"Moving Parts" is a Matchbox line**, so it
leaked through. Operator's insight: the source page carries a `Labels: Matchbox`
tag — filter by that instead of guessing from the title.

## Root cause
`_is_hot_wheels_relevant` judged t-hunted posts by title keywords only. Title
keywords are ambiguous across brands ("Moving Parts" = Matchbox; also a HW-ish
phrase). The 06-23 whitelist over-trusted the title.

## Fix — authoritative brand label from the source's own taxonomy
t-hunted is a Blogger blog; every post is tagged (`Labels:` / `Marcadores:`),
and the RSS feed carries these as `<category>` → feedparser `entry.tags`.
Verified on the live feed (`?alt=rss`): the Moving Parts post is tagged
`['Matchbox']`; HW posts carry `Pop Culture` / `Car Culture` / `RLC` /
`Silver Series` / `Trackin Trucks`, or say "Hot Wheels" in the title.

Changes (`news_bot.py`):
- `_fetch_rss_entries`: carry `labels` (from `entry.tags` `term`s) into the item
  dict so the filter can see them.
- `_is_hot_wheels_relevant` decision order: (1) "hot wheels" in title → keep
  (cross-over round-ups); (2) **sibling-brand LABEL → reject** (Matchbox, Maisto,
  Tomica, Johnny Lightning, Tarmac Works, …); (3) **HW series LABEL → keep**
  (Pop Culture, Car Culture, Silver Series, RLC, …); (4) "matchbox" in title →
  reject; (5) HW series name in title → keep; (6) broad-diecast default reject.
- Removed `'moving parts'` from the title-substring guesses (it's a Matchbox
  line); `_SIBLING_BRAND_LABELS` + `_HW_SERIES_LABELS` added.

Non-t-hunted sources (autoevolution etc.) carry no labels → `labels=[]` → label
steps are no-ops, title fallbacks unchanged (no regression).

## Validation
- Live-feed run over all 25 current t-hunted entries: every Matchbox/Maisto/
  Tomica/Johnny-Lightning/Tarmac post → reject; every genuine HW (incl. the
  Pop Culture Porsche the old title filter would have DROPPED) → keep. The
  reported Moving Parts post → reject.
- Tests: +7 in `test_relevance_filter.py` (sibling-label reject incl. the exact
  Moving Parts case, HW-series-label keep, sibling-beats-series, "hot wheels"
  title beats sibling label, label-less Moving Parts still rejected, label
  plumbing in `_fetch_rss_entries`). Updated the item-shape test in
  `test_sources_registry.py` for the new `labels` key. Suite: 1141 → **1148**.
- Review: self-review + the live-feed validation (more decisive than an agent
  review for a taxonomy-matching change).

## Shipped
- dev → prod via the (now healthy) pipeline. Asymmetric-cost stance: ambiguous
  no-label posts ("lote M", bare "linha básica") are conservatively rejected —
  better a rare missed HW post than another off-topic publish.
