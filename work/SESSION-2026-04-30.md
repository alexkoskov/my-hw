## Security + code review pass (post-EOD)

After "all green, observe production" the operator requested an explicit
audit. Two specialised agents (security-auditor + code-reviewer) ran in
parallel against the prod code paths. Findings were ranked and addressed
in priority order:

### Critical (P1) — fixed
- **C1+C4 outage recovery dead code** — `record_recovery_event` was
  defined but never called. Any transient OpenRouter/Claude outage left
  the bot stuck on Google fallback forever. Fix: new
  `news_bot._maybe_record_recovery` helper called from every successful
  Claude transcreation in `_fallback_publish` AND from a healthy startup
  probe in `main()`. Two tests updated to assert the auto-recovery
  contract.
- **C2+C3 inline retry-with-sleep** — `_fallback_publish` blocked the
  slot loop for up to 10 minutes synchronously per failing article (3
  retries × 5 min). Removed the entire retry-with-sleep loop +
  `_LLM_PER_ARTICLE_*` constants + tests/conftest fixture. Per-article
  hiccups now strike immediately and retry on the next slot
  (≥ MIN_INTERVAL_MINUTES = 90 min later) — same eventual outcome,
  no in-process blocking.

### High (security) — fixed
- **H1 deploy.yml shell-injection-via-secret-value** — heredoc passed
  secret values as `'$VAR'` (unquoted heredoc). Any value containing
  `'` / `\\` / `\n` could escape its quoting and inject shell on prod
  via the `systemctl restart` sudoers rule. Reworked: 11 NUL-delimited
  values are streamed via `printf '%s\\0' ...` followed by a QUOTED
  heredoc body. Remote uses `IFS= read -r -d ''` per variable,
  preserving every byte verbatim regardless of content.

### Medium (security) — fixed
- **M3 lamley substring host check** — upstream `news_bot.fetch_full_article`
  uses `'lamleygroup.com' in domain` which would accept
  `lamleygroup.com.attacker.example`. New `_is_allowed_lamley_url` exact
  allowlist (`lamleygroup.com` / `www.lamleygroup.com`) at the top of
  `lamley_source.fetch_lamley_article`; rejected URLs return None +
  notify operator without touching the network. 6 unit tests in a new
  `TestHostAllowlist` class.
- **M4 Markdown in admin pings** — sanitised exception text containing
  `*` / `_` / `[` caused `can't parse entities` and silently dropped
  the alert. Plus an article-derived sanitised string could rewrite the
  visible message via crafted `[label](url)` syntax. Switched to
  `parse_mode=None` (plain text) — operational alerts have no need
  for inline formatting.

### Important (correctness) — fixed
- **I3 retry_from_failed** — used to drop `telegraph_url` /
  `telegraph_path` when re-queueing, creating an orphan Telegraph page
  on every retry. Idempotent ALTER TABLE migration adds the two columns
  to `failed_articles`; `move_to_failed` and `retry_from_failed`
  preserve them across the boundary. 2 new repo tests.
- **I7 outage signal scope** — verified by-design (the protocol probes
  Claude again between ping #1 and ping #3 on the off chance the outage
  was transient). Added a code comment explaining the scope so future
  reviewers don't re-litigate.
- **I8 _google_translate EN-leak guard** — under double-engine outage
  Google's `transcreate_text` returns the source verbatim. Without a
  guard the article would publish with EN body. New
  `news_bot._llm_translation_is_russian` (Cyrillic-share heuristic
  mirroring the LLM-module helper) raises `GoogleTranslationError` on
  rejection. 1 new test asserting the regression. Defensive `isinstance`
  guards added on block text/caption iteration so a malformed upstream
  block dict can't crash the loop.
- **I10 skip already-translated text in B+** — variant B+ second-pass
  was re-translating already-RU paragraph blocks (after
  `_patch_text_with_ru_paragraphs` filled them) — wasted one API call
  per long article. New `skip_patched_text=True` kwarg on all 4 LLM
  modules' `_translate_block_strings` skips the `text` field on
  `lead/paragraph/heading` blocks; `caption` and other types unchanged.
  Backward-compat via `skip_patched_text=False` for legacy callers.
  2 new tests.

**Net test count:** 683 → 694 (+11 regression / contract tests).
