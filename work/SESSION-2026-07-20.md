## The backfill trap (why backfill is now ABANDONED, not just deferred)

Re-verification before enabling (correctly gated) exposed two things:

1. **Base not warm.** Re-run dry-run on 07-20 still showed **42 rows** un-processed (not `~0`).
   The 46→42 drift is just the 30-day window sliding — proof the real backfill never persisted.
2. **autoevolution HTTP 403 on the article scrape** — 17 of 42 rows unreachable during the
   bulk dry-run. **Live 403 count over 3 days = 0**: the 403 is a *bulk-request rate-limit*
   artifact (backfill hits ~42 URLs in ~1 min), NOT an IP block. Paced live scraping (1
   article/slot) is unaffected.

**The trap (code read of `backfill_fingerprints.py:180-242`):** on a 403 the source returns
`None` (defer/retry semantics for the live path), so `fetch_full_article` returns falsy →
backfill's `empty-fp` branch **persists a terminal `{"strict":[],"brands":[],"series":[],
"pairs":[]}`** (has `$.pairs` → `_already_backfilled` True → never re-selected). Only a *raised*
exception takes the retryable `'error'`→NULL path. So a real backfill run right now would
**permanently write off ~17 recent articles** from dedup over a transient 403. → **Do not run
backfill against a rate-limiting source.** Latent bug worth fixing (offered as `/write-code`).

## Decision: skip backfill, self-warm, enable at first out-of-window slot

Warm-up is unnecessary here: since the 17th every live publish writes a proper four-key
fingerprint, and the gate looks back only 7 days — so the window self-warms and is fully
covered by ~24th with **no backfill**. Enabling early is **safe**: a hard-block needs a
`|D` pair *match*; cold historical rows have no pairs → cannot false-block. Worst case of a
partly-cold base = slightly lower recall for a few days, ramping to full. So:

- **Backfill: dropped from the plan.**
- **Enable (`DEDUP_SERIES_ENABLED=1` + rebuild):** at the next out-of-window slot
  (07-20 was ~11:40 МСК = inside 10:00–20:00, so earliest = after 20:00 МСК 07-20 or before
  10:00 07-21). Then watch `[E014]`/`[E015]` for false positives. **PENDING operator.**

## Code fix — backfill 403 write-off trap (DONE, on `dev`, via /write-code)

fingerprint on a no-body fetch. A `None` / no-`paragraphs` result (the 403 case)
now returns a new `'unreachable'` verdict, persists NOTHING, leaves the row NULL
for retry. Only a REACHABLE body persists (incl. the legitimate computed-empty
four-key marker — still terminal). Summary counter/label `Empty fp`→`Unreachable`
(uniform single-space lines). Documented trade: a persistently-dead URL is
re-selected each run until it ages out of the `--days` window (≤90d) — harmless,
