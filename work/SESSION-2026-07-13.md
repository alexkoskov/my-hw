## 1. dedup-model-series — new tiered dedup rule (full AI-First flow)

**What / why.** Extends the shipped cross-source dedup. New rule keyed on
**(car model + series/theme) PAIRS**, 30-day window, ANY source (incl. same-source
follow-ups). Tiering: a distinctive pair (concrete model + tagged franchise/event,
e.g. `porsche 911|k-pop demon hunters|D`) **hard-blocks** (`[E015]`, irreversible);
a broad match (theme-only, or a recurring line like Car Culture, `|B`) **soft-flags
and publishes** (`[E014]`). Fail-safe: untagged/unknown series → broad, never a
silent hard-block. Motivated by SDCC-2026 pop-culture tie-ins the old car-only
fingerprint missed.

**Flow.** user-spec → tech-spec → task decomposition (11 tasks, 2 validation rounds,
both validators approved) → feature-execution by waves:
- Wave 1: T1 series/theme extraction + tier-tagged `SERIES_LEXICON` (`model_extractor.py`);
  T2 pair-aware `[E015]`/`[E014]` builders (`admin_alerts.py`); T3 8-pair calibration fixture.
- Wave 2: T4 toggle `DEDUP_SERIES_ENABLED` (default on) + tiered gate refactor on the
  publish path (`news_bot.py`); T5 widened backfill re-select (`backfill_fingerprints.py`).
- Wave 3: T6 pair-tier calibration test (turns the by-design-red calibration green) +
  deploy runbook in `deployment.md`.
- Audit wave: T7 code READY, T8 security PASS (0 findings), T9 test PASS — no blockers/majors;
  applied the non-blocking cleanups (acronym regex derived from aliases; pin pair-1's
  must-not-hard-block; extend `TestSqlAudit` to backfill; runbook operator note).
- Final: T10 pre-deploy QA **PASSED** (1244 tests, 17 ACs / 0 fail / 2 deferred to prod).
  T11 post-deploy = operator-applied.

**Key decisions / deviations (see work/dedup-model-series/decisions.md).** Toggle env
name == const name `DEDUP_SERIES_ENABLED`; blank/unset → ON. Connector-word primary
tokens ("Porsche de K-Pop") degrade to theme-only `|B` (not a bogus `|D`). Known

model (fail-safe direction; lexicon top-up + the 2-week spot-check mitigate).

## 2. pipeline-diagnostic watchdog (via /write-code shortcut)

**What / why.** The `[E009]` «Бот сработал, новых статей нет» ping fired flat, with no
cause — the operator couldn't tell WHERE the articles disappeared. Now `job()` step (b)
accumulates a per-tick **intake funnel** (plain-int counters: sources_fetched/failed →
new → dropped_no_article/checklist/dedup_block, dedup_degraded → staged), logs one
`[funnel]` line, and the tick ping renders it — `[E009]` shows «Где схлопнулось: дубль-блок (3)»,
`[E008]` gets a compact intake summary. Fail-safe (counts only, formatting degrades to
the legacy line, never breaks the tick). Security PASS (no untrusted text in the ping).
Scope = intake/staging only (translation/post are later, at slots). +18 tests.
