# Task 7: `hw_review` CLI with `list` / `show` / `stage` / `skip` / `preview`

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Создаём новый модуль `hw_review.py` в корне репозитория — CLI-поверхность для ручного ревью очереди переводов. Это первая из двух волн на `hw_review.py`: текущая задача делает скелет argparse + пять команд (`list`, `show`, `stage`, `skip`, `preview`), следующая волна (Task 8) дописывает `publish` и в Wave 6-7 дойдём до `take` и `retry`.

CLI — единственный способ, через который оператор и Claude Code работают с очередью `pending_articles`. По тех-спеку (Decisions 1, 3, 6, 8) и §9.3 / §9.6 / §9.13 code-research он должен:

- `list` — показывать пронумерованную очередь с учётом возраста и числа параграфов, а **всегда** (даже на пустой очереди) добавлять футер `⚠️` по `failed_articles`, если таблица непустая (Decision 8).
- `show N` — печатать EN оригинал + состояние ru-полей + служебные поля (attempt_count, fetched_at, notified_at, sanitized `last_error`, telegraph_url если есть).
- `stage N` — читать `ru_paragraphs` и `ru_blocks` как JSON со stdin; `ru_title` / `ru_subtitle` — через флаги. Вся нагрузка перед записью проходит через **жёсткий валидатор** (Decision 6): лимит 256 KiB, глубина ≤ 3, allowlist ключей и типов, cross-check паритета блоков с EN-строкой (если `blocks` в pending-строке NULL — `ru_blocks` обязан быть NULL; и наоборот).
- `skip N` — если в строке уже лежит staged ru (`ru_paragraphs IS NOT NULL`), обязательно показать interactive y/N promt, а на любой ответ кроме `y`/`Y` — отменять операцию без изменений в БД (AC L49, L65). На подтверждении — `skip_pending(link)`: ссылка уходит в `processed_news`, строка удаляется из pending, в `published_articles` ничего не пишется (AC L74).
- `preview N` — ленивый рендер локального HTML (Decision 3, не создаём заранее). Путь создаётся через `tempfile.NamedTemporaryFile(delete=False, dir=CACHE_DIR, suffix='.html')` под `~/.cache/hw-review/` с правами `0700`. CLI вызывает `telegraph_publisher.preview_nodes(...)` → `preview_renderer.render_html(...)` → пишет файл → перед `webbrowser.open` проверяет `path.parent == CACHE_DIR.resolve()` (path-guard, AC). Флаг `--no-open` — печатает путь и выходит без открытия браузера (используется тестами и headless-env; §9.13 п.4).

Номер `N` во всех командах — 1-based индекс текущего `list_pending()` (он **не** стабилен между prep-tick-ами; каждая команда пере-резолвит свежим запросом).

Все человеческие сообщения идут в stdout, ошибки — в stderr. Exit 0 на успех, 1 на любую ошибку. Логгер — `news_bot.logger` (AC L75): `hw_review` не создаёт свой — получает уже сконфигурированный.

## What to do

1. Создать `hw_review.py` в корне репозитория. Импортировать `argparse`, `json`, `sys`, `os`, `pathlib`, `tempfile`, `webbrowser`, `html` (как stdlib); импортировать `pending_articles_repo`, `preview_renderer`, `telegraph_publisher`, `news_bot` (чтобы переиспользовать `logger` и `DB_FILE`).
2. Собрать argparse с подкомандами `list`, `show`, `stage`, `skip`, `preview` — subparser-паттерн. `preview` принимает `--no-open`. `stage` принимает `--ru-title` и `--ru-subtitle` как обязательные строки. Все остальные — позиционный `N: int`.
3. Реализовать вспомогательный `_resolve_pending(n)` — получает 1-based индекс, возвращает строку из `pending_articles_repo.list_pending()` или печатает в stderr `"index out of range"` и возвращает None + exit 1. Применяется в `show` / `stage` / `skip` / `preview`.
4. Реализовать `cmd_list` — если `count_pending() == 0`, печатает `"queue is empty"`. Иначе — one-line-per-row в формате `"{i}. [{source_emoji}] {title} ({n_paragraphs}п, {age_hours}h)"`. Эмодзи — из `news_bot.SOURCE_EMOJI`; возраст — `(datetime.utcnow() - fetched_at)` в целых часах. **После** основного вывода, **безусловно** (Decision 8): если `list_failed()` непустой, дописать в stdout `"⚠️ {K} неопубликованных в failed: [title1, title2, ...]. hw_review retry N чтобы переподнять."`.
5. Реализовать `cmd_show N` — EN title, subtitle, список параграфов (каждый обрезан до ~200 символов для читабельности, `…` в конце если обрезали), `len(images)`, `len(blocks) if blocks else 0`, затем ru-поля с маркером FILLED/NULL per-field, `telegraph_url` / `last_error` / `attempt_count` / `fetched_at` / `notified_at`. `last_error` уже sanitized на write-path (Task 3), выводится verbatim. Логгер использовать для trace-уровня; основной вывод — в stdout.
6. Реализовать `cmd_stage N` — шаги:
   - Прочитать stdin: `data = sys.stdin.buffer.read(262145)`; если `len(data) == 262145` — reject с exit 1 и stderr `"stdin too large (>256 KiB)"`.
   - Попытаться `json.loads(data.decode('utf-8'))` в try/except; при ошибке — exit 1 и stderr `"invalid JSON: {err}"`.
   - Вызвать валидатор (см. пункт 7). При провале — exit 1 с осмысленным stderr (`"staging rejected: {reason}"`).
   - Получить строку через `_resolve_pending(n)`; если row пропала — exit 1.
   - Cross-check block-parity: `row['blocks'] is not None` ↔ `payload['ru_blocks'] is not None`. Несовпадение — exit 1, stderr `"staging rejected: ru_blocks required"` или `"staging rejected: ru_blocks must be null (EN has no blocks)"`.
   - Вызвать `pending_articles_repo.update_staged(link, ru_title, ru_subtitle, ru_paragraphs, ru_blocks)`; если False (строка уже ушла из pending) — exit 1 с stderr `"row no longer pending"`.
   - На успех — exit 0 без вывода (соблюдать тишину на happy-path `stage`).
7. Реализовать `_validate_stage_payload(parsed)` — проверяет:
   - Депс ≤ 3 (либо через `object_hook` считаем глубину, либо один раз пройти рекурсивно). Глубина 4+ → raise ValueError с `"depth exceeded"`.
   - Top-level — dict с **точно** ключами `{'ru_paragraphs', 'ru_blocks'}` — любые extra ключи отвергаются.
   - `ru_paragraphs` — `list[str]`, длина ≤ 100, каждая строка ≤ 10240 байт (в utf-8).
   - `ru_blocks` — либо `None`, либо `list[dict]`. Для каждого блока: `type` ∈ `{'paragraph', 'lead', 'heading', 'image', 'video'}`; допустимые ключи по типу: paragraph/lead/heading — `{'type', 'text', 'level'}` (level только для heading, ∈ `{3, 4}`); image — `{'type', 'src', 'caption'}`; video — `{'type', 'src', 'caption'}`. Любой неизвестный ключ или несовпадающий тип — reject. Строковые поля ≤ 10 KiB.
   - Каждая reject-ветка поднимает `ValueError` с конкретной причиной; `cmd_stage` перехватывает и печатает stderr.
8. Реализовать `cmd_skip N` — получить строку через `_resolve_pending`. Если `row['ru_paragraphs'] is not None` (staged), напечатать в stderr prompt `"В записи {n} сохранён русский. Точно скипнуть? [y/N]: "` и прочитать `input()` — **только** `y` или `Y` продолжают; любой другой ответ (включая `n` / `N` / пустую строку / что-угодно) → stdout `"skip cancelled"`, exit 0, без изменений в БД. На подтверждении — `pending_articles_repo.skip_pending(link)`, exit 0. Если ru не staged — выполнять без prompt.
9. Реализовать `cmd_preview N` с `--no-open`. Алгоритм (Decision 1 + 3):
   - Получить строку через `_resolve_pending`.
   - Precondition: все `ru_title` / `ru_subtitle` / `ru_paragraphs` не NULL. Если нет — stderr `"nothing to preview — stage Russian text first"`, exit 1.
   - Построить node tree: `nodes = telegraph_publisher.preview_nodes(title=ru_title, paragraphs=ru_paragraphs, images=row['images'], source_url=row['link'], subtitle=ru_subtitle, blocks=ru_blocks)`.
   - Рендер: `html = preview_renderer.render_html(nodes, ru_title)`.
   - Подготовить `CACHE_DIR = Path('~/.cache/hw-review/').expanduser().resolve()`; создать с `mode=0o700` если отсутствует.
   - Если `row['preview_html_path']` уже указан и файл существует — удалить его (идемпотентная замена, §risks).
   - `tempfile.NamedTemporaryFile(delete=False, dir=CACHE_DIR, suffix='.html', prefix='hw-')` → записать html → закрыть.
   - `path = Path(tmp.name).resolve()`; assert `path.parent == CACHE_DIR`; **если не совпадает** — удалить файл, вывести в stderr `"preview path escaped cache dir"`, exit 1, **не** вызывать `webbrowser.open`.
   - Записать путь обратно в строку: `pending_articles_repo.set_preview_path(link, str(path))` (если такой helper есть в репо-модуле после Task 1; иначе — update через `update_staged`-аналог или вынести в `pending_articles_repo`). Если метода нет — ограничиться stdout-выводом пути без записи и оставить пометку для Task 8.
   - Если не `--no-open` — `webbrowser.open(f"file://{path}")`; игнорировать возвращаемое значение (`False` на headless — не ошибка, путь уже напечатан; логировать warning).
   - Всегда печатать абсолютный путь в stdout на одной строке. Exit 0.
10. Сделать `main()` — парсит argparse, диспатчит в cmd_*, возвращает exit code; блок `if __name__ == '__main__': sys.exit(main())`.
11. Создать `tests/test_hw_review_cli.py` — unit-тесты на каждую команду и валидатор (см. TDD Anchor). Использовать tempfile DB паттерн из `tests/test_integration.py:23`. Мокировать `webbrowser.open`, `sys.stdin`, `input`.

## Acceptance Criteria

- [ ] `hw_review.py` создан в корне репозитория, импортируется без ошибок.
- [ ] `python hw_review.py list` на пустой БД печатает `"queue is empty"` и exit 0.
- [ ] `python hw_review.py list` **всегда** дописывает `⚠️` футер, когда `failed_articles` непустой — даже при пустой основной очереди (Decision 8 / AC L71).
- [ ] `python hw_review.py show N` на out-of-range индексе → stderr `"index out of range"`, exit 1.
- [ ] `python hw_review.py stage N` принимает `ru_paragraphs` + `ru_blocks` из stdin как JSON; `ru_title` / `ru_subtitle` — через флаги.
- [ ] Валидатор `stage` отклоняет все 8+ категорий атак (Decision 6): stdin > 256 KiB, depth > 3, unknown top-level key, non-list `ru_paragraphs`, non-dict block, unknown block `type`, unknown block key, string field > 10 KiB. Каждая ветка покрыта отдельным тестом.
- [ ] Block-parity cross-check: `ru_blocks=None` при `pending.blocks != NULL` → reject; `ru_blocks != None` при `pending.blocks == NULL` → reject.
- [ ] `skip N` при staged ru запрашивает подтверждение; любой ответ кроме `y`/`Y` отменяет операцию без изменений в БД (AC L49, L65).
- [ ] `skip N` при подтверждении вызывает `skip_pending(link)` — ссылка в `processed_news`, строка удалена из pending, нет записи в `published_articles` (AC L74).
- [ ] `preview --no-open N` печатает абсолютный путь к HTML-файлу, exit 0, `webbrowser.open` **не** вызван.
- [ ] Preview-файл создаётся **только** при вызове `preview` (Decision 3) — не при `stage`, не при `list`, не в prep-фазе.
- [ ] Preview-файл лежит внутри `~/.cache/hw-review/` с правами `0700` на директорию.
- [ ] Перед `webbrowser.open` CLI ассёртит `path.parent == CACHE_DIR.resolve()`; escape — выход 1 с осмысленным stderr и **без** вызова `webbrowser.open` (Decision 1 / Security AC).
- [ ] Все stdout-строки идут в stdout, все ошибки — в stderr; ни одного raw traceback на стандартные сбои (index out of range, vanished row, invalid JSON).
- [ ] CLI использует `news_bot.logger`, а не `print` для диагностики (AC L75).
- [ ] Тестовый файл `tests/test_hw_review_cli.py` создан и зелёный.

**Edge cases (собрать явно, покрыть тестами):**
- Очередь пустая + failed пустой → `"queue is empty"` без футера.
- Очередь пустая + failed непустой → `"queue is empty"` + `⚠️` футер (Decision 8).
- `N` вне диапазона → `"index out of range"` на stderr, exit 1.
- `stage N` на vanished row (уже ушла через fallback между `list` и `stage`) → `update_staged` вернёт False → stderr `"row no longer pending"`, exit 1 (AC L63).
- `stage` с пустым `ru_paragraphs: []` → валиден (§9.13 п.1): JSON `[]` не NULL, считаем как staged. Чек `is staged` идёт по `IS NOT NULL`, а не по truthiness.
- `stage` на `ru_blocks=null` при `pending.blocks IS NULL` → валидно. При `pending.blocks` non-NULL и `ru_blocks=null` → reject.
- `skip N` без stdin (не tty): на interactive prompt `input()` на не-tty вернёт EOF → ловим `EOFError` → `"skip cancelled"`, exit 0.
- Cyrillic в JSON: `json.loads` работает, `ensure_ascii=False` — для записи обратно (реализуется в репо). stdin читаем как bytes + decode utf-8 явно — не через `sys.stdin.read()` (байтовый лимит точен только на `buffer.read`).
- `preview` повторный на той же строке: старый файл по `preview_html_path` удалить до создания нового (см. Risks в tech-spec).
- `preview` на headless Docker: `webbrowser.open` вернёт False — не ошибка, путь уже в stdout, exit 0 (§9.13 п.4).
- Path-guard: `tempfile.NamedTemporaryFile` не должен выдать путь вне `CACHE_DIR`, но ассёрт остаётся последней линией защиты — тестируется моком `Path.resolve`, возвращающим `/tmp/evil.html`.

**Implementation hints:**
- Используй `sys.stdin.buffer.read(N)` для побайтового лимита. `sys.stdin.read()` ломает подсчёт на multi-byte символах.
- Глубина JSON: либо `object_hook` с счётчиком, либо рекурсивный обход после parse — второе проще и достаточно для depth=3.
- `CACHE_DIR = Path('~/.cache/hw-review/').expanduser()`. Создавать через `mkdir(parents=True, exist_ok=True, mode=0o700)` — но Python игнорирует `mode` на уже существующей директории; проверять + `chmod(0o700)` отдельно, если важно (security-auditor попросит).
- `webbrowser.open(f"file://{path}")` — строка, не `Path`. Логировать предупреждение через `news_bot.logger.warning`, если вернулся False, но exit-код не менять.
- Для ассерта path-guard: `resolved = path.resolve(); if resolved.parent != CACHE_DIR: ...`. Сравниваем `Path` объекты, а не строки (чтобы `/` vs trailing-slash не ломал).
- `main()` возвращает int exit code; `sys.exit(main())`. Так же в тестах можно вызывать `main()` напрямую и ловить exit code без `subprocess`.
- Для тестов stdin мока используй `monkeypatch.setattr('sys.stdin', io.BytesIO(b'...'))` + `sys.stdin.buffer` — или оберни чтение stdin в свой helper `_read_stdin_bytes()` для удобной подмены.
- Все exit-коды возвращай через `return 1` / `return 0` в `cmd_*`; `main` пробрасывает их в `sys.exit`. Не используй `sys.exit()` внутри `cmd_*` — это ломает unit-тесты.
- Для `list_pending()` `N`-индексации: 1-based, ясно; держи индексацию снаружи (`rows = list_pending(); row = rows[n-1] if 1 <= n <= len(rows) else None`) — проще тестируется.
