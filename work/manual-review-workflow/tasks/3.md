## Description

Добавляем в `news_bot.py` три foundational-хелпера, которые потребляются последующими волнами фичи `manual-review-workflow`:

1. **Словари `SOURCE_EMOJI` и `SOURCE_LABEL`**, ключи — `'autoevolution'` / `'mattel'` / `'lamley'` (Decision 4 tech-spec). Общий вокабуляр для `source_name` в `pending_articles` и для форматирования админ-пинга. Никакого ключа `'rss'` — lamley тоже приходит через RSS, и оба источника должны различаться в ping-строке.
2. **`build_admin_ping(rows: list[dict]) -> str | None`** — собирает пинг-строку в формате из user-spec L25 / L57: `"N ждут review: 🟠 autoevolution ×K, 🟣 mattel ×M, 🟢 lamley ×L"`. Источники с нулевым счётчиком в строку не попадают. На пустой очереди возвращает `None` (запрет на пинг про пустую очередь, user-spec AC L57).
3. **`sanitize_error_message(exc) -> str`** (Decision 11) — приводит `str(exc)` к виду без четырёх секретов окружения (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, `TELEGRAM_ADMIN_ID`, `TELEGRAPH_ACCESS_TOKEN`), заменяя каждое значение на `[REDACTED]`. Пустые/None/whitespace-only переменные окружения пропускаются, чтобы не нарваться на `str.replace('', ...)` (взрывает каждый символ). Используется перед записью `last_error` в БД и перед отправкой в админ-чат — чтобы токены не утекали ни в `news.db`, ни в `hw_review show N`, ни в Telegram.

Задача — fundamentals-wave: сам пайплайн prep-фазы и CLI их ещё не вызывают, но Task 6 (job refactor), Task 7 (CLI show) и Task 9 (idle-fallback) на них опираются.

## What to do

1. Добавить в `news_bot.py` константы `SOURCE_EMOJI` и `SOURCE_LABEL` — словари, ключи `'autoevolution'`, `'mattel'`, `'lamley'`. Разместить рядом с `_source_hashtag` (строка ~291). Эмодзи-вокабуляр: 🟠 `autoevolution`, 🟣 `mattel`, 🟢 `lamley` (user-spec L25).
2. Реализовать функцию `build_admin_ping(rows: list[dict]) -> str | None`:
   - На пустом `rows` возвращает `None`.
   - Считает количество строк по `row['source_name']` через `collections.Counter`.
   - Собирает фрагменты `"{emoji} {label} ×{count}"` **в фиксированном порядке** `('autoevolution', 'mattel', 'lamley')` — порядок стабильный, не зависит от порядка ключей в `Counter`. Источники с нулём пропускает.
   - Возвращает `f"{len(rows)} ждут review: " + ", ".join(parts)`.
   - Матчит user-spec byte-for-byte, включая двоеточие+пробел, эмодзи, знак `×` (U+00D7), запятую+пробел как разделитель.
3. Реализовать функцию `sanitize_error_message(exc: BaseException) -> str`:
   - Берёт `str(exc)` как базу.
   - Для каждого из четырёх env-имён (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, `TELEGRAM_ADMIN_ID`, `TELEGRAPH_ACCESS_TOKEN`): читает значение через `os.getenv(name)`, проверяет что значение **не None, не пустое и не whitespace-only** (`value and value.strip()`); только если проверка прошла — заменяет все вхождения `value` на `[REDACTED]`.
   - Возвращает очищенную строку. Исключение внутри функции не поднимает (любой баг в sanitizer не должен ломать основной error-path).
   - Разместить рядом с `send_admin_notification` (строка ~38), чтобы было очевидно, что notifier тоже должен этот хелпер использовать (хотя сам вызов из notifier — уже Task 6/9, не здесь).
4. Создать `tests/test_admin_ping.py` с набором тестов (см. TDD Anchor). Тесты автономные, без зависимости от БД/сети.

## Details

**Files:**
- `news_bot.py` — добавить `SOURCE_EMOJI`, `SOURCE_LABEL` рядом с `_source_hashtag` (~строка 291). Добавить `sanitize_error_message` рядом с `send_admin_notification` (~строка 38). Добавить `build_admin_ping` рядом со словарями. Существующий код не трогать.
- `tests/test_admin_ping.py` (новый) — набор unit-тестов из TDD Anchor. Использовать `pytest` + `monkeypatch` для изоляции env. В каждом sanitize-тесте **сначала** `monkeypatch.delenv(...)` для всех четырёх переменных, затем устанавливать только нужные — чтобы реальное окружение dev-машины не загрязняло тесты.

**Dependencies:**
- Только stdlib: `os`, `collections.Counter`, `typing` (для аннотаций — опционально).
- Никаких новых внешних пакетов (user-spec ограничение: no new deps).
- Task 3 сам не зависит ни от одной задачи (wave 1).

**Edge cases:**
- `build_admin_ping` на `rows` с `source_name='other'` (пришло из `_resolve_source_name` для неизвестного netloc — Task 5): такой ключ в `SOURCE_EMOJI`/`SOURCE_LABEL` отсутствует. Решение: итерация идёт по фиксированному tuple `('autoevolution', 'mattel', 'lamley')`, поэтому `'other'` просто игнорируется — он не попадёт в пинг. Это допустимое поведение (user-spec говорит о трёх источниках явно). Добавить тест `test_ignores_unknown_source_name` — строка с `source_name='other'` и строка с `source_name='autoevolution'` в `rows` → в выводе есть autoevolution, нет упоминания other, **но** `N` в префиксе равен полному `len(rows)` (включая other — это количество записей в очереди, а не сумма counters). Это важно: `"2 ждут review: 🟠 autoevolution ×1"` — N=2, но сумма counters=1.
- `sanitize_error_message`: два секрета с одинаковым значением (например, одинаковые `TELEGRAM_BOT_TOKEN` и `TELEGRAPH_ACCESS_TOKEN` в dev-окружении) — второй `replace` на уже-заменённой строке no-op, работает корректно.
- `sanitize_error_message`: значение секрета является подстрокой другого секрета (редкий, но возможный кейс) — поведение зависит от порядка замен. Это не угроза безопасности (оба будут заменены в конечном счёте), но тест `test_sanitize_redacts_all_four_in_one_string` покрывает общий кейс.
- `sanitize_error_message`: exception чей `str(exc)` — пустая строка. `''.replace(value, '[REDACTED]')` возвращает `''` — корректно.
- `build_admin_ping`: если в `rows` попал элемент без ключа `'source_name'` — это баг вызывающей стороны (строка из `pending_articles` всегда имеет source_name после Task 5). Строгое поведение: `Counter(r['source_name'] for r in rows)` поднимет `KeyError`. Для этой задачи оставляем строгое поведение (никаких `.get` с fallback) — пусть баг проявится рано.

**Implementation hints:**
- Снипет `build_admin_ping` в code-research §9.4 (строки 450-458) — канонический reference, матчит spec. Использовать его как скелет.
- Для `sanitize_error_message` держать список имён переменных локальным константным tuple — легко расширять, легко тестировать. Не читать env на import-time (env может измениться между импортом и вызовом — например, в тестах через monkeypatch).
- Порядок ключей в итерации `('autoevolution', 'mattel', 'lamley')` — литерал в коде, не `sorted()` и не список из словаря. Явный порядок = стабильность формата на случай будущих рефакторов.
- В тестах для sanitize использовать фикстуру `monkeypatch.setenv`/`delenv` — не трогать `os.environ` напрямую.
- Telegram-токены в тестах — выдуманные короткие строки (`'abc'`, `'xyz789'`, `'bot123'`), никаких реальных значений. Это на случай, если тесты будут где-то залогированы.
- Docstring каждой функции: одно предложение + референс на decision/AC.
