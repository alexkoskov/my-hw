# Task 15: Post-deploy verification

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:post-deploy-qa` — [skills/post-deploy-qa/SKILL.md](~/.claude/skills/post-deploy-qa/SKILL.md)

## Description

Финальная верификация фичи `manual-review-workflow` на живом окружении после того, как пользователь выкатил изменения в Docker/VPS. Pre-deploy QA (Task 14) уже прогнала тестовый набор и прошла по acceptance criteria в изолированном окружении — эта задача закрывает то, что нельзя проверить без реального Telegram + Telegraph + крона: формат админ-пинга в живом админ-чате, визуальный и машинный облик поста в канале `@myhwchannel123`, Instant View превью-карточка и корректность финальной Telegraph-страницы.

Задача не пишет код и не модифицирует production-данные, кроме одного реального end-to-end прогона review-цикла на одной неопубликованной статье (stage → preview → publish). Итог — отчёт `post-deployment-verification.md` в `logs/working/qa/` с результатами каждой проверки.

## What to do

1. Запустить `pytest tests/` в production check-out (актуальный задеплоенный коммит). Убедиться, что все тесты зелёные — 0 failures, 0 errors. Зафиксировать полный вывод в отчёте.
2. Через Telegram MCP прочитать последние 24 часа сообщений из админ-чата (ID берётся из `TELEGRAM_ADMIN_ID`). Найти админ-пинги от бота за этот период. Для каждого пинга проверить:
   - формат строго `"N ждут review: 🟠 autoevolution ×K, 🟣 mattel ×M, 🟢 lamley ×L"`;
   - источники с нулевым счётом отсутствуют в строке;
   - на пустую очередь пинг не отправлялся;
   - `N` равно сумме `K + M + L`.
   Если за 24 часа пингов не было вообще и очередь на момент проверки пуста — это валидный сценарий, отметить в отчёте.
3. Выполнить один полный review-цикл на реальной неопубликованной статье из `pending_articles`:
   - `python hw_review.py list` — увидеть нумерованную очередь.
   - `python hw_review.py show <N>` — получить EN-оригинал.
   - Написать качественный русский пересказ, затем `python hw_review.py stage <N>` с `--ru-title`/`--ru-subtitle` флагами и `ru_paragraphs`/`ru_blocks` JSON на stdin.
   - `python hw_review.py preview --no-open <N>` — получить путь к локальному HTML-файлу; `cat` для проверки структуры (hero, subtitle, параграфы, футер).
   - `python hw_review.py publish <N>` — реальный publish в канал.
4. Через Telegram MCP прочитать последнее сообщение в канале `@myhwchannel123`. Проверить:
   - текст содержит корректный хэштег источника (`#autoevolution` / `#mattel` / `#lamleygroup`);
   - `link_preview_options.show_above_text == true`;
   - `link_preview_options.url` указывает на только что созданную Telegraph-страницу (совпадает с тем, что записалось в `published_articles.telegraph_url`);
   - Instant View превью-карточка отображается (наличие `link_preview` в raw-сообщении, `is_disabled == false`).
5. Спот-чек Telegraph-страницы через `curl`:
   - `curl -s <telegraph_url>` — получить HTML.
   - Убедиться, что в ожидаемых позициях присутствуют: hero-картинка (первый `<figure>` с `<img>`), italic subtitle с `💬 «…»`, `<hr>`-сепаратор между subtitle и body, параграфы body-текста, футер «Источник: …» со ссылкой.
   - Визуальный порядок совпадает с golden-reference `work/telegraph-pipeline/post-format.md` (msg 35 в `@myhwchannel123`).
6. Опционально: сравнить новый пост с msg 35 по структурным инвариантам (те же теги, тот же порядок блоков).
7. Записать отчёт `work/manual-review-workflow/logs/working/qa/post-deployment-verification.md`. Структура: заголовок с датой/коммитом, раздел на каждую из пяти проверок (pytest / admin ping / review cycle / channel post / Telegraph spot-check) с pass/fail маркером, raw-выводами, найденными отклонениями; итоговый статус в самом верху.

## Acceptance Criteria

- [ ] `pytest tests/` в production check-out проходит полностью — 0 failures, 0 errors.
- [ ] Админ-пинги за последние 24 часа в админ-чате соответствуют формату `"N ждут review: 🟠 autoevolution ×K, 🟣 mattel ×M, 🟢 lamley ×L"` — источники с нулём отсутствуют, пинг приходил только при непустой очереди, `N` = сумма счётчиков.
- [ ] Выполнен один полный review-цикл `list → show → stage → preview → publish` на реальной неопубликованной статье без ошибок; строка переехала из `pending_articles` в `published_articles` с `via_review=1`.
- [ ] Канальный пост в `@myhwchannel123` (прочитан через Telegram MCP) содержит корректный хэштег источника, `link_preview_options.show_above_text=true`, URL указывает на созданную Telegraph-страницу.
- [ ] Instant View превью-карточка видна в канальном посте.
- [ ] `curl` Telegraph-страницы показывает hero + subtitle + параграфы + футер в ожидаемых позициях — порядок совпадает с `post-format.md`.
- [ ] Отчёт `logs/working/qa/post-deployment-verification.md` создан: pass/fail на каждую проверку, raw-выводы, итоговый статус.

## Verification Steps

### Automated

- `pytest tests/` в production check-out → all pass.

### Smoke

Все smoke-проверки выполняются агентом по ходу задачи:

- `pytest tests/` в задеплоенной копии кода.
- Telegram MCP: чтение админ-чата за последние 24ч; проверить формат всех найденных админ-пингов байт-в-байт против регулярки `^\d+ ждут review: (🟠 autoevolution ×\d+(, )?)?(🟣 mattel ×\d+(, )?)?(🟢 lamley ×\d+)?$` (минимум один источник, никаких нулей).
- Bash: один полный прогон CLI `python hw_review.py list`, `show <N>`, `stage <N>`, `preview --no-open <N>`, `publish <N>` на реальной неопубликованной строке.
- Telegram MCP: чтение канала `@myhwchannel123`; ассерт на текст = `#<source>`, `link_preview_options.show_above_text == true`, `url` совпадает с Telegraph-URL только что опубликованной строки, Instant View превью-карточка активна.
- `curl -s <telegraph_url>` — грэп на `<figure>`, `<i>`, `💬`, `<hr>`, `Источник` — все присутствуют, порядок совпадает с golden-reference.

### User

Подтверждение пользователем нужно только если агент обнаружил расхождение или неоднозначность (например, Instant View не показывается в конкретной версии клиента) — в этом случае агент спрашивает пользователя, показывается ли превью-карточка визуально в его Telegram-клиенте на канальном посте.

## Details

**Tools required:**
- `bash` — `pytest`, CLI-вызовы `hw_review.py`, `curl`, SQL-пробы через `sqlite3 news.db "..."`.
- `Telegram MCP` — чтение админ-чата и канала `@myhwchannel123`.
- `curl` — HTTP-GET на Telegraph-URL.

**Environment prerequisites:**
- Production контейнер (Docker или VPS) уже задеплоен из целевого коммита.
- `.env` содержит актуальные `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_ID`, `TELEGRAM_CHANNEL_ID`, `TELEGRAPH_ACCESS_TOKEN`.
- В `pending_articles` есть хотя бы одна реальная статья, которую оператор согласен пропустить через review-цикл (не тестовая подставная) — обычно свежая запись из последнего cron-tick.
- Оператор доступен для финального подтверждения визуала, если агент запросит (см. User секцию).

**Report file (new):**
- `work/manual-review-workflow/logs/working/qa/post-deployment-verification.md` — финальный отчёт. Структура: заголовок с датой/коммитом, раздел на каждую из 5 проверок (pytest / admin ping / review cycle / channel post / Telegraph spot-check) с pass/fail маркером, raw-выводами, найденными отклонениями; итоговый статус в самом верху.

**Dependencies:**
- Task 14 (Pre-deploy QA) должна быть завершена — если она упала, развёртывание не состоялось и эта задача не запускается.
- Пользователь должен подтвердить, что деплой в Docker/VPS выполнен и контейнер работает стабильно хотя бы один cron-tick до запуска этой задачи.

**Edge cases:**
- За последние 24 часа не было ни одного админ-пинга — это валидно, если очередь была пуста (убедиться SQL-пробой `sqlite3 news.db "SELECT COUNT(*) FROM pending_articles"`).
- `pending_articles` пустая на момент запуска — нельзя выполнить review-цикл. Действие: попросить пользователя дождаться следующего cron-tick ИЛИ запустить `python news_bot.py` вручную один раз.
- `hw_review publish N` упал после успеха Telegraph — зафиксировать в отчёте; `telegraph_url` должен сохраниться в строке, повторный `publish N` не должен создать вторую Telegraph-страницу (Decision 9).
- Канальный пост пришёл, но Instant View-карточка не отображается визуально — эскалировать пользователю; проверить `link_preview_options.is_disabled == false`.
- Telegram MCP вернул пустой массив сообщений для канала — убедиться, что chat_id правильный (`@myhwchannel123`); если канал приватный для бота — эскалировать.

**Implementation hints:**
- Начать с `pytest` — быстрее всего поймать регрессии сборки.
- Затем Telegram MCP на админ-чат (read-only, безопасно).
- Реальный `publish` — последним, после того как smoke-проверки прошли; в отчёте зафиксировать ссылки на опубликованный пост и Telegraph-страницу, чтобы пользователь мог сверить глазами.
- Не запускать cron-tick вручную, если `pending_articles` и так непустая — работать с тем, что уже в очереди.
- Отчёт писать инкрементально по ходу проверок, а не в конце — если на шаге 3 что-то сломается, уже собранный контекст не потеряется.
