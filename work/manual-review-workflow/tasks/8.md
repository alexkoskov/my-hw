# Task 8: `hw_review publish` with Telegraph-URL reuse

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Extend the `hw_review.py` CLI (created in Task 7) with the `publish N` subcommand — the final operator-driven step of the review flow that moves a staged pending row to the Telegram channel.

The command composes three existing building blocks (`telegraph_publisher.publish_article`, `pending_articles_repo.mark_telegraph_published` / `move_to_published`, `news_bot.send_telegraph_teaser`) and adds the critical retry-idempotency contract per Decision 9: once `createPage` has succeeded, the resulting Telegraph URL is persisted on the pending row; a retry after a Telegram-send failure reuses that URL and never creates a second Telegraph page. This closes a real failure mode (Telegraph OK, Telegram fail) without polluting the Telegraph account with orphan pages.

On a fully successful publish, the row leaves `pending_articles` for `published_articles(via_review=1)` atomically (single SQLite transaction owned by the repo), the corresponding `processed_news` row is written, and the local HTML preview file (if any, tracked via the `preview_html_path` column) is deleted. On a vanished row (already published, already failed, or never existed) the CLI prints a clean one-line stderr message citing current state and exits 1 — no Python traceback.

The channel-post hashtag continues to flow through `_source_hashtag(source_url)` per Decision 14 — `publish N` passes the original source URL (not `source_name`) into `send_telegraph_teaser` so the existing TLD-stripped hashtag format (`#autoevolution`, `#mattel`, `#lamleygroup`) is preserved byte-for-byte.

## What to do

1. Add a `publish` subparser to `hw_review.py` alongside the `list` / `show` / `stage` / `preview` / `skip` subparsers introduced in Task 7. Positional arg `n: int` (1-based index into `list_pending()` output, same resolution pattern as the other subcommands).

2. Implement `cmd_publish(n)`:
   - Resolve `link` from the 1-based index over `list_pending()`. Index out of range → stderr `"publish: index {n} out of range"` + exit 1.
   - Call `pending_articles_repo.get_pending(link)`. If None, resolve current state:
     - `get_published(link)` hit → stderr `"{link} already published at {telegraph_url}"`, exit 1.
     - `get_failed(link)` hit → stderr `"{link} in failed: {last_error}"`, exit 1.
     - Neither → stderr `"{link} not found"`, exit 1.
   - Precondition: if `row['ru_paragraphs'] is None` → stderr `"nothing to publish — stage Russian text first"`, exit 1.
   - Telegraph step (idempotent per Decision 9):
     - If `row['telegraph_url']` is set, skip `createPage` entirely. Reuse stored `telegraph_url` + `telegraph_path`.
     - Otherwise call `telegraph_publisher.publish_article(title=ru_title, subtitle=ru_subtitle, paragraphs=ru_paragraphs, images=images, blocks=ru_blocks, source_url=link)`. On `TelegraphError` / `requests.RequestException` log via `news_bot.logger`, stderr a clean one-liner, exit 1. On success derive `telegraph_path = urlparse(url).path.lstrip('/')`, persist both via `mark_telegraph_published(link, url, path)`.
   - Telegram step: call `news_bot.send_telegraph_teaser(telegraph_url, row['link'])`. The helper already derives the channel hashtag from the source URL via `_source_hashtag(source_url)` (Decision 14) — pass the original `row['link']`, not `source_name`. On `False` / exception: stderr `"telegram send failed. Telegraph URL saved — rerun publish {n} to retry send."`, exit 1. Pending row stays with `telegraph_url` populated so retry is idempotent.
   - Success step: `move_to_published(link, telegraph_url, telegraph_path, via_review=True)` (single transaction inside the repo: INSERT published + INSERT OR IGNORE processed_news + DELETE pending). Then, if `row['preview_html_path']` is non-NULL, delete the file (try/except `OSError`, log-only on failure — file may already be gone). Print `"Published: {telegraph_url}"` to stdout, exit 0.

3. Write `tests/test_hw_review_publish_flow.py` (new file). Cover:
   - Happy path: staged row → `publish 1` → Telegraph mocked to return URL → teaser mocked to return True → row appears in `published_articles` with `via_review=1`, disappears from `pending_articles`, appears in `processed_news`; `preview_html_path` file is deleted if it existed; stdout contains the URL; exit 0.
   - Retry idempotency (smoke-verify target): first publish has `send_telegraph_teaser` return `False`; second publish of the same N succeeds. Assert `publish_article` is called exactly once across both runs via mock `call_count == 1`. After first run: pending row still present with `telegraph_url` populated, exit 1, stderr hint. After second run: row moved to `published_articles`, exit 0.
   - Retry via exception: same as above but first `send_telegraph_teaser` raises; assert same idempotency.
   - Vanished row three-state matrix: (a) link in `published_articles` only → stderr cites `telegraph_url`, exit 1; (b) link in `failed_articles` only → stderr cites `last_error`, exit 1; (c) link in none → stderr `"not found"`, exit 1. All three: no Python traceback, no `publish_article` call, no `send_telegraph_teaser` call.
   - Not-staged precondition: pending row with `ru_paragraphs IS NULL` → stderr `"nothing to publish — stage Russian text first"`, exit 1, no Telegraph / Telegram calls.
   - Telegraph failure: `publish_article` raises `TelegraphError` → exit 1, clean stderr, no Telegram call, pending row unchanged (`telegraph_url` still NULL).
   - Hashtag wiring assertion (Decision 14): mock `send_telegraph_teaser`, assert it is called with positional args `(telegraph_url, row['link'])` — NOT with `source_name`. Spot-check that a Lamley row keeps `#lamleygroup` behaviour (call the real `_source_hashtag(row['link'])` in the assertion to compare).
   - Channel-post AC shape (machine-checkable via mock): the teaser mock captures its args; assert the URL passed matches the freshly-created Telegraph URL (happy path) AND the reused URL (retry path), proving both runs point the channel post at the same Telegraph page.
   - Preview-file cleanup: row with `preview_html_path` pointing at a real tempfile → publish happy path → assert file no longer exists.

4. Before committing, run the full `pytest tests/` locally and confirm the new file plus the previously-flipped integration tests (Wave 3) still pass.

**Edge cases:**
- `urlparse(tg_url).path.lstrip('/')` returns empty string for malformed Telegraph URLs — log a warning and store the empty string rather than NULL, so the column's non-NULL state still signals "createPage succeeded". Happy-path URLs (`https://telegra.ph/Some-Title-04-22`) always yield non-empty paths.
- Retry after a successful publish: if `move_to_published` succeeds but the CLI process is killed before printing stdout (a pathological race), a second `publish N` would hit the vanished-row path (`get_published(link)` non-None) and exit 1 with `"already published at URL"` — correct behaviour.
- `send_telegraph_teaser` can return False in three scenarios: missing env var (no crash, just False), `TelegramError` caught internally (False), or some unexpected exception bubbling up. Treat all three identically — stderr + exit 1 + keep pending row. Do NOT wrap the call in a broader try/except that swallows KeyboardInterrupt.
- `row['preview_html_path']` may reference a file already deleted by a previous `preview` re-run (Decision 1's "remove old → create new → update column" pattern). Wrap the `os.unlink` in try/except `FileNotFoundError` / `OSError` and log-only on failure.
- Importing `send_telegraph_teaser` directly from `news_bot` pulls the module's module-level env reads — acceptable under the existing pattern (`tests/test_integration.py:26-29` patches these). Do not introduce a new indirection layer.

**Implementation hints:**
- Prefer `from news_bot import send_telegraph_teaser, logger` and `from telegraph_publisher import publish_article, TelegraphError` at the top of `hw_review.py` — matches the existing import style in `news_bot.py`.
- The three-state vanished-row branching is clearest as sequential `if pub := repo.get_published(link): ... elif fail := repo.get_failed(link): ... else: ...` using walrus assignments (Python 3.13 available on CI per code-research §8).
- For the retry idempotency test, construct the mocks like: `mock_publish = MagicMock(return_value='https://telegra.ph/Test-04-22'); mock_teaser = MagicMock(side_effect=[False, True])`. Then call `cmd_publish(1)` twice, asserting `mock_publish.call_count == 1` and `mock_teaser.call_count == 2` after both.
- Log at INFO on happy path (`"Published {link} via_review=True url={tg_url}"`), ERROR on any failure branch — matches the existing `news_bot.logger` usage pattern (patterns.md Logging section).
- Do not add a `--yes` flag or any confirmation prompt to `publish`. Publish is a pure commit step — the operator already confirmed by running `preview` and deciding to proceed.
