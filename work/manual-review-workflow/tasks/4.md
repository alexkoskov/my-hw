# Task 4: Public `preview_nodes` wrapper in `telegraph_publisher`

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Добавляем публичную функцию-обёртку `preview_nodes(...)` в `telegraph_publisher.py`, которая возвращает дерево Telegraph-узлов (`list[dict]`) ровно в том виде, в котором его отправил бы `publish_article` в `createPage`, но **без** сетевого вызова `_api_call` и без зависимости от `TELEGRAPH_ACCESS_TOKEN`.

Зачем: новый модуль `preview_renderer.render_html(nodes, title)` (Task 2) рендерит локальный HTML-превью для `hw_review preview N` (Decision 1 в tech-spec — локальный HTML вместо Telegraph-draft). Рендереру нужна **та же** структура узлов, что уходит в Telegra.ph, иначе превью разойдётся с реальной публикацией. Логика построения дерева (`_build_content`, `_build_content_from_blocks`) должна остаться внутри модуля-издателя — дублировать её в `preview_renderer` нельзя (см. code-research §9.6: "keeps render logic inside the publisher module").

Приватные функции `_build_content` и `_build_content_from_blocks` **не переименовываются и не меняют сигнатуры** — они остаются приватными деталями реализации. Публичная поверхность модуля расширяется ровно на одну функцию.

Задача также закрывает User-Spec Deviation #3 в tech-spec — явно фиксирует новый публичный API.

## What to do

1. В `telegraph_publisher.py` добавить публичную функцию `preview_nodes(...)` с сигнатурой, совместимой с релевантным подмножеством аргументов `publish_article`: `title`, `paragraphs`, `images`, `source_url`, `subtitle`, `blocks`. Значения по умолчанию — такие же, как у `publish_article` (`paragraphs=None`, `images=None`, `source_url=None`, `subtitle=""`, `blocks=None`).
2. Внутри `preview_nodes` воспроизвести ту же ветвящуюся логику выбора билдера, что и в `publish_article`: при непустом `blocks` — делегировать `_build_content_from_blocks(subtitle, blocks, source_url)`, иначе — `_build_content(subtitle, paragraphs or [], images or [], source_url)`. Вернуть полученный `list[dict]`.
3. Никаких сетевых вызовов (`_api_call`, `requests`), никаких проверок `TELEGRAPH_ACCESS_TOKEN`, никаких `os.environ` — функция должна быть чистой и детерминированной, вызываться в оффлайне.
4. Параметр `title` принимается для симметрии с `publish_article` (и для прозрачности вызывающего кода в `hw_review preview`), но в дерево узлов **не включается** — Telegra.ph API передаёт `title` отдельным полем, в `content` он не входит; `_build_content*` заголовок не получают. Документировать это поведение в docstring.
5. Обновить docstring модуля `telegraph_publisher.py` (module-level), чтобы упомянуть новую публичную функцию рядом с `publish_article` / `ensure_access_token`.
6. В `tests/test_telegraph_publisher.py` добавить новый тест-класс `TestPreviewNodes` с набором тестов (см. TDD Anchor).

## Details

**Files:**
- `telegraph_publisher.py` — добавить публичную функцию `preview_nodes(...)` после `_build_content` / перед `publish_article` (или сразу после `publish_article` — в любом случае на уровне модуля, не вложенной); обновить module docstring, чтобы упомянуть её рядом с `publish_article`. Приватные `_build_content` (`:175-222`) и `_build_content_from_blocks` (`:92-161`) не трогать.
- `tests/test_telegraph_publisher.py` — добавить `class TestPreviewNodes:` с тестами по списку из TDD Anchor. Импорт `telegraph_publisher as tp` уже есть в файле (строка 12), использовать его.

**Dependencies:** отсутствуют — задача в Wave 1 и не зависит от других задач фичи. Никаких новых пакетов в `requirements.txt`.

**Edge cases:**
- `paragraphs=None` и `images=None` одновременно, без `blocks` — должно корректно уйти в `_build_content('', [], [], None)` через `paragraphs or []` / `images or []` без `TypeError` (точное поведение `publish_article`).
- Пустой список `blocks=[]` трактовать как «блоков нет» и идти по flat-ветке — ровно как `publish_article` делает через `if blocks:` (пустой список falsy).
- `subtitle=""` — flat-ветка не вставляет декоративный лид и `hr` (поведение `_build_content`).
- Значение `title` никогда не попадает в узлы — в Telegraph API `title` отдельный параметр `createPage`, а `content` — это только массив узлов; `_build_content*` параметр `title` вообще не принимают.

**Implementation hints:**
- Сигнатуру копировать с `publish_article`, убрав параметры, относящиеся к сети (`access_token`, `author_name`, `session`) — они здесь не нужны.
- Ветвление `if blocks:` повторить 1-в-1 с `publish_article:251-254`, чтобы preview гарантированно матчил то, что полетит в `createPage`.
- Для теста `test_no_network_call` проще всего monkeypatch'ить `telegraph_publisher._api_call` на функцию, которая поднимает `AssertionError("no network")`, и затем вызывать `preview_nodes`.
- Для теста `test_flat_path_matches_build_content` — напрямую сравнить два `list[dict]` через `==` (порядок ключей в dict в CPython 3.7+ стабилен, сравнение по значению корректно).
- Docstring функции должен явно указывать, что она — offline-mirror того, что `publish_article` отправляет в `createPage`, и что `title` не включается в возвращаемое дерево.
