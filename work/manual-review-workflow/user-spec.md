# User Spec: manual-review-workflow

## Что делаем

Разделяем пайплайн бота на две независимые фазы. **Prep-фаза** (автоматическая, на cron) фетчит источники, дедуплицирует и складывает каждую новую статью в очередь на ревью — в канал ничего не публикует. **Review + publish фаза** (ручная, через Claude Code + новый CLI `hw_review.py`) даёт оператору прочитать английский оригинал, написать русский пересказ вместе с Claude Code, посмотреть локальный HTML-превью и по команде опубликовать пост в канал в уже залоченном формате. Для случаев, когда оператор недоступен, сохраняется деградированный автоматический путь через существующий `transcreate_text` (Google Translate).

## Зачем

Текущий полностью автоматический флоу печатает в канале машинный русский (Google Translate + regex-замены): кальки, неправильные согласования, неточно переведённые термины Hot Wheels. В живом прогоне 22 апреля 2026 на Mattel-статье это выглядело как «Тур Legends», «великий чемпион увидит, как его творение будет создано», «в основной линейки». Оператор хочет ревьюить каждый пост с качеством, которое Claude Code даёт прямо в интерактивной сессии, — при этом без оплаты OpenAI API (нет желания платить за токены сегодня) и без смены стека (бот остаётся Python-ом, никакого n8n). Max-подписка Claude, которой пользуется оператор, уже покрывает переводчик. Бот из end-to-end автомата превращается в подготовщика очереди и публикатора благословлённого контента, с страховочной сеткой на случай отлучки оператора.

## Как должно работать

**Утренний happy-path:**
1. В 12:00 cron запускает prep-фазу. Она фетчит autoevolution RSS + Mattel corporate + Lamley, дедуплицирует по таблице «видели», для каждой новой ссылки вытаскивает полный текст статьи и кладёт его в очередь на ревью с пустыми русскими полями.
2. Если очередь непустая — бот шлёт оператору в Telegram пинг в жёстком формате: `"3 ждут review: 🟠 autoevolution ×2, 🟣 mattel ×1"`. Источники с нулём новых записей в строку не попадают. На пустой очереди пинг не приходит.
3. Оператор в удобный момент открывает Claude Code в папке бота, говорит триггер-фразу «посмотрим очередь». Claude запускает CLI, показывает пронумерованные строки (источник, заголовок, число параграфов, возраст в часах). Если в таблице failed что-то накопилось — внизу вывода появляется футер `⚠️ 2 неопубликованных в failed: [titles]. hw_review retry N чтобы переподнять.`.
4. Оператор выбирает запись; Claude дампит английский оригинал, читает, пишет русский пересказ прямо в чате. Оператор даёт правки («сократи», «оставь корпоративку», «добавь ироничности»); Claude переписывает.
5. По готовности Claude сохраняет перевод: передаёт финальный русский заголовок, subtitle, параграфы (и блоки для autoevolution) в CLI, который обновляет строку в очереди.
6. Claude запускает preview — CLI рендерит локальный HTML-файл с тем же node tree, что уйдёт на Telegraph, открывает в браузере через системный `webbrowser`. Оператор проверяет вёрстку (hero-картинка, subtitle с `💬 «…»`, параграфы, блоки, футер «Источник»).
7. Оператор говорит «публикуй». CLI последовательно: (а) создаёт финальную Telegraph-страницу, (б) шлёт в канал `@myhwchannel123` пост с хэштегом источника и Instant View превью, (в) переносит строку из очереди в таблицу published с флагом «through-review», (г) пишет ссылку в таблицу-dedup. Если Telegram-пост упал после успеха Telegraph (сеть, лимиты), строка остаётся в очереди со staged ru, повторный `publish N` переиспользует уже созданную Telegraph-страницу (URL хранится в строке, не создаётся вторая) и повторяет только Telegram-вызов. Временный HTML-файл удаляется.
8. Цикл повторяется для остальных записей в очереди.

**Fallback-путь (если оператор не пришёл):**
- Запись простояла в очереди >48 часов. На ближайшем cron-tick fallback-пасс шлёт оператору `"Will auto-publish in ~2h: [titles]. Intercept via hw_review take N"`. Ставит метку «предупреждён».
- Если за окно grace оператор вызвал `take N`, метка снимается, статья идёт через обычный review.
- Если нет — бот зовёт `transcreate_text` на original paragraphs, публикует через тот же публиковочный код, переносит в published с флагом «через-GT-не-ревью».

**Overflow-путь (очередь забита):**
- Prep-фаза обнаружила: `pending + new_count > 10`. Отбирает самые старые записи **у которых русский текст ещё не заполнен оператором** (`ru_*` NULL), прогоняет через `transcreate_text` + полный publish, освобождает слоты. Строки с непустым русским текстом не трогаются — это защита от race: оператор, который редактирует сейчас, никогда не увидит свою работу «заменённой» автопереводом.
- Если `transcreate_text` падает для статьи в overflow-пассе, запись остаётся в очереди с инкрементом счётчика попыток; новые записи, которые не влезли, дропаются до следующего cron-tick; оператор получает пинг: `"Queue pressure: fast-track failed for N, Y new entries deferred"`.

**Retry-путь (ручное спасение failed):**
- Оператор видит футер failed в `hw_review list`.
- Вызывает `hw_review retry N` — строка возвращается из failed обратно в очередь со свежим `fetched_at` и нулевым счётчиком попыток.
- Следующий cron-tick прогоняет её через fallback-пасс. Три новых провала подряд → снова в failed.

**Skip с сохранённым русским:**
- Оператор зовёт `hw_review skip N` после того, как уже `stage`-нул русский текст.
- CLI спрашивает y/N: «В записи N сохранён русский. Точно скипнуть?».
- На y: ссылка попадает в dedup-таблицу (больше не всплывёт из RSS), строка удаляется из очереди, русский текст теряется; в published запись не создаётся (skip ≠ публикация).

## Критерии приёмки

- [ ] Prep-фаза больше не публикует в канал напрямую — ни одного вызова публиковочного кода по ходу prep-цикла.
- [ ] Каждая новая запись из каждого источника (autoevolution RSS, Mattel corporate, Lamley) сохраняется в очередь с заполненными оригинальными полями (title, subtitle, paragraphs, images, блоки если источник отдаёт) и пустыми русскими полями на момент INSERT.
- [ ] Очередь имеет UNIQUE-constraint по ссылке — параллельные cron-прогоны не создают дубликатов.
- [ ] Админ-пинг отправляется **только когда очередь непустая**, в формате `"N ждут review: 🟠 autoevolution ×K, 🟣 mattel ×M, 🟢 lamley ×L"`. Источники с нулём новых в строку не попадают.
- [ ] `hw_review list` на пустой очереди показывает «queue is empty»; на непустой — нумерованные строки (источник, заголовок, возраст). Если таблица failed непустая — в любом случае показывает футер с количеством и списком, даже когда основная очередь пуста.
- [ ] `hw_review stage N` отклоняет частичный staging (не все русские поля заданы) с понятной ошибкой.
- [ ] `hw_review preview N` без предварительного `stage` возвращает ошибку `"nothing to preview — stage Russian text first"`. С заполненным русским — рендерит локальный HTML и открывает системный браузер.
- [ ] `hw_review publish N` в одной команде создаёт Telegraph-страницу, отправляет канальный пост, переносит строку в published. Канальный пост машиночекаем: текст = хэштег источника (`#autoevolution` / `#mattel` / `#lamleygroup`), `LinkPreviewOptions(show_above_text=True)` присутствует, `url` указывает на только что созданную Telegraph-страницу.
- [ ] Если Telegram-пост упал после успешной Telegraph-публикации, строка остаётся в очереди со staged ru; Telegraph-URL сохраняется в строке, повторный `hw_review publish N` **переиспользует** существующую Telegraph-страницу (вторая не создаётся), повторяя только вызов Telegram.
- [ ] `hw_review publish N`, где запись уже не в очереди (эвикнута overflow, автопубликована fallback-ом, или вообще не существует), возвращает ошибку с указанием текущего состояния (published/failed/not-found) и, если применимо, Telegraph-URL уже опубликованной страницы. Без PK-collision stacktrace.
- [ ] Очередь ровно в 10 записей + prep нашёл 0 новых — overflow fast-track не запускается (нет давления на слоты).
- [ ] `hw_review skip N` с непустым русским требует явного подтверждения y/N. Скипнутая ссылка пишется в dedup-таблицу и больше не всплывает при новых прогонах RSS. В published ничего не появляется.
- [ ] `hw_review take N` снимает метку «предупреждён» (`notified_at = NULL`), запись остаётся в очереди со статусом «pending», дальше обычный review-флоу.
- [ ] `hw_review take N` после истечения grace и автопубликации возвращает ошибку `"N already auto-published"`.
- [ ] Запись, простоявшая >48h без действия оператора, получает heads-up пинг, затем (после grace-окна по умолчанию 2 часа, значение параметризуется) автопубликуется через `transcreate_text`. Запись уходит в published с флагом «не-через-review».
- [ ] Очередь никогда не превышает 10 pending-записей. При переполнении **только записи с пустым русским** прогоняются через GT-fast-track перед INSERT новых.
- [ ] Если fast-track GT упал, очередь остаётся забитой, новые записи дропаются до следующего cron-tick, оператор получает пинг-предупреждение с счётчиком отложенных. Провалы в overflow-пути инкрементируют общий счётчик попыток по строке — после 3 провалов (в любом сочетании idle-fallback и overflow) строка уезжает в failed, её слот освобождается.
- [ ] `hw_review list` всегда показывает футер с failed (если непустая): `"⚠️ K неопубликованных в failed: [titles]. hw_review retry N чтобы переподнять."`.
- [ ] `hw_review retry N` возвращает строку из failed обратно в очередь с нулевым счётчиком попыток и свежим `fetched_at`.
- [ ] Источник Mattel подключён через общий реестр в том же месте, где перечисляются RSS-фиды; добавление нового источника — редактирование одного списка.
- [ ] Dedup-таблица содержит ссылку для любой статьи, которая была опубликована ИЛИ скипнута. Объединение published и скипнутых = полное множество «обработанных».
- [ ] CLI пишет диагностику в тот же логгер, что и `news_bot` (INFO на нормальном флоу, ERROR на сбое). Коды возврата: 0 на успех, ненулевой на любую ошибку. `hw_review show N` отображает состояние строки: заполненные/пустые поля ru_*, последняя ошибка (если есть), Telegraph-URL (если уже опубликована).

## Ограничения

- Бот остаётся на Python. Миграция в n8n отвергнута 2026-04-22 из-за стоимости переписывания Cloudflare-bypass для autoevolution и трёх существующих парсеров.
- В этой фиче **нет** внешних LLM-API — ни OpenAI, ни Anthropic API. Переводчик — это Claude Code-сессия оператора под Max-подпиской. Feature `llm-transcreation` (заменитель Google Translate на OpenAI) вынесена в будущую работу, `work/archived/llm-transcreation-deferred/`.
- Locked post format из `work/telegraph-pipeline/post-format.md` не изменяется: тот же хэштег источника, тот же `LinkPreviewOptions(show_above_text=True)`, та же структура Telegraph-страницы (hero → italic subtitle → `<hr>` → параграфы → футер с источником).
- Существующая таблица dedup не меняет схемы; её семантика расширяется с «что опубликовано» до «что видели» (any link that was published OR skipped OR historically processed).
- Cron продолжает бежать минимум раз в сутки (текущая частота — 12:00 ежедневно). Возможный bump до часовой гранулярности — осознанный 1-строчный follow-up; решение отложено до tech-spec, дефолт в этой фиче остаётся дневным.
- Queue hard cap — 10 одновременных записей в очереди. Жёсткое ограничение.
- Idle timeout — 48 часов от времени фетча до heads-up пинга. Grace-окно до автопубликации — дефолт 2 часа, значение параметризуется в tech-spec (может быть увеличено, если cron останется дневным).
- Триггер для Claude Code — фраза «посмотрим очередь». Описана как UX-конвенция, не продуктовый invariant.
- Intercept-команда — `hw_review take N`.
- Preview — локальный HTML-файл во временной папке, открывается системным `webbrowser.open`. Telegraph-страница создаётся **только** при финальной публикации.
- Никаких новых зависимостей в `requirements.txt`. CLI на stdlib `argparse`, БД на stdlib `sqlite3`.
- Бот при старте контейнера продолжает запускать prep-фазу немедленно (существующее поведение). Побочный эффект в день деплоя: два админ-пинга (один сразу, второй по расписанию) — осознанная простота вместо спец-логики подавления.

## Риски

- **Рефакторинг ломает существующие auto-publish тесты** в `test_integration.py`, `test_mattel_integration.py`, `test_feed_iteration.py`. **Митигация:** переписываем в том же PR; green-run по всему `tests/` перед merge.
- **Bump частоты cron с дневного на часовой увеличивает число запросов к RSS/Mattel.** **Митигация:** дефолт остаётся дневной, bump только по явному решению.
- **CLI-cron race:** параллельный cron в overflow-пассе затирает работу оператора. **Митигация:** overflow fast-track смотрит только на записи с пустым русским; записи со staged ru никогда не трогаются автопереводом.
- **SQLite concurrent INSERT при двух cron-прогонах подряд.** **Митигация:** UNIQUE-constraint по ссылке в очереди; race-IntegrityError ловится + логируется как ожидаемый случай.
- **Оператор отсутствует >48h и таблица failed накапливается из-за хиккапов Google Translate.** **Митигация:** футер в `hw_review list` на каждом вызове делает backlog видимым; `hw_review retry N` — прямой путь к ручному разрешению.
- **`news.db` повреждается (редкий crash SQLite или ошибка в обращении).** **Митигация:** RSS при следующем прогоне повторно поднимает все необработанные записи; потеря только на русские черновики — переписать заново из Claude Code дешево.
- **Бот переезжает из локального Docker на VPS в середине разработки.** **Митигация:** фича hosting-agnostic — код одинаково работает в любом окружении с `news.db` на файловой системе.

## Технические решения

- Мы решили **держать `transcreate_text` как legacy-fallback**, потому что он закрывает idle-таймаут и overflow-очистку без добавления LLM-зависимости. Удалять рано.
- Мы решили **завести три новые таблицы (очередь pending, аудит published, «мёртвый ящик» failed)** вместо расширения одной существующей, потому что семантика разная: WIP-очередь, аудит публикаций, terminal-state backlog — у каждой свой набор колонок и запросов.
- Мы решили **хранить скипнутые ссылки только в dedup-таблице**, не в published, потому что скип — не публикация; аудит публикаций должен оставаться чистым.
- Мы решили **переместить Mattel-источник в общий реестр** вместе с RSS-фидами, потому что сейчас он зашит в пайплайне и это раздражает при добавлении новых источников.
- Мы решили **делать preview локальным HTML-файлом**, а не Telegraph-драфтом, потому что структурная проверка (порядок абзацев, картинки, subtitle, футер) одинаковая в обоих режимах, а local HTML не создаёт публично-видимых страниц, не требует API `editPage`, не требует отдельной колонки под путь draft, не требует отдельной команды `cleanup-drafts`. Точный шрифт/отступы Instant View — косметическая разница, поймать её можно на финальной Telegraph-странице после `publish`.
- Мы решили **не делать overflow-эвикцию для строк со staged ru**, потому что это тот самый race, от которого фича должна уходить: оператор видит свою правку заменённой автопереводом. Эвикция допускается только для записей с пустым русским.
- Мы решили **не подавлять немедленный `job()` на старте контейнера**, потому что один лишний админ-пинг в день деплоя — приемлемая цена за отсутствие специальной логики startup-режима.
- Мы решили **не делать отдельного staging-окружения**, потому что фича в момент деплоя перестаёт автопубликовать — риск «залить канал мусором при rollout» структурно отсутствует.
- Мы решили **сделать `hw_review retry N` перемещением строки из failed обратно в очередь**, а не синхронным GT-вызовом в CLI, потому что команда должна быть быстрой и не блокировать на сетевых вызовах.
- Мы решили **не делать отдельную retention/auto-purge для published и failed в этой фиче**, потому что объём низкий (до 100 записей в месяц) и ручной SQL с DELETE WHERE <date> достаточен.

## Тестирование

**Unit-тесты:** делаются всегда, не обсуждаются. Покрываем CRUD для трёх новых таблиц, парсинг аргументов CLI, формат admin-ping, подсчёт источников для пинга, рендер локального HTML из node tree, правила overflow-эвикции (не трогать staged ru).

**Интеграционные тесты:** делаем. Фича затрагивает пайплайн end-to-end и переворачивает поведение существующих интеграционных тестов. Нужно:
- prep-фаза end-to-end с мок-источниками: в таблицу-очередь кладутся записи, в Telegram-канал ничего не уходит;
- publish-фаза end-to-end с мок-Telegraph/Telegram: финальная страница создана, канальный пост отправлен, запись перенесена в published;
- idle-fallback: стэйлим `fetched_at`, запускаем cron-tick, проверяем heads-up пинг и автопубликацию через grace;
- overflow без staged: заполняем очередь до 10, следующий prep прогоняет старые через GT;
- overflow со staged: старые со staged ru **не** трогаются, новые дропаются, пинг-предупреждение отправлен;
- миграция: на пустой БД после инициализации существуют все новые таблицы с ожидаемыми колонками;
- retry из failed: возврат в очередь со свежим счётчиком попыток.

**E2E тесты:** не делаем отдельно. Smoke-проверка после деплоя — публикация одной статьи через полный review flow с визуальным сравнением с msg 35 в `@myhwchannel123` — закрывает E2E без автоматического фреймворка.

**CI-гейт:** на каждом PR `pytest tests/` должен быть зелёным (полный существующий suite + все новые тесты), включая новый migration-тест, который на tempfile-БД после инициализации проверяет существование всех новых таблиц.

**Sizing note.** Фича формально M, но на верхней границе (20 acceptance criteria, 3 новые таблицы, CLI с 8 командами). Tech-spec автор волен разбить реализацию на два инкремента: (1) prep/publish split + core CLI (`list`/`show`/`stage`/`preview`/`publish`/`skip`) + таблицы + админ-пинг; (2) idle-fallback + overflow + retry + failed-таблица. Разбиение не меняет acceptance criteria и не требует правки user-spec.

## Как проверить

### Агент проверяет

| Шаг | Инструмент | Ожидаемый результат |
|-----|-----------|-------------------|
| 1. Прогнать `pytest tests/` | bash | Все тесты зелёные, 0 failures |
| 2. Запустить prep-фазу на тестовой БД с мок-env | bash | В очереди N строк; dedup-таблица пополнена; ни одного вызова отправки в канал |
| 3. Прочитать последнее сообщение в админ-чате | Telegram MCP | Формат `"N ждут review: 🟠 autoevolution ×K, 🟣 mattel ×M, 🟢 lamley ×L"`, без нулевых источников |
| 4. Пройти review-flow на одной записи через CLI | bash: `list` → `show` → `stage` → `preview` → `publish` | preview открывает HTML-файл; после `publish` запись в published (через-review), Telegraph-URL валидный, канальный пост в канале |
| 5. Машиночек канального поста | Telegram MCP + ассерты | Текст = `#{source}` хэштег, `link_preview_options` заполнено и `show_above_text=true`, URL указывает на Telegraph-страницу, созданную на шаге 4 |
| 6. Симулировать idle >48h на тестовой записи | bash + SQL: стейлим `fetched_at` → вручную вызвать fallback-пасс | Heads-up пинг пришёл; через grace-окно запись автопубликована с флагом «не-через-review» |
