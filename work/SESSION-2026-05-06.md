## What broke and why — chronological cascade

### Break 1: deploy_test.yml silently SCPed wrong code

**Symptom:** GitHub showed `deploy_test.yml` green, but on-server
`news_bot.py` had no orangetrack wiring; `orangetrack_source.py` didn't
exist on disk.

**Root cause:** `deploy_test.yml` triggers via `workflow_run` after CI
on dev. `actions/checkout@v4` without explicit `ref` defaults to
the repo's default branch (`main`) — NOT the dev SHA that the CI
actually ran on. So when we pushed orangetrack code to dev, CI on dev
passed (using dev's code), then deploy_test.yml ran and SCPed
**main's** stale code (no orangetrack) to `/home/hwbot/bot_test/`. The
restart succeeded because main's code was structurally fine — just had
no orangetrack.

**Fix:** `861f030` adds explicit
`ref: ${{ github.event.workflow_run.head_sha || github.ref }}` to the
checkout step in BOTH deploy.yml and deploy_test.yml. After this fix
landed on main, future workflow_run-triggered deploys correctly track
the SHA that triggered CI.

**Workaround used during the gap:** manual `workflow_dispatch` from
GitHub Actions UI, picking branch=dev. workflow_dispatch uses the
selected branch's HEAD via github.ref — bypasses the bug.

**Lesson saved to memory:** workflow_run-triggered actions/checkout
needs explicit `ref` or it silently deploys default-branch code. This
is a project-wide concern, applicable to any workflow_run pattern in
this repo or elsewhere.

### Break 2: half-translated articles on first prod publication

**Symptom:** First orangetrack post published to test channel had
the lead paragraph translated to Russian, but the rest of the article
remained in English. Looked like LLM gave up partway.

**Root cause (round 1):** Parser extracted first paragraph as `subtitle`
field and put `paragraphs[1:]` into the flat list. But `blocks` still
contained ALL paragraph-type entries. LLM translated `paragraphs` (K-1
entries), returned `ru_paragraphs` (K-1 entries). The variant-B fallback
`_patch_text_with_ru_paragraphs` consumes `ru_paragraphs` sequentially
for blocks of type paragraph/lead/heading — counts didn't match, the
last 1+ blocks left in English.

**Fix (round 1):** `d346934` — set `subtitle=""` always, put first
paragraph in body. Telegraph just doesn't render the italic `💬 «…»`
lead decoration; acceptable.

**Root cause (round 2):** Even with subtitle fix, blocks contained
heading-type entries (h5 case sections). `_patch_text_with_ru_paragraphs`
also consumes `ru_paragraphs` for headings. With paragraphs flat list
having only paragraph-block text (no heading text), ru_paragraphs was
shorter than count of patchable blocks → trailing blocks left in
English again.

**Fix (round 2):** `9c3b490` — include heading text in
`paragraphs_flat` alongside paragraph text. Now LLM translates
everything; ru_paragraphs has matching length; `_patch` maps 1-to-1
correctly. **Supersedes original tech-spec Decision 15** which said
"h5 heading goes to blocks-only, NOT flat paragraphs" — that decision
was based on a misanalysis of the patching pipeline.

### Break 3: uneven typography (one paragraph in big bold)

**Symptom:** Translation now full, but one paragraph in published
article rendered with prominent bold/larger typography while
surrounding paragraphs were normal.

**Root cause:** Parser still emitted h5 elements as `type: "heading"`
with `level: 5`. Telegraph renders heading-type blocks with prominent
styling (`<h3>`-equivalent). Brad's section markers translated to
longer Russian phrases or were used for descriptive text — looked
visually uneven amid normal paragraphs.

**Fix:** `babc67c` — emit h5 as `type: "paragraph"` (drop the heading
typing). Sacrifice section visual separation for uniform typography.
Operator can revisit later if section markers are missed.

### Break 4: missing video embeds (Porsche Targa Turbo article)

**Symptom:** Telegraph article had no embedded YouTube player while
the source article (orangetrackdiecast.com) clearly had Brad's
unboxing video front and center.

**Root cause:** WordPress.com **strips iframes from `content:encoded`**
when exporting RSS for some article types. The empty wrapper
`<div class="wp-block-embed__wrapper"></div>` survives but the actual
`<iframe>` is gone. The live HTML page DOES have the iframe — RSS is
the lossy layer. Affected ALL 10 orangetrack articles in the feed
(the strip is consistent, not edge-case).

**Fix:** `e7d0527`:
- New helper `_has_empty_embed_wrapper(html_str)` detects the marker.
- Triggered from `fetch_orangetrack_article` BEFORE accepting primary
  parse — when marker is present, treat feed body as incomplete and
  fall through to the existing HTTP-scrape fallback path. The live
  HTML has the iframe intact.
- Bonus: figure handler in parser was missing iframe-search
  (only looked for `<img>`). Brad's video embed is `<figure><div><iframe>`
  shape — added recursive `find_all("iframe")` in the figure walker.

### Break 5: full-page chrome bleeding into Telegraph (after fallback)

**Symptom:** After Break 4 fix, video appeared on Telegraph — but
the article also picked up the OTD logo, "Меню", "Место для всех
фанатов Hot Wheels" navigation text, 1 Stop Diecast affiliate banner,
and footer chrome.

**Root cause (round 1):** HTTP-scrape fallback parsed the WHOLE page
HTML including header, sidebar, footer, comment form, related posts.

**Fix (round 1):** `497b740` — scope `_fetch_article_html` output to
`<article>` element only (orangetrackdiecast uses HTML5 article tag,
fallback to `div.entry-content` / `<main>` for theme drift). Return
only that subtree's HTML.

**Symptom (round 2 of break 5):** Header chrome gone, video clean,
but article still showed "Оригинальный лот на Mattel Creations: …",
"Share this:", "Теги: …" trailing.

**Root cause (round 2):** Even inside `<article>`, WordPress.com
appends `<div class="sharedaddy">` (share buttons), `<div class="taxonomies">`
(tag list), and a "Original listing on …" plain paragraph with `<a>`
to the source store.

**Fix (round 2):** `6d90bf2` — chrome class filter
(`sharedaddy`, `sd-`, `taxonomies`, `jp-related`, `post-comments`,
`comment-form`) skipped during DOM walk. The "Original listing on
Mattel Creations:" paragraph is **kept** (operator's request — that
link is content, not chrome).

    (set subtitle="").
