# Task 7: Error handling and admin notifications

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Enhance error handling: catch exceptions in Facebook fetching, log detailed errors, send admin notification via `send_admin_notification` when all methods fail. Ensure other RSS feeds continue processing.

## What to do

1. Enhance error handling in `fetch_facebook_posts` (in `facebook_source.py`):
   - Wrap each method call (RSS, Graph API, HTML) in individual try‑except blocks.
   - Log each failure with level WARNING, including exception details.
   - Continue to the next method unless the failure is a critical error that should stop the whole fetch (e.g., missing page URL).
   - If all methods fail, raise a custom exception `FacebookFetchError` (or return empty list and log error). The caller (`job()`) will catch this and send admin notification.

2. Modify `job()` in `news_bot.py` to handle `FacebookFetchError` (or any exception from Facebook fetching):
   - Catch the exception, log error with level ERROR.
   - Call `send_admin_notification` with a descriptive message (e.g., “Facebook source failed: all methods exhausted”).
   - Ensure the exception does not propagate further; continue processing RSS entries.

3. Ensure admin notifications are sent only for critical failures (all methods fail) and not for transient errors (single method failure with fallback success).
   - Decide threshold: if `fetch_facebook_posts` returns empty list because all methods failed, send notification.
   - If at least one method succeeds (returns posts), no notification needed.

4. Add logging to `load_config` for configuration errors (missing file, invalid JSON) and skip Facebook fetching without notification.

## Details

**Files:** 
- `facebook_source.py` — modify `fetch_facebook_posts` error handling, add `FacebookFetchError` exception
- `news_bot.py` — modify `job()` to catch Facebook errors and call `send_admin_notification`

**Dependencies:** Tasks 1‑6 (configuration, fetch methods, integration)

**Edge cases:**
- RSS returns HTTP 404 (RSS unavailable) → log warning, try next method
- Graph API token expired → log error, try HTML
- HTML parsing fails (selector mismatch) → log warning, raise `FacebookFetchError` if last method
- Network timeout → retry up to 3 times, then treat as failure
- `send_admin_notification` itself raises exception → log error but do not crash job

**Implementation hints:**
- Define `FacebookFetchError` as a subclass of `Exception`.
- Use existing logger (`logger.warning`, `logger.error`).
- Reuse `send_admin_notification` function signature (expects message string).
- Consider adding a metric counter for Facebook failures (optional).
