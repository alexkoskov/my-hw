## Description

Full-feature code quality audit. Read all source files created/modified in this feature (from decisions.md + tech-spec "Files to modify"). Review holistically for cross-component issues: duplicate resource initialization, shared resources compliance with Architecture decisions, architectural consistency. Write audit report.

## What to do

1. Identify all source files created or modified for the Facebook Hot Wheels Source feature:
   - `facebook_source.py` (new)
   - `facebook_source.json` (new)
   - `news_bot.py` (modified)
   - `tests/test_facebook_source.py` (new)
   - `tests/integration/test_facebook_pipeline.py` (new)
   - Any other files referenced in decisions.md.

2. Review each file for:
   - **Code quality**: adherence to Python best practices (PEP 8), readability, naming, comments.
   - **Architectural consistency**: compliance with decisions in tech‑spec (e.g., fallback order, error isolation, rate‑limiting).
   - **Cross‑component issues**: duplicate resource initialization (e.g., multiple HTTP sessions), shared resources (database connection) used correctly.
   - **Error handling**: exceptions caught and logged appropriately, no silent failures.
   - **Logging**: appropriate log levels, meaningful messages.
   - **Configuration**: config loading respects environment variables, validation.

3. Look for potential bugs, performance issues, security vulnerabilities (though security audit is separate).

4. Write an audit report summarizing findings:
   - List of files reviewed.
   - Positive observations (what works well).
   - Issues found (categorized by severity: critical, major, minor).
   - Recommendations for fixes (if any).
   - Overall assessment of code quality.

5. If issues are found, create follow‑up tasks (or note them for the lead to decide).
