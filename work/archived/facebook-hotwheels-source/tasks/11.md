# Task 11: Security Audit

## Required Skills

## Description

Full-feature security audit. Read all source files created/modified in this feature. Analyze for OWASP Top 10 across all components, cross-component auth/data flow. Write audit report.

## What to do

1. Identify all source files created or modified for the Facebook Hot Wheels Source feature (same as Task 10).

2. Review each file for security vulnerabilities, focusing on:
   - **Injection**: SQL injection (though SQLite uses parameterized queries), command injection (e.g., via `os.system`), XML/JSON injection.
   - **Broken Authentication**: Facebook access token handling (environment variable vs config file), token expiration, credential leakage in logs.
   - **Sensitive Data Exposure**: tokens, URLs, user data printed in logs or error messages.
   - **XML External Entities (XXE)**: RSS parsing with `feedparser` (likely safe).
   - **Broken Access Control**: URL validation for Facebook page (SSRF risk), rate‑limiting bypass.
   - **Security Misconfiguration**: default configurations, verbose error messages, missing HTTPS enforcement.
   - **Cross‑Site Scripting (XSS)**: irrelevant for backend but any web output?
   - **Insecure Deserialization**: JSON parsing (`json.load`) with untrusted input (config file is trusted).
   - **Using Components with Known Vulnerabilities**: check `requirements.txt` for outdated packages with known CVEs.
   - **Insufficient Logging & Monitoring**: security events (failed auth, rate‑limit hits) logged appropriately.

3. Analyze cross‑component data flows:
   - Facebook page URL validation: ensure it matches expected domain pattern to prevent SSRF.
   - Graph API token: stored in environment variable, not hardcoded.
   - HTML parsing: potential for malicious HTML leading to XSS? Not relevant.
   - HTTP requests: use of `requests` with timeout, SSL verification.

4. Write a security audit report summarizing findings:
   - List of files reviewed.
   - Security strengths (e.g., token stored in env, URL validation).
   - Vulnerabilities found (categorized by severity: critical, high, medium, low).
   - Recommendations for mitigation.
   - Overall risk assessment.

5. If critical/high vulnerabilities are found, create follow‑up tasks.

**Edge cases:**
- Facebook page URL could be manipulated to target internal services (SSRF). Ensure validation restricts to `facebook.com` domain.

- Rate‑limiting bypass by sending many requests quickly. Verify delays are enforced.
