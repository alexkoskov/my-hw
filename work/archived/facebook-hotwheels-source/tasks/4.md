# Task 4: Keyword filtering and entry formatting

## Description

Implement `filter_posts_by_keywords(posts, keywords)` that excludes posts containing any keyword (case‑insensitive substring). Also implement function `format_facebook_entry(post)` that maps Facebook post fields to RSS‑like entry fields.

## What to do

1. Implement `filter_posts_by_keywords(posts, keywords)`:
   - Receive a list of post dictionaries (each with at least `message` field) and a list of keyword strings.
   - For each post, check if any keyword appears as a substring in `message` (case‑insensitive). Also check `title` if present.
   - If a keyword is found, exclude the post from the result.
   - Return filtered list of posts.

2. Implement `format_facebook_entry(post)`:
   - Take a raw post dictionary (from RSS, Graph API, or HTML) with possibly different field names.
   - Map to a uniform entry dictionary with the following fields:
     - `link` (string): URL of the post
     - `title` (string): first 50 characters of message (or empty string)
     - `published` (datetime): parsed publication date (or current time if missing)
     - `message` (string): full post text (cleaned)
     - `images` (list of strings): up to 2 image URLs
   - Ensure the mapping handles missing fields gracefully (default values).

3. Ensure both functions are pure (no side effects) and well‑tested.

## Details

**Files:**

**Dependencies:** None (wave 1)

**Edge cases:**
- Post message is `None` → treat as empty string, no keyword match
- Keyword list empty → return all posts unchanged
- Keyword appears multiple times → still filter out
- Substring matching across word boundaries (e.g., “event” matches “events”) – acceptable per spec
- Non‑string fields (e.g., `published` as string) → convert to datetime if possible, else default

**Implementation hints:**
- Use `any(keyword.lower() in (post.get('message') or '').lower() for keyword in keywords)` for filtering.
- For date parsing, reuse existing utility from `news_bot.py` (e.g., `parse_rfc2822`).
- Keep mapping simple; avoid complex transformations.
