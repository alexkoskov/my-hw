# Task 2: RSS and Graph API fetchers

## Required Skills

## Description

Implement `fetch_facebook_rss(page_url)` and `fetch_facebook_graph(page_id, access_token)` functions that retrieve posts from Facebook RSS endpoint and Graph API, returning uniform entries with `link`, `title`, `published`, `message`, `images`. Handle HTTP errors and rate limits.

## What to do

1. Implement `fetch_facebook_rss(page_url)`:
   - Use `feedparser` (already in dependencies) to parse the RSS feed at `{page_url}/rss`
   - Extract each post’s link, title, published date, description (message), and image URLs (if any)
   - Map RSS fields to the uniform entry format: `link`, `title`, `published` (datetime), `message` (string), `images` (list of URLs)
   - Handle HTTP errors (e.g., 404, 500) and RSS parsing errors gracefully (return empty list, log warning)

2. Implement `fetch_facebook_graph(page_id, access_token)`:
   - Use `requests` to call Graph API endpoint `https://graph.facebook.com/{page_id}/posts` with required parameters (`access_token`, `fields`, `limit`)
   - Parse JSON response, extract posts with fields: `id`, `permalink_url`, `message`, `created_time`, `attachments` (for images)
   - Map Graph API fields to uniform entry format (link = permalink_url, title = first 50 chars of message, published = created_time, message = full message, images = extract up to 2 image URLs from attachments)
   - Handle Graph API errors (invalid token, rate limiting) according to Facebook’s policies (exponential backoff, retry logic)

3. Both functions should respect rate limits:
   - For RSS: add a small delay between requests if needed
   - For Graph API: implement exponential backoff on HTTP 429 responses, sleep 2 seconds between calls as per spec

## Details

**Files:** 
- `facebook_source.py` — add `fetch_facebook_rss` and `fetch_facebook_graph` functions

**Dependencies:** None (wave 1)

**Edge cases:**
- RSS endpoint returns 404 (RSS not available) → return empty list, log warning
- Graph API token expired → raise `FacebookGraphError` or return empty list, log error
- Graph API returns empty data array → return empty list
- Posts without message field → use empty string for message
- Images missing or unsupported type → skip, keep empty list
- Network timeouts → retry up to 3 times with exponential backoff

**Implementation hints:**
- Use `feedparser.parse(url)` for RSS; handle `feedparser.FeedParserDict`.
- Use `requests.get(url, params=...)` for Graph API; check `response.status_code`.
- For exponential backoff, consider using `tenacity` library or implement simple retry loop.
- Follow existing patterns in `news_bot.py` for logging and error handling.
