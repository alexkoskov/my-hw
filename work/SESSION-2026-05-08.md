## Five features shipped

### 1. publish-idempotency-fix (M-size, full Molyanov)

**Symptom:** `_fallback_publish` re-published the same article when a
zombie row with cached `telegraph_url` reappeared in `pending_articles`
for a `link` already present in `published_articles`. Each retry sent
the Telegram teaser BEFORE `move_to_published` raised
`UNIQUE constraint failed: published_articles.link`. Slot-loop counted
the failure as a strike, retried on next slot — duplicate post repeated.

**Fix:**
- Idempotency guard at `news_bot._fallback_publish` line 985 —
  `pending_repo.get_published(link)` check **before any side effect**.
  On hit: log INFO, admin-ping, `skip_pending`, return True.
- `pending_articles_repo.move_to_published` Step 1 changed to
  `INSERT OR IGNORE INTO published_articles` — defense-in-depth so the
  transaction is idempotent on duplicate `link`.

**Tests:** 7 new — 5 unit (`tests/test_fallback_publish_paths.py`),
1 repo (`test_pending_articles_repo.py::test_move_to_published_idempotent_on_duplicate_link`),
1 integration (`tests/test_distributed_schedule_integration.py::test_slot_loop_does_not_repost_already_published`).

**Decisions documented:** 8 (incl. AC6 vs AC8 deviation — cleanup-failure
returns True, doesn't strike).

**Audits:** code PASS, security PASS, test PASS.

### 2. orangetrack-rendering-fixes (M-size, full Molyanov)

Three visual bugs in orangetrack.com publications, found during post-deploy
observation:

1. **`<li>` items dropped** — `_walk` recursed into `<li>` but its
   NavigableString children were skipped (`<p> walker handles text`).
2. **`<h2>/<h3>/<h4>` rendered as paragraph** — earlier `babc67c` carve-out
   for h5-as-paragraph was over-applied to higher heading levels.
3. **Same-site links stripped** — `_runs_from_tag` captured `href` metadata
   in `block.runs` but `telegraph_publisher` ignored it.

**Fix:**
- New `list_item` block type. Bullet «• » prepended at publisher level
  (after LLM, immune to LLM stripping).
- h2/h3/h4 → `type: heading, level: 3`. h5 stays paragraph (preserves
  `babc67c` for in-paragraph markers — see SESSION-2026-05-06.md break 3).
- `_render_paragraph_with_runs` helper in `telegraph_publisher.py`
  walks `block.runs`, finds same-site `run.text` substrings via
  case-sensitive `str.find`, wraps first occurrence in `<a>`. Strict
  scheme + non-empty netloc + `removeprefix("www.")` (NOT `lstrip` —
  character-set bug). DoS bounds: text > 100KB or runs > 100 → fall
  through plain text with WARNING.

**Tests:** 38 new across 2 test files. Integration test does exact
node-tree dict assertions on `<h3>` + `<a>`-wrapped paragraph + 2 bulleted
list items.

**Decisions documented:** 10.

**Audits:** code PASS, security PASS (lookalike-domain bypass prevented),
test PASS.

**Commits:** `e4ed9fb` `18ea5a6` `43d078f` `828e503` `78338d7` `cd762ba`.

### 4. orangetrack inline formatting (S-size, /write-code shortcut)

Operator asked: orangetrack uses `<strong>` tags for emphasis and
`class="has-vivid-red-color"` for highlight; can these visual cues
be preserved?

**Fix:**

  `<strong>/<b>/<em>/<i>/<u>/<s>/<del>` tags. Any element with a

### 6. move_to_published defensive dozapis (S-size, hotfix)

**Found:** post-deploy backup analysis revealed
`published_articles` had two rows (team-transport-k @ 2026-05-06 11:01
UTC, ferrari-5-pack @ 2026-05-06 14:01 UTC) with **NO matching
`processed_news` entries** until guard wrote them on 2026-05-07/08. The
May 7 02:00 UTC backup, taken 15 hours after publish, lacked the rows.
Single-connection SQLite transactions should be atomic — Step 2 cannot
silently fail while Steps 1 and 3 succeed.

Root cause unrecoverable from logs at this point. Hypotheses:
- transient SQLite issue,
- older code path that lacked Step 2,
- manual `ATTACH ... INSERT OR IGNORE INTO processed_news ...` merge
  (recipe in `deployment.md`) overwriting the table at some past point.

**Fix:** post-commit verification in `move_to_published`. Re-query
`processed_news` for the link; if missing, dozapis with `INSERT OR IGNORE`.
WARNING log surfaces the anomaly to operator iff dozapis actually fires.
Self-healing — the zombie-row cycle never starts because original
publish itself enforces consistency.

**Commit:** `75ad9e2`.

## Late-evening 2026-05-08: bare-checklist filter

Operator flagged that orangetrack publishes regular "Q3 Mainline
Checklist"-style posts that are just a title + image grid of car
names, no editorial body. Subscribers don't want translated bullet
lists.

**Two-condition rule** in new
`news_bot._is_text_only_checklist(entry, article)`:

1. Title matches `\bcheck[\s-]?list\b` (whole-word, case-insensitive)
   — covers "checklist", "check list", "check-list".
2. `article['paragraphs']` total length < 500 chars — well below any
   real review article's prose floor.

Both conditions together → drop. A review article with "checklist" in
the title but substantive body text passes through unchanged.

**Wired in** `job()` step (b3) AFTER `fetch_full_article` runs (need
the body for condition 2); on True the row never enters
`pending_articles` — also saves the LLM translation API call. Source-
agnostic; orangetrack happens to be the worst offender but the rule
applies wherever a title has "checklist" with a near-empty body.

**Files touched:** `news_bot.py` (helper + call site),
`tests/test_relevance_filter.py` (+9 unit tests covering bare drop,
review-with-checklist-keep, hyphen/space variants, word-boundary,
case-insensitivity, missing/None article). `architecture.md` step
(b3) and `patterns.md` `### Bare-checklist filter` updated.

**Test count:** 901 → 910 (+9 checklist tests).
