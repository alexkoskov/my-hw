## Description

Покрываем тестами изменения парсера и end-to-end рендеринг (Wave 1: Tasks 1-3).
Задача добавляет в `tests/test_orangetrack_source.py`:

- **10 unit-тестов** на парсинг `<li>` (в `<ul>` и `<ol>`), пустого `<li>`, `<li>` с inline-якорем
  и `<strong>`, на эмиссию h2/h3/h4 как `heading level=3`, регрессию h5 → `paragraph`
  (защита `babc67c`), игнор h1/h6, включение `list_item` в `paragraphs_flat`, и КРИТИЧЕСКИЙ
  негативный AC2-литмус — парсер НЕ префиксует `block.text` буллетом.
- **1 интеграционный тест** `test_orangetrack_rendering_end_to_end`, который собирает синтетический
  HTML с `<h3>`, `<a href>` на `orangetrackdiecast.com` и `<ul><li>`, прогоняет через
  `_parse_content_encoded`, имитирует LLM-патч RU-строк в `block.text`, вызывает
  `telegraph_publisher.preview_nodes` и сверяет ТОЧНУЮ dict-структуру итогового node-tree
  (НЕ substring match).

Эти тесты — gate для всего фичефлоу: подтверждают, что Tasks 1-2 (парсер + LLM-patch types)
и Task 3 (publisher) работают вместе и AC1, AC2, AC3, AC4, AC5 соблюдаются end-to-end.

## TDD Anchor

Тесты пишем ДО запуска (или параллельно с чтением Task 1-3 кода). Запускаем → убеждаемся,
что Task 1-3 действительно реализуют ожидаемое поведение.

Unit:
- `tests/test_orangetrack_source.py::test_li_parsed_as_list_item_block` — `<ul><li>Ferrari Testarossa</li></ul>` → блок `{type: "list_item", text: "Ferrari Testarossa", runs: [...]}`.
- `tests/test_orangetrack_source.py::test_ol_parsed_as_list_item_block` — то же с `<ol>`-родителем.
- `tests/test_orangetrack_source.py::test_li_with_inline_anchor` — `<li><a href="...">Mercedes</a></li>` → `block.text` содержит `"Mercedes"`, `block.runs` содержит run с этим href.
- `tests/test_orangetrack_source.py::test_li_with_strong` — `<li><strong>X</strong></li>` → `block.text == "X"`.
- `tests/test_orangetrack_source.py::test_empty_li_dropped` — `<li></li>` → блок не эмитится.
- `tests/test_orangetrack_source.py::test_li_block_text_does_not_contain_bullet` — **КРИТИЧЕСКИЙ AC2 литмус:** `<li>Ferrari</li>` → `block.text == "Ferrari"`, НЕ `"• Ferrari"`. Буллет добавляется только в publisher.
- `tests/test_orangetrack_source.py::test_h2_h3_h4_parsed_as_heading_level_3` — для каждого из h2/h3/h4 → `type == "heading"`, `level == 3`.
- `tests/test_orangetrack_source.py::test_h5_remains_paragraph` — `<h5>Section</h5>` → `type == "paragraph"` (регрессия `babc67c`).
- `tests/test_orangetrack_source.py::test_h1_h6_ignored` — `<h1>` и `<h6>` → блоки не эмитятся.
- `tests/test_orangetrack_source.py::test_paragraphs_flat_includes_list_item` — `paragraphs_flat` включает текст list_item-блоков в порядке fetch.

Integration:
- `tests/test_orangetrack_source.py::test_orangetrack_rendering_end_to_end` — synthetic HTML →
  `_parse_content_encoded` → ручной LLM-патч → `preview_nodes` → ТОЧНЫЕ dict-ассерты на 4 ноды:
  - `{"tag": "h3", "children": ["Раздел"]}`
  - `{"tag": "p", "children": [{"tag": "a", "attrs": {"href": "https://orangetrackdiecast.com/x"}, "children": ["Mercedes"]}, " — быстрая машина."]}`
  - `{"tag": "p", "children": ["• ", "Ferrari"]}`
  - `{"tag": "p", "children": ["• ", "Porsche"]}`
  - И порядок: heading → paragraph → list_item × 2.

**Dependencies:**
- Task 1 (парсер `<li>` + heading dispatch + `paragraphs_flat` extension) — ДОЛЖЕН быть выполнен.
- Task 2 (`_PATCHED_TEXT_BLOCK_TYPES`) — ДОЛЖЕН быть выполнен (хотя в этих тестах LLM-патч
  имитируем ручной записью в `block["text"]`, корректность production-флоу зависит от Task 2).
- Task 3 (publisher: helper + bullet rendering) — ДОЛЖЕН быть выполнен. Интеграционный тест
  завязан на `_render_paragraph_with_runs` и list_item рендеринг с `"• "`.

**Edge cases:**
- Пустой `<li></li>` → блок не эмитится. Тест `test_empty_li_dropped`.
- `<li>` со вложенным `<a href>` → run сохраняется в `block.runs`. Тест `test_li_with_inline_anchor`.
- `<li>` со вложенным `<strong>` → текст извлекается. Тест `test_li_with_strong`.
- h2/h3/h4 → одинаковый `level=3`. Параметризовать (`pytest.mark.parametrize`) или 3 ассерта.
- h5 — НЕ heading, остаётся `paragraph`. Регрессия `babc67c`.
- h1/h6 → блоки не эмитятся вообще. Тест `test_h1_h6_ignored`.
- Bullet "• " добавляется ТОЛЬКО в publisher — парсер чистый. Litmus
  `test_li_block_text_does_not_contain_bullet`.
- Интеграция: same-site link (`orangetrackdiecast.com/x`) рендерится как `<a>` внутри `<p>`,
  буллеты префиксуются к list_item. Все 4 целевые ноды сравниваются по точной структуре.

**Implementation hints:**
- Стиль ассертов: для unit-тестов — `assert blocks[i]["type"] == "list_item"`,
  `assert blocks[i]["text"] == "Ferrari"`. Для интеграционного — `assert nodes[idx] == {...}`
  (точное равенство dict).
- Для интеграционного теста взять минимальные dummy-значения для `title` / `paragraphs` /
  `images` / `subtitle` — проверка только структуры основных блоков, не header/footer
  Telegraph-страницы. Если `preview_nodes` возвращает целиком node-tree включая обвес,
  фильтровать или сравнивать срез нод, соответствующих основным блокам.
- Для целевой проверки сравнивать целиком dict (`==`), а не substring `in` — это явное
  требование AC.
- Для `test_h2_h3_h4_parsed_as_heading_level_3` — использовать
  `pytest.mark.parametrize("tag", ["h2", "h3", "h4"])` или 3 отдельных теста.
- Имитация LLM-патча: после `_parse_content_encoded` найти блоки нужного типа в порядке,
  в котором они идут в `blocks`, и присвоить `block["text"] = "..."`. НЕ использовать реальный
  `_patch_text_with_ru_paragraphs` — упрощает тест и изолирует от Task 2.
