# Task 2: LLM-patch — extend `_PATCHED_TEXT_BLOCK_TYPES` with `list_item`

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Однострочное изменение в `_llm_common.py`: добавить `"list_item"` в кортеж `_PATCHED_TEXT_BLOCK_TYPES`. Этот кортеж используется функцией `_patch_text_with_ru_paragraphs` (variant B fallback): когда LLM возвращает `blocks: null` для длинных block-shaped статей, вызывается фолбэк, который последовательно вливает русские строки из `ru_paragraphs` в блоки соответствующих типов. Сейчас в кортеж входят только `("lead", "paragraph", "heading")` — поэтому при появлении нового типа `list_item` (вводится в Task 1 в `orangetrack_source.py`) текст таких блоков не получает русский перевод во flow с `blocks=null` и попадает в Telegraph как английский исходник. Расширение кортежа закрывает этот пробел: `_patch_text_with_ru_paragraphs` начинает обновлять `block.text` и для `list_item` блоков, последовательно расходуя элементы `ru_paragraphs` по тому же порядку, в котором `paragraphs_flat` отдаёт текст в LLM (Task 1 добавляет `"list_item"` в этот сбор). Реализует часть Decision 1 из tech-spec ("LLM-patch fallback updates list_item text when LLM returns blocks=null").

## What to do

1. В `_llm_common.py` найти строку определения кортежа `_PATCHED_TEXT_BLOCK_TYPES` (текущее значение: `("lead", "paragraph", "heading")`, строка 106).
2. Добавить элемент `"list_item"` в конец кортежа: новое значение — `("lead", "paragraph", "heading", "list_item")`.
3. Никаких других правок в файле не делать (ни импортов, ни тела `_patch_text_with_ru_paragraphs`, ни вспомогательных функций — фильтр уже корректно опирается на `_PATCHED_TEXT_BLOCK_TYPES` через проверку `block.get("type") in _PATCHED_TEXT_BLOCK_TYPES`, так что новый тип подхватывается автоматически).
4. Прогнать smoke-проверку (см. Verification Steps → Smoke).

## Details

**Files:**
- `_llm_common.py` — текущее состояние: на строке 106 определён модульный кортеж `_PATCHED_TEXT_BLOCK_TYPES = ("lead", "paragraph", "heading")`. Кортеж используется на строке 340 внутри `_patch_text_with_ru_paragraphs` как множество допустимых типов блоков для splice-операции (`if block.get("type") in _PATCHED_TEXT_BLOCK_TYPES:`). Также упоминается в docstring функции (строки 322-329) — фраза "(lead / paragraph / heading)" описывает текущий состав, при желании её можно расширить до "(lead / paragraph / heading / list_item)" для согласованности, но это косметика; основное изменение — только сама строка 106.
  - Что изменить: единственная замена строки 106 — добавить `"list_item"` четвёртым элементом кортежа.
  - Что НЕ менять: импорты (стр. 19 уже экспортирует `_patch_text_with_ru_paragraphs` — импорт-список расширять не нужно), тело `_patch_text_with_ru_paragraphs` (фильтр уже параметризован кортежом), любые другие функции и константы.

**Dependencies:**
- Никаких пакетных зависимостей. Координационная связка с Task 1 (которая добавляет `"list_item"` в `paragraphs_flat` extraction в `orangetrack_source.py`) — порядок splice-а в `_patch_text_with_ru_paragraphs` зависит от того, чтобы `paragraphs_flat` отдавал `list_item`-тексты в LLM, тогда `ru_paragraphs` придёт обратно в правильном порядке. Технически Task 1 и Task 2 независимы (могут идти в любом порядке внутри Wave 1, конфликтов файлов нет), но без обоих фолбэк ru-перевода для `list_item` не работает.

**Edge cases:**
- LLM вернул `blocks: null` (variant B fallback) и в статье есть `list_item` блоки — после фикса они получат русский текст.
- LLM вернул нормальный массив `blocks` — этот фолбэк не вызывается; изменение `_PATCHED_TEXT_BLOCK_TYPES` ни на что не влияет.
- В RSS нет `<li>` — `paragraphs_flat` не содержит list_item-текстов, `_patch_text_with_ru_paragraphs` ведёт итерацию по `ru_paragraphs` строго последовательно, изменение состава кортежа не может его сломать.
- Несовпадение количества `ru_paragraphs` и блоков-кандидатов — обрабатывается существующим `try/except StopIteration` (строки 341-346), новые типы не добавляют рисков.

**Implementation hints:**
- Используй Edit с уникальным `old_string = '_PATCHED_TEXT_BLOCK_TYPES = ("lead", "paragraph", "heading")'` — этого достаточно, чтобы строка была однозначной в файле.
- После правки сразу прогоняй smoke-команду в shell — это самый быстрый способ убедиться, что синтаксис тапла валиден и импорт `_llm_common` не сломан.
- Если решено расширить docstring `_patch_text_with_ru_paragraphs` — это разрешено как косметика, но не обязательно; ревьюер не должен блокировать на отсутствии этой правки.
