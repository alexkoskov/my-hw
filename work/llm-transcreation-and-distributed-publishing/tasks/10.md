# Task 10: Strip bureaucratic regex + 4000-char truncation from `transcreate_text`

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Применяем Decision 11 из tech-spec: чистим легаси из `transcreate_text` в `news_bot.py`. Эта функция теперь не основной путь транскреации (после Wave 1–4 основным стал `claude_transcreation.transcreate_via_claude`), а fallback для двух сценариев — per-article отказ Claude по конкретной статье и глобальный Google-fallback во время API-outage.

Что убираем и почему:
- **Bureaucratic regex (19 паттернов + 4 passive→active)** — это был cleanup Google Translate, который любит канцелярит («является», «осуществляется», «в рамках» и т.д.). Claude канцелярит не пишет, поэтому в основном пути регекс мёртвый груз. И в Google-fallback он тоже снимается (по Decision 11): false-positive rate на и так нормальном тексте не оправдывает поддержки 23 паттернов.
- **4000-char truncation тела статьи** — пережиток pre-Telegraph эпохи, когда тело лилось напрямую в Telegram caption. Теперь body публикуется на Telegraph без лимита, в канал летит только тизер `#<source> #news` (~30 символов). Truncation бессмыслен.

Что оставляем:
- **HW glossary (14 паттернов)** — брендовая терминология Hot Wheels (Hot Wheels вместо «Хот Уилс», «дайкаст-модель» вместо «литой автомобиль», «гаражный проект» вместо «сборка гаража», «Legends Tour» вместо «тур легенд» и т.д.). Это safety net — даже Claude может ошибиться без явного guidance, поэтому пост-обработка остаётся.
- **Emoji prefix для титулов** — content-aware deterministic emoji остаётся (это часть AC, не легаси).
- **Сам Google Translate вызов и fallback на оригинал при ошибке** — функция всё ещё нужна как Google-fallback.

Поддерживает user-spec AC10 (косвенно, через AC12), AC12 (HW glossary keep, bureaucratic remove) и AC13 (no body truncation).

## What to do

1. В `news_bot.py`, в функции `transcreate_text`:
   - Удалить весь блок `bureaucratic = {...}` со словарём 19 паттернов и цикл `for pattern, repl in bureaucratic.items(): ...`.
   - Удалить 4 строки `re.sub(...)` для passive→active (`был выполнен`, `был представлен`, `было объявлено`, `был запущен`) — это часть того же канцелярит-cleanup.
   - Удалить блок body truncation в конце функции (`if len(result) > 4000: ...` и всю логику с поиском sentence boundary, last_space и hard cut).
   - Оставить нетронутыми: вызов `GoogleTranslator(...).translate(...)`, fallback `if not translated: return text`, блок `hw_glossary = {...}` с 14 паттернами, цикл применения glossary, ветку `if is_title:` с emoji prefix, финальный `return result` для body-варианта.
   - Обновить docstring: убрать упоминание "replaces bureaucratic phrasing" и "flips a few passive constructions to active". Оставить упоминание "fixes common Hot Wheels mistranslations" и emoji prefix logic.
   - `import re` остаётся (используется в hw_glossary и emoji prefix регексах).

2. В `tests/test_translation.py`:
   - Сейчас файл тестирует только `translate_text`. Добавить класс `TestTranscreateText` для тестирования новой (укороченной) логики. Покрытие:
     - HW glossary применяется: вход «Хот Уилс анонсировали...» → выход содержит «Hot Wheels», не содержит «Хот Уилс».
     - HW glossary применяется для другого ключевого паттерна: «сборка гаража» → «гаражный проект».
     - Bureaucratic regex НЕ применяется: вход с моком GoogleTranslator, возвращающим «является важной частью», → выход содержит «является» (не заменено на «это»). Это регрессионный тест на удаление.
     - Passive→active НЕ применяется: вход «был выполнен» → выход содержит «был выполнен» (не заменён на «сделали»).
     - Body не обрезается на 4000 символов: вход на 5000+ символов → выход той же длины (или близко — без принудительного cut на 4000). Это регрессионный тест на удаление truncation.
     - Emoji prefix для is_title=True работает: один из ожидаемых emoji в начале результата (хотя бы один тест на title path).
     - Fallback на оригинал при exception в GoogleTranslator: остаётся (если уже есть в test_translate_text — продублировать для transcreate_text не обязательно, можно один acceptance-style тест).
   - Использовать `unittest.mock.patch('news_bot.GoogleTranslator')` по тому же паттерну, что и существующие `TestTranslateText`.
   - Если в репо где-то есть тесты, ассертившие удалённое поведение (bureaucratic substitution, 4000-cap) — найти и удалить/обновить (на момент чтения `tests/test_translation.py` таких ассертов нет — файл тестирует только `translate_text`, но проверь grep по всему `tests/`).

3. Прогнать `pytest tests/test_translation.py -v` локально, убедиться что все тесты зелёные.
4. Прогнать `pytest tests/ -q` целиком, убедиться что не сломано остальное (Wave 5 уже удалила ряд тестов — состояние должно быть зелёное на момент старта Wave 6).

## Details

**Files:**
- `news_bot.py` — функция `transcreate_text` (~lines 327–439). Текущее состояние: содержит `bureaucratic` dict (19 паттернов, ~lines 351–371), цикл применения, 4 passive→active `re.sub` (~lines 376–379), `hw_glossary` dict (~lines 384–402), ветку `is_title` с emoji (~lines 405–423), body truncation (~lines 425–437). Изменения: удалить bureaucratic dict + цикл, удалить 4 passive→active, удалить весь блок truncation. Остальное — нетронуто.
- `tests/test_translation.py` — текущее состояние: один класс `TestTranslateText`, покрывающий только `translate_text`. Изменения: добавить новый класс `TestTranscreateText` с описанными выше тестами. Импорт расширить: `from news_bot import translate_text, transcreate_text`.

**Dependencies:**
- Task 9 (легаси-удаления в `news_bot.py`) — должна быть `done` перед стартом этой таски, чтобы не было merge conflict в news_bot.py.
- Никаких новых пакетов; `re` и `unittest.mock` уже используются.

**Edge cases:**
- Пустая строка на входе: `if not translated or not translated.strip(): return text` — поведение остаётся.
- Exception в GoogleTranslator: try/except остаётся, fallback на оригинальный текст работает.
- Title с очень длинным текстом: emoji prefix добавляется без обрезки (truncation удалён, и для тела, и для тайтла он всё равно не применялся — `if is_title: return ...` срабатывал раньше блока truncation).
- Body на 5000+ символов: проходит через hw_glossary без cut и возвращается полностью.
- Регекс `\bХот[-\s]?[УВв]илс\b` уже case-insensitive (через flag в re.sub) — не трогаем.

**Implementation hints:**
- Удаление чистое: после правки в функции остаются три блока — Google translate call с try/except, hw_glossary apply, и развилка `if is_title: ... else: return result`. Никаких новых веток или переменных.
- Документировать удаление в commit message: ссылка на Decision 11 + AC12/AC13.
- Не трогать функцию `translate_text` (выше в файле) — она другая и используется отдельно.
- При написании тестов — использовать `@patch('news_bot.GoogleTranslator')` и `mock_translator.translate.return_value = '...'` по образцу существующего `TestTranslateText` (строки 1–80 файла теста).
- Тест на «не обрезается на 4000» лучше написать на ~5000 символов с маркерным хвостом («END_MARKER»): после вызова assert эта подстрока в результате (если truncation остался — её не будет).
