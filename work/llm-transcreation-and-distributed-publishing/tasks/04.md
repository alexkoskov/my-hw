# Task 4: Extend `_TokenRedactingFilter` for `ANTHROPIC_API_KEY` (3-layer)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Сейчас `_TokenRedactingFilter` в `news_bot.py` защищает только Telegram-bot-токен (паттерн `\d{6,12}:[A-Za-z0-9_-]{30,}`) — он установлен на root logger и на «шумные» HTTP-логгеры (`httpx`, `httpcore`, `urllib3`, `requests`). Параллельно `_SECRET_ENV_NAMES` + `sanitize_error_message` чистят сохраняемые в БД error-строки от значений конкретных env-переменных. Эта защита не покрывает грядущий `ANTHROPIC_API_KEY` (форма `sk-ant-...`), потому что:

1. Регекс `_BOT_TOKEN_RE` не матчит `sk-ant-`-формат.
2. `_SECRET_ENV_NAMES` не содержит `'ANTHROPIC_API_KEY'`.
3. Anthropic SDK логирует через свои собственные логгеры (`anthropic`, `anthropic._client`, `anthropic._base_client`), к которым redaction-фильтр сейчас не привязан — root filter сработает только если запись пропагируется наверх и не отрезана своим хэндлером ниже.
4. `send_admin_notification` строит payload Telegram через f-string — это путь ВНЕ `logging` pipeline, и фильтр там не работает в принципе.

Задача — реализовать Decision 12 «3-layer defence» так, чтобы `sk-ant-...` ключ не утёк ни в логи (свои и SDK), ни в admin-чат, ни в строки БД, и закрепить это регрессионными тестами. Это закрывает user-spec AC25.

## What to do

0. **Reorder module-level definitions (предусловие, обязательно).** В текущем `news_bot.py` `send_admin_notification` определён на строках 116–130, тогда как блок token-redaction (`_BOT_TOKEN_RE`, `_TokenRedactingFilter`, `_TOKEN_FILTER`) идёт ниже на строках 209–245. Поскольку по этой задаче `send_admin_notification` начнёт вызывать `_redact_text` (новый module-level helper), и `_redact_text` логически живёт рядом с остальным redaction-блоком, **необходимо переместить блок token-redaction (`_BOT_TOKEN_RE`, новый `_ANTHROPIC_KEY_RE`, новый `_redact_text`, `_TokenRedactingFilter`, `_TOKEN_FILTER` + `addFilter`-цикл) ВЫШЕ определения `send_admin_notification`** — иначе обращение к `_redact_text` из тела `send_admin_notification` упадёт `NameError` на runtime (Python резолвит globals в момент вызова, и хотя для синхронной семантики forward-reference в одном модуле часто «прощается», тут запутаннее: `send_admin_notification` вызывается, например, из `load_feeds` ещё на этапе module-level setup в некоторых тестах). Чистый порядок — определить redaction-инфраструктуру до её первого использователя. Проверить, что после перестановки: (a) `import news_bot` проходит без ошибок; (b) импорт `from telegram import Bot, LinkPreviewOptions` и `from telegram.error import TelegramError` остался выше блока, где они нужны (он и так на строке 31, выше любого `send_admin_notification` использования); (c) `logging.basicConfig(...)` на строках 184–187 остаётся ДО кода, который вызывает `logging.getLogger(...)` для добавления фильтров.

1. **Слой 1 — расширить regex-покрытие.** Добавить отдельный compiled regex для anthropic-ключа: `sk-ant-[A-Za-z0-9_=.-]{16,}` (шире старого — покрывает sandbox/admin-формы с `=` и `.`). `_TokenRedactingFilter.filter` должен прогонять обе регулярки (Telegram + Anthropic) по одному pre-rendered тексту записи и заменять оба класса токенов на `***`.

2. **Слой 2 — env-name list.** Добавить `'ANTHROPIC_API_KEY'` в `_SECRET_ENV_NAMES`, чтобы `sanitize_error_message` (и любые будущие пути, читающие этот кортеж) автоматически чистили его значение из произвольных error-строк.

3. **Слой 3a — extract `_redact_text(text: str) -> str` helper.** Вытащить ядро редактирования (применение обоих regex) в чистую функцию модульного уровня. И `_TokenRedactingFilter.filter`, и `send_admin_notification` должны звать именно её — единый источник правды. Helper никогда не должен бросать наружу: при внутренней ошибке возвращает входной текст без модификации (как сейчас делает фильтр через `try/except: pass`).

4. **Слой 3b — applied to admin-notify path.** В `send_admin_notification(message)` пропустить входной `message` через `_redact_text` ДО построения Telegram-payload. Это гарантирует: даже если кто-то на верхнем уровне написал `send_admin_notification(f"Claude API auth failed: {exc}")` и в `str(exc)` оказался ключ — оператор увидит `***`, а не реальный ключ.

5. **Слой 3c — attach filter to anthropic SDK loggers.** Расширить блок установки `_TOKEN_FILTER`: помимо root и `("httpx", "httpcore", "urllib3", "requests")` добавить `("anthropic", "anthropic._client", "anthropic._base_client")`. Это покрывает случаи, когда SDK сам пишет `logger.exception(...)` со встроенным ключом в URL/headers.

6. **Admin-ping template guard.** На путях, отправляющих admin-пинги по поводу outage / ошибок Anthropic SDK, в видимой оператору строке использовать `type(exc).__name__` вместо `str(exc)`. Полный текст ошибки уходит в логи (которые теперь редактируются). Применяется к новому коду из последующих задач — здесь зафиксировать инвариант коротким комментарием возле `send_admin_notification` и/или строкой в module docstring, чтобы reviewer'ы будущих задач его соблюдали.

7. **Регрессионные тесты в `tests/test_no_token_leak_in_logs.py`.** Использовать только синтетические ключи. Покрыть:
   - prod-shape ключ `sk-ant-api03-...` редактируется фильтром через `record.msg`;
   - sandbox-shape ключ `sk-ant-...something-with-=-and-.` тоже редактируется;
   - synthetic anthropic SDK exception text (типа `BadRequestError: invalid_request_error: ... key=sk-ant-...`) редактируется при прохождении через root logger;
   - filter привязан к каждому из `anthropic`, `anthropic._client`, `anthropic._base_client` (assert по `logger.filters`);
   - `'ANTHROPIC_API_KEY'` присутствует в `_SECRET_ENV_NAMES`;
   - `send_admin_notification` редактирует ключ в `message` ДО send (мокаем `Bot.send_message`, проверяем, что в `text=` параметре нет реального ключа, есть `***`).
   Сохранить существующие тесты Telegram-токена работающими — расширение НЕ должно их ломать.

**Dependencies:** нет новых пакетов. Только stdlib `re` / `logging`. Anthropic SDK как пакет ставится в Task 6 — здесь мы только привязываемся к именам логгеров (не импортируем `anthropic`), что безопасно: `logging.getLogger(name)` создаёт логгер по требованию.

**Edge cases:**
- Пустой / `None` `message` в `send_admin_notification` — `_redact_text` должен вернуть его как есть (helper не должен бросать на `None`; либо caller гарантирует строку, тогда добавить assert/coercion на стороне helper'а).
- Запись лога без `record.msg` (редкий случай — кто-то логирует через `logger.handle(LogRecord)` напрямую) — поведение должно остаться идентично текущему: при ошибке rendering фильтр молча возвращает `True`.
- Регекс с `=` и `.` не должен «съесть» хвост строки за разделителями. `[A-Za-z0-9_=.-]{16,}` в python `re` будет жадным до первого не-матчащего символа (пробел, кавычка, `,`). Покрыть тестом, что после ключа в той же строке остальной текст не сожран.
- Регекс anthropic не должен ложно матчить `sk-ant-` короче 16 символов после префикса — покрыть тестом negative match.
- `send_admin_notification` уже имеет `try/except` вокруг send-call; добавление redaction до него не должно менять контракт ошибок.

**Implementation hints:**
- Reordering из шага 0 «What to do» — обязательное предусловие; это не hint. После переноса блока `_BOT_TOKEN_RE` / `_ANTHROPIC_KEY_RE` / `_redact_text` / `_TokenRedactingFilter` / `addFilter` выше `send_admin_notification` все имена резолвятся обычным module-scope порядком, без `globals()` хаков.
- Структурирование списка целевых логгеров — на усмотрение реализующего. Существующий tuple `("httpx", "httpcore", "urllib3", "requests")` для `setLevel(WARNING) + addFilter` хорошо читается; anthropic-семейство имеет другой инвариант (только `addFilter`, без `setLevel`), поэтому разумно либо завести второй tuple, либо явно разнести два цикла. Главное — не понизить уровень anthropic-логгера случайно (он не «шумный», `INFO` приемлем).
- Для теста админ-нотификации — образец см. в `tests/test_telegram.py::TestSendTelegraphTeaser` (~строки 44–68): рабочий шаблон подмены `news_bot.Bot` через `@patch('news_bot.Bot')` + `mock_bot.send_message = AsyncMock()` + извлечение captured-args через `mock_bot.send_message.await_args.kwargs`. Конкретные требования к подмене см. в TDD Anchor секции этого таска.
- Для anthropic-логгер тестов: `logging.getLogger(name)` создаёт логгер при первом обращении, поэтому `news_bot` может «привязать» фильтр к `"anthropic._client"` без установленного пакета `anthropic` — это безопасный no-op до момента, когда SDK реально начнёт логировать. Тесты проверяют присутствие фильтра в `.filters`, не реальные SDK-вызовы.
