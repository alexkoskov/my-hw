# Task 7: Refactor _fallback_publish for Claude primary + Google per-article fallback

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Сейчас `_fallback_publish` (news_bot.py, ~line 639) переводит статью полностью через Google Translate (`transcreate_text`) — title, subtitle, paragraphs и blocks. Качество ощутимо хуже manual-review пути, поэтому в рамках фичи мы вводим Claude API как primary translator (Decision 1) и оставляем Google только как fallback.

Задача — переделать **Step 1 (translate)** функции `_fallback_publish` на двухуровневый контракт перевода:

1. **Primary path (Claude):** если `outage_state.is_fallback_active()` возвращает `False`, попробовать `claude_transcreation.transcreate_via_claude(row)` (модуль из Task 3). Это вернёт готовый dict с `ru_title` (с emoji prefix), `ru_subtitle`, `ru_paragraphs` (а для autoevolution — ещё и `ru_blocks`).
2. **Per-article fallback (Google):** при `ClaudeTranscreationError` (per-article problem — refusal, malformed JSON, BadRequestError, UnprocessableEntityError) ровно для этой статьи выполнить старый Google путь через `transcreate_text(...)`. Состояние outage НЕ трогаем — это per-article проблема (Decision 5).
3. **API-level outage (OutageError):** при `OutageError` (RateLimit, AuthError, APIConnection, APITimeout, 5xx, 401, 403, 404) — состояние машины уже было advance'нуто внутри `claude_transcreation` через `outage_state.record_outage_event(...)` и admin-ping уже отправлен. После этого в этой же функции выполнить Google-путь как degraded mode (одна публикация не должна простаивать). Декомпозиция: при выходе из `try` через `except OutageError` мы попадаем на тот же Google-блок, что и при `ClaudeTranscreationError`, плюс логируем `degraded mode via google after outage`.
4. **Уже-в-fallback shortcut:** если `outage_state.is_fallback_active()` уже `True` на входе в Step 1, идём сразу на Google-блок без попытки Claude (см. Decision 5 + tech-spec "Publish loop" пункт «if `is_fallback_active()`, route directly to Google»).

**Steps 2–5 функции (Telegraph publish + persist `update_staged` + Telegram teaser + `move_to_published` + preview cleanup) остаются БЕЗ ИЗМЕНЕНИЙ** — Decision 9 idempotency из manual-review-workflow обязывает: `telegraph_url` персистится через `mark_telegraph_published` ДО отправки Telegram teaser; `via_review=False`, `auto_marker=True` для auto-fallback пути сохраняются; уникальный маркер `↳ автоперевод` остаётся одинаковым для Claude и Google путей (user-spec AC18).

Тесты в новом файле `tests/test_fallback_publish_paths.py` фиксируют оба branches (Claude success + Google per-article fallback) ДО начала рефакторинга — это safety net против поломки Decision 9 idempotency (см. Risks-таблицу tech-spec).

## Details

**Files:**
- `news_bot.py` (`_fallback_publish`, ~lines 639–772) — Step 1 рефакторится; Steps 2–5 не трогаем. Импорты сверху файла дополняются (`claude_transcreation`, `outage_state`). Комментарий-хедер функции (`# Step 1: EN → RU. ...`) обновить, чтобы отражать новый двухуровневый контракт.
- `tests/test_fallback_publish_paths.py` (новый) — два обязательных теста + опционально 2 расширения (already-in-fallback, OutageError-degraded).

**Текущее состояние `_fallback_publish` (важные инварианты):**
- Step 1 сейчас полностью на Google: `transcreate_text(en_title, is_title=True)` для title, `transcreate_text(en_subtitle)` для subtitle, list-comprehension для paragraphs, отдельный цикл для blocks (text + caption).
- Step 2 (Telegraph): если `row['telegraph_url']` уже есть — переиспользовать (Decision 9). Иначе `telegraph_publisher.publish_article(..., auto_marker=not via_review)` → `pending_repo.mark_telegraph_published(link, telegraph_url, telegraph_path)`. Это ОТДЕЛЬНАЯ транзакция, чтобы Telegram-failure не уничтожал URL.
- Step 3: `pending_repo.update_staged(link, ru_title, ru_subtitle, ru_paragraphs, ru_blocks)` — персистит RU поля в pending row.
- Step 4: `send_telegraph_teaser(telegraph_url, link)` → False raise → caller bumps `attempt_count`.
- Step 5: `pending_repo.move_to_published(link, telegraph_url, telegraph_path, via_review=via_review)` + best-effort `_cleanup_preview_html`.

**Контракт между новым Step 1 и Step 2:** после Step 1 в локальных переменных функции должны быть `ru_title: str`, `ru_subtitle: str`, `ru_paragraphs: list[str]`, `ru_blocks: list[dict] | None`. Что Claude, что Google путь обязаны вернуть это в одинаковой shape.

**Dependencies:**
- Task 3 (`claude_transcreation.py` создан, экспортирует `transcreate_via_claude`, `ClaudeTranscreationError`, `OutageError`).
- Task 5 (`outage_state.py` создан, экспортирует `is_fallback_active()`).

**Edge cases:**
- Article has empty `subtitle` (en_subtitle=='') → Claude path и Google path обе должны возвращать `ru_subtitle=''` без падения.
- Article has `blocks` (autoevolution) → Claude путь возвращает `ru_blocks` уже структурированными; Google путь сохраняет старую логику цикла.
- `transcreate_via_claude` raises `OutageError` ВНУТРИ — state machine + admin-ping уже отработали внутри claude_transcreation. Этот `_fallback_publish` ловит исключение и идёт на Google для текущей публикации (degraded mode — не оставлять её unpublished).
- `is_fallback_active() == True` на входе — Claude не вызываем, сразу Google. Это не «отказ» а штатный режим до следующего cron-tick'а или recovery-probe.
- Per-article failure → НЕ advance'ить state machine. Это per-article проблема, не API outage (Decision 5).
- `row['telegraph_url']` уже не пустой (retry после Telegram-failure) → Step 1 всё равно надо выполнить (RU поля могут быть не персистнуты)? Нет — `update_staged` в Step 3 идемпотентен, перезапись теми же значениями ОК. Но если RU уже в row, можно пропустить Claude/Google — это micro-оптимизация, оставляем for now (Step 1 всегда переводит заново; existing behaviour).

**Implementation hints:**
- Импорты в начале файла: `from claude_transcreation import transcreate_via_claude, ClaudeTranscreationError, OutageError`. Точные названия классов синхронизируй с тем, что реально экспортирует Task 3.
- Проверка `outage_state.is_fallback_active()` идёт ДО try/except: shortcut path не должен ловить исключения от Claude, потому что Claude вообще не вызывается.
- В блоке Google-fallback можно вызвать существующую вспомогательную функцию или просто переиспользовать старый код перевода title/subtitle/paragraphs/blocks через `transcreate_text` — он остаётся в файле (Task 10 чистит ВНУТРЕННОСТИ `transcreate_text`, но не удаляет саму функцию).
- Тесты: использовать существующие fixture-паттерны из `tests/test_fallback_paths.py` или `tests/test_idle_fallback.py` (если ещё не удалён) — те же row dict shape, те же mocks для `telegraph_publisher`, `pending_repo`, `send_telegraph_teaser`.
- НЕ амальгамируй с Task 8 (`job()` рефакторинг): Task 7 трогает только `_fallback_publish`. `job()` остаётся текущим — следующая волна.
- НЕ удаляй legacy use sites `_fallback_publish` (`_overflow_fast_track`, inline idle-fallback в `job()`) — это Task 9. Сейчас они продолжают вызывать ту же функцию; обе ветви Step 1 обязаны работать.
- Order of mock-assertions в тестах: используй `mock_calls` order или `assert_called_before(...)` паттерн (через `manager.attach_mock` + проверка `manager.mock_calls` last index) для проверки «`mark_telegraph_published` ДО `send_telegraph_teaser`» — это проверка Decision 9 idempotency.
