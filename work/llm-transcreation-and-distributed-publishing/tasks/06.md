# Task 6: Update requirements.txt + .env.example

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Зафиксировать новые runtime-зависимости и привести `.env.example` в соответствие с новой моделью авто-публикации (Claude API + распределённое расписание).

Текущий `requirements.txt` содержит 8 пакетов, среди которых нет `anthropic` и `pytz`. Без `anthropic` модуль `claude_transcreation` (Wave 1, Task 3) не сможет вызывать Claude API. Без `pytz` cron-триггер `schedule.every().day.at("12:00", tz=...)` (Wave 4, Task 8) упадёт с `ScheduleValueError`, потому что `schedule==1.2.1` не принимает `zoneinfo.ZoneInfo` (Decision 4).

Текущий `.env.example` документирует только `FALLBACK_THROTTLE_SECONDS` из легаси-переменных и не упоминает `QUEUE_CAP`, `IDLE_TIMEOUT_HOURS`, `GRACE_WINDOW_HOURS` (они никогда не были задокументированы — лежат в коде). После Wave 5 (Task 9) все четыре переменные будут удалены из `news_bot.py`; `.env.example` должен отразить новый набор: `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` (опционально, закомментирован с дефолтом `claude-haiku-4-5`), `TZ=Europe/Moscow`. Эта задача — единственное место, где обновляется операторская инструкция о новых env-переменных, поэтому каждая из них должна быть снабжена inline-комментарием.

Поддерживает user-spec AC26 (легаси env vars удалены, `.env.example` обновлён) и tech-spec Acceptance Criteria раздел "Dependencies & config" (anthropic+pytz pinned, `.env.example` cleanup).

## What to do

1. В `requirements.txt` добавить две новые строки в логичной группировочной позиции:
   - `anthropic>=0.45.0,<0.46.0` — нижняя граница 0.45.0 фиксирует stable exception hierarchy, использованную в Decision 5; верхняя `<0.46.0` страхует от breaking changes в minor-bump (security-validator более строгий пин, чем `<1.0`).
   - `pytz>=2024.1` — требуется `schedule==1.2.1` для `Job.at(tz=...)`; стандартная `zoneinfo` отвергается с TypeError.

2. В `.env.example` удалить устаревший комментированный блок `FALLBACK_THROTTLE_SECONDS` (8 строк объяснения + сама переменная). `QUEUE_CAP`, `IDLE_TIMEOUT_HOURS`, `GRACE_WINDOW_HOURS` в текущем `.env.example` отсутствуют — отдельно удалять нечего.

3. В `.env.example` добавить новый блок (логичная позиция — после блока "Optional: Log level", в конце файла):
   - `ANTHROPIC_API_KEY=your_anthropic_api_key_here` — обязательная переменная, без неё `claude_transcreation` не запустится; формат `sk-ant-...`.
   - `# Optional: Anthropic model override (default: claude-haiku-4-5)` + закомментированный `# ANTHROPIC_MODEL=claude-haiku-4-5` — комментарий объясняет, что Sonnet 4.6 даст более высокое качество за ~5x cost.
   - `TZ=Europe/Moscow` — требуется для cron-триггера в 12:00 МСК и для читаемых timestamps в логах. Startup health check #2 (Decision 14) пингует оператора при несоответствии.

4. Каждую новую переменную сопроводить inline-комментарием в стиле текущего файла (одна строка-комментарий перед переменной, с поясняющим назначением и/или дефолтом).
