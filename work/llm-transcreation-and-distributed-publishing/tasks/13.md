# Task 13: Update deploy bundle (deploy.sh + GitHub Actions + PK docs)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:deploy-pipeline` — [skills/deploy-pipeline/SKILL.md](~/.claude/skills/deploy-pipeline/SKILL.md)

## Description

Финальная задача 8-й волны: довести deploy bundle и проектную документацию до состояния, в котором новый auto-publish путь (Claude API + распределённое расписание) реально запускается на проде.

Сейчас `deploy.sh` и `.github/workflows/deploy.yml` копируют только старый набор cron-side модулей и не везут НИ новые runtime-модули (`claude_transcreation.py`, `compute_publish_slots.py`, `outage_state.py` — все три импортируются `news_bot.py` на старте), НИ `ux-guidelines.md` (читается `claude_transcreation._load_prompt` как system prompt для Claude API). Без новых модулей `news_bot` падает с `ImportError` сразу при старте cron — бот вообще не запускается. Без `ux-guidelines.md` на старте срабатывает Decision 14 health-check #1, бот пингует оператора и до конца дня сидит в Google Translate fallback. Кроме того, GitHub Actions не пробрасывает на сервер новые секреты `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `TZ` — без них Claude SDK падает на старте на `AuthenticationError`, а cron срабатывает в UTC, а не в MSK.

Итого: в FILES обоих скриптов деплоя должны добавиться ЧЕТЫРЕ новых файла — `claude_transcreation.py`, `compute_publish_slots.py`, `outage_state.py`, `ux-guidelines.md`.

Параллельно нужно зафиксировать архитектурный сдвиг (AC28): `ux-guidelines.md` — больше не operator-side-only, а runtime cron-side dependency. И обновить `patterns.md` (новый auto-publish паттерн вместо удалённых overflow/throttle/idle-fallback) и `deployment.md` (новые env vars + Anthropic console + cost monitoring + secrets ANTHROPIC_*).

Эта задача — последняя перед Audit Wave: в момент её мерджа bundle должен быть deploy-ready.

## Verification Steps

### Smoke

Dry-run deploy на staging path (или локально через `/tmp`-имитацию VPS), без реального VPS-доступа:

1. **FILES list integrity check.** `bash -n deploy.sh` (синтаксис), затем выполнить локально подмену:
   ```
   SSH_HOST=localhost DEPLOY_PATH=/tmp/hwbot-staging mkdir -p /tmp/hwbot-staging
   ```
   Прогнать FILES через `for f in "${FILES[@]}"; do test -f "$f" && echo OK || echo MISSING $f; done` — все 13 файлов должны быть OK, включая четыре новых: `claude_transcreation.py`, `compute_publish_slots.py`, `outage_state.py`, `.claude/skills/project-knowledge/references/ux-guidelines.md`.
2. **scp flatten check + post-copy presence assertion.** Эмулировать `scp` на локалку: `cp "${FILES[@]}" /tmp/hwbot-staging/` (cp без `-r` ведёт себя так же flat-плющащим способом, что и scp). Затем явный grep/test, что все ЧЕТЫРЕ новых файла легли в `$DEPLOY_PATH/` flat:
   ```
   for f in claude_transcreation.py compute_publish_slots.py outage_state.py ux-guidelines.md; do
       test -f "/tmp/hwbot-staging/$f" && echo "OK $f" || { echo "MISSING $f"; exit 1; }
   done
   ```
   Все четыре должны лежать в `/tmp/hwbot-staging/` (последний — flat, не в подпапке). Это закрывает AC27 (файл присутствует на сервере к моменту первого Claude API call) + критичный фикс из reality-batch5/6 review (без `*.py` модулей бот падает на `ImportError`). Decision 8 fallback в `_load_prompt` именно flat-расположение `ux-guidelines.md` и закрывает.
3. **`.env` env-var append check.** Создать `/tmp/hwbot-staging/.env` с парой существующих ключей, прогнать локально логику env-write step (heredoc + grep -v + append) с фиктивными значениями `ANTHROPIC_API_KEY=sk-ant-test-XXX`, `ANTHROPIC_MODEL=claude-haiku-4-5`, `TZ=Europe/Moscow`. Запустить дважды подряд. Проверить:
   - все три ключа присутствуют в `.env` ровно по одному разу (идемпотентность);
   - старые ключи (которые там были до) не повреждены;

**Edge cases:**

- **Повторный деплой не должен дублировать строки в `.env`.** Реализация env-write step через ssh+heredoc, секреты передаются по stdin (через `env:` шага), а не как command args:
  ```
  ssh -o StrictHostKeyChecking=yes "$SSH_USER@$SSH_HOST" "bash -s" <<'REMOTE'
    cd "$DEPLOY_PATH"
    touch .env
    grep -v '^ANTHROPIC_API_KEY=' .env | grep -v '^ANTHROPIC_MODEL=' | grep -v '^TZ=' > .env.tmp
    cat >> .env.tmp <<EOF
  ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY}
  ANTHROPIC_MODEL=${ANTHROPIC_MODEL}
  TZ=${TZ}
  EOF
    mv .env.tmp .env
  REMOTE
  ```
  Значения подставляются через `env:` шага GitHub Actions (GH автоматически редактирует их в логах). НИКОГДА не использовать `echo "KEY=$VALUE" >> .env` в shell-команде на хосте раннера — секрет попадёт в `ps -ef` и в логи команды. Идемпотентность гарантирована тройным `grep -v` cleanup перед append. Тест на это в Smoke step 3. Альтернатива: `printenv ANTHROPIC_API_KEY ANTHROPIC_MODEL TZ | ssh ... "cat > .env.new && ..."` — тоже передаёт через stdin.
- **Пропавший `ux-guidelines.md` в репо.** `deploy.sh` строки 37–41 уже падают с «Error: $file not found in current directory» при отсутствующем FILES-элементе. Это работает — значит пропуск файла поймается на самом первом запуске, до scp.
