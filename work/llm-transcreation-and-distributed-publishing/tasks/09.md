# Task 9: Delete legacy auto-publish code + env vars

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

После того как Wave 4 (Task 8) полностью переключил `job()` на новый distributed-publish loop с фиксированным cron в 12:00 МСК, окнами публикации, crash-loop guard'ом и Claude-primary translation, старый legacy-код auto-publish пути становится мёртвым весом. Эта задача физически удаляет его из `news_bot.py` и сопровождающих тестов.

Удаляются три бывших механизма и четыре env var'а (user-spec AC26). Все номера строк ниже — приблизительные ориентиры на текущем снимке `news_bot.py`; перед редактированием перепроверять `grep -n` (Task 8 двигает соседний код):
- **`_overflow_fast_track`** (~80 LoC, начало около news_bot.py:799) — fast-track-evict pending rows, чтобы влезть в `QUEUE_CAP`. Новый алгоритм не имеет hard cap, излишек carry-over.
- **Inline idle-fallback в `job()` (steps 1a/1b, ~80 LoC, в районе news_bot.py:1140–1200)** — admin-ping для stale rows + auto-publish overdue. Заменён на детерминистический schedule из `compute_publish_slots`.
- **`FALLBACK_THROTTLE_SECONDS` throttle** (news_bot.py:70 + три use sites внутри `_overflow_fast_track` и idle-блока) — `time.sleep` между batch publish'ами. Новый distributed schedule сам разносит публикации min-interval=40 минут.
- **Env vars `IDLE_TIMEOUT_HOURS`, `GRACE_WINDOW_HOURS`, `QUEUE_CAP`, `FALLBACK_THROTTLE_SECONDS`** (блок около news_bot.py:58–70) — больше не читаются, удаляются вместе с их `os.getenv` строками и комментариями.

Также удаляются companion тесты `tests/test_overflow.py` (полностью) и `tests/test_idle_fallback.py` (полностью), а из `tests/test_fallback_throttle.py` удаляются разделы Part A (throttle constant + TestOverflowThrottle + TestIdleFallbackThrottle) — оставляем только `TestTeaserAlwaysSingleLine` и `TestFallbackPublishPassesAutoMarkerToPublishArticle` (их предмет — auto_marker и one-line teaser, не throttle).

Цель: после задачи `pytest tests/ -q` зелёный, `grep -nE 'FALLBACK_THROTTLE_SECONDS|QUEUE_CAP|IDLE_TIMEOUT_HOURS|GRACE_WINDOW_HOURS|_overflow_fast_track' news_bot.py tests/` пустой (кроме истории git). Проверка удаления inline idle-fallback — отдельным grep'ом по конкретным символам, которые он использовал: `grep -nE 'list_pending_stale|list_notified_overdue|mark_notified' news_bot.py` — эти три helper-функции вызывались только из inline idle-блока в `job()`, после удаления matches должно не быть в `news_bot.py` (в `pending_articles_repo.py` они остаются как библиотечные функции — не трогаем).
