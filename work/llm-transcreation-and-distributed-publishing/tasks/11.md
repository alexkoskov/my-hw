# Task 11: Update integration tests for new auto-publish path

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

После того как Wave 3–6 переработали `_fallback_publish` на Claude-as-primary + Google per-article fallback, переписали `job()` под TZ-aware cron + distributed-publish loop, удалили `_overflow_fast_track` / inline idle-fallback / `FALLBACK_THROTTLE_SECONDS` / `QUEUE_CAP` / `IDLE_TIMEOUT_HOURS` / `GRACE_WINDOW_HOURS`, и срезали bureaucratic regex и 4000-char truncation из `transcreate_text` — оба integration-файла (`tests/test_integration.py` и `tests/test_job_prep_phase.py`) больше не отражают актуальное поведение модуля.

Эта задача синхронизирует именно integration-тесты, которые проверяют end-to-end-поведение `news_bot` против реальной SQLite БД (с моками внешних сетевых вызовов). Цель — оставить эти файлы зелёными после Wave 6, перевести patch-таргеты с `news_bot.transcreate_text` на новый Claude-путь, добавить assertions на содержимое таблицы `bot_state` для outage-сценариев, и удалить assertions про удалённые символы. Дополнительно покрываем integration-уровнем четыре сценария из tech-spec: outage, recovery, container restart mid-window, manual-review preemption.

End-to-end happy path / outage drill / restart-recovery / preemption также покрываются новым файлом `tests/test_distributed_schedule_integration.py` в Task 12 (создаётся параллельно). Эта задача — про ремонт существующих integration-файлов, а не про новый файл.

Покрываемые AC: AC14 (API-level outage → 2-ping protocol), AC15 (per-article problem → single-article Google fallback), AC16 (auto-recovery + switch-back ping), AC17 (edge case empty queue at recovery — bot stays in fallback до следующего cron-тика), AC21 (manual-review путь не ломается).

**Edge cases:**
- Mock-injected `RateLimitError` должен импортироваться из `anthropic` (real SDK pinned к 0.45.x). Если import дорогой — patch'ить через `unittest.mock.patch.object(news_bot, 'transcreate_via_claude', side_effect=...)` без реального anthropic-импорта в тесте. Использовать `news_bot.OutageError` если он re-export'ится из `claude_transcreation`.

**Implementation hints:**

- Для outage-сценариев — настроить `mock_claude.side_effect = anthropic.RateLimitError(...)` так, чтобы каждый вызов поднимал ошибку. После каждого `job()`-прогона читать `bot_state` через публичный API из `outage_state`.
