## Description

Создаём новый pure-функциональный модуль `compute_publish_slots.py` — алгоритм распределения публикаций в окне 13:00–20:00 МСК. Это foundation-модуль (Wave 1), от которого зависит refactor `job()` в Task 8: новый distributed-publish loop в news_bot.py будет вызывать `compute_publish_slots(count_pending(), now_msk)` после фетча и публиковать статьи по полученному списку datetime-слотов.

Цель — реализовать формулу `interval = max(420 / N, 40)` с floor=40 минут и cap=11 публикаций/день (естественное следствие `(20:00 − 13:00) / 40 + 1 = 11`). Excess carry-over в pending до следующего дня. Функция должна корректно работать на:

- **Cron tick в 12:00** (now < window_start) — первый слот в 13:00.
- **Container restart mid-window** (now=16:00, N=5) — пересчёт расписания от текущего времени до 20:00 с тем же floor=40.
- **Container restart late-window** (now=19:50, N=5) — 1 слот сейчас, 4 в carry_over.
- **Cron tick после 20:00** — пустой список, всё в carry_over.
- **TZ-naive datetime на входе** — ValueError (инвариант: scheduler работает только с MSK-aware datetime).

Модуль чисто stdlib (`datetime`, `typing`), без внешних зависимостей, без сайд-эффектов — идеально тестируется и реюзается в integration-тестах Task 12.

Тесты (~12 штук) покрывают граничные значения N (0, 1, 4, 7, 10, 11, 15, 20), restart-сценарии и TZ-инвариант. Это обеспечит, что любая регрессия в формуле или инварианте поймается до того как сломает production cron.

## What to do

1. Создать новый файл `compute_publish_slots.py` в корне репозитория (рядом с `news_bot.py`, `pending_articles_repo.py`).
2. Объявить module-level константы: `WINDOW_START = time(13, 0)`, `WINDOW_END = time(20, 0)`, `MIN_INTERVAL_MINUTES = 40`, `MAX_POSTS_PER_DAY = 11` (последняя — для документации; реально cap получается естественно из floor=40).
3. Реализовать функцию `compute_publish_slots(n, now, window_start=WINDOW_START, window_end=WINDOW_END, min_interval_min=MIN_INTERVAL_MINUTES) -> Tuple[List[datetime], int]` с алгоритмом из code-research.md §14.2 / §8 и tech-spec Decision 2:
   - Валидация: `now.tzinfo is None` → `ValueError("compute_publish_slots requires tz-aware datetime")`.
   - Если `n == 0` → return `([], 0)`.
   - Если `now > combine(now.date(), window_end)` → return `([], n)` (всё carry-over).
   - `effective_start = max(combine(now.date(), window_start, tzinfo=now.tzinfo), now)`.
   - `remaining_minutes = (combine(now.date(), window_end, tzinfo=now.tzinfo) − effective_start).total_seconds() / 60`.
   - `raw_interval = (window_end − window_start) total minutes / n` если n > 0.
   - `interval = max(raw_interval, min_interval_min)`.
   - `max_publishable_now = floor(remaining_minutes / interval) + 1` (если remaining_minutes >= 0, иначе 0).
   - `slots_count = min(n, max_publishable_now, MAX_POSTS_PER_DAY)`.
   - `slots = [effective_start + timedelta(minutes=interval * i) for i in range(slots_count)]`.
   - `carry_over = n − len(slots)`.
   - Возвращаемые datetime'ы наследуют tzinfo из `now`.
4. Создать файл `tests/test_compute_publish_slots.py` с ~12 тестами (см. TDD Anchor). Использовать tz-aware datetime через `datetime.timezone(timedelta(hours=3))` (МСК = UTC+3 круглогодично с 2014) — это избегает зависимости от pytz, который добавится в Task 6, и не привязывает тесты модуля к внешней либе.
5. Убедиться, что `pytest tests/test_compute_publish_slots.py -v` проходит зелёным и `pytest tests/ -q` не показывает регрессий.

**Dependencies:**

- Stdlib only: `datetime` (datetime, time, timedelta, timezone), `typing` (List, Tuple).
- Никаких dependency на другие модули проекта (pure function).
- Никаких dependency на другие задачи в Wave 1 (Task 1, 3, 4 идут параллельно).

**Edge cases:**

- `n == 0` → `([], 0)` без обращения к window_start.
- `n == 1, now < window_start` → 1 слот в `window_start`, не в `now`.
- `now > window_end` (т.е. позже 20:00) → `([], n)` — всё переносится на завтра.
- `now == window_end` (ровно 20:00) → `remaining_minutes == 0`; `max_publishable_now = floor(0/40) + 1 = 1` → 1 слот в 20:00. Если это нежелательно — добавить strict `now >= window_end → ([], n)`.
- `now > window_start` (restart mid-window) → `effective_start = now`; интервал пересчитывается от оставшегося окна.
- `n > 11` → cap by floor=40 даст max 11 слотов; carry_over = n − 11.
- TZ-naive `now` → `ValueError`. Не silently aware-ить — явно фейлить.
- Window crosses midnight (window_start > window_end) — out of scope в этой задаче, текущее окно 13–20 интра-day.

**Implementation hints:**

- `datetime.combine(date, time, tzinfo=now.tzinfo)` — корректный способ построить window_start/end на дату now с тем же tzinfo. Не использовать `replace(hour=..., minute=...)` — теряет читаемость намерения.
- Floor-divide через `int(remaining_minutes // interval)` — целочисленное деление. `math.floor` тоже подойдёт.
- Для `interval`: всегда `float` (не int) — иначе `420 / 7 = 60.0` ок, но `420 / 11 = 38.18…` округлится. Сохранять float для precision; финальный `timedelta(minutes=interval * i)` принимает float корректно.
- Не возвращать numpy arrays / generators — только plain `list[datetime]`.
- Docstring с примерами из user-spec («N=7 → 7 постов через час; N=15 → 11 сегодня + 4 завтра») сильно помогает читателю.
