## Description

Brad Bannach (orangetrackdiecast.com) пишет короткие standalone-параграфы вида
`*QUICK LINK!* Buy from 1 Stop Diecast now.` или `Buy now from 1 Stop Diecast` —
это affiliate-плаги, которые мусорят перевод и засоряют Telegraph-страницу. Нужно
расширить существующий `_BOILERPLATE_PATTERNS` в `boilerplate_filter.py` 1-3 регексами,
которые ловят эту форму. Inline-affiliate внутри настоящих параграфов — out of scope
(per user-spec Q5 = I, Decision 12).

Жёсткие ограничения из tech-spec Decision 12:
- **Все паттерны анкернуты на `^`** — никакого matching посередине строки.
- **Никаких nested greedy quantifiers** (форма `(.+)+`, `(\w+)+` и т. п.) — это
  гарантия от ReDoS catastrophic backtracking.
- **Длина-bound 120 символов** уже обеспечивается существующей константой
  `_MAX_BOILERPLATE_LEN` в `is_boilerplate()` — не трогаем её, не дублируем
  длину внутри регекса.
- Новые паттерны кладутся в существующий список `_BOILERPLATE_PATTERNS`,
  следуя тому же стилю, что A1-A5 author-plug-блок (комментарий-разделитель + блок паттернов).

Тесты добавляются:
- В существующие `parametrize`-листы `TestIsBoilerplatePositive.test_english_patterns_filtered`
  и `TestIsBoilerplateNegative.test_real_content_preserved` — где это естественно ложится.
- Новый класс `TestAffiliateLengthBound` для boundary-кейсов: ровно 120 символов
  фильтруется, 121 символ остаётся; и ReDoS-safety тест с pathological input.

## What to do

1. **Расширить `_BOILERPLATE_PATTERNS` в `boilerplate_filter.py`:** добавить 1-3
   `re.compile(...)` записей в конец списка (или сразу перед русским блоком — выбрать
   наиболее логичное место по комментариям). Каждый паттерн начинается с `^`,
   case-insensitive (`re.I`). Покрыть как минимум формы:
   - `*QUICK LINK!*`-prefix перед `Buy from <store>` / `Shop at <store>` / `Get yours at <store>` /
     аналогичными affiliate-CTA — например, `^\*?quick link!?\*?\s+(buy|shop|get|order)\s+(from|at)\s+`.
   - Standalone CTA без префикса: `^buy\s+(now|it|from|at)\b`, `^shop\s+(now|at|here)\b`,
     `^order\s+(now|here)\b`.
   - Если уверены, можно объединить несколько вариантов в одну альтернацию
     `(buy|shop|order|get)\s+...` — но без вложенных quantifiers.
   - Над блоком — комментарий-разделитель в стиле существующих
     (`# ---...---` + 1-2 строки описания: ссылка на Decision 12, scope = standalone short paragraph).
2. **Добавить позитивные кейсы** в `TestIsBoilerplatePositive.test_english_patterns_filtered`
   `parametrize`-список: как минимум `*QUICK LINK!* Buy from 1 Stop Diecast now.`
   и `Buy now from 1 Stop Diecast`. Можно добавить 1-2 ещё для покрытия других форм.
3. **Добавить негативные кейсы** в `TestIsBoilerplateNegative.test_real_content_preserved`:
   `I'd buy that for $1` и длинный (>120 символов) content paragraph, который содержит слово
   `buy` или `shop` — должен сохраняться.
4. **Создать новый класс `TestAffiliateLengthBound`** в `tests/test_boilerplate_filter.py`
   (поместить логически после `TestLengthThreshold` или рядом — не в конец файла,
   чтобы не разбивать integration-блоки):
   - `test_affiliate_at_120_chars_exact_filtered` — построить affiliate-строку ровно 120 символов
     (использовать `assert len(s) == 120`), проверить `is_boilerplate(s) is True`.
   - `test_affiliate_at_121_chars_preserved` — построить affiliate-строку 121 символ,
     проверить `is_boilerplate(s) is False` (срабатывает length-bound, не паттерн).
   - `test_redos_safety_pathological_input` — измерить wall-time `is_boilerplate()` на
     pathological-входе типа `'a' * 60 + 'buy' * 20 + ' shop now'` (или иной adversarial pattern,
     который ловил бы catastrophic backtracking, если бы регекс был уязвим). Использовать
     `time.perf_counter()`, утвердить `elapsed < 0.1` (100 ms) с запасом.

## Details

**Files:**
- `boilerplate_filter.py` — добавить 1-3 `re.compile(...)` записей в `_BOILERPLATE_PATTERNS`
  (текущий список — строки 51-111). Логичное место: между author-plug-блоком (строки 67-98)
  и русским блоком (строки 100-110), с собственным comment-divider в стиле существующих.
  Не трогать `_MAX_BOILERPLATE_LEN`, не трогать `is_boilerplate()` / `filter_boilerplate()` /
  `filter_blocks()` сигнатуры. Никаких новых публичных символов.
- `tests/test_boilerplate_filter.py` — расширить два существующих parametrize-листа
  (positives на строках 29-63, negatives на строках 99-110) и добавить новый класс
  `TestAffiliateLengthBound`. Поместить новый класс рядом с `TestLengthThreshold`
  (строки 127-138) — это тематически близкие boundary-проверки.

**Dependencies:** никаких новых пакетов. Только `re` (уже в проекте), `time` (стандартная
библиотека) для ReDoS-теста.

**Edge cases:**
- Регистр: pattern должен ловить `BUY NOW`, `Buy Now`, `buy now` одинаково — `re.I` обязателен.
- Пунктуация: trailing `.` / `!` / `?` не должны мешать матчу (но и не нужны для матча).
  Не пытаться форсить trailing punctuation в регексе — `^buy now\b` достаточно.
- Префикс `*QUICK LINK!*` — звёздочки могут быть, могут отсутствовать (Brad иногда
  пишет без них). Использовать `\*?` (optional star), не `\*` (required).
- Слово `now` после `buy`/`shop`/`order` — частая, но не обязательная форма; покрыть оба варианта.
- Длина 120 — измерять `len(s.strip())` после strip, как делает существующий `is_boilerplate`.
  Тест-кейс должен учитывать, что строка проходит через `s.strip()` перед проверкой.
- Inline-affiliate в реальных параграфах (`...this is great. *QUICK LINK!* Buy from X.`) —
  не должен фильтроваться: длина обычно >120 и/или анкер `^` не сматчится в середине.
  Это проверяется существующим `TestLengthThreshold` + новым negative-кейсом.

**Implementation hints:**
- Для boundary-теста собрать строку точной длины можно как:
  `s = '*QUICK LINK!* Buy from ' + 'X' * (120 - len('*QUICK LINK!* Buy from '))` — pad ровно до 120.
- Для ReDoS-теста pathological pattern должен быть таким, который вызвал бы catastrophic
  backtracking при наличии вложенных quantifiers. Поскольку наши паттерны простые (без `(.+)+`),
  тест должен пройти за миллисекунды — но он останется регрессионным щитом, если кто-то
  потом добавит уязвимый регекс.
- Стиль комментария-разделителя: `# ---<длинный отступ>---` + 2-3 строки описания.
  Скопировать формат из строк 66-71 (`Author social-media plugs (author-plug-filter feature, variant A)`).
