# Task 1: Create `orangetrack_source.py` parser module

## Required Skills

Перед выполнением задачи загрузи:

## Description

Это первая (и самая большая) задача фичи orangetrack-source — она создаёт изолированный parser-модуль для четвёртого источника новостей (Brad Bannach's `orangetrackdiecast.com`, WordPress.com hosted, EN, Hot Wheels-only). Модуль — самостоятельная единица, которая в Wave 2 (Task 3) будет подключена к `news_bot.py`. Вся логика, которая касается *парсинга* сайта (RSS feed → article body → canonical dict) и *учёта проблем* (admin-ping aggregator), помещается сюда; интеграция с `news_bot.py` (registry, dispatcher, SOURCES list) — задача Task 3.

Модуль реализует семь Decisions из tech-spec одновременно: (1) гибридный feed-first парсер с bounded HTTP fallback (5 MB cap, `allow_redirects=False`, streaming `iter_content`), (2) blocks-path output с фильтрацией href/src по схемам, (3) walk DOM по HTML-тегам (не по `wp-block-*` классам), (5) `OrangetrackPingAggregator` с bounds 50/500/3500 и control-char sanitization, (8) YouTube embed wrapper с hostname allowlist (защита от content-spoofing), (13) SSRF allowlist `_is_allowed_orangetrack_url` — критично, что guard вызывается **в двух местах** (entry-level в `_fetch_orangetrack_entries` будущей Task 3 *И* fallback-level прямо здесь, перед HTTP GET), (15) `<h5>` идёт только в `blocks` как `heading`, не в плоский `paragraphs`.

Отдельно — unit-тесты в `tests/test_orangetrack_source.py` (~40-50 кейсов) по шести классам: `TestPrimaryPath`, `TestSSRFAllowlist`, `TestFallbackPath`, `TestWPBlockDriftMitigation`, `TestYouTubeEmbedWrapping`, `TestOrangetrackPingAggregator`. Тесты пишем ДО кода (TDD anchor ниже): тесты падают → пишем модуль → тесты проходят.

Ничего из `news_bot.py` / `feeds.json` / `deploy.sh` / `.github/workflows/deploy.yml` в этой задаче не трогаем — это полностью изолированный новый модуль + новые тесты.

3. Создать `orangetrack_source.py` со следующими публичными и приватными символами (точные имена из tech-spec):
   - **Module-level constant** `_FEED_URL = 'https://orangetrackdiecast.com/feed/'`
   - **Module-level constant** `_ALLOWED_HOSTS = ('orangetrackdiecast.com', 'www.orangetrackdiecast.com')`
   - **Module-level constant** `_YOUTUBE_HOSTS = ('youtube.com', 'www.youtube.com', 'm.youtube.com', 'music.youtube.com', 'youtube-nocookie.com', 'www.youtube-nocookie.com', 'youtu.be')`
   - **Module-level constants** `REQUEST_TIMEOUT`, `MAX_BODY_BYTES = 5 * 1024 * 1024`, `IMAGE_LIMIT = 10`, `_PING_PER_CODE_CAP = 50`, `_PING_TOTAL_CAP = 500`, `_PING_OUTPUT_CAP = 3500`, `_SAFE_FOR_PING_LEN = 200`.
   - **Public function** `fetch_orangetrack_article(entry, notifier=None) -> Optional[Dict]` — точка входа. Принимает feedparser entry-like (dict) с ключами `title`, `link`, `summary`, и (опционально) `content` с непустым `value`. Если `content:encoded` присутствует и непустой — парсим его (primary path, silent при успехе). Иначе — fallback: проверка `_is_allowed_orangetrack_url(entry['link'])`, потом bounded-stream HTTP GET. Возвращает canonical dict `{title, subtitle, paragraphs, images, blocks}` или `None` при любой невозможности (notifier уже вызван с подходящим code).
   - **⚠ Notifier signature ОТЛИЧАЕТСЯ от lamley:** lamley использует `Callable[[str], None]` (одна строка-сообщение). Здесь `notifier: Callable[[str, str], None]` — пара `(code, link)`, для прямой интеграции с `OrangetrackPingAggregator.add(code, link)`. Не путать при копировании lamley-паттерна.
   - **Helper** `_is_allowed_orangetrack_url(link: str) -> bool` — exact host match через `urlparse`. False для не-http(s) схем, malformed URL, scheme-relative `//evil`, любого host вне `_ALLOWED_HOSTS`. Логика мирорится с `lamley_source._is_allowed_lamley_url` (см. файл).
   - **Helper** `_video_embed_url(youtube_url: str) -> Optional[str]` — извлекает YouTube ID через regex (тот же паттерн, что в `autoevolution_source.YOUTUBE_ID_RE`), но **до** regex проверяет `urlparse(url).hostname.lower() in _YOUTUBE_HOSTS`. Возвращает `https://telegra.ph/embed/youtube?url=<urlencoded watch URL>` или `None` если hostname не в allowlist либо ID не извлёкся.
   - **Helper** `_safe_for_ping(s: str) -> str` — sanitization для admin-ping: (1) удалить ASCII control chars (`\r`, `\n`, `\t`, `\x00`–`\x1f`); (2) заменить остальные non-printable bytes на `?`; (3) обрезать до 200 chars с суффиксом `…` если truncated. Порядок операций фиксированный (control chars удаляются первыми, чтобы их нельзя было «протащить» через truncation).
   - **Helper** `_parse_content_encoded(html_str: str, link: str) -> Optional[Dict]` — BS4 walk по тегам (`<p>`, `<figure>`, `<img>`, `<iframe>`, `<h5>`), игнорируя `wp-block-*` классы. Собирает `paragraphs` (только prose; h5 текст не попадает сюда — Decision 15), `images` (dedup по URL до `?`, cap=`IMAGE_LIMIT`, http(s) only), `blocks` (typed entries: `paragraph`, `image`, `video`, `heading{level:5}`). href в `<a>` фильтруется по схемам (`http`, `https`, `mailto`); другие схемы (включая `javascript:`, `data:`, `file:`, scheme-relative `//…`) — drop href, оставляем plain text. `<img src>` принимается только с http(s); `data:`, `file:`, относительные — drop. `<iframe>` проходит через `_video_embed_url` — если возвращает None, iframe drop. Извлекает `title` (из entry или из `<h1>`), `subtitle` (первый `<p>` или из entry summary), применяет `boilerplate_filter.filter_boilerplate` к paragraphs и `filter_blocks` к blocks. Если paragraphs пустой и blocks содержит хотя бы один `video` — синтезирует `paragraphs = [entry.title]` (Decision видео-only поста).
   - **Helper** `_fetch_article_html(url: str, notifier, link) -> Optional[str]` — bounded-stream HTTP GET. `requests.get(url, timeout=REQUEST_TIMEOUT, stream=True, allow_redirects=False)`. Маппинг исходов на notifier-коды (см. tech-spec Decision 5 taxonomy и Architecture per-article path):
     - 3xx (302/301) → `('ART_FALLBACK_REDIRECT_<status>', link)` → None.
     - 4xx/5xx → `('ART_FALLBACK_HTTP_<status>', link)` → None.
     - `requests.Timeout` или ConnectionError → `('ART_FALLBACK_TIMEOUT', link)` → None.
     - Чтение через `iter_content(chunk_size=...)` с накапливаемым размером; если перешагнули `MAX_BODY_BYTES` — оборвать loop, `('ART_FALLBACK_TOO_LARGE', link)` → None.
     - 200 + успешное чтение → возвращает body (UTF-8 decoded).
   - **Class** `OrangetrackPingAggregator`:
     - `__init__(self, instance_label: Optional[str] = None)` — читает instance_label напрямую, **не** читает env (env-чтение делает caller в Task 3).
     - Internal state: `dict[code -> list[link]]` order-preserving + dedup; `dict[code -> int]` raw-counter; `int` total-add-call counter.
     - `add(self, code: str, link: str)` — пропускает оба через `_safe_for_ping`. Если total counter ≥ `_PING_TOTAL_CAP` (500) — silent no-op (НЕ raise). Если для данного code уже 50 уникальных links — следующие links игнорируются для list (но total counter инкрементится). Дедуп links по точному значению.
     - `is_empty(self) -> bool` — True если за весь lifetime не было ни одного `add()` (пустой state).
     - `format_summary(self) -> str` — формат:
       ```
       [<INSTANCE_LABEL>] orangetrack: N issues this tick
         • <CODE> (<count>×) — <link1>[, <link2>...]
       ```
       N = число distinct (code, link) pairs. count = raw call count для code. Codes sorted: FEED_* группа → ENTRY_* → ART_*; внутри группы — лексикографическая сортировка целой строки кода (так что `FEED_HTTP_429` < `FEED_HTTP_503` < `FEED_TIMEOUT`). Префикс `[<INSTANCE_LABEL>]` опускается если `instance_label` None или пустая. Для code, у которого list был truncated к 50, последним элементом строки добавляется `… <N> more truncated` (где N = `count - 50`). Финальный output truncate-ится до `_PING_OUTPUT_CAP` = 3500 chars.
     - `emit(self, send_fn: Callable[[str], None])` — вызывает `send_fn(self.format_summary())`. Любая exception от `send_fn` логируется через module logger на ERROR (с traceback) и **swallow-ится** — не пробрасывается. Если `is_empty()` → no-op (send_fn НЕ вызывается).

4. Использовать существующие зависимости: `requests`, `feedparser` (только для type-shape entry — фактически entry-параметр это любой dict-like), `bs4.BeautifulSoup`, `re`, `urllib.parse.urlparse`, `urllib.parse.quote`, `logging`. Никаких новых пакетов (Decision 7).

5. Запустить `pytest tests/test_orangetrack_source.py -v` — все ~40-50 тестов зелёные. Запустить smoke-команду из секции `Verification Steps → Smoke` ниже — должна напечатать функцию + класс и aggregator-формат с `[test]` префиксом.

6. Запустить full pytest — `pytest tests/ -v` — убедиться что не сломали ничего соседнего (хотя задача изолированная — это страховка).

## Acceptance Criteria

- [ ] `orangetrack_source.py` создан в корне репозитория. Содержит публичную функцию `fetch_orangetrack_article(entry, notifier=None)`, класс `OrangetrackPingAggregator`, helper-ы `_is_allowed_orangetrack_url`, `_video_embed_url`, `_safe_for_ping`, `_parse_content_encoded`, `_fetch_article_html`, и module-level constant `_FEED_URL = 'https://orangetrackdiecast.com/feed/'`.
- [ ] `_is_allowed_orangetrack_url` принимает `https://orangetrackdiecast.com` и `https://www.orangetrackdiecast.com`, отклоняет subdomain attack (`orangetrackdiecast.com.attacker.example`), cloud metadata IP, malformed URL, non-http scheme, scheme-relative URL — все 7 SSRF-кейсов покрыты тестами.
- [ ] Fallback-level SSRF guard вызывается ВНУТРИ `fetch_orangetrack_article` ДО `requests.get`. Тест `test_fallback_level_guard_blocks_http` зелёный и подтверждает, что `requests.get` НЕ вызывался ни разу.
- [ ] Парсер возвращает `{title, subtitle, paragraphs, images, blocks}`. `blocks` содержит typed entries (paragraph, image, video, heading). `paragraphs` синтезируется из `entry.title` для video-only постов.

**Edge cases:**
- `entry['content']` может отсутствовать, быть пустой list, быть list с пустым `value`. Все три → fallback path.
- `entry['link']` может быть строкой с whitespace или с трейлинг-слешем — `_is_allowed_orangetrack_url` должен переваривать (urlparse сам нормализует).
- `<iframe>` без `src` атрибута → drop тихо, никакого notifier-кода.
- `<img>` с `src=""` или без `src` → drop тихо.
- `<a>` без `href` → keep как plain text.
- BOM в content:encoded → BS4 переваривает, но проверь.
- HTML-encoded entities в title (`&amp;`, `&#x27;`) → BS4 декодирует автоматически.
- Очень длинный link (>200 chars) в `_safe_for_ping` → truncate до 200 с `…`.
- Control char В СЕРЕДИНЕ link (Unicode separator U+2028, U+2029) — наш filter удаляет ASCII control chars; non-ASCII non-printable bytes должны заменяться на `?`.
- `<iframe src='//www.youtube.com/embed/x'>` (scheme-relative) → urlparse даёт пустой scheme; hostname будет извлечён, но мы должны отбраковать (либо в `_video_embed_url` отдельной проверкой `if not parsed.scheme: return None`).
- Aggregator `add('', '')` — пустые строки после sanitization → разумно либо принять (счёт растёт), либо silent no-op; задокументировать выбор в docstring.
- `INSTANCE_LABEL` env-переменная — НЕ читаем в этом модуле, только в Task 3 (`news_bot._fetch_orangetrack_entries`); сюда передаём готовое значение через ctor.

**Implementation hints:**
- Для DOM walk-by-tag используй BS4 `soup.find_all` либо рекурсивный walk через `soup.descendants` с фильтром по `tag.name in ('p', 'figure', 'img', 'iframe', 'h5')`. Порядок появления в DOM = порядок в `blocks` list.
- Для image-dedup pre-`?`: split по `?`, дедуп по part[0] через `seen` set, сохрани порядок.
- Для YouTube watch-URL построения после извлечения ID: `f'https://www.youtube.com/watch?v={vid_id}'`, потом `urllib.parse.quote(watch_url, safe='')`, потом `f'https://telegra.ph/embed/youtube?url={encoded}'`.
- Для bounded streaming: типичный паттерн `for chunk in resp.iter_content(chunk_size=65536): total += len(chunk); if total > MAX_BODY_BYTES: break; buf.append(chunk)`.
- Для notifier callback signature: `Callable[[str, str], None]` — принимает `(code, link)`. В `fetch_orangetrack_article` сигнатура `notifier=None`; если None — wrap в no-op helper `_notify(notifier, code, link)`.
- Для aggregator status-suffix codes (`FEED_HTTP_<status>`, `ART_FALLBACK_HTTP_<status>`, `ART_FALLBACK_REDIRECT_<status>`): просто конкатенация — caller передаёт уже сформированную строку, aggregator не парсит.
- Логирование: на каждый notifier-trigger ничего не логируем сами (caller — aggregator — лог сделает в emit). Но на `ART_PARSE_EXCEPTION` — логируй `logger.exception(...)` ПЕРЕД re-raise, чтобы traceback был в journalctl.
- НЕ копируй curl_cffi из lamley/autoevolution — orangetrackdiecast не за Cloudflare. Простой `requests` достаточно.
- НЕ имплементируй throttle / Retry-After (Decision 6 — user-spec R4 verbatim).
