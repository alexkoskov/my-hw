## Description

Заменить извлечение `<script id="__NEXT_DATA__">` в `mattel_news_source.py` на парсинг RSC-flight-payload (`self.__next_f.push([1, "..."])`), сохранив публичный контракт модуля 1:1. После миграции Mattel на Next.js App Router тег `__NEXT_DATA__` исчез, и `fetch_mattel_news()` тихо возвращает `[]` каждые 12 часов, заодно засирая админ-чат `Mattel news parsing error: __NEXT_DATA__ script tag not found in HTML`. Решение — читать те же поля (`handle`, `title`, `date`, `excerpt`, `seo_description`, `thumbnail`) из встроенного streaming-payload, который Next.js использует для гидрации. Тело статьи теперь ссылочное (`body: "$<row-id>"`), резолвится отдельным маркером `<row-id>:T<hex-len>,<content>`, который может растягиваться на несколько чанков — нужна корректная сборка через границы.

Это атомарная одноволновая правка: переписать парсер, оба Mattel-теста и собрать новый builder-модуль `tests/fixtures/mattel_flight_builder.py` нужно одним коммитом, потому что parser↔test контракт двусторонний — любое промежуточное состояние оставит сьют красным. Старый файл-фикстуру `tests/fixtures/mattel_news.html` (1.16 MB) удалить через `git rm`. Все детали ошибочной матрицы (12 строк ES1–ES10), 8 решений (включая Decision 8 — security hardening: SSRF guard, linear-time regex, JSON depth guard, bracket-match safety, notifier sanitisation, `allow_redirects=False`) и тестовый инвентарь (≥32 unit-теста) описаны в tech-spec. Внешние символы (`fetch_mattel_news`, `fetch_mattel_article`, `MattelNewsError`, `NEWS_URL`, `ARTICLE_URL_PREFIX`, `MAX_RESPONSE_SIZE`) и внутренние имена, импортируемые тестами (`_is_hotwheels`, `_build_entry`, `_extract_entries`), сохраняются. `_notify` сохраняется по имени + сигнатуре для module-internal стабильности (тесты его напрямую НЕ импортируют — фиксируем имя, чтобы не менять внутренние call-sites в error-paths).

**Edge cases (must be covered explicitly):**
- Body растянут на 2–3 чанка (AC8) — `_concat_flight` склеивает все push-ы в один unescaped стринг до резолюции body.
- Body отсутствует (entry без `body` поля) — `paragraphs=[]`, без notifier (AC9, ES9c).
- Body advertised hex-length > available content (truncate) — `paragraphs=[]`, без notifier (AC9, ES9c).
- Body advertised hex-length > `MAX_RESPONSE_SIZE` — content-empty path, без notifier (Security AC, ES9c).
- Excerpt в dict-форме `{"text": "..."}` (AC6) — `_excerpt_to_str` нормализует.
- Handle не совпадает со slug, но `url` поле равно link (AC7) — `_find_entry_by_handle_or_url` пробует оба.
- Listing без HW-записей (AC3) — `[]` БЕЗ notifier.
- HTML без flight-payload (rollback на старый формат) — ES3, notifier с "flight payload not found" + `[]`.
- Адверсариальный hex-length, deeply nested JSON, `RecursionError` — ловятся (Decision 8).
- SSRF guard (ES10) — `link="https://evil.example.com/..."` отбивается ДО HTTP-вызова, malicious URL НЕ эхо-ится в notifier.

**Implementation hints (landmarks, не пошаговые алгоритмы — детали алгоритма см. в code-research):**
- `_iter_flight_payloads(html)` — генератор по всем match-ам `_FLIGHT_PUSH_RE`; для каждого делает JS-string-unescape (см. code-research §5 — JS-string-unescape pattern). Все ошибки декода → swallow через try/except.
- `_concat_flight(html)` — конкатенация всех unescaped пушей в один стринг (нужно, потому что body-маркер может растягиваться через границы чанков).
- `_extract_listing_entries(html)` — следуй listing-pipeline pattern из code-research §5 (regex-find pushes, JS-string unescape, anchor-search `"article2":{"entries":[`, bracket-match с depth+string-литерал awareness, JSON-decode slice). Точный алгоритм bracket-match и cap → §5 + Decision 8 control 4.
- `_resolve_body_html(concat, body_ref)` — body_ref в форме `$<row-id>`. Алгоритм резолюции маркера `<row-id>:T<hex-len>,<content>` — см. code-research §6. Все три фейл-кейса (маркер отсутствует, length > available, length > `MAX_RESPONSE_SIZE`) → `""`, ES9c content-empty (без notifier).
- `_paragraphs_from_body(body_html)` — паттерн извлечения параграфов уже есть инлайн в текущем `fetch_mattel_article` (BeautifulSoup + теги `p`/`li`/`h1`–`h4` + `get_text(" ", strip=True)` + фильтр пустых) — вынести в helper без изменения логики.
- Notifier-сообщения: format strings уже зафиксированы ниже в разделе «Notifier-сообщения». Используй ТОЛЬКО safe scalars (sizes, slugs, anchor names, `type(exc).__name__`); НЕ включай `str(exc)` целиком — там могут быть URL/headers/cookies.
- ES10 SSRF — link сам в notifier-сообщение НЕ выдаём, чтобы не амплифицировать malicious URL в админ-чат.
