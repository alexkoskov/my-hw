## Description

Полнофункциональный аудит качества тестов фичи `mattel-parser-rewrite` по результатам Task 01 (rewrite-parser). Это AUDIT-задача: test-master ЧИТАЕТ тесты и пишет JSON-отчёт; код и тесты НЕ модифицируются. Если найдены пробелы покрытия или слабые ассерты — оркестратор `feature-execution` развернёт отдельный fix-таск.

Цель аудита — независимо подтвердить, что переписанный `tests/test_mattel_news_source.py` (≥ 32 теста: tech-spec target 15 keep + 11 update + 6 new = 32; фактически больше после round-2 additions для AC3/AC6/AC7/SSRF/anti-drift), обновлённый `tests/test_mattel_integration.py` (3 теста: 1 keep + 2 update) и новый `tests/fixtures/mattel_flight_builder.py` (синтетический builder вместо удалённого HTML-фикстура) обеспечивают поведенческое покрытие AC1–AC13 user-spec, всех 12 строк error-matrix (ES1–ES10, включая ES9b и ES9c), регрессионный lock на thumbnail-only image policy и устойчивость анти-дрейф smoke-тестов к отсутствию live-snapshots в CI.

Аудит охватывает: оба тестовых файла на полную глубину (assertion meaningfulness, AC-маппинг, ES-маппинг, отсутствие leftover `__NEXT_DATA__`-references, отсутствие references на удалённый `tests/fixtures/mattel_news.html`, skip-guard на анти-дрейф smoke), новый fixture-builder модуль (API соответствует Decision 4 и code-research §11.4), и косвенно — продуктовый код `mattel_news_source.py` для верификации test↔code контракта (имена внутренних helper'ов, экспортированные публичные символы, формы возвращаемых структур). Code-quality issues — out of scope (Task 02). Security-quality issues — out of scope (Task 03). Этот аудит фокусируется ИСКЛЮЧИТЕЛЬНО на качестве тестов.

- [ ] **Test count `test_mattel_integration.py`** — ровно 3 теста: 1 keep (`test_mattel_duplicate_is_not_restaged` или эквивалент), 2 update (`test_mattel_post_flows_into_pending_queue`, `test_mattel_http_failure_does_not_crash_job` — фикстура swap'нута на builder, тела/ассерты unchanged). Total = 3.
- [ ] **AC1–AC13 mapping completeness** — каждый AC из user-spec (AC1–AC13) имеет минимум один тест, который поведенчески его проверяет. AC13 (live smoke) — допустимо «no test, covered by manual smoke + anti-drift snapshot tests» в `additional_findings`. Остальные 12 AC — обязательно поведенческое покрытие.
- [ ] **ES1–ES10 mapping completeness** — каждая строка error-matrix (ES1, ES2, ES3, ES4, ES5, ES6, ES7, ES8, ES9, ES9b, ES9c, ES10) имеет минимум один тест, который проверяет: правильный return (`[]` / `None` / dict с `paragraphs=[]`), наличие/отсутствие notifier call (assert_called/assert_not_called), формат сообщения notifier'а (sanitised, без leak'а exception text).
- [ ] **AC3 silent-zero verified** — тест `test_listing_with_no_hotwheels_returns_empty_without_notifier` (или эквивалент) присутствует, ассертит `result == []` И `notifier.assert_not_called()`. Это ключевая регрессия: отсутствие HW ≠ парс-ошибка.
- [ ] **AC6 dict-form excerpt verified** — тест `test_dict_form_excerpt_extracts_text_field` (или эквивалент) проверяет ветку, где `excerpt` приходит как `{text: "..."}` dict, а не как raw string; ассертит, что `subtitle` в article-dict — это `text`-поле, не `str(dict)`.
- [ ] **AC7 url-fallback verified** — тест `test_article_falls_back_to_url_field_when_handle_mismatch` (или эквивалент) проверяет ветку: `handle` записи не совпадает с URL slug, но `entry["url"] == link`. Ассертит, что entry найден через url-fallback и article возвращён корректно.
- [ ] **AC8 multi-chunk verified** — тест `test_body_split_across_multiple_chunks` (или эквивалент) использует `_make_flight_article(body_chunks=N>=2)` и ассертит: (а) `paragraphs` содержит ровно те же блоки, что и при `body_chunks=1`; (б) порядок параграфов сохранён; (в) нет дублей; (г) нет пропусков. Минимум один тест с `body_chunks >= 2`.
- [ ] **AC9 empty body verified** — тест на ветку «entry без `body` field» ассертит: `result["paragraphs"] == []` И `notifier.assert_not_called()` (это контентная пустота, не парс-ошибка).
- [ ] **AC9 truncated body verified** — тест на ветку «body length > available content» (через `_make_flight_article(truncate=True)` или эквивалент) ассертит: `result["paragraphs"] == []` И `notifier.assert_not_called()`. Обе подветки AC9 (empty AND truncated) должны быть покрыты — это две разные кодовые пути в `_resolve_body_html`.
- [ ] **AC10 thumbnail-only regression locked** — тест `test_parses_paragraphs_and_uses_thumbnail_only` (или эквивалент) присутствует и ассертит: (а) `images` длины ≤ 1 (только thumbnail URL, если он есть); (б) `download_media` НЕ присутствует в выходном dict (key absent), даже если payload содержит `download_media` field. Это lock на image-policy от случайного расширения.
- [ ] **ES10 SSRF guard test** — класс `TestSsrfGuard` (или эквивалентный тест) присутствует в `test_mattel_news_source.py`, передаёт evil-link (например, `https://evil.example.com/news/foo`) в `fetch_mattel_article`. Ассертит: (а) функция возвращает `None`; (б) `notifier.assert_called_once()`; (в) сообщение notifier'а НЕ содержит саму malicious-URL подстроку (через `assert "evil.example.com" not in notifier.call_args[0][0]` или эквивалент).
- [ ] **No `__NEXT_DATA__` literals в тестах** — текстовый поиск по обоим тестовым файлам (`grep -F "__NEXT_DATA__"`) возвращает 0 hit'ов. Старая система парсинга должна быть полностью вычищена из тестового кода.
- [ ] **No reference to deleted file fixture** — текстовый поиск по обоим тестовым файлам и по `mattel_flight_builder.py` (`grep -F "mattel_news.html"`) возвращает 0 hit'ов. Файл удалён в Task 01 — никаких leftover'ов в тестовом коде.
- [ ] **Anti-drift smoke skip-guarded** — тесты, которые читают live snapshots `/tmp/mattel_news.html` / `/tmp/mattel_article.html`, обёрнуты в `pytest.skip(...)` (или `@pytest.mark.skipif(not os.path.exists(...), ...)`), при отсутствии файлов CI никогда не падает. Зафиксировать file:line + точный механизм skip-guard'а.
- [ ] **Integration tests use the builder, not file fixture** — все 3 теста в `test_mattel_integration.py` импортируют из `tests.fixtures.mattel_flight_builder` (или `from .fixtures.mattel_flight_builder import ...`); ни один не открывает `tests/fixtures/mattel_news.html`. Тела + ассерты структурно unchanged по сравнению с pre-rewrite состоянием (зафиксировать через diff-чтение, что меняется только fixture source, а не assertion logic).
- [ ] **Meaningful assertions throughout** — для каждого теста зафиксировать: ассертит ли он на actual return values + notifier call count, или только на «не упало». Тесты, ассертящие только `result is not None` без структурной проверки — записать в `weak_assertions` секцию отчёта. Целевой порог: 0 weak-assertion тестов в финальной версии.
