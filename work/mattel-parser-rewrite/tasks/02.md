## Description

Полнофункциональный аудит качества кода по результатам Task 01 (rewrite-parser). Это AUDIT-задача: ревьюер ЧИТАЕТ код и пишет JSON-отчёт; код НЕ модифицируется. Если найдены проблемы — оркестратор `feature-execution` развернёт отдельный fix-таск.

Цель аудита — независимо подтвердить, что переписанный `mattel_news_source.py` и новый `tests/fixtures/mattel_flight_builder.py` соблюдают все 7 архитектурных решений из tech-spec (Decisions 1–7), сохраняют fail-soft notifier-контракт, не вводят дублирующих shared-resources и читаются как чистый, поддерживаемый Python без следов старого `__NEXT_DATA__`-пайплайна. Decision 8 (security hardening) намеренно вне scope этого аудита — он покрывается параллельной Task 3 (Security Audit), чтобы избежать дублирования и конфликта рекомендаций.

Аудит охватывает: основной модуль `mattel_news_source.py`, новый builder-модуль `tests/fixtures/mattel_flight_builder.py`, и косвенно — оба тестовых файла (`tests/test_mattel_news_source.py`, `tests/test_mattel_integration.py`) на предмет того, что они не содержат `__NEXT_DATA__`-references и корректно импортируют сохранённые внутренние имена. Глубокий тест-аудит — отдельная Task 4.

## Acceptance Criteria

Чек-лист аудита (каждый пункт — отдельная строка отчёта, обязательна evidence-цитата для каждого pass/fail):

- [ ] **Decision 1 honored** — парсер читает RSC flight payload (`self.__next_f.push([1, "..."])`); в `mattel_news_source.py` нет ни одного упоминания `__NEXT_DATA__`, `_NEXT_DATA_RE`, `<script id=`.
- [ ] **Decision 2 honored** — anchor'ы семантические: substring `"article2":{"entries":[`, имена полей (`handle`, `title`, `body`, `excerpt`, `thumbnail`). Нет hardcoded row-id (типа `:6:`, `:T<hardcoded-hex>`), нет positional-логики «biggest push wins».
- [ ] **Decision 3 honored** — name + signature preservation: `_is_hotwheels`, `_build_entry`, `_extract_entries` сохранены по имени и сигнатуре И импортируются тестами (`tests/test_mattel_news_source.py` import-блок); `_notify` сохранён по имени и сигнатуре для module-internal consistency (НЕ импортируется тестами — не искать его в test imports). `_extract_entries` существует как импортируемый символ (даже если это тонкая обёртка над `_extract_listing_entries`).
- [ ] **Decision 4 honored** — builder-функции (`_make_flight_listing`, `_make_flight_article`) живут в `tests/fixtures/mattel_flight_builder.py`, а не инлайн-копиями в каждом тестовом файле; оба `test_mattel_*.py` импортируют из этого модуля.
- [ ] **Decision 5 honored** — атомарная одноволновая поставка: парсер, тесты, builder, удалённая HTML-фикстура — всё в одной волне (Task 01); промежуточных half-deleted состояний в коде нет (нет references на удалённый `tests/fixtures/mattel_news.html`).
- [ ] **Decision 6 honored** — fail-soft notifier-контракт: для каждой ES-строки матрицы (ES1–ES10, кроме ES9c) есть путь, который вызывает `_notify(notifier, msg)` и возвращает `[]` (для listing) или `None` (для article). ES9c-пути (body absent, body truncated, body length > MAX) — НЕ вызывают notifier и возвращают dict с `paragraphs=[]`. Notifier swallowing exceptions сохранён.
- [ ] **Decision 7 honored** — анти-дрейф smoke-тесты в `tests/test_mattel_news_source.py` для `/tmp/mattel_news.html` и `/tmp/mattel_article.html` присутствуют, оба skip-guarded через `pytest.skip(...)` при отсутствии файла; CI никогда не падает из-за их отсутствия.
- [ ] **`_FLIGHT_PUSH_RE` compiled at module level** — `re.compile(...)` вызван один раз в module scope, а не внутри функции (нет `re.compile` в теле helper-а).
- [ ] **Architecture «Shared resources: None» соблюдено** — в модуле нет module-level mutable shared state (нет глобального DB pool, нет глобального `requests.Session` объекта, нет module-level кэшей). Module-level скомпилированная regex — допустимо (стандартная Python-практика, не shared resource).
- [ ] **No NEW shared `Session` introduced** — текущий `mattel_news_source.py` не создаёт `requests.Session` (caller передаёт `session` опционально). Аудит должен подтвердить, что переписанный модуль НЕ вводит нового `Session()` (ни module-level, ни inline-конструкцию внутри listing/article-путей). Если обнаружен новый `Session()` — fail с цитатой.
- [ ] **Code quality: clear naming, single-responsibility helpers, no dead code** — каждый helper делает одно понятное дело, имена самодокументирующие; нет неиспользуемых функций/переменных/констант; нет закомментированного кода со старой логикой.
- [ ] **No leftover comments referencing `__NEXT_DATA__`** — нет docstring-ов, inline-комментариев или TODO, упоминающих `__NEXT_DATA__`, `_NEXT_DATA_RE`, или старый dict-путь `props.pageProps.page.data.state.article2.entries`.
- [ ] **Imports clean** — нет неиспользуемых импортов, оставшихся со старой версии (например, если `_NEXT_DATA_RE` использовал какие-то импорты, которые больше не нужны); порядок импортов соответствует проекту (stdlib → third-party → local).
- [ ] **Audit report written** — JSON-отчёт записан по адресу `/workspaces/debian-2/my-hw/work/mattel-parser-rewrite/logs/tasks/code-audit-report.json` со структурой из «What to do» п. 7. Содержит summary, полный checklist, additional_findings (даже если пустой массив).
