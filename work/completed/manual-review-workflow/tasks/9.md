# Task 9: Idle-fallback pass + hw_review take command

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Добавляем последнее недостающее звено автопубликации: idle-fallback проход в начале `job()` и CLI-команду `hw_review take N`, которая позволяет оператору «перехватить» строку, уже получившую heads-up.

Флоу idle-fallback (тех-спек §9.10, Architecture «Prep phase» пункты 1a/1b):
1. **Heads-up (1a)** — `list_pending_stale(IDLE_TIMEOUT_HOURS)` отдаёт строки, у которых `fetched_at` старше 48ч и `notified_at IS NULL`. Для всех них отправляется **один** admin-ping по шаблону Decision 12: `"Will auto-publish in ~{GRACE_WINDOW_HOURS}h: {title1}, {title2}, …. Intercept via hw_review take N"`. После отправки — `mark_notified(link)` на каждую.
2. **Auto-publish (1b)** — `list_notified_overdue(GRACE_WINDOW_HOURS)` отдаёт строки, где `notified_at` старше 2ч и `ru_paragraphs IS NULL`. Для каждой — внутренний `_fallback_publish(row, via_review=False)` (GoogleTranslate через `transcreate_text` → `publish_article` с переиспользованием `telegraph_url` из строки, если он уже есть, — Decision 9 → `send_telegraph_teaser` → `move_to_published(via_review=False)`). На любой ошибке: `sanitize_error_message(exc)` (Decision 11) → `increment_attempt(link, safe)`; на третьей попытке — `move_to_failed(link, safe)`. Тот же счётчик `attempt_count` используется overflow-путём из Task 10 (Decision 13 — общий счётчик на строку).

CLI-команда `hw_review take N` (тех-спек «Review + publish» §7):
- `N` — индекс в `list_pending()` (та же нумерация, что у `list` / `show` / `stage` / `publish` / `skip`).
- Если строка всё ещё в `pending_articles` — вызываем `pending_repo.clear_notified(link)`, stdout: `"notification cleared — row returned to normal review cycle"`, exit 0.
- Если строка уже ушла из pending (есть в `published_articles` или в `failed_articles`) — отказываемся: stderr `"N already auto-published"` (формулировка из AC user-spec L67), exit 1, никаких DB-мутаций.

Задача атомарна: одна волна, две фичи делятся на два тест-файла (`test_idle_fallback.py` для prep-части, `test_hw_review_take.py` для CLI), `_fallback_publish` — общий helper, который будет переиспользован Task 10 (overflow).

## Acceptance Criteria

- [ ] `job()` в начале запускает idle-fallback проход из двух шагов (heads-up + overdue auto-publish), после которого продолжается существующая prep-логика (fetch sources → filter → overflow fast-track → insert → ping).
- [ ] Heads-up шаг шлёт **один** admin-ping на cron-tick даже при 3+ stale-строках (Decision 12); текст содержит все title через запятую + `Intercept via hw_review take N` + `~{GRACE_WINDOW_HOURS}h`.
- [ ] После heads-up `notified_at` у всех просроченных строк — NOT NULL.
- [ ] Overdue auto-publish использует `_fallback_publish` с `via_review=False`; `published_articles.via_review = 0`.
- [ ] Ошибка в `_fallback_publish` → `sanitize_error_message(exc)` → `increment_attempt(link, safe)`; `last_error` без секретов (Decision 11).
- [ ] Три провала в любом сочетании idle-fallback + overflow (общий `attempt_count`, Decision 13) → `move_to_failed`.
- [ ] Если `telegraph_url` уже проставлен на pending-строке, fallback-ветка не вызывает `publish_article` повторно (Decision 9).
- [ ] `hw_review take N` во время grace-окна (строка в pending с `notified_at != NULL`) очищает `notified_at`, exit 0.
- [ ] `hw_review take N` после автопубликации (строка уже в `published_articles` или `failed_articles`) → exit 1, clean stderr `"N already auto-published"`, никаких DB-мутаций (AC user-spec L67).
- [ ] `hw_review take N` с `N` вне диапазона `list_pending()` → exit 1, clean stderr без traceback.
- [ ] `_fallback_publish` — единственная точка, переводящая EN-статью и вызывающая `publish_article` + `send_telegraph_teaser` в prep-пути; Task 10 (overflow) использует тот же helper (Decision 13).
- [ ] Все записи в `last_error` и admin-notify про исключения проходят через `sanitize_error_message` (Decision 11).
- [ ] Константы `IDLE_TIMEOUT_HOURS`, `GRACE_WINDOW_HOURS` читаются из модульного уровня `news_bot.py` (добавлены Task 6, не дублировать).
- [ ] Тесты `tests/test_idle_fallback.py` и `tests/test_hw_review_take.py` зелёные.

**Edge cases:**
- **Пустой pending.** И (1a), и (1b) получают пустые списки → no-op, никаких admin-ping'ов из idle-пути. Не должно ломать остальные этапы `job()`.
- **Stale-строка с уже проставленным `notified_at`.** `list_pending_stale` фильтрует `notified_at IS NULL`, heads-up не повторяется. Юнит на репо-функцию (Task 1) это уже покрывает, но интеграционный тест полезен.
- **Overdue-строка со staged ru.** `list_notified_overdue` фильтрует `ru_paragraphs IS NULL` — строки, которые оператор уже перевёл, не трогаем (AC — автопубликация только того, что оператор не тронул).
- **`send_telegraph_teaser` возвращает False** в fallback-ветке. Считать это ошибкой — `raise` → `increment_attempt`. Не молчи.
- **`sanitize_error_message` на исключении с пустыми ENV-переменными.** Task 3 уже обрабатывает (пропускает пустые), но помни про контракт: не вызывай `str.replace('', ...)` — это выстрелит.
- **`take N` на только что evicted-строке.** Race: CLI читает `list_pending()`, но к моменту `get_pending(link)` строка уже в `published_articles`. Покрывается тестом `test_take_after_autopublish_returns_exit_1_with_error`.
- **Telegraph URL reuse в fallback-ветке.** Если `row['telegraph_url']` уже заполнен (Decision 9 — предыдущий частичный успех), не вызываем `publish_article`; только `send_telegraph_teaser` + `move_to_published`. Если Telegram опять упал — `attempt_count++`, URL остаётся на строке.
- **`preview_html_path` у fallback-строки.** Fallback-строка, скорее всего, не имела превью (оператор её не смотрел), но на всякий случай — после `move_to_published(via_review=False)` вызываем тот же `_cleanup_preview_html`, что и `cmd_publish` (безопасно на `None`).

**Implementation hints:**
- Helper `_fallback_publish` живёт в `news_bot.py` (не в `hw_review.py`), потому что вызывается из `job()`. Task 10 импортирует его оттуда же.
