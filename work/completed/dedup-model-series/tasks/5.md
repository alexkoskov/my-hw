# Task 5: Backfill widened re-select (`backfill_fingerprints.py`)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

`backfill_fingerprints.py` — разовый оператор-скрипт, который дозаполняет
`published_articles.model_fingerprint` за N дней (по умолчанию 14). Сейчас он
считает «необработанной» строку **только** по `model_fingerprint IS NULL`. После
фичи `dedup-model-series` фингерпринт расширяется с `{strict, brands}` до
`{strict, brands, series, pairs}` (Task 1). Значит, строки, у которых уже есть
**старый** car-фингерпринт (из прежнего 14-дневного прогона или из живого гейта до
деплоя), но **нет ключа `pairs`**, текущий `IS NULL`-фильтр молча пропустит — и
они никогда не получат пары «машина+серия». На московском проде база почти
наверняка «холодная» (снимок со старого NL до фичи дедупа, backfill там не
запускался — см. Risks в tech-spec), поэтому прогрев обязателен.

Задача — расширить выборку и skip-guard так, чтобы дозабирались и строки с
car-фингерпринтом, но без ключа `pairs`; при этом сохранить 30-дневное окно
(`--days 30` уже валиден, clamp `[1,90]`) и **идемпотентность** (повторный прогон —
no-op). Это прогревает и базовый car-фингерпринт, и новые пары одновременно.
Обслуживает пользовательский **AC10** (backfill + предпроверка) и попутно **AC9**
(непустая структура фингерпринта в БД). Реализация — по tech-spec Decision 7 и
code-research §4.3.

## What to do

1. **Расширить SELECT** (`backfill_fingerprints.py:243-249`): добавить к
   `WHERE ... AND model_fingerprint IS NULL` дизъюнкцию по отсутствию ключа пар —
   `AND (model_fingerprint IS NULL OR json_extract(model_fingerprint, '$.pairs') IS NULL)`.
   `days` остаётся единственным связанным `?`-параметром; `json_extract(..., '$.pairs')` —
   **статический литерал** (никакого f-string/интерполяции untrusted-данных в тело SQL).
2. **Расширить skip-guard в `backfill_one`** (`backfill_fingerprints.py:164`): сейчас
   `if row.get('model_fingerprint') is not None: return 'skipped'` — этот guard заново
   отбросил бы ровно те старообразные строки, ради которых расширяем SELECT. Пропускать
   строку только если её blob уже содержит ключ `pairs`. Учесть, что SELECT кладёт в
   `row['model_fingerprint']` **сырую JSON-строку** (не десериализованный dict, в отличие
   от repo-хелперов), — распарсить перед проверкой ключа.
3. **Обновить маркер computed-empty** (`backfill_fingerprints.py:191`): сейчас
   `empty_fp = {'strict': [], 'brands': []}` — без ключей `series`/`pairs`. Иначе такая
   строка при каждом прогоне снова попадёт под `json_extract(..., '$.pairs') IS NULL` и
   будет переобрабатываться бесконечно (ломает идемпотентность). Привести к
   4-ключевой пустой форме, совпадающей с пустым ранним возвратом `extract_fingerprint`
   из Task 1: `{'strict': [], 'brands': [], 'series': [], 'pairs': []}`.
4. **Обновить docstring/комментарии** идемпотентности (module docstring «Idempotency
   contract» строки 16-31; комментарий над SELECT 236-249; лог-строка 254-258): новый
   маркер «ещё не обработана» — `model_fingerprint IS NULL ИЛИ отсутствует '$.pairs'`.
5. **Тесты** (`tests/test_backfill_fingerprints.py`): добавить сценарии re-upgrade и
   30-дневного окна (см. TDD Anchor), обновить существующий
   `test_fetch_empty_stores_computed_empty` под 4-ключевую пустую форму, дополнить
   docstring-список сценариев.

Не менять: clamp `--days [1,90]`, дефолт 14, `_FETCH_SLEEP_SECONDS`, узкий try/except
только вокруг `fetch_full_article`, порядок импортов, `print()`-сводку, exit-коды.

## Details

**Files:**
- `backfill_fingerprints.py`:
  - SELECT `:243-249` — заменить `AND model_fingerprint IS NULL` на
    `AND (model_fingerprint IS NULL OR json_extract(model_fingerprint, '$.pairs') IS NULL)`.
    Единственный связанный параметр — `(f"-{int(args.days)}",)` — не трогать.
  - `backfill_one` guard `:164` — заменить `if row.get('model_fingerprint') is not None:
    return 'skipped'`. `row['model_fingerprint']` здесь — сырая JSON-строка (SELECT →
    `dict(zip(col_names, r))`, не repo-хелпер): распарсить (`json.loads` в try/except на
    случай битого blob) и пропускать (`return 'skipped'`) только если результат — dict с
    ключом `'pairs'`. Иначе (NULL, не-dict, старая форма без `pairs`) — обрабатывать.
    Добавить `import json` в шапку (сейчас его нет: импортируются только argparse,
    logging, sqlite3, sys, time).
  - empty-fp `:191` — `{'strict': [], 'brands': []}` → `{'strict': [], 'brands': [],
    'series': [], 'pairs': []}` (иначе строка вечно пере-выбирается; см. Edge cases).
  - Docstring/комментарии — синхронизировать формулировку «not yet processed» с новым
    условием (module docstring 16-31; комментарий над SELECT 236-249; INFO-лог 254-258,
    где сейчас `... AND model_fingerprint IS NULL`).
- `tests/test_backfill_fingerprints.py`: новые тесты из TDD Anchor + правка
  `test_fetch_empty_stores_computed_empty` (строки 274-275: `decoded == {...4 keys...}`)
  + дополнить docstring-список сценариев (строки 10-31). Посев старообразной строки —
  `_seed_published(temp_db, url, model_fingerprint={'strict': ['toyota 4runner'],
  'brands': ['toyota']})` (хелпер сам json.dumps'ит). Для строки «уже с pairs» —
  `model_fingerprint={'strict': [], 'brands': [], 'series': [], 'pairs': []}`. Окно
  ~29/~31 день — как в `test_days_window_honored`: `UPDATE ... SET published_at =
  datetime('now', '-31 days')` прямым запросом (не через параметризованный INSERT).

**Dependencies:**
- **Task 1** (Wave 1) — `model_extractor.extract_fingerprint` должен возвращать
  `{strict, brands, series, pairs}` (иначе backfill запишет старую 2-ключевую форму и
  пары не появятся). Это единственная жёсткая зависимость.
- Repo **не менять**: `update_published_fingerprint`/`list_recent_*_fingerprints` уже
  готовы, `pairs`/`series` едут внутри opaque `model_fingerprint` blob без миграции.

**Edge cases:**
- Старообразный blob `{"strict": [...], "brands": [...]}` (нет `pairs`) → пере-выбран +
  upgrade. Основной мотив задачи.
- Computed-empty старой формы `{"strict": [], "brands": []}` → пере-выбран + переписан в
  4-ключевую пустую форму; далее идемпотентен. Без правки `:191` — бесконечное
  переобработка.
- Строка уже с ключом `pairs` (в т.ч. `"pairs": []`) → `json_extract` вернёт `'[]'`
  (не NULL) → не выбрана; и guard бы её пропустил.
- `model_fingerprint IS NULL` → короткое замыкание `OR` ловит первым; `json_extract(NULL,
  ...)` в любом случае вернёт NULL.
- Битый/не-JSON blob в guard → json.loads кинет — обернуть в try/except, трактовать как
  «нет pairs» (переобработать), не падать.
- Гонка с конкурентным писателем: guard пропускает строку, только если `pairs` уже
  появился между SELECT и обработкой.
- JSON1 (`json_extract`) вкомпилен в CPython ≥3.9 по умолчанию; in-memory/tempfile
  sqlite в тестах его имеет. Подтверждение на прод-образе — в runbook (Task 6), не здесь.

**Implementation hints:**
- SqlAudit-инвариант: `TestSqlAudit` сканирует **только** `pending_articles_repo.py`,
  поэтому `backfill_fingerprints.py` им НЕ покрыт (tech-spec AC-примечание). Держать
  `json_extract('$.pairs')` статическим литералом; `days` — связанный `?`. Опционально
  (по желанию) расширить `TestSqlAudit` на файл backfill — не обязательное требование
  задачи.
- Не переусложнять: одно изменение SELECT + один guard + один маркер empty-fp + docstrings.
  Никаких новых функций/флагов CLI.
- Прогон под tempfile-БД: скрипт сам делает `repo.init_schema(conn)` (`:234`), схема
  поднимется на свежей БД.
