# Task 2: Pair-aware [E015] + broad [E014] builders (`admin_alerts.py`)

## Required Skills

## Description

Задача поставляет два operator-ping builder'а для нового тирингового парного
правила дедупа (`машина + серия/тема`). Это Wave 1, чистый модуль `admin_alerts.py`
(pure str-builder'ы) + его юнит-тесты. Гейт `news_bot.py`, который будет ВЫЗЫВАТЬ
эти builder'ы с данными пары/серии — это Task 4 (вне scope этой задачи).

Что меняем:

- **E015 `alert_cross_source_blocked`** (жёсткий блок, distinctive-пара). Сейчас
  рендерит `new_link` + `existing_link` + строку `Совпадение: {overlap_pct}%`. Новое
  парное правило блокирует по совпавшей distinctive-паре `(model+series)` — там нет
  осмысленного процента set-overlap. Builder должен уметь отрендерить **совпавшую(ие)
  пару(ы) + ссылку на более раннюю (каноническую) статью**, сохранив якорь
  `[E015] 🚫 Заблокирован дубль` и короткий формат (без блока «Что сделать»). Serves
  user-spec **AC3**.

- **E014 `alert_cross_source_dupe`** (мягкий флаг, broad-тир). Сейчас рендерит
  модельные overlap-параметры (`overlap_pct`/`n_matches`/`n_total`/`models`). Broad-
  совпадение может быть **тема-only** (`*|stranger things|B`) — общей конкретной
  модели нет, процента overlap нет, старые параметры не подходят. Builder нужно
  **адаптировать** так, чтобы для broad-случая он рендерил **совпавшую серию/тему +
  ссылку**, сохранив якорь `[E014] 🤔 Похож на дубль` и блоки «Что произошло»/«Что
  сделать». Serves user-spec **AC4**.

Ключевое ограничение — **обратная совместимость**: оба builder'а ПРОДОЛЖАЕТ вызывать
существующий set-overlap дедуп, который остаётся живым как бэкстоп (tech-spec
Decision 3): его block-ветка зовёт E015 с `overlap_pct`, а soft-flag — E014 с
`overlap_pct`/`n_matches`/`n_total`/`models`. Поэтому адаптация не должна ломать эти
вызовы: пиновые тесты `test_e015_cross_source_blocked`, `test_e014_cross_source_dupe`
и `test_all_alerts_have_unique_codes` должны остаться зелёными, подстроки-якори
`Заблокирован дубль` / `Похож на дубль` — дословными. Builder'ы остаются чистыми
(params → str), plain-text (parse_mode=None — без Markdown/HTML), без токенов/секретов.

## What to do

1. Расширить `alert_cross_source_blocked` (E015): дать ему рендерить совпавшую(ие)
   distinctive-пару(ы) `(model+series)` рядом со ссылкой на раннюю каноническую
   статью, сохранив заголовок `[E015] 🚫 Заблокирован дубль` и короткий формат
   «без «Что сделать»». Существующий вызов `(new_link, existing_link, overlap_pct)`
   (set-overlap block-путь + его тест) должен продолжить работать — то есть
   добавление обратно-совместимое (напр. опциональный аргумент с парами: если пары
   переданы — рендерим блок пар; если нет — старую строку `Совпадение: {overlap_pct}%`).
2. Адаптировать `alert_cross_source_dupe` (E014): для broad-тира дать рендерить
   совпавшую серию/тему + раннюю ссылку, сохранив заголовок `[E014] 🤔 Похож на дубль`
   и operator-подсказки «Что произошло»/«Что сделать». Существующий модельный вызов
   (`overlap_pct`/`n_matches`/`n_total`/`models`) для set-overlap soft-flag-пути и его
   тест должны остаться рабочими — рендер серии/темы это дополнительная/альтернативная
   ветка, а не ломающая замена.
3. Оба builder'а оставить чистыми (params → str), plain-text, без Markdown/HTML
   (отправляются с parse_mode=None) и без содержимого токенов/секретов; значения
   пары/серии/ссылки вставлять как есть, не ломая plain-text.
4. Написать/поправить юнит-тесты в `tests/test_admin_alerts.py`: новые кейсы на
   pair-aware E015 и broad-series E014; существующие модельные E014/E015-тесты и
   `test_all_alerts_have_unique_codes` держать зелёными (список вызовов в последнем
   править только если сигнатура изменилась обратно-несовместимо — чего лучше избегать).

**Формат данных пары/серии** (из tech-spec Data Models + code-research §2.2, §3.4):
- Ключ пары: `"<model>|<series>|<tier>"`, напр. `"porsche 911|k-pop demon hunters|D"`;
  тема-only `"*|stranger things|B"`. Суффикс `|D` = distinctive, `|B` = broad.
- E015 получает совпавшие **distinctive**-пары (всегда с конкретной моделью, `|D`).
  E014 (broad) получает совпавшую серию/тему (может быть тема-only `*|…|B`).
- Рендер operator-facing: раскодировать сырой ключ в читаемый вид
  (`porsche 911 + k-pop demon hunters`) читается лучше, чем сырое `porsche 911|k-pop
  demon hunters|D`: убрать суффикс тира `|D`/`|B`, заменить `|` на ` + `, тему-only
  `*` рендерить как тему без модели. Держать детерминированно и пинать точную
  подстроку в тесте.

**Dependencies:** нет (Wave 1, depends_on: []). Пакеты не добавляются. Task 4
(news_bot.py) будет ПОТРЕБИТЕЛЕМ этих builder'ов — здесь только сами builder'ы + тесты.

**Edge cases:**
- Несколько совпавших пар → отрендерить все (join через newline), детерминированный
  порядок (сортировка).
- Тема-only пара `*|series|B` → рендерить как тему без фиктивной модели; в E015 не
  появляется (тема-only всегда broad → E014).
- Пустой/None опциональный аргумент → откат на legacy-рендер модельного overlap
  (не выводить `Совпадение: None%`).
- Длинные/необычные строки серии (пробелы, дефисы) — ок в plain-text, экранирование не
  нужно (parse_mode=None). НЕ вводить Markdown/HTML: случайный `_`/`*` в серии не
  должен требовать экранирования.

**Implementation hints (НЕ псевдокод):**
- Предпочесть обратно-совместимое расширение через **опциональные keyword-параметры**,
  а не смену позиционных сигнатур: E015 — опциональный `pairs`-аргумент (переданы →
  блок пар; нет → сегодняшняя строка `Совпадение: {overlap_pct}%`), причём `overlap_pct`
  оставить 3-м позиционным, чтобы `test_e015_cross_source_blocked` (позиционные, 72)
  оставался зелёным; E014 — опциональный `series`/`pairs`-аргумент, который при наличии
  рендерит блок темы/серии и может сделать модельные overlap-параметры опциональными.
- Если используешь опциональные типы — добавь `Optional` в импорт typing.
- Первую строку с severity-эмодзи сохранить (🚫 у E015, 🤔 у E014) — тесты их проверяют.
- Для E014 переиспользовать существующие формулировки «Что произошло / Что сделать»;
  E015 остаётся коротким.
- Set-overlap бэкстоп ВСЁ ЕЩЁ зовёт оба builder'а с модельными параметрами
  (news_bot.py `:2174-2176` для E015; flag-ветка для E014) — НЕ ломать эти вызовы.
- Альтернатива (допустима, если чище): отдельный sibling-builder под broad-случай —
  но только если коды `[E014]`/`[E015]` + якори + существующие тесты остаются целыми;
  один builder на код проще для `test_all_alerts_have_unique_codes` и call-site'ов news_bot.
