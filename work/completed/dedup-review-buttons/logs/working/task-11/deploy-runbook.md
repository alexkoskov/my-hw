# Runbook: раскатка фичи «кнопки проверки дублей» (dedup-review-buttons)

**Для кого:** оператор. Все команды ниже выполняете вы — Claude только подготовила их.
**Что раскатываем:** под сообщением-предупреждением `[E014] Похож на дубль` появятся
две кнопки — «🚫 Не публиковать» и «👍 Оставить». Нажатие кнопки обрабатывает сам бот.
**Что менять в деплой-скриптах:** НИЧЕГО. Весь код фичи лёг в файлы, которые и так
деплоятся (`news_bot.py`, `admin_alerts.py`, `pending_articles_repo.py`). Списки FILES
в `deploy.sh` / `deploy.yml` / `deploy_test.yml` проверены — правки не нужны.

Подробное описание процедуры также есть в документации:
`.claude/skills/project-knowledge/references/deployment.md`, раздел
«Feature rollout: dedup-review-buttons». Этот runbook ей не противоречит.

---

## Два главных правила (прочитайте до начала)

1. **Кнопки включаются только на ОДНОМ боте — на проде (Москва).**
   У прода и теста один и тот же бот-аккаунт Telegram. Слушать нажатия кнопок
   через этот аккаунт может только один процесс. Если включить на двух —
   второй начнёт получать ошибку `409 Conflict` (по-русски: «этот канал уже занят»).
   Включатель — переменная `REVIEW_BUTTONS_ENABLED=1` в файле настроек `.env`.
   На тесте её НЕ ставим, и автодеплой её туда сам не пропишет — проверено.

2. **Прод перезапускаем только ВНЕ окна публикаций 10:00–20:00 по Москве.**
   Перезапуск контейнера сбрасывает внутреннее расписание постов
   (слоты 10:00 / 15:00 / 19:30 МСК). Сервер живёт по UTC (МСК = UTC+3).
   Удобное время: утром до 10:00 МСК или вечером после 20:00 МСК.

---

## Фаза 1. Тест (Нидерланды) — раскатывается сам после push

На тесте кнопки будут «спать»: код приедет, но флаг выключен — ни кнопок, ни ошибок.

1. Отправить ветку `dev` на GitHub (из папки проекта на вашей машине):

   ```
   git push origin dev
   ```

2. Открыть GitHub → вкладка **Actions**. Дождаться зелёных галочек:
   сначала `CI` (тесты), затем `Deploy test bot` (авто-раскатка на тестовый сервер).

3. Проверить логи тестового бота (одной строкой; journalctl теперь только под root —
   у пользователя hwbot этот доступ отобран при усилении безопасности 2026-07-07):

   ```
   ssh root@148.135.207.54 "journalctl -u news_bot_test.service -n 100 --no-pager"
   ```

   **Что должно быть:** обычный чистый старт сервиса.
   **Чего быть НЕ должно:**
   - строки `review listener active` (её отсутствие = кнопки на тесте выключены — так и надо);
   - слов `409` или `Conflict`.

   Быстрая проверка одной строкой (в идеале ответ ПУСТОЙ):

   ```
   ssh root@148.135.207.54 "journalctl -u news_bot_test.service -n 200 --no-pager | grep -iE 'review listener|409|conflict' || echo OK: ничего не найдено"
   ```

Если тест стартовал чисто — переходим к проду. Если нет — остановиться и показать лог Claude.

## Фаза 2. Промоут dev → main (вне окна 10:00–20:00 МСК)

На вашей машине, в папке проекта:

```
git checkout main && git merge dev && git push origin main && git checkout dev
```

Push в `main` сам по себе прод НЕ трогает (старый авто-деплой прода отключён) —
прод обновляется руками в Фазе 3. Но делаем это уже вне окна, чтобы Фаза 3 шла сразу следом.

## Фаза 3. Прод (Москва, 45.90.216.165) — вне окна 10:00–20:00 МСК

### Шаг 3.1. Узнать свой числовой Telegram id (один раз)

Боту нужен ваш **числовой** id (ваш: `8481233034` — найден в локальном .env, записан в шпаргалку deployment.md), а не имя `@sunny413x`.
Это защита: если id не число, бот из осторожности просто не включит кнопки
(тихо, без поломок — но и без кнопок).

Как узнать id: в Telegram найдите бота **@userinfobot**, нажмите Start —
он ответит сообщением, где в строке `Id:` будет ваше число. Скопируйте его.

### Шаг 3.2. Посмотреть, что сейчас в настройках прода

```
ssh root@45.90.216.165 "grep -E '^(TELEGRAM_ADMIN_ID|REVIEW_BUTTONS_ENABLED)=' /root/hw-news/.env || echo 'этих строк пока нет'"
```

Команда показывает только эти две строки — токены и ключи она НЕ выводит.

### Шаг 3.3. Прописать числовой id (id уже подставлен)

```
ssh root@45.90.216.165 "sed -i 's/^TELEGRAM_ADMIN_ID=.*/TELEGRAM_ADMIN_ID=8481233034/' /root/hw-news/.env"
```

### Шаг 3.4. Включить флаг кнопок (команда сама допишет строку, если её нет)

```
ssh root@45.90.216.165 "grep -q '^REVIEW_BUTTONS_ENABLED=' /root/hw-news/.env && sed -i 's/^REVIEW_BUTTONS_ENABLED=.*/REVIEW_BUTTONS_ENABLED=1/' /root/hw-news/.env || echo 'REVIEW_BUTTONS_ENABLED=1' >> /root/hw-news/.env"
```

### Шаг 3.5. Проверить, что обе строки встали как надо

```
ssh root@45.90.216.165 "grep -E '^(TELEGRAM_ADMIN_ID|REVIEW_BUTTONS_ENABLED)=' /root/hw-news/.env"
```

Ожидание: `TELEGRAM_ADMIN_ID=<ваше число>` и `REVIEW_BUTTONS_ENABLED=1`.

### Шаг 3.6. Раскатать (вне окна!)

```
ssh root@45.90.216.165 "cd /root/hw-news && git pull && docker compose up -d --build"
```

Займёт ~3–4 минуты (пересборка контейнера).

## Фаза 4. Проверка после раскатки

1. Логи прода:

   ```
   ssh root@45.90.216.165 "docker logs hw-news-bot --tail 80"
   ```

   **Должно быть:** чистый старт и строка
   `[startup] review listener active (daemon thread started)` — значит, слушатель кнопок работает.
   Бонус-признак: в личку админа придёт сообщение «✅ Review listener active …».

   **Чего быть НЕ должно:** строк с `[E018]` (проверка базы при старте не прошла)
   и строк с `409` / `Conflict`.

   Быстрая проверка одной строкой:

   ```
   ssh root@45.90.216.165 "docker logs hw-news-bot --tail 200 2>&1 | grep -iE 'review listener|E018|409|conflict'"
   ```

   Ожидание: ровно одна строка — про `review listener active`. Если строки нет —
   ворота закрылись (флаг не 1 или id не число) → вернуться к шагам 3.3–3.5.

2. Ещё раз глянуть тест — там по-прежнему тихо (нет 409, нет listener):

   ```
   ssh root@148.135.207.54 "journalctl -u news_bot_test.service -n 200 --no-pager | grep -iE 'review listener|409|conflict' || echo OK: ничего не найдено"
   ```

3. Живое нажатие кнопок на реальном `[E014]` — это уже **Task 12** (post-deploy
   проверка): «🚫 Не публиковать» → статья не выходит, кнопки меняются на
   «✅ Отменено оператором»; «👍 Оставить» → выходит как обычно.
   Нажатие после того, как слот уже опубликовал → «⚠️ Уже опубликовано,
   отменить нельзя» — это норма, не ошибка.

После пункта 1–2: сообщите Claude «прод раскатан, логи чистые» — дальше Task 12.

## Фаза 5. Откат (если что-то пошло не так)

### Вариант А — быстрый: просто выключить кнопки (код остаётся, фича «засыпает»)

Фича сделана так, что с выключенным флагом бот ведёт себя В ТОЧНОСТИ как до неё.

```
ssh root@45.90.216.165 "sed -i 's/^REVIEW_BUTTONS_ENABLED=.*/REVIEW_BUTTONS_ENABLED=0/' /root/hw-news/.env"
```

затем перезапуск (вне окна):

```
ssh root@45.90.216.165 "cd /root/hw-news && docker compose up -d --build"
```

Уже отправленные кнопки в чате станут «мёртвыми» (нажатие ничего не делает) — это безопасно.

### Вариант Б — полный: откатить сам код

На вашей машине:

```
git checkout main && git revert HEAD && git push origin main && git checkout dev
```

затем на проде (вне окна):

```
ssh root@45.90.216.165 "cd /root/hw-news && git pull && docker compose up -d --build"
```

В любом непонятном случае — вариант А (выключить флаг) и позвать Claude.
