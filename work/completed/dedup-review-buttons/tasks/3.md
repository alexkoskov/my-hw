# Task 3: Attach keyboard at the E014 send site

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [SKILL.md](../../../.claude/skills/code-writing/SKILL.md) (файлы под `my-hw/` → используй scoped-вариант `my-hw:code-writing`)

## Description

Финальный «send»-кусок фичи кнопок ревью: в утреннем прогоне `job()`, ровно в
той ветке, где бот уже решил отправить оператору личный алерт **`[E014]` «Похож
на дубль»**, надо прикрепить к этому — и только к этому — сообщению inline-клавиатуру
с двумя кнопками. Прикрепление включается **только** когда поднят флаг
`REVIEW_BUTTONS_ENABLED` (Decision 6: прод-only, по умолчанию выключен). Когда флаг
выключен — код обязан вести себя байт-в-байт как сегодня: ни токена, ни записи в БД,
ни `reply_markup`.

Это Wave 2: задача опирается на готовое из Wave 1 —
`pending_articles_repo.put_review_token(token, link)` (Task 1, хранит `token→link` в
`bot_state`) и `admin_alerts.build_dedup_review_keyboard(token)` +
keyword-only `reply_markup=` у `send_admin_notification` (Task 2). Здесь мы только
соединяем их в точке отправки E014 и вводим сам флаг `REVIEW_BUTTONS_ENABLED`.

Границы строгие: трогаем **исключительно** отправку `alert_cross_source_dupe` (E014).
Другие алерты (E006/E008/E009/E015/E016/E034) не меняем — под ними кнопок быть не должно.

## What to do

1. Ввести module-level флаг `REVIEW_BUTTONS_ENABLED` в `news_bot.py` рядом с
   `DEDUP_SERIES_ENABLED` (~L130). Разбор env по конвенции проекта, но **по умолчанию
   OFF**: unset / blank / `0/false/no/off` → выключен; включён только на явных
   on-словах (`1/true/yes/on`, регистр не важен). Это **единственное** определение
   константы — Task 5 (Wave 3) будет читать ту же `news_bot.REVIEW_BUTTONS_ENABLED`;
   второго определения не заводить. Если к моменту выполнения другой таск уже добавил
   константу — переиспользовать её, не дублировать.
2. Добавить `import secrets` (stdlib) в блок импортов, если его там ещё нет.
3. В ветке `if decision == 'flag':` → `if alerted:` (там, где сейчас
   `send_admin_notification(admin_alerts.alert_cross_source_dupe(...))`, ~L2374-2397):
   когда `REVIEW_BUTTONS_ENABLED` истинно — до отправки сминтить
   `token = secrets.token_urlsafe(9)`, сохранить пару через
   `pending_repo.put_review_token(token, link)`, собрать
   `kb = admin_alerts.build_dedup_review_keyboard(token)` и передать `reply_markup=kb`
   в тот самый вызов `send_admin_notification`.
4. Когда `REVIEW_BUTTONS_ENABLED` ложно — вызов остаётся прежним: без токена, без
   записи в `bot_state`, без `reply_markup`. Текст алерта (`alert_cross_source_dupe`)
   и якоря вроде «Похож на дубль» не менять.
5. Написать интеграционные тесты в `tests/test_integration.py` (см. TDD Anchor),
   переиспользуя существующий харнесс `TestCrossSourceDedup` для триггера soft-flag.

  несёт только вызов E014; остальные вызовы `send_admin_notification` — без кнопок.

## Details

**Files:**
- `news_bot.py`:
  - **Флаг (~L130, рядом с `DEDUP_SERIES_ENABLED`).** Сейчас `DEDUP_SERIES_ENABLED`
    парсится как `os.getenv("DEDUP_SERIES_ENABLED","1").strip().lower() not in ("0","false","no","off")`
    (default ON). Ввести `REVIEW_BUTTONS_ENABLED` **зеркально, но default OFF** —
    истинно только на on-словах: `os.getenv("REVIEW_BUTTONS_ENABLED","").strip().lower() in ("1","true","yes","on")`.
    Имя env-переменной обязано совпадать с именем константы (та же логика, что описана
    в комментарии `DEDUP_SERIES_ENABLED`: дрейф const↔env → «тихий» no-op на деплое).
  - **Импорт `secrets`** (stdlib) в блок импортов L7-17, если его там нет (сейчас нет).
  - **Send site (`job()`, ветка `if decision == 'flag':` → `if alerted:`, ~L2374-2397).**
    Сейчас там `send_admin_notification(admin_alerts.alert_cross_source_dupe(new_link=link, ...))`
    внутри `try/except`, а следом `pending_repo.mark_pair_pinged(...)`. Переменная `link`
    уже в области видимости (assign на L2279 `link = entry.get('link')`). Изменение:
    когда `REVIEW_BUTTONS_ENABLED` истинно — перед отправкой сминтить token, вызвать
    `pending_repo.put_review_token(token, link)`, собрать `kb` и добавить `reply_markup=kb`
    в аргументы `send_admin_notification`. Флаг читать как bare-name модуля
    (`REVIEW_BUTTONS_ENABLED`), чтобы тесты монкипатчили `news_bot.REVIEW_BUTTONS_ENABLED`.
- `tests/test_integration.py`: добавить класс `TestDedupReviewButtons`, переиспользуя
  базу/харнесс soft-flag (`_seed_published`, `_make_entry`, мок фидов/статьи, мок
  `news_bot.send_admin_notification`). В тесте вытащить E014-вызов из
  `mock_admin.call_args_list` (тот, у кого `args[0]` содержит `'[E014]'`), взять
  `call.kwargs['reply_markup']`, распарсить `callback_data` кнопок, извлечь token из
  `dd:c:<token>` и проверить `get_review_token_link(token)`.

**Dependencies:**
- Task 1 — `put_review_token` / `get_review_token_link` (`pending_articles_repo.py`).
- Task 2 — `build_dedup_review_keyboard` (`admin_alerts.py`) + keyword-only
  `reply_markup=` в `send_admin_notification`.
- Пакеты новые не нужны: `secrets` — stdlib; `python-telegram-bot` уже даёт
  `InlineKeyboardMarkup`.

**Edge cases:**
- Флаг ВЫКЛ — строго no-op: ни `secrets.token_urlsafe`, ни `put_review_token`, ни
  `reply_markup`. Проверить, что в `bot_state` нет `review_token:*` после прогона.
- Rate-limited soft-flag (`alerted == False`): пинг не отправляется — значит и токен
  не минтим, и кнопки не вешаем (минт/put держим внутри `if alerted:`).
- Прочие алерты (E015/E016/E006/…): `reply_markup` им не передаём — тест это фиксирует.
- Монкипатч: флаг читается как module-global в момент вызова, поэтому
  `patch('news_bot.REVIEW_BUTTONS_ENABLED', True/False)` доходит до send-site.

**Implementation hints:**
- Разбор флага — зеркало `DEDUP_SERIES_ENABLED`, но default OFF (on-words only). Не
  копировать логику «not in off-words» дословно — это дало бы default ON.
- `put_review_token(token, link)` + сборку `kb` разумно держать внутри существующего
  `try` E014-блока, чтобы сбой записи/сборки логировался как «Failed to send E014
  notification», а не ронял публикацию (контракт «dedup never blocks publishing»).
- Текст алерта не трогать: `alert_cross_source_dupe` и его якоря («Похож на дубль»)
  остаются как есть — иначе ломаются substring-тесты.
- Не заводить кнопки под E015 (`alert_cross_source_blocked`) и E016
  (`alert_dedup_degraded`) — это соседние вызовы в том же `job()`.
