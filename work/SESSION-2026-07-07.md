the OLD NL VPS via scp + `sudo systemctl restart news_bot.service`. Since the NL
prod bot is stopped+disabled, that `restart` would REVIVE it → double-post. So a
naive `dev→main` push was unsafe.

**Fix (this session):** disarmed `deploy.yml` ON `dev` (the default branch —
GitHub evaluates `workflow_run` against the default branch's copy):
- removed the `workflow_run` trigger → left `workflow_dispatch` only;
- hard-guarded the job with `if: false` (even manual dispatch is a no-op);
- deprecation header + TODO to rewrite for the Docker/Moscow host.

`news_bot_test.service`), which legitimately still lives there. A `dev` push
re-triggers it (normal; test channel only, no prod impact).
