# Task 2: Publication-watch classifier

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Создать единственный stdlib-only классификатор свежести публикаций Telegra.ph, который используют и тесты, и scheduled workflow. Классификатор должен получать явный timezone-aware clock, один раз переводить его в Europe/Moscow и возвращать ровно одно из трёх состояний: `fresh`, `stale` или `inconclusive`.

В этой задаче также закрепляется реальный CLI-контракт модуля: bounded-чтение evidence из stdin, один verdict в stdout и отсутствие исходного payload или token-shaped данных в stderr. Интеграция модуля в `.github/workflows/uptime.yml` выполняется отдельно в Task 4; текущий workflow в этой задаче не изменять.

## What to do

1. Сначала добавить unit- и subprocess-тесты полной boundary/calendar/inconclusive-матрицы и убедиться, что они падают из-за отсутствующего `publication_watch.py`.
2. Создать публичный тип `PublicationState` и чистую функцию `classify_telegraph_response(body: str, now: datetime)`, строго валидирующую Telegraph JSON, первую страницу и suffix даты в её path.
3. Реализовать MSK-правила свежести: вчерашняя страница свежа до 20:59 включительно и stale с 21:00; дата старше вчерашней stale; same-day fresh; перенос на предыдущий год допустим только для декабрьского suffix при текущем январе.
4. Все невалидные, отсутствующие, неоднозначные или ресурсоопасные входы переводить в `inconclusive`, не раскрывая body в выводе или диагностике.
5. Добавить workflow-compatible entry point: читать stdin с жёстким пределом 1 MiB плюс один sentinel byte и печатать ровно один tri-state verdict.
6. Прогнать focused-тесты и точный smoke-check из tech-spec без сети и секретов.
7. Соблюдать изоляцию параллельной Wave 1: изменять только `publication_watch.py`, `tests/test_publication_watch.py` и task-unique артефакты внутри `work/publication-silence-recovery/logs/working/task-2/`. `decisions.md`, `user-spec.md`, `tech-spec.md` и все остальные файлы доступны только для чтения.
8. После проверок и ревью записать краткий handoff в `work/publication-silence-recovery/logs/working/task-2/completion-summary.json` по exact shared schema из tech-spec: `task` (number), `status` (`done` или `blocked`), `summary` (1–3 предложения), `commit` (SHA или `null`), `reviews` (массив объектов `reviewer`/`round`/`status`/`report-path`), `verification` (массив объектов `command`/`result`) и `proposedDeviation` (`null` или объект `reason`/`impact`/`decision-needed`). Этот отчёт предназначен для зависимой Task 5, которая единолично консолидирует решения Tasks 1–5 в `decisions.md`.
9. Если обнаружено материальное отклонение от утверждённых user/tech specs, остановить расходящуюся реализацию, отметить задачу blocked и эскалировать предложение feature lead через task-unique handoff. Не редактировать утверждённые спецификации в этой задаче.

## Acceptance Criteria

- [ ] `publication_watch.py` не имеет сторонних зависимостей и экспортирует `PublicationState = Literal['fresh', 'stale', 'inconclusive']` и `classify_telegraph_response(body: str, now: datetime) -> PublicationState`.
- [ ] Функция принимает только aware clock, один раз переводит его в `Europe/Moscow` и не смешивает дату одного timezone с часом другого.
- [ ] Payload с обязательной формой `{"ok": true, "result": {"pages": [{"path": "...-MM-DD"}]}}` и валидной датой участвует в freshness-решении; лишние API-поля допустимы, а malformed, missing и unexpected shapes возвращают `inconclusive`.
- [ ] Same-day возвращает `fresh`; вчера возвращает `fresh` до 20:59 МСК и `stale` начиная с 21:00; любая однозначная дата старше вчерашней возвращает `stale`.
- [ ] Декабрьский suffix относится к предыдущему году только при текущем январе; любой другой future `MM-DD`, невозможная дата и неоднозначный leap-day возвращают `inconclusive`.
- [ ] Чрезмерно глубокий JSON/`RecursionError` и любые штатные ошибки декодирования не прерывают CLI и дают `inconclusive`.
- [ ] CLI измеряет предел по входным bytes, читает не более 1 MiB + 1 sentinel byte, принимает evidence ровно 1 MiB и отклоняет 1 MiB + 1 byte как `inconclusive` до JSON decode.
- [ ] Для `fresh`, `stale` и `inconclusive` CLI завершается workflow-compatible образом и пишет в stdout только `<state>\n`; raw evidence, token-shaped fixtures и traceback не попадают в stderr.
- [ ] Тесты не используют сеть, реальные Telegraph/Telegram данные или production secrets; `.github/workflows/uptime.yml` в этой задаче не изменён.
- [ ] Единственные mutable targets задачи — `publication_watch.py`, `tests/test_publication_watch.py` и task-unique review/completion artifacts в `work/publication-silence-recovery/logs/working/task-2/`; `decisions.md`, `user-spec.md` и `tech-spec.md` не изменены.
- [ ] `logs/working/task-2/completion-summary.json` точно соответствует shared schema: `task` — number; `status` — только `done` или `blocked`; `summary` — 1–3 предложения; `commit` — SHA или `null`; `reviews` — массив объектов только с `reviewer`, `round`, `status`, `report-path`; `verification` — массив объектов только с `command`, `result`; `proposedDeviation` — `null` либо объект только с `reason`, `impact`, `decision-needed`.
- [ ] Материальное расхождение со спецификацией не реализовано молча: задача остановлена и эскалирована как blocked через task-unique handoff; approved specs остаются неизменными, а Task 5 получает данные для последовательной записи в `decisions.md`.

## Details

**Files:**
- `publication_watch.py` — новый stdlib-only pure classifier и CLI entry point; файла сейчас нет.
- `tests/test_publication_watch.py` — новый unit/subprocess suite; файла сейчас нет.
- `.github/workflows/uptime.yml` — текущая реализация разбирает Telegraph body inline и сводит fresh/skipped/API error к boolean `ok`; использовать как контекст, не редактировать до Task 4.

**Write ownership:** задача может изменять только `publication_watch.py`, `tests/test_publication_watch.py` и собственные JSON-артефакты под `work/publication-silence-recovery/logs/working/task-2/`. В этот каталог входят reviewer reports и exact handoff `work/publication-silence-recovery/logs/working/task-2/completion-summary.json`. Нельзя изменять `work/publication-silence-recovery/decisions.md`, `user-spec.md`, `tech-spec.md`, workflow, Project Knowledge или любые иные файлы.

**Completion handoff:** `completion-summary.json` должен быть самодостаточным машинночитаемым пакетом для Task 5 и использовать только exact shared fields: `task` (number); `status` (`done` или `blocked`); `summary` (1–3 предложения); `commit` (SHA или `null`); `reviews` (массив объектов `reviewer`, `round`, `status`, `report-path`); `verification` (массив объектов `command`, `result`); `proposedDeviation` (`null` либо объект `reason`, `impact`, `decision-needed`). `report-path` указывает на соответствующий task-unique reviewer JSON. При материальном отклонении `status` равен `blocked`, `commit` может быть `null`, реализация не продолжается за рамками approved spec, а `decision-needed` фиксирует требуемое решение для feature lead. Task 5 является единственным writer `decisions.md` для Tasks 1–5 и переносит туда согласованный краткий итог по этому handoff.

**Dependencies:** внешних пакетов и task-зависимостей нет. Использовать только Python stdlib (`datetime`, `json`, `re`, `sys`, `typing`, `zoneinfo` по необходимости). Публичный контракт этой задачи будет потребителем Task 4.

**Edge cases:** timezone-aware `now` с любым offset; UTC→MSK rollover; январь после декабрьской публикации; 29 февраля в високосном и невисокосном году; path с дополнительным текстом до конечного `-MM-DD`; JSON primitives вместо объектов; empty/heterogeneous pages; UTF-8 boundary и multibyte symbols около лимита; decoder recursion failure.

**Implementation hints:**
- Использовать один `ZoneInfo("Europe/Moscow")` conversion внутри pure function; naive clock считать неубедительным evidence, а не исключением для caller-а.
- Валидировать обязательные контейнеры и значения строго, включая `ok is True`, первую страницу и конечный suffix path; допустимые дополнительные API-поля игнорировать и не угадывать год вне принятого Dec→Jan правила.
- Держать лимит входа в одной именованной константе. Для точного byte-boundary CLI читать binary stdin не более лимита плюс один byte, а затем безопасно декодировать UTF-8.
- Ловить ожидаемые parsing/date/Unicode/recursion ошибки и возвращать `inconclusive`; не логировать body, исключение с body или traceback.
- Сохранить CLI минимальным и детерминированным: все три состояния являются нормальными verdict-ами, а не ошибочными строками. Не добавлять env-переменную для подмены времени и не принимать Telegraph token.
- Subprocess-тесты должны запускать реальный `publication_watch.py`, вычисляя representative path относительно текущей московской даты там, где verdict зависит от wall clock.
