# Task 9: Pre-deploy QA

## Required Skills

Перед выполнением задачи загрузи:

- `/skill:pre-deploy-qa` — [skills/pre-deploy-qa/SKILL.md](../../../.claude/skills/pre-deploy-qa/SKILL.md)

## Description

Выполнить финальную offline-приёмку `publication-silence-recovery` после завершения всех implementation и audit tasks. QA должен доказать, что scheduler/review и publication-watch contours совместно закрывают утверждённые user/technical acceptance criteria, не ломают полный regression suite и проходят repository quality gates.

Machine-readable QA-артефакт — `work/publication-silence-recovery/logs/working/pre-deploy-qa-report.json`. В нём фиксируются фактические команды, счётчики, evidence по каждому AC, findings и post-deploy handoff по exact schema pre-deploy-qa agent. После чтения параллельных audit reports Task 9 также единолично обновляет `decisions.md` краткими linked summaries за Tasks 6, 7, 8 и собственный QA; implementation не исправляет, не мержит и не разворачивает изменения.

## What to do

1. Подтвердить, что задачи 6, 7 и 8 завершены, прочитать все три JSON audit-отчёта и `deployment.md`, включить каждый незакрытый finding в финальную QA-оценку и сверить activation/rollback claims с фактической single-production/manual-rollout моделью.
2. Запустить focused scheduler/repository/callback/watcher/workflow suites и зафиксировать totals, passed, failed и skipped.
3. Запустить полный `tests/` suite и зафиксировать точный итог без выборочного игнорирования failures.
4. Запустить pre-commit только на feature-файлах, затем `git diff --check` и read-only status inspection. Если hook переписал файл, не включать это молча в QA: зафиксировать как failure и вернуть на implementation/fix flow.
5. Сопоставить каждый критерий из user-spec и tech-spec с `passed`, `failed` или `not_verifiable` и привести конкретное evidence: test node id + result, code/workflow path или audit finding. Не засчитывать import/static-existence check как evidence для behavioral AC.
6. Проверить coverage по файлам фичи: scheduler helper, atomic repository snapshot, `news_bot.job()`/callbacks, watcher classifier/CLI и workflow должны иметь тесты, которые действительно проходят изменённые branches и проверяют row/alarm state, а не только mock call count.
7. Проверить все краевые случаи из user-spec: release между slots/после cutoff, cancel/reject/silence, dual gate, restart, mixed backlog, defer expiry, watcher MSK/Dec-Jan/invalid evidence, snapshot/classifier failure и secret/log isolation.
8. Создать `logs/working/pre-deploy-qa-report.json` по exact schema: `status`, `summary`, `testSuite`, `acceptanceCriteria`, `findings`, `deferredToPostDeploy`. Писать plain JSON без Markdown fences; не выдавать живую проверку за выполненную.
9. Явно оставить pending для пользователя: merge, production rebuild/restart, ручную публикацию и natural-article/Telegram/Telegraph/GitHub-issue verification.
10. После формирования JSON последовательно дополнить `decisions.md`: краткие summaries со ссылками на `logs/audit/code-audit.json`, `logs/audit/security-audit.json`, `logs/audit/test-audit.json`, затем собственный QA summary со ссылкой на `logs/working/pre-deploy-qa-report.json`. Не копировать findings dumps; Task 9 является единственным writer общего decisions-файла для параллельных Audit/Final contours.

## Acceptance Criteria

- [ ] Все три audit-отчёта прочитаны; каждый finding отражён в QA, ни один unresolved critical/major не скрыт зелёным статусом.
- [ ] Focused scheduler/repository/callback/watcher/workflow suites прошли; точные totals, passed, failed и skipped записаны в отчёт.
- [ ] Полный `tests/` suite прошёл без failures; точные счётчики записаны, skipped не скрыты.
- [ ] Scoped pre-commit и `git diff --check` прошли; hooks не оставили необъяснённых перезаписей или unrelated changes.
- [ ] Каждый user-spec и tech-spec AC имеет статус и конкретное evidence; behavioral criteria не обоснованы shallow/import-only tests.
- [ ] Каждый изменённый production contour имеет соответствующий behavioral test; scheduler timelines утверждают exact SQLite row identity/state, workflow tests — три alarm transitions и secret/outcome gates.
- [ ] Все edge cases user-spec и tech-spec либо проверены, либо явно отмечены `not_verifiable` с причиной и post-deploy steps.
- [ ] `logs/working/pre-deploy-qa-report.json` является валидным JSON и содержит exact top-level schema: `status`, `summary`, `testSuite`, `acceptanceCriteria`, `findings`, `deferredToPostDeploy`.
- [ ] `summary` содержит `totalChecks`, `passed`, `failed`, `notVerifiable`, `criticals`, `majors`, `minors`; `testSuite` содержит `status` и точные details focused/full runs; все counts сходятся с criteria/findings.
- [ ] Каждый acceptance entry содержит `criterion`, `status: passed|failed|not_verifiable`, конкретное `evidence`; каждый finding — `severity`, `title`, `expected`, `actual`, `reproduction`; каждый deferred entry — `criterion`, `reason`, `verificationCondition`, `verificationSteps`.
- [ ] Overall status не `passed`, если есть failed tests, failed AC или critical finding; major findings не игнорируются и явно эскалируются.
- [ ] `deployment.md` прочитан до оценки activation/rollback: workflow merge и будущий manual runtime Docker rollout не смешаны, no-deploy window и отсутствие staging сохранены в handoff.
- [ ] `decisions.md` обновлён только Task 9 после завершения Tasks 6–8: добавлены короткие linked summaries для code/security/test audit JSON и собственного pre-deploy QA JSON, без параллельных shared writes и findings dumps.
- [ ] Merge, deploy, Docker rebuild/restart, production DB mutation, live SSH/curl, Telegram/Telegraph/LLM/GitHub action и тестовая публикация не выполнялись.

## Details

**Files:**

- `work/publication-silence-recovery/logs/working/pre-deploy-qa-report.json` (new) — создать единственный полный QA report как plain JSON. Exact schema из `.claude/agents/pre-deploy-qa.md`: `status: passed|failed`; numeric summary; testSuite status/details; acceptance criteria array; findings array; deferredToPostDeploy handoff array.
- Этот path из amended tech-spec и pre-deploy-qa agent заменяет generic skill path `logs/working/qa-report.json`. Дополнительный Markdown QA report или второй JSON не создавать.
- `work/publication-silence-recovery/decisions.md` — shared summary file; Task 9 пишет его только после завершения параллельных Tasks 6/7/8 и является единственным writer для их четырёх итоговых entries.
- Production files и tests из Context читаются для evidence и coverage и не меняются в QA-задаче.
- `publication_watch.py`, watcher tests и audit reports могут ещё не существовать при декомпозиции; к моменту выполнения Task 9 они обязаны быть артефактами completed dependencies; отсутствие — QA blocker.

**Dependencies:**

- Tasks 6, 7 и 8 — code, security и test audits. Они зависят от implementation/documentation contour, поэтому их завершение является косвенным гейтом Tasks 1–5.
- Audit tasks оставляют `decisions.md` read-only и передают summaries через свои JSON reports; последовательная Task 9 владеет их консолидацией, устраняя shared-write conflict.
- Новых пакетов, credentials, live services и migration нет.

**Edge cases:**

- `pytest -q` может показать skipped; каждый skip нужно объяснить, а не считать молча покрытием.
- Passing mock-only test не доказывает SQLite transition или workflow alarm transition; evidence должно проверять exact resulting state.
- Existing unrelated dirty-worktree changes не считаются finding фичи, но их нельзя переписывать или включать в feature diff.
- Pre-commit hooks могут менять whitespace; QA после запуска обязан перепроверить status и не выдавать rewritten source за QA-only artifact.
- Live natural-article behavior и GitHub issue/Telegram delivery неверифицируемы offline и должны попасть в deferred handoff, а не в `passed`.
- Отсутствие live E2E не finding: оно явно принято user/tech specs из-за единственного production-канала.

**Implementation hints:**

- Не переписывать test output по памяти: копировать точные totals и итог из фактического запуска.
- Для passed AC указывать хотя бы один test node id и описать, какой production branch/state он проходит.
- Finding записывать с severity, expected, actual и concrete reproduction; пустой findings section явно помечать `None`.
- Для каждого `not_verifiable` записать criterion ID/text, причину, условие и конкретные post-deploy steps.
- Status отчёта: `failed` при любом critical; failed tests или failed AC также несовместимы с `passed`. Major findings не скрывать: включить в summary и вернуть на fix flow.
- `deferredToPostDeploy` всегда должен быть массивом, даже если пуст; live natural-article/GitHub-issue/Telegram checks из approved spec ожидаемо формируют конкретные deferred entries.
- При консолидации `decisions.md` брать verdict/counts из каждого JSON `summary`/`metrics`, добавлять ссылку на полный report и не переписывать результаты параллельных аудиторов своими словами сверх 1–3 предложений.
- QA не запускает live `curl`, SSH, Docker, Telegram, Telegraph, LLM, GitHub workflows/issues и не создаёт test article.
