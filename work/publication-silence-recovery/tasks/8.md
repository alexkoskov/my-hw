# Task 8: Test Audit

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:test-master` — [SKILL.md](../../../.claude/skills/test-master/SKILL.md)

## Description

Провести read-only аудит качества тестов фичи `publication-silence-recovery`. Проверить не только наличие перечисленных кейсов, но и способность тестов поймать реальный регресс: потерю следующего fixed slot после пустого read, публикацию не той SQLite-строки или повтор head row, обход второго gate, московское полуночное oscillation, ложный recovery на `inconclusive` и запуск repository classifier после failed checkout.

Фокус аудита — meaningful behavioral assertions, реальные tempfile-SQLite transitions, полная boundary/error matrix, разумный test pyramid, отсутствие mock-only false confidence, redundancy и fragmentation. Единственный изменяемый артефакт — `work/publication-silence-recovery/logs/audit/test-audit.json`; тесты и production files в этой задаче не исправлять.

## What to do

1. Дождаться завершения и fixes Tasks 3–4, затем прочитать approved user/tech specs, task TDD anchors, decisions и все шесть test files из Context Files целиком.
2. Составить traceability map от десяти user acceptance criteria и технических scheduler/watcher contracts к конкретным тестам и assertions; отсутствие или ложное покрытие оформить finding.
3. Для каждого нового/изменённого теста применить litmus test: удалить мысленно load-bearing production строку/branch и определить, упадёт ли тест по содержательному assertion, а не только из-за mock wiring.
4. Проверить scheduler unit/repository tests на границы fixed times и атомарную mutually-exclusive/exhaustive partition, включая elapsed defer и dual-gate held dominance.
5. Проверить real-SQLite integration timelines E014/E036: первый empty read, реальный callback state transition, следующий slot, точная row identity, движение в `published_articles`/удаление из pending, отсутствие дублей и отсутствие callback-side publish.
6. Проверить negative/error/observability timelines: cancel/reject, silence/expiry, mixed gates, mixed publishable+withheld rows, after-19:30 next-day selection, ordinary queue/restart, snapshot fallback/fallback failure, plan/recap/heartbeat truthfulness.
7. Проверить watcher unit/subprocess matrix и static workflow contracts: MSK/date/year/leap/future/invalid/size/recursion inputs, exact CLI output, checkout/action/secret/outcome gates и содержательный tri-state alarm no-op.
8. Оценить redundancy/fragmentation: same-shaped values должны быть параметрами/subTests одного поведения; отдельные functions оправданы только разным поведением или materially different setup.
9. Запустить focused suite offline, записать валидный JSON-отчёт по exact test-reviewer schema и согласовать status/metrics с findings.

## Acceptance Criteria

- [ ] Все шесть test files прочитаны целиком после завершения зависимостей; отсутствующий `test_publication_watch.py` или `test_uptime_workflow.py` является блокирующим coverage gap, а не заменяется обещанием из tech-spec.
- [ ] Для каждого US-AC1…US-AC10 и каждого load-bearing технического failure contract найден конкретный test + assertion либо создан prescriptive `missing_coverage` finding.
- [ ] Litmus test применён ко всем feature-specific test behaviours; `metrics.litmusTest.checked/passed/failed` отражают фактическое число проверенных behaviors и сходятся арифметически.
- [ ] Fixed-time helper tests закрепляют remaining-time/grace/restart/after-cutoff policy и доказывают, что existing `compute_fixed_slots(n)` slicing/carry-over contract не изменился.
- [ ] Repository tests используют реальную tempfile SQLite и доказывают, что один snapshot partition взаимоисключающий и exhaustive: publishable, future-deferred, elapsed-deferred, held и dual-gate row учитываются ровно один раз.
- [ ] E014 и E036 timeline tests воспроизводят пустой первый read и реальный keep/approve transition между слотами, а затем assert exact released link и фактическое queue/published-table состояние, не только `_fallback_publish.call_count`.
- [ ] Cancel/reject/silence/expiry/mixed-gate tests доказывают отсутствие публикации и правильное конечное DB-состояние; callback никогда не используется как publisher.
- [ ] Mixed publishable+withheld test доказывает разные row identities в 10:00 и 15:00, отсутствие повторного выбора head и ровно одно движение каждой опубликованной строки.
- [ ] After-19:30 test доказывает сохранение pending row и её выбор в 10:00 следующего дня без callback-side publish; ordinary empty/N=1 и restart-at-16:00 regressions не ждут фиктивные opportunities.
- [ ] Snapshot error tests отличают aggregate failure от fallback failure, проверяют ровно один `count_pending()` fallback, отсутствие release opportunities/gate bypass и propagation второй ошибки.
- [ ] Plan/carry-over/recap/dry-spell/heartbeat assertions проверяют результирующие values/calls так, чтобы empty opportunity не выглядела publication outcome или promised slot.
- [ ] Watcher matrix содержит same-day, yesterday 20:59/21:00, older at 00:00/02:59/03:00, Dec→Jan, valid/impossible leap-day, non-December future suffix, malformed/API/shape/path/naive inputs, exact 1 MiB/+1 byte и recursive JSON.
- [ ] Real CLI subprocess tests покрывают `fresh`, `stale`, `inconclusive`, exact one-line stdout, workflow-compatible exit и отсутствие raw/token-shaped evidence в stderr; tests не зависят от сети, secrets или production time race.
- [ ] Workflow tests проверяют named step contracts и cross-step semantics, а не только свободные substrings: immutable checkout/default ref, success-outcome execution gate, bounded temp evidence, secret confinement, tri-state validation и `inconclusive` без raise/resolve.
- [ ] Host contour test доказывает независимый SSH verdict и host-down suppression публикации; удаление checkout failure tolerance или no-op branch должно ломать соответствующий test.
- [ ] Не обнаружены meaningless/no-assertion/mock-return tests; каждый test защищает отличимое поведение, а same-shaped input matrices не раздроблены на десятки функций.
- [ ] Test pyramid оценён с учётом проекта: pure unit + real-SQLite integration + static workflow contract являются целевыми слоями, а отсутствие live E2E является утверждённым production-only safety constraint, не автоматическим finding.
- [ ] `test-audit.json` валиден, следует exact schema и содержит prescriptive findings с конкретным replacement approach/assertions/mock changes; статус и metrics согласованы.
- [ ] Task 8 не меняет tests, implementation, workflow или PK; допустимы только audit report и стандартный post-completion summary в `decisions.md`.

## Details

**Files:**
- `work/publication-silence-recovery/logs/audit/test-audit.json` — новый единственный audit deliverable. Создать `logs/audit/` при необходимости и писать plain JSON без Markdown fences.
- `tests/test_compute_fixed_slots.py`, `tests/test_pending_articles_repo.py`, `tests/test_job_distributed_publish.py`, `tests/test_integration.py` — существующие suites с историческим покрытием; оценить только feature-specific additions и их взаимодействие с regression seams.
- `tests/test_publication_watch.py`, `tests/test_uptime_workflow.py` — отсутствуют на момент декомпозиции и должны быть созданы зависимыми задачами до запуска аудита.

**Dependencies:** Task 3 завершает scheduler/SQLite/callback integration tests, Task 4 завершает static workflow tests и зависит от classifier suite Task 2. Аудит можно выполнять параллельно с Code/Security Audit: все три создают разные JSON reports и не меняют тесты/код.

**Report schema:** использовать exact contract из `.claude/agents/test-reviewer.md`:
- `status`: `passed | needs_improvement | failed`.
- `summary`: краткий общий assessment с наиболее важным coverage/litmus выводом.
- `findings[]`: `severity: critical|major|minor`, `category: empty_test|mock_only|missing_coverage|pyramid_violation|excessive_mocking|anti_pattern|wrong_test_type|redundant_testing`, точный `location`, `issue`, prescriptive `recommendation`.
- `metrics`: `filesReviewed`; `litmusTest.checked/passed/failed`; `coverageAssessment: insufficient|adequate|excellent`; `pyramidBalance.unit/integration/e2e/assessment: healthy|inverted|unbalanced`.
- Status matrix: `passed` при 0 critical/major; `needs_improvement` при 0 critical и 1–2 major либо multiple minor; `failed` при ≥1 critical или ≥3 major.

**Edge cases:** callback commit между empty read и следующим slot; same row с hold+defer; mixed snapshot row identity; expiry через секунды после 10:00; callback after 19:30; fallback itself fails; watcher at MSK/UTC date rollover; Jan/Dec and leap-day; byte vs character evidence limit; recursive decoder; checkout partial/failure; classifier stdout with whitespace/extra lines; publication issue open/closed on inconclusive; simultaneous host-down.

**Implementation hints:**
- При litmus review указывать конкретную load-bearing строку/branch, удаление которой тест обязан поймать: slicing remaining slots, empty `continue`, held-dominant SQL CASE, callback clear, DB move, year inference, outcome gate или no-op branch.
- Mock call count допустим как вторичный assertion, но не как единственное доказательство публикации. Для scheduler timelines требовать exact link и реальное pending/published state.
- Отличать static workflow contract от пустого substring test: извлекать named step/branch boundaries и проверять связи producer output → consumer env/outcome → alarm transition.
- Не требовать live E2E, workflow dispatch, SSH, Telegraph или Telegram: approved scope сознательно исключает единственный production channel и внешние state changes.
- Same-shaped calendar/payload values должны быть `pytest.mark.parametrize` или `unittest.subTest`; отдельная функция оправдана другим expected behavior или materially different setup.
- Каждый finding обязан предлагать конкретную замену: test type, setup, assertions и какие mocks убрать/оставить. Общая фраза «добавить тест» недостаточна.
- Если findings отсутствуют, оставить массив пустым, metrics честными и явно подтвердить load-bearing tests в summary; не создавать cosmetic issues ради заполнения отчёта.
