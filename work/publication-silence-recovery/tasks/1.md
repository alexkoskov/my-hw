# Task 1: Scheduler planning primitives

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Создать единый planning-input contract для Task 3. Он состоит из двух взаимодополняющих production-примитивов: один отвечает, какие fixed-time opportunities ещё допустимы, второй — есть ли в очереди атомарно наблюдаемая причина эти opportunities сохранить. Task 3 не может безопасно интегрировать ни одну половину отдельно: opportunities без atomic backlog snapshot могут открыться из неполного состояния, а snapshot без общего time helper не закрывает production-гонку.

Первая половина контракта — чистый helper, возвращающий все ещё допустимые сегодня фиксированные времена 10:00, 15:00 и 19:30 с five-minute grace. `compute_fixed_slots()` переиспользует его, но сохраняет публичный API, лимит по `n` и `carry_over`.

Вторая половина — `pending_articles_repo.get_schedule_backlog_counts()`, который одним SQLite statement возвращает атомарный снимок `(publishable, deferred, held)`. Content hold доминирует над любым `publish_after`; future defer без hold считается deferred; NULL или elapsed defer без hold — publishable. Два production-файла и два соответствующих тестовых файла — это две source/test пары одного контракта, а не четыре несвязанных scope. Схема БД и `news_bot.job()` в этой задаче не меняются; integration выполняет Task 3 только после готовности обеих половин.

## What to do

1. До production-кода добавить RED-тесты для полного списка remaining opportunities и атомарной partition pending-строк. Убедиться, что они падают из-за отсутствующих API.
2. Добавить `remaining_fixed_slots(now, daily_times=DAILY_PUBLISH_TIMES, grace_minutes=5) -> list[datetime]` в `compute_publish_slots.py`. Helper возвращает все ещё допустимые fixed times текущей даты в timezone `now`.
3. Перевести `compute_fixed_slots()` на helper как единственный источник grace/cutoff-арифметики. Сохранить сигнатуру, `n <= 0`, cap по `n`, timezone-контракт и `carry_over`.
4. Добавить `get_schedule_backlog_counts() -> tuple[int, int, int]` в `pending_articles_repo.py`: одно short-lived connection, один aggregate `SELECT`, результат `(publishable, deferred, held)` и `(0, 0, 0)` для пустой таблицы.
5. Закрепить grace/restart/cutoff/custom-times/tz-aware границы и NULL/future/elapsed/hold/dual-gate категории на real tempfile SQLite.
6. Прогнать оба фокусных тестовых файла и сохранить все existing scheduling/repository contracts зелёными.

- [ ] SQLite schema, existing queue APIs и `news_bot.py` не изменены; SQL static/parameterized, `TestSqlAudit` зелёный, новых packages нет.

## Details

**Files:**
- Четыре пути образуют две пары «production primitive ↔ matching unit tests»: `compute_publish_slots.py` ↔ `tests/test_compute_fixed_slots.py` и `pending_articles_repo.py` ↔ `tests/test_pending_articles_repo.py`. Обе пары вместе образуют один planning boundary между SQLite state и fixed-time policy; вне этой границы задача не меняет orchestration.
- `compute_publish_slots.py` — вынести из current `compute_fixed_slots()` построение/sorting today datetimes и grace filtering; dormant `compute_publish_slots()` не трогать.
- `pending_articles_repo.py` — добавить read-only aggregate рядом с queue-count helpers, не меняя existing API и DDL.
- `tests/test_compute_fixed_slots.py` — импортировать helper и добавить компактные behavior-oriented subTests.
- `tests/test_pending_articles_repo.py` — добавить один real-tempfile класс и проверять resulting partition, а не internal helper calls.

**Dependencies:**
- `depends_on: []`; Wave 1 может идти параллельно с watcher foundation.
- Task 3 потребит оба API как один неделимый input contract: backlog snapshot выбирает, нужны ли release opportunities, а time helper задаёт их единый список. Новых dependencies нет: stdlib, SQLite и existing tests.

**Edge cases:**
- Точно 10:05 ещё включает 10:00; момент позже его исключает. Restart в 16:00 не догоняет 10:00/15:00.
- Empty/custom/unsorted `daily_times`; helper не мутирует input.
- Empty conditional aggregates могут дать SQL `NULL`; API возвращает int zero.
- Future defer + hold считается только held; elapsed defer с hold тоже held.
- SQLite exception пропагирует: fallback — responsibility Task 3.

**Implementation hints:**
- Перенести в helper current verified `datetime.combine` + sorting + grace cutoff; planned API только применяет `n`/carry.
- Для snapshot использовать conditional aggregates внутри одного static `SELECT`; SQLite `CURRENT_TIMESTAMP` совпадает с UTC-форматом `publish_after`.
- Не собирать snapshot из existing трёх API: separate SELECTs возвращают callback race.
