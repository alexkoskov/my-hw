Operator forwarded a `[test] [E011] 🔴 Claude API всё ещё недоступна (1 час)`

## Part 1 — Incident diagnosis (no code change)

**Alert.** `[test] [E011]` outage ping at 10:01 МСК 2026-06-10, plus the
daily `[E008]` plan-of-day.

**External checks all green.** status.claude.com = operational;
status.openrouter.ai = operational, Opus 4.8 available; OpenRouter balance
positive; key `my-hw` (sk-or-v1-7a8…d81) limit not exhausted ($1.96/$5),
not expired. So the outage was NOT Claude, OpenRouter, or billing.

**Root cause — server lost its network.** `journalctl -u news_bot_test.service`
showed, around the outage window:
- `Failed to resolve 'translate.google.com' ([Errno -3] Temporary failure in
  name resolution)` — DNS broken on the VPS.
- `urlopen error [Errno 101] Network is unreachable` — no route at times.
- The Google fallback ALSO failed to resolve `translate.google.com` — both
  primary and fallback dying the same way ⇒ it's the server's link, not any
  provider.

The bot self-recovered: at 10:07 МСК it published the held article via the
(then) Google fallback. By the time we checked, connectivity was back.
`ping 8.8.8.8` / `ping google.com` from the operator's Mac were green (run on
the Mac, not the server — noted for next time).

**Memory written:** `incident_e011_can_be_server_dns.md` — E011 can be a false
attribution; check server connectivity in logs before auditing Claude/OR/billing.

**sudoers gotcha (logged for ops):** `hwbot` may run only the EXACT
`sudo journalctl -u news_bot_test.service` — adding `--since` breaks the
sudoers match. Filter with `| grep | tail` after the pipe instead.

## Part 2 — Change shipped: remove Google fallback, HOLD on outage (`dev`)

**Operator decision.** Google machine-translation is lower quality; better to
wait for the LLM than publish a bad auto-translation. So: when the LLM is
unavailable, **do not Google-translate — HOLD the article and retry until the
LLM recovers.** Operator chose the `/write-code` shortcut + reworded alerts.

### Behavior before → after

| Situation | Before | After |
|---|---|---|
| API-level outage (`ClaudeOutageError`) | 2-ping/2h, then degraded-mode **Google publish** + re-raise; ping #3 flips `fallback_active` → all slots go straight to Google | **HOLD**: record outage event (pings), re-raise BEFORE any publish. Row stays in `pending`, retried next slot/day. No Google. |
| Already-in-fallback (`is_fallback_active`) | skip Claude, route straight to Google | shortcut removed — LLM always attempted (so recovery is detected) |
| Per-article failure (`ClaudeTranscreationError`) | strike → 3 → `failed_articles` (no Google) | **unchanged** — keeps the queue head from wedging on one bad article |
| Startup probe fail | ping E004 + `set_fallback_active(True)` (Google-only day) | ping E004 only; `job()` attempts LLM each slot and holds |
