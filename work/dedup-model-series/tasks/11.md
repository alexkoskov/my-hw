# Task 11: Post-deploy verification (operator-applied)

## Description

Финальная стадия — верификация фичи на живом прод-окружении. Прод — это Docker-контейнер `hw-news-bot` на московском VPS `45.90.216.165` (каталог `/root/hw-news`, БД на bind-mount `/root/hw-news/data/news.db`, `DB_FILE=/data/news.db`). Деплой ручной, вне окна 10:00–20:00 МСК.

**Ключевое ограничение:** Claude НЕ может ходить по SSH на прод (операционку на проде ведёт оператор — Claude готовит, оператор применяет). Поэтому все живые прод-действия (проверка состояния БД, пересборка контейнера, backfill, переключение тумблера) — **operator-applied**: Claude выдаёт оператору точные однострочные команды, оператор запускает и вставляет вывод обратно, Claude сверяет с ожидаемым. Секреты не эхоим; прод-`.env` руками ведёт оператор на московском хосте.

Задача покрывает три группы живых проверок (из tech-spec Task 11, user-spec «Как проверить» → «Пользователь проверяет», и Сценария 8 «деплой + прогрев»):
1. **Предпроверка холодной базы** — `SELECT COUNT(*) FROM published_articles WHERE model_fingerprint IS NOT NULL` (ожидаем ~0: база скопирована со старого NL до фичи дедупа, базовый backfill на ней, скорее всего, не запускался — Risk 3 / Decision 7).
2. **Прогрев после безопасной выкатки** — после пересборки контейнера и `backfill_fingerprints.py --days 30` тот же COUNT должен стать **> 0** (backfill прогрел и базовый car-fingerprint, и новые пары за 30 дней).
3. **2-недельный мониторинг канала @myhwchannel (Telegram-визуал)** — нет повторов «машина+серия»; спот-чек пингов `[E015]` (ложные жёсткие блоки?) и `[E014]` (реально дубли?).

Плюс, по методологии post-deploy-qa: подобрать отложенные критерии из pre-deploy отчёта Task 10 (`deferredToPostDeploy`) и сверить AC1–AC11 (user-spec) + технические AC (tech-spec) против живого поведения. Итог — JSON-отчёт; критерии, требующие 2-недельного окна, помечаются `blocked` с конкретным планом ручной проверки для оператора.

## What to do

Конкретные шаги — ЧТО, не КАК. Не псевдокод.

1. **Прочитать pre-deploy отчёт Task 10** (`logs/working/qa-report.json`, секция `deferredToPostDeploy`) — забрать критерии, которые нельзя было проверить без живого окружения.
2. **Предпроверка холодной базы (operator-applied):** выдать оператору однострочную SSH-команду `SELECT COUNT(...)`; получить вывод; зафиксировать значение (ожидание ~0 = база холодная, подтверждает необходимость backfill).
3. **Сопроводить безопасную выкатку (operator-applied), строго в порядке Сценария 8:**
   - деплой «тёмным» (тумблер `DEDUP_SERIES_ENABLED=0` в прод-`.env`) → пересборка контейнера **вне окна 10:00–20:00 МСК**; схема БД не меняется;
   - разовый `backfill_fingerprints.py --days 30` внутри контейнера (наследует `DB_FILE=/data/news.db`);
   - повторный `SELECT COUNT(...)` → должен быть **> 0**;
   - наблюдение `[E014]`/логов пару дней на свежей базе;
   - затем включить тумблер (`DEDUP_SERIES_ENABLED=1`/убрать оверрайд — дефолт on) + перезапуск, снова вне окна.
4. **Сверить каждый живой AC** (user-spec AC1–AC11 + технические AC tech-spec) с фактическим поведением прода; то, что требует времени/потока статей — пометить `blocked` с планом ручной проверки.
5. **2-недельный спот-чек канала (Telegram-визуал):** просмотреть @myhwchannel на повторы «машина+серия» и пинги `[E015]`/`[E014]`; применить SLA-ориентиры (по distinctive-тиру: 0 видимых дублей + ≤1 ложный жёсткий блок/мес; по широкому тиру — дубли публикуются с `[E014]`, это осознанный компромисс). При превышении порогов — рекомендовать отключить тумблером и разобрать.
6. **Сформировать JSON-отчёт** по Output Format скилла post-deploy-qa; критерии, зависящие от 2-недельного окна, — `blocked` + `manualVerificationPlan` (что смотреть на @myhwchannel, когда, по каким порогам, как откатывать тумблером).

### Operator-applied (живой прод — Claude готовит, оператор применяет)

Прод: `ssh root@45.90.216.165`, каталог `/root/hw-news`, БД `/root/hw-news/data/news.db`, compose-сервис `news-bot`, контейнер `hw-news-bot`. Однострочные команды (секреты не эхоятся):

1. **Предпроверка холодной базы** →
   `ssh root@45.90.216.165 "sqlite3 /root/hw-news/data/news.db 'SELECT COUNT(*) FROM published_articles WHERE model_fingerprint IS NOT NULL;'"`
   → ожидаем ~0 (холодная база — подтверждает Risk 3).
2. **Деплой «тёмным» (вне окна 10:00–20:00 МСК)** — в прод-`.env` `DEDUP_SERIES_ENABLED=0`, затем
   `ssh root@45.90.216.165 "cd /root/hw-news && git pull && docker compose up -d --build"`
   → контейнер `hw-news-bot` пересобран, схема БД не менялась.
3. **Backfill за 30 дней (внутри контейнера, наследует `DB_FILE=/data/news.db`)** →
   `ssh root@45.90.216.165 "cd /root/hw-news && docker compose exec -T news-bot python3 backfill_fingerprints.py --days 30"`
   → сводка в выводе; повтор — no-op (идемпотентно).
4. **Повторный COUNT** — та же команда, что в шаге 1 → теперь **> 0**.
5. **Включить тумблер (вне окна)** — в прод-`.env` `DEDUP_SERIES_ENABLED=1` (или убрать оверрайд), затем
   `ssh root@45.90.216.165 "cd /root/hw-news && docker compose up -d"`
   → правило активно.

### User / Telegram-визуал (2-недельное окно, канал @myhwchannel — оператор смотрит, Claude интерпретирует)

- Просмотреть ленту канала за 2 недели → **нет повторов «машина+серия»** (distinctive-тир).
- Спот-чек пингов `[E015]` в админ-канале → ложные жёсткие блоки? SLA-ориентир: **≤1/мес**; каждый `[E015]` рендерит совпавшую пару + ссылку на прошлую статью.
- Спот-чек пингов `[E014]` → реально дубли по теме/линейке? Широкий тир **публикуется** с флагом (осознанный компромисс тиринга); оператор при желании удаляет вручную.
- **Порог/remedy:** много ложных `[E015]` ИЛИ зашумлённый поток `[E014]` → отключить тумблером (`DEDUP_SERIES_ENABLED=0` + рестарт) и разобрать.

## Details

**Прод-окружение:** Moscow VPS `45.90.216.165` (`ssh root@45.90.216.165`, password auth). Каталог/деплой `/root/hw-news`; состояние на bind-mount `/root/hw-news/data` (`./data:/data`), БД `data/news.db` (`DB_FILE=/data/news.db`). Compose-сервис `news-bot`, контейнер `hw-news-bot`. Хост на UTC, контейнер на `TZ=Europe/Moscow`. Прод-`.env` руками ведёт оператор на московском хосте (не пишется CI). Тестовый бот — отдельный NL-хост `148.135.207.54` (systemd, ветка `dev`), его НЕ трогаем.

**Роль Claude vs оператора:** Claude не ходит по SSH на прод — готовит однострочные команды, оператор запускает и вставляет вывод, Claude сверяет с ожидаемым и ведёт отчёт. Секреты никогда не эхоим; команды выше секретов не печатают.

**Окно деплоя (жёстко):** любая пересборка/рестарт — **вне 10:00–20:00 МСК**. Рестарт сбрасывает единственное in-process дневное расписание (слоты 10:00/15:00/**19:30** МСК) → в окне это ломает публикации.

**Порядок безопасной выкатки (Сценарий 8, Decisions 4 и 7):** pre-check COUNT (~0) → деплой «тёмным» (тумблер выкл) → `backfill --days 30` → повторный COUNT (>0) → наблюдение `[E014]`/логов ~2 дня на свежей базе → включить тумблер + рестарт. Тумблер по дефолту on — «тёмный» деплой нужен именно для первого включения.

**Холодная база (Risk 3 / Decision 7):** прод поднят из снимка `news.db` со старого NL до фичи дедупа; запуск базового backfill на нём не подтверждён → предпроверочный COUNT ожидается ~0. `backfill --days 30` лечит холод: греет и базовый car-fingerprint, и новые пары.

**Dependencies:** Task 10 (pre-deploy QA — весь набор тестов зелёный, калибровка ≥7/8) завершён; runbook в `deployment.md` из Task 6; тумблер `DEDUP_SERIES_ENABLED` из Task 4; расширенный backfill из Task 5.

**Edge cases:**
- Предпроверочный COUNT НЕ ~0 (база оказалась тёплой) → всё равно прогнать `backfill --days 30` ради пар; повторный COUNT должен вырасти либо остаться прежним (идемпотентно) — не блокер.
- Backfill упал/сводка с ошибками → зафиксировать, тумблер НЕ включать, разбирать по логам.
- Всплеск ложных `[E015]` после включения → немедленно тумблер выкл + рестарт (аварийный рубильник), пометить критичный finding.
- 2-недельные критерии нельзя закрыть в один прогон → это нормальный `blocked` с `manualVerificationPlan`, требует follow-up оператора, а не `failed`.

**Implementation hints:** повторно использовать команды/пути из runbook `deployment.md`; сервис в compose называется `news-bot` (ср. `docker compose stop news-bot`), контейнер — `hw-news-bot`; backfill запускать через `docker compose exec` (не с хоста напрямую), чтобы подтянулся контейнерный `DB_FILE=/data/news.db`.
