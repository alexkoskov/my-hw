## Description

Целостный аудит качества кода ВСЕЙ фичи `dedup-model-series` — не одного файла, а всего написанного и изменённого в Task 1–6 как единого целого. Задачи Wave 1–3 создавали каждый свой кусок изолированно (экстракция, алерты, гейт, backfill, калибровка); отдельные ревьюеры внутри тех задач смотрели только свой diff. Эта задача проверяет то, что не видит ни один пофайловый ревьюер: **межкомпонентную согласованность** и **системные инварианты фичи**, где ошибка проявляется только на стыке модулей.

Задача — только анализ. Код не меняется. Результат — audit-отчёт с находками (severity + файл/строка + проблема + предлагаемое исправление). Если найдены проблемы уровня blocker/major, lead этапа (feature-execution) на основании отчёта запускает отдельного fixer'а; сам аудит фиксы не вносит.

Ключевые инварианты для проверки (из tech-spec Decisions и Acceptance Criteria):
- **Согласованность рефактора гейта** (Decision 3): `_check_cross_source_dedup` — тройной вердикт block/flag/pass; block и flag ТЕРМИНАЛЬНЫ, старый 7-дневный set-overlap backstop запускается ТОЛЬКО на pass. Никакого двойного вердикта / двойного пинга за один тик.
- **Полярность fail-safe** (Decision 2): непомеченная/неизвестная серия → **broad** (`_SERIES_DEFAULT_TIER='broad'`), НИКОГДА не distinctive. distinctive только когда серия помечена distinctive В лексиконе И присутствует конкретная модель. `|D` побеждает `|B`.
- **Отсутствие дублирующей инициализации**: `DEDUP_SERIES_ENABLED` объявлена один раз на import-time (как `DB_FILE`), нет повторного `os.getenv` в теле гейта, нет параллельных источников истины для тира/дефолта.
- **Инвариант deploy FILES-массивов** (Decision 6, tech-spec AC): ни один НОВЫЙ first-party import не добавлен в `news_bot.py` без записи во ВСЕ три FILES-массива (`deploy.sh`, `.github/workflows/deploy.yml`, `.github/workflows/deploy_test.yml`). Фича по проекту НЕ должна добавлять новый модуль — если добавила, это находка (риск ImportError-crashloop на тест-боте, класс дефекта из cross-source-dedup Task 10).

## Details

Аудит запускается ПОСЛЕ того, как Task 1–6 записали код. Читать нужно фактическое состояние файлов на момент запуска, а не tech-spec как «как должно быть» — расхождение между spec и кодом само по себе является находкой (сверять с decisions.md: агенты могли зафиксировать легитимные отклонения).

**Files (текущее состояние → что проверять):**
- `model_extractor.py` (~325 стр.) — единственный продюсер pair-ключей. Проверить: bounded-квантификаторы в новых regex (`\s{1,3}`, НЕ `\s+`/`\s*` — ReDoS-safe, как `_MODEL_AFTER_BRAND_RE`); load-time assertion, что канонические имена лексикона не содержат `|`/newline (целостность ключа); `_SERIES_DEFAULT_TIER='broad'`; тир-классификатор distinctive iff tagged-distinctive AND модель present.
- `news_bot.py` (~2612 стр.) — гейт `_check_cross_source_dedup` + `DEDUP_SERIES_ENABLED`. Сердце аудита. Проверить терминальность block/flag; backstop только на pass; single-source-of-truth для toggle (объявлена на import-time один раз, гейт читает `news_bot.DEDUP_SERIES_ENABLED`, а не повторный `os.getenv`); `try/except` вокруг всего блока → `[E016]` + `fp=None` + публикация; кандидаты фетчатся один раз на 30 дней, 7-дневный сабсет выводится в Python; `|D` побеждает `|B` независимо от порядка кандидатов.
- `admin_alerts.py` (~494 стр.) — `[E015]` рендерит matched pair(s) + earlier link (сохранён anchor «Заблокирован дубль»); `[E014]` адаптирован под theme/series-матч (старые model-overlap параметры `overlap_pct`/`n_matches`/`models` НЕ должны фигурировать в theme-only ветке); pure-Russian admin-ping формат (patterns.md).
- `backfill_fingerprints.py` (~306 стр.) — re-select содержит `OR json_extract(model_fingerprint,'$.pairs') IS NULL`; skip-guard требует ключ `pairs`; 30-дн окно; идемпотентность на втором прогоне. `json_extract('$.pairs')` — статический литерал (untrusted-токены живут ВНУТРИ opaque blob, в SQL не попадают).
- `pending_articles_repo.py` (~1007 стр.) — НЕ изменялся; убедиться, что `series`/`pairs` действительно проезжают через `insert_pending`/`move_to_published` без потери (carry-through в `published_articles.model_fingerprint`).

**Dependencies:** зависит от Task 1–6 (весь код фичи должен быть написан). Параллельна Task 8 (security) и Task 9 (test) — три аудита не пересекаются по правкам (все analysis-only), общего ресурса нет.

**Edge cases для проверки в коде:**
- Статья с ОБОИМИ пейрами (distinctive + broad) при любом порядке кандидатов → block, не flag.
- Broad/theme-only матч → flag `[E014]` + публикация + терминальность (старый set-overlap НЕ запускается вторым, ровно один вердикт/пинг, нет `[E015]`).
- pass-ветка (нет общего пейра / нет серии / toggle off) → старый 7-дн backstop запускается и в позитивном кейсе реально блокирует.
- both-empty (нет strict И нет series) → pass/publish.
- Degraded (экстрактор бросает исключение) → `[E016]`, статья публикуется.
- Same-source distinctive («ещё фото»/«mais fotos») → block (any-source в pair-loop); НО backstop остаётся cross-source-only.
- Строка `model_fingerprint` без `pairs`/`series` (не-backfill'нутая) → корректно пропускается в extraction-пути и подхватывается backfill'ом.

**Implementation hints (для аудитора):**
- Читать код как единое целое: сначала продюсер (`model_extractor`), затем все потребители, проверяя, что формат ключа и семантика тира совпадают в каждой точке. Рассинхрон формата ключа между продюсером и потребителем — типичная межкомпонентная находка, которую пофайловый ревьюер не видит.
- FILES-инвариант: `grep` новых `import`/`from ... import` верхнего уровня в `news_bot.py`, затем сверить каждый first-party модуль с тремя FILES-массивами. Ожидание по Decision 6 — новых first-party import'ов нет (лексикон и экстракция живут в уже залистенном `model_extractor.py`). Любой незалистенный новый импорт — blocker.
- Двойной вердикт/пинг: пройти по коду одного тика для broad-матча и убедиться, что после `flag` управление НЕ доходит до вызова старого set-overlap дедупа (нет fall-through).
- Severity: blocker = ломает публикацию/даёт silent hard-block/крашит деплой; major = нарушает инвариант фичи, но обходится; minor/nit = стиль, читаемость, мелкая несогласованность.
- НЕ дублировать security-периметр (ReDoS/SQL/injection в untrusted-токенах — зона Task 8) и глубокий разбор качества тестов (зона Task 9) — при пересечении достаточно короткой отметки со ссылкой на смежный аудит.
