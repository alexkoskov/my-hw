# Task 3: Калибровочная фикстура — 8 пар (реальные дубли + не-дубли)

## Required Skills

- `/skill:code-writing` — [.claude/skills/code-writing/SKILL.md](../../../.claude/skills/code-writing/SKILL.md) — универсальный процесс качественного кода (план → TDD → ревью). Файлы правки под `my-hw/`, поэтому активна скоуп-версия `my-hw:code-writing`.

## Description

Фича `dedup-model-series` добавляет НОВОЕ парное правило дедупа по ключу
`«машина + серия/тема»` с двухуровневым вердиктом (тиринг): **distinctive** пара
(конкретная модель + помеченная в лексиконе distinctive-франшиза/событие) →
**жёсткий блок**; **broad** совпадение (тема без конкретной машины, либо частая
линейка вроде Car Culture) → **мягкий флаг** (статья публикуется). Фейл-сейф:
неизвестная/непомеченная серия → всегда broad, никогда не жёсткий блок.

Эта задача — собрать **калибровочную фикстуру** из 8 размеченных пар статей в
`tests/fixtures/cross_source_dedup_pairs.py`, на которой Task 6 прогонит НОВЫЙ
классификатор (`shares_pair` → `(any_shared, shared_pairs, any_distinctive)`) и
проверит порог ≥7/8 плюс **жёсткие асимметричные инварианты**. Инварианты
важнее агрегата: молчаливый жёсткий блок необратим (нет ручной пере-публикации,
нет пер-подписчикового восстановления), поэтому каждая пара несёт явный флаг
`expected_any_distinctive`, который пиннит «обязан заблокировать» / «обязан НЕ
заблокировать».

Существующая фикстура написана под СТАРЫЙ классификатор по набору машин
(`similarity` / jaccard, порог 0.50). Поп-культурные SDCC-дубли имеют пустой
`strict` (машины не распознаются), старый классификатор ставит им ~0 и промахнулся
бы по ровно тем мотивирующим кейсам, ради которых делается фича. Поэтому фикстуру
надо переписать под парный вердикт (`shares_pair` + тир `|D`/`|B`), а НЕ под
similarity. Сам прогон через классификатор и перепись гейта-харнесса
(`tests/test_model_extractor.py`) — это **Task 6** (Wave 3); эта задача правит
ТОЛЬКО файл фикстуры.

Служит **AC11** (калибровка) и подтверждает **AC3/AC4/AC7** (жёсткий блок точной
пары; мягкий флаг широкой; фейл-сейф).

**Как классификатор увидит пары (из code-research §2, для правильной разметки):**
- Ключ пары `"<model>|<series>|<tier>"`; `<model>` — полный `strict`-токен (не бренд);
  тема-only (нет распознанной кастинги) → `"*|<series>|B"`, тема-only ВСЕГДА broad.
- `|D` (distinctive) ⟺ серия помечена distinctive в `SERIES_LEXICON` И есть конкретная
  модель. Distinctive-серии в лексиконе: k-pop demon hunters, stranger things, top gun,
  san diego comic-con/sdcc/comic-con, rlc/red line club, super treasure hunt/sth. Broad:
  car culture, boulevard, team transport, zamac, pop culture, monster trucks, fast & furious.
- `shares_pair` возвращает `(any_shared, sorted_shared_pairs, any_distinctive)`; `|D`
  побеждает `|B`. Жёсткий блок ⟺ есть общий `|D`; иначе есть общий любой → мягкий флаг.
- Чтобы SDCC-дубли дали `|D`: ОБЕ стороны должны называть один и тот же конкретный
  Porsche (полный strict-токен, напр. «Porsche 911») И «K-Pop Demon Hunters» в теле —
  иначе выйдет только тема-only `*|…|B` (broad) и жёсткого блока не будет. Проверить,
  что модель формулируется так, как её извлекает `model_extractor` (свериться с
  `model_extractor.py`).

**Совместимость с переживающим тестом старого харнесса (важно):**
