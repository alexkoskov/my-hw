## Description

Два взаимосвязанных результата, закрывающих user-spec **AC10** и **AC11**.

**1. Калибровочный тест на НОВОМ pair-tier вердикте (AC11).** Сейчас в
`tests/test_model_extractor.py` калибровка построена на старом харнессе
`_classify(similarity(fp_a, fp_b))` поверх старого фингерпринта `{strict, brands}`
(функции `test_calibration_accuracy` и `test_calibration_real_pair_must_pass`). Для
этой фичи он **непригоден**: мотивирующие дубли — поп-культурные тай-ины (K-Pop Demon
Hunters, Stranger Things, Top Gun) — дают **пустой `strict`**, старый классификатор
оценивает их ~0 и молча пропускает именно те кейсы, ради которых делается фича. Нужно
прогнать 8-парную фикстуру через **новый вердикт** — `shares_pair(fp_a, fp_b)` +
тир по суффиксу ключа `|D`/`|B` (из `model_extractor.py`, добавлено Task 1). Порог —
**агрегат ≥7/8** правильных tier-вердиктов, ПЛЮС — и это важнее, потому что молчаливый
жёсткий блок необратим (нет ручной перепубликации) — **жёсткие асимметричные
инварианты**: 3 реальных SDCC-дубля ОБЯЗАНЫ жёстко блокировать (`any_distinctive is
True`), а каждая not-dupe проба ОБЯЗАНА НЕ жёстко блокировать (`any_distinctive is
False`).

**2. Деплой-раннбук в `deployment.md` (AC10).** Задокументировать: предпроверку
холодной прод-базы `SELECT COUNT(*) FROM published_articles WHERE model_fingerprint
IS NOT NULL` (ожидаем ~0 / «no such column» — база на московском проде почти
наверняка холодная, снята с NL до фичи дедупа) и безопасную поэтапную выкатку
(«тёмный» деплой с тумблером выкл → `backfill --days 30` → наблюдение `[E014]`/логов
пару дней → включение тумблера), строго **вне окна 10:00–20:00 МСК**.

**Контракт `shares_pair` (из code-research §2.1):**
`shares_pair(fp_a, fp_b) -> tuple[bool, list[str], bool]` = `(any_shared,
sorted_shared_pairs, any_distinctive)`. Пары пересекаются, если `set(a['pairs']) &
set(b['pairs'])` непусто; жёсткий блок ⇔ среди общих пар есть ключ, оканчивающийся на
`|D` (`any_distinctive`); тир читается из суффикса ключа, повторный lookup в лексиконе
не нужен. `|D` побеждает `|B` в одном сравнении.

**Маппинг вердикта в харнессе** (сравнивается с `pair['expected_verdict']`):
`any_distinctive is True` → `'duplicate'`; `any_shared and not any_distinctive` →
`'soft-flag'`; `not any_shared` → `'non-duplicate'`. Task 3 расширил `expected_verdict`
фикстуры до трёх значений (`'duplicate' | 'soft-flag' | 'non-duplicate'`), метки
SDCC-дублей и not-dupe проб проставлены там же — опираться на метки/структуру, которые
приземлит Task 3, а не на старые тела фикстуры.

**Раннбук — фактура для deployment.md:**
- Предпроверка (оператор, до деплоя): `SELECT COUNT(*) FROM published_articles WHERE
  model_fingerprint IS NOT NULL` на московском проде. Ожидаем ~0 (холодная база);
  ошибка «no such column» — сама по себе подтверждение, что ALTER ещё не прошёл.
- Тумблер: `DEDUP_SERIES_ENABLED` (по умолчанию `"1"`), читается на импорте (Task 4).
  «Тёмный» деплой = выставить `DEDUP_SERIES_ENABLED=0` в прод-`.env` на хосте перед
  сборкой.
- Backfill (оператор, после деплоя): `python3 backfill_fingerprints.py --days 30`
  (в прод-контейнере: `docker exec hw-news-bot python3 backfill_fingerprints.py
  --days 30`). Прогревает и старый car-fingerprint, и новые пары за 30 дней;
  идемпотентен; есть `--dry-run`; `--days` зажат в `[1, 90]`.
- Прод-контекст (из существующего deployment.md): московский Docker-хост, репо
  `/root/hw-news`, `git pull && docker compose up -d --build`, БД на
  `/root/hw-news/data/news.db`, прод-`.env` правится руками на хосте, **вне окна
  10:00–20:00 МСК** (рестарт сбрасывает in-process расписание). SSH/ops выполняет
  оператор — Claude готовит команды, не ходит по SSH сам.
- Порядок безопасной выкатки: (1) предпроверка `SELECT COUNT`; (2) `DEDUP_SERIES_
  ENABLED=0` в `.env`; (3) `git pull && docker compose up -d --build` вне окна;
  (4) `backfill --days 30`; (5) наблюдать `[E014]`/логи пару дней на свежей базе;
  (6) `DEDUP_SERIES_ENABLED=1` + пересборка вне окна.
