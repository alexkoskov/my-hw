## Description

Это Wave-2 задача — сердце фичи. Она подключает новое **опциональное тиринговое
парное правило** (машина + серия/тема, 30 дней, любой источник) к существующему
дедуп-гейту в `news_bot.py`, поверх старого set-overlap правила (≥50%, 7 дней), не
ломая degraded-mode.

Task 1 (зависимость) уже расширил `model_extractor.extract_fingerprint` до
`{strict, brands, series, pairs}`, где `pairs` — список ключей
`"<model>|<series>|<tier>"` (или `"*|<series>|B"` для темы без машины),
`tier ∈ {D, B}`: `D` — distinctive (жёсткий блок), `B` — broad (мягкий флаг).
Эта задача НЕ трогает извлечение — она только читает `fingerprint['pairs']` и
`fingerprint['series']`, сравнивает с кандидатами и выносит вердикт.

Три изменения в `news_bot.py`:
1. Новая import-time константа-тумблер `DEDUP_SERIES_ENABLED` (рядом с `DB_FILE`,
   читается один раз на старте, по умолчанию включена; гейт читает
   `news_bot.DEDUP_SERIES_ENABLED` как атрибут модуля, чтобы тесты могли
   monkeypatch, а оператор — выключить env-переменной + рестарт).
2. Рефактор `_check_cross_source_dedup` — прогнать парное правило ПЕРВЫМ, затем
   (только если не было блока/флага) добить старым set-overlap бэкстопом.
3. Обновить `.env.example` — добавить закомментированную строку тумблера с дефолтом.

Плюс — обновить интеграционные сценарии в
`tests/test_integration.py::TestCrossSourceDedup` (TDD-first).

Обслуживает user-spec **AC3, AC4, AC5, AC6, AC8**.

## What to do

1. **Тумблер `DEDUP_SERIES_ENABLED`** (`news_bot.py`, рядом с `DB_FILE`, ~стр.116):
   импорт-time константа, читается из env один раз (паттерн `DB_FILE`/`TZ`), по
   умолчанию **включена** (unset/blank → on). Имя env-переменной — по рекомендации
   code-research `DEDUP_SERIES_PAIRS` (значения `0/false/no/off`, case-insensitive →
   выкл). Гейт обращается к `news_bot.DEDUP_SERIES_ENABLED` через атрибут модуля
   (монкипатчится в тестах, оператор флипает через env + рестарт без правки кода).

2. **Рефактор `_check_cross_source_dedup`** — вставить парное правило в начало
   хелпера, ПЕРЕД существующим set-overlap телом:
   - Прочитать `pairs = fingerprint.get('pairs') or []` и
     `series = fingerprint.get('series') or []` (защита от `KeyError` на
     back-compat строках без ключей).
   - Если `news_bot.DEDUP_SERIES_ENABLED and pairs`: **один раз** забрать кандидатов
     за **30 дней** (pending + published, `list_recent_*_fingerprints(conn, 30)`).
     Пройти ВСЕХ кандидатов **без same-source skip** (любой источник). Для каждого —
     `shared = set(pairs) & set(cand_fp.get('pairs') or [])`. Scan-and-remember:
     первый shared с суффиксом `|D` (distinctive) → запомнить как блок и прервать
     скан; иначе первый broad shared → запомнить как флаг, но **продолжить скан**
     (чтобы `|D` позже победил `|B`).
   - Вердикт: есть distinctive-совпадение → `('block', match)` (→ `[E015]`); иначе
     есть broad-совпадение → `('flag', match)` (→ `[E014]`, статья публикуется).
     **Оба вердикта TERMINAL** — старый set-overlap НЕ запускается (иначе двойной
     вердикт / двойной пинг).
   - Если парное правило не дало ни блока, ни флага (нет shared пары), ИЛИ `pairs`
     пуст, ИЛИ тумблер выключен → провалиться дальше в set-overlap бэкстоп.
   - **Re-gate пустого short-circuit:** нынешний ранний выход по пустому `strict`
     (`:975-980`) заменить на «пусто `strict` **И** пусто `series`». Поп-культурная
     статья имеет пустой `strict`, но непустые `series`/`pairs` — она ОБЯЗАНА пройти
     парный скан, а не короткоза́мкнуться.
   - **Set-overlap бэкстоп** (7 дней, cross-source-only) — оставить логику как есть,
     включая same-source skip (`:990-994`). Он теперь достижим только на «pass»
     парного правила.
   - **Один 30-дневный fetch на оба правила:** забрать кандидатов один раз за 30
     дней, а 7-дневное подмножество для бэкстопа вывести в Python (сравнить
     `fetched_at`/`published_at` с `now-7d`), чтобы не делать второй SQL-round-trip.

3. **`match`-dict для парного правила** — построить совместимый с обеими ветками
   гейта (`block`→E015, `flag`→E014). Нести `link`, `source_name` и поля, которые
   читает `alert_cross_source_dupe` (`overlap_pct`, `n_matches`, `n_total`,
   `models`). Для парного совпадения `models = sorted(shared_pairs)`,
   `n_matches = len(shared)`, `n_total = len(set(a_pairs) | set(b_pairs))`,
   `overlap_pct = int(round(100*n_matches/n_total))`.

4. **Degraded-mode** — не трогать `try/except` + `[E016]` в `job()` (`:2213-2247`).
   Извлечение серий уже внутри `extract_fingerprint` (`:2156`), под тем же guard —
   краш переиспользует `[E016]` и публикует (AC9). Новых точек отказа нет.

5. **`.env.example`** — добавить закомментированную строку тумблера рядом с
   `# DB_FILE=news.db` с комментарием «default on; 0/false/no/off → выкл».

6. **Тесты** (`tests/test_integration.py::TestCrossSourceDedup`) — обновить сценарии
   (см. TDD Anchor). Писать/обновлять тесты ДО рефактора.

**Edge cases:**
- Back-compat: строки, записанные до фичи (и pending в 7-дневном окне до деплоя),
  имеют `model_fingerprint` dict БЕЗ `pairs`/`series` — читать через
  `cand_fp.get('pairs') or []`, никогда не `KeyError`.
- Кандидат с `model_fingerprint = None`/не-dict (NULL/malformed) — пропускать молча
  (как сейчас в set-overlap).
- Поп-культурный тай-ин: пустой `strict`, но непустые `series`/`pairs` — ОБЯЗАН
  пройти парный скан; именно поэтому empty short-circuit ре-гейтится на «strict И
  series пусты» (иначе `:975-980` его пропустит — это и есть баг, который фича чинит).
- `|D` побеждает `|B` внутри ОДНОГО сравнения и через несколько кандидатов: scan-and-
  remember — distinctive прерывает скан (block немедленно), broad только
  запоминается и не подавляет более поздний distinctive.
- Флаг — терминал: не запускать set-overlap после broad-флага, иначе статья может
  получить и `[E014]` «публикуется», и `[E015]` «заблокирована» в одном тике (double
  ping, отмеченный completeness-валидатором).
- Toggle off: гейт вообще не трогает `pairs`; поведение бит-в-бит как сегодня.
- 30д fetch: derive 7-дневное подмножество в Python по `fetched_at`/`published_at`;
  ~200 строк на 30 днях — full-scan-fine, индекс не нужен (shipped §13.5).

**Implementation hints:**
- Тумблер: паттерн `DB_FILE` — `os.getenv("DEDUP_SERIES_PAIRS", "1").strip().lower()
  not in ("0","false","no","off","")`. Гейт использует `news_bot.DEDUP_SERIES_ENABLED`
  (атрибут модуля), НЕ локальную копию — иначе monkeypatch в тестах не сработает.
- Порядок ветвей строго: toggle+pairs → 30д скан (block/flag terminal) → empty
  short-circuit (strict И series) → set-overlap backstop. Единственный ранний

- ReDoS/инъекции здесь не создаём — извлечение в Task 1; SQL — параметризованные
  репо-хелперы (`json_extract` не используется в этом файле).
- Не менять сигнатуру `_check_cross_source_dedup(article, fingerprint, conn,
  new_source=None)` — `job()` вызывает её так.
