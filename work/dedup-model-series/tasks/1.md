# Task 1: Series/theme extraction + tier-tagged lexicon (`model_extractor.py`)

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` (для файлов под `my-hw/` — скоуп-версия `my-hw:code-writing`) — [.claude/skills/code-writing/SKILL.md](../../../.claude/skills/code-writing/SKILL.md)

## Description

Первый (чистый, stateless) кирпич фичи «дедуп по машина+серия/тема». Всё живёт
внутри существующего `model_extractor.py` — **без нового top-level модуля, без новой
зависимости, без миграции схемы** (см. tech-spec Decision 6, user-spec Ограничения).

Задача добавляет в экстрактор:
1. **Tier-tagged лексикон** `SERIES_LEXICON` (alias → `(canonical, tier)`), покрывающий
   линейки Hot Wheels (Car Culture, Boulevard, Team Transport, Super Treasure Hunt, RLC,
   Zamac…), события (San Diego Comic-Con) и поп-культурные франшизы (Stranger Things, Top
   Gun, K-Pop Demon Hunters). Каждый вход помечен `distinctive` или `broad`; дефолт для
   любого разрешимого-но-непомеченного пути — `_SERIES_DEFAULT_TIER = 'broad'` (фейл-сейф).
2. **Третий проход извлечения** серий/тем поверх уже собранного `text = _gather_text(article)`
   (сейчас `extract_fingerprint` делает Pass 1 на строке 248 и Pass 2 на строке 279).
3. **Обогащение результата** `extract_fingerprint` c 2 ключей `{strict, brands}` до 4:
   `{strict, brands, series, pairs}`. `pairs` — список ключей `"<model>|<series>|<tier>"`;
   theme-only вариант (серия распознана, конкретной модели нет) → `"*|<series>|B"`.

Тир пары: **distinctive (`|D`)** тогда и только тогда, когда серия помечена в лексиконе
как distinctive **И** в паре есть конкретная модель (не `*`); во всех остальных случаях —
**broad (`|B`)**. Это load-bearing свойство безопасности (tech-spec Decision 2, code-research
§2.2/§7.2): неизвестная/новая франшиза никогда не может молча дать жёсткий блок.

Задача обслуживает user-spec **AC1** (пары извлекаются в `model_fingerprint`, новый JSON-ключ
без миграции) и **AC7** (охват темы: линейки+события+франшизы; предмет без модели → тема-ключ;
неизвестная/непомеченная серия → broad-фейл-сейф). Также закладывает `pairs`/тиры, которые
потребляют тумблер (AC6) и гейт (AC3–AC5) в Task 4, и держит 4-ключевую непустую структуру
для пустого входа (вклад в AC8).

## What to do

1. Добавить константу `SERIES_LEXICON: dict[str, tuple[str, str]]` (alias → `(canonical, tier)`,
   `tier ∈ {'distinctive','broad'}`) рядом с `_BRAND_ALIASES` (строки 83–87). Засеять из семей
   user-spec «Что делаем»/AC7; distinctive — конкретные франшизы/события/лимит-серии, broad —
   частые рекуррентные линейки. Добавить `_SERIES_DEFAULT_TIER = 'broad'`.
2. Добавить **load-time-ассерт** сразу после определения `SERIES_LEXICON`: ни один canonical
   не содержит `|` и `\n` (целостность pair-ключа). Экстрактор — singleton-модуль, ассерт
   срабатывает на импорте (как компилируются regex-константы).
3. Скомпилировать `_SERIES_RE` из ключей лексикона как **ReDoS-safe** ограниченную мультислов-
   альтернацию, зеркаля `_MODEL_AFTER_BRAND_RE` (строки 115–132): только ограниченные кванторы
   (`\s{1,3}`, `\s{1,2}`), **никогда `\s+`/`\s*`**; мультисловные алиасы — раньше коротких.
   Короткие/двусмысленные акронимы (`SDCC`, `RLC`, `STH`, `Zamac`) — **case-sensitive** отдельным
   проходом по образцу `_UPPERCASE_BRANDS_RE` (строка 165), чтобы прозаические коллизии
   (`sth`, `rlc` в тексте) не матчились.
4. Добавить чистые helper-функции (co-located, без I/O, без логирования):
   - `_canonical_series(raw) -> tuple[str, str] | None` — зеркалит `_canonical_brand` (187–195):
     lower + `re.sub(r'\s{1,3}', ' ', …)` + `SERIES_LEXICON.get(key)`; возвращает `(canonical, tier)`
     или `None`.
   - `extract_series(article_or_text) -> list[str]` — отсортированный список canonical-серий.
   - `_build_pairs(strict: set, series_with_tier) -> list[str]` — картезиан модель×серия →
     `"<model>|<series>|<tier>"`; при пустом `strict` и непустой серии → theme-only `"*|<series>|B"`.
   - `shares_pair(fp_a, fp_b) -> tuple[bool, list[str], bool]` — `(any_shared, sorted_shared_pairs,
     any_distinctive)` через `set(a['pairs']) & set(b['pairs'])`; `any_distinctive` = любой общий ключ
     оканчивается на `|D`.
5. Встроить третий проход в `extract_fingerprint` (223–287): после Pass 2 (строка 282) собрать
   `series` + `pairs` и вернуть 4-ключевой dict (строки 284–287). Пустой ранний return (строка 242)
   расширить до `{'strict': [], 'brands': [], 'series': [], 'pairs': []}` — каждый фингерпринт
   несёт 4 ключа (непустая структура для AC8).
6. Обновить тип `Fingerprint` (строка 45) и модуль-docstring под 4-ключевую форму и новый public API.
7. Написать тесты в `tests/test_model_extractor.py` (см. TDD Anchor). Обновить существующие тесты,
   которые пинят старую 2-ключевую форму (`test_empty_body`, `test_empty_dict_input` — строки 92–97),
   на 4-ключевую.
8. Провалидировать лексикон против реального текста ленты (Verification → Smoke): убедиться, что
   засеянные canonical-строки и casing совпадают с реальными названиями серий.

**Dependencies:** нет зависимостей от других задач (Wave 1). Никаких новых пакетов. Task 4 (гейт) и Task 3

`shares_pair(fp_a, fp_b) -> (any_shared, sorted_shared_pairs, any_distinctive)`.

**Edge cases:**
- Тайтл/тело без серии → `series == []`, `pairs == []` (только car-fingerprint как раньше).
- Серия есть, `strict` пуст (поп-культурный тай-ин без узнаваемой машины) → theme-only `"*|<series>|B"`
  (всегда broad — держит фейл-сейф честным, code-research §7.3).
- Distinctive-франшиза + конкретная модель на обеих сторонах → `|D`. Distinctive-франшиза без модели → `|B`.
- Непомеченная/новая серия: экстрактор эмитит только серии из лексикона → нет токена → нет пары → не может
  дать `|D` (двойная защита фейл-сейфа, code-research §2.3).
- Обратная совместимость: старые строки в БД имеют `model_fingerprint` без ключей `series`/`pairs` —
  все читатели обязаны использовать `fp.get('pairs') or []`, никаких `KeyError` (актуально для Task 4, но
  форму пустого return задаём здесь).
- ReDoS: `_SERIES_RE` — только ограниченные кванторы; акронимы — case-sensitive, чтобы `sth`/`rlc`/`sdcc`
  в прозе не матчились.

**Implementation hints (НЕ псевдокод):**
- Тир нужно вычислять на этапе извлечения и вшивать суффиксом `|D`/`|B` в ключ, чтобы гейт делал чистое
  пересечение множеств и читал тир прямо из ключа (code-research §2.2 — «carry the tag in the key»).
- `<model>` в ключе — всегда полный `strict`-токен (`"porsche 911"`), НИКОГДА не голый бренд: бренд-only
  ключи возвращают ровно тот класс ложных срабатываний, который убрал реверс same-source 2026-06-14.
- Мультисловные алиасы (`san diego comic-con`, `super treasure hunt`) в альтернации — раньше коротких
  однословных, чтобы не отгрызался префикс (общий приём «длинная альтернатива идёт раньше своего префикса»;
  ср. multi-word-first порядок в `_MODEL_AFTER_BRAND_RE`).
- `|` безопасен как разделитель: model-токены — `[a-z0-9 -]`, series-токены — lexicon-canonical; ни тот ни
  другой не содержат `|` (это и защищает load-time-ассерт).
- FILES-arrays: `model_extractor.py` уже во всех трёх (deploy.sh, deploy.yml, deploy_test.yml) — новый
