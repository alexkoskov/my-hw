# Task 10: Pre-deploy QA

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:pre-deploy-qa` — [pre-deploy-qa/SKILL.md](../../../.claude/skills/pre-deploy-qa/SKILL.md)

## Description

Финальная приёмка фичи `dedup-model-series` **перед деплоем**. Весь код и тесты
уже написаны (Task 1–6) и прошли три аудита (Task 7 — код, Task 8 — безопасность,
Task 9 — тесты). Эта задача — независимая приёмочная проверка: прогнать весь
тестовый набор и по спекам подтвердить, что каждый критерий приёмки выполнен, а
регрессий в существующем поведении нет.

Особый фокус (из тех-спека и scope этой задачи):
- **Toggle-off parity** — при `DEDUP_SERIES_ENABLED=0` парное правило полностью
  пропущено, поведение **идентично сегодняшнему** дедупу (только старый 7-дневный
  set-overlap). Это аварийный рубильник — его паритет критичен.
- **Degraded mode** — любой сбой экстрактора/сравнения → статья всё равно
  публикуется (`[E016]`, rate-limited), не теряется.
- **Калибровка ≥7/8 + асимметричные инварианты** — агрегатный порог И жёсткие
  инварианты: 3 реальных SDCC-дубля ОБЯЗАНЫ жёстко блокироваться
  (`any_distinctive is True`), каждая not-dupe проба ОБЯЗАНА НЕ блокироваться
  (`any_distinctive is False`). Молчаливый жёсткий блок неисправим — это важнее
  агрегата.
- **Нет регрессий** — весь набор зелёный, старый дедуп по машинам работает как
  раньше, `test_deploy_files_invariant` держит FILES-массивы.

Задача — только чтение и запуск тестов. Код НЕ меняем: если находится дефект —
он фиксируется как finding в отчёте, а не правкой прямо здесь.

## Verification Steps

### Automated
Запускается из корня проекта `my-hw/`.
- `pytest -q` → весь набор зелёный (базовая проверка «нет регрессий»; зафиксировать числа).
- `pytest tests/test_model_extractor.py -v` → извлечение серий/тем + классификация пар (точная/широкая), fail-safe untagged→broad.
- `pytest tests/test_integration.py::TestCrossSourceDedup -v` → block(`[E015]`)/flag-terminal(`[E014]`)/бэкстоп-блокирует/toggle-off/degraded/пустой-фингерпринт → проход.
- `pytest tests/test_model_extractor.py -k calibration -v` → агрегат ≥7/8 И асимметричные инварианты (3 SDCC = жёсткий блок; not-dupe пробы = не блок). Калибровочные тесты Task 6 переименовал в `test_calibration_pair_tier_accuracy` / `test_calibration_sdcc_dupes_hard_block` / `test_calibration_not_dupes_never_hard_block`.
- `pytest tests/test_backfill_fingerprints.py -v` → widened re-select/skip, 30-дневное окно, идемпотентность.
- `pytest tests/test_admin_alerts.py -v` → `[E015]` рендерит пару+ссылку; `[E014]` — тему/серию+ссылку.
- `pytest tests/test_deploy_files_invariant.py -v` → FILES-массивы (deploy.yml/deploy_test.yml/deploy.sh) согласованы.

### Smoke (информационные — `verify: []`, не гейтящие; дополняют набор из Agent Verification Plan тех-спека)
- `DB_FILE=/tmp/qa_backfill_test.db python3 backfill_fingerprints.py --days 30 --dry-run` → на изолированной временной БД печатает сводку; повторный прогон — no-op (заполняет и пары, и базовый car-fingerprint). Явный `DB_FILE` обязателен: скрипт резолвит подключение через `news_bot.DB_FILE` (env, дефолт — относительный `news.db` в корне репо), иначе проба тронет рабочий `./news.db`.
- Toggle-off прогон гейта: `DEDUP_SERIES_ENABLED=0` (env / monkeypatch в интеграционном тесте) → парное правило пропущено, отрабатывает только старый дедуп; сверить, что вывод/вердикт совпадает с сегодняшним поведением.

**Что относить к `not_verifiable` / deferredToPostDeploy (это норма для pre-deploy):**

(контракт для Task 11 / post-deploy-qa).

(тест-аудит) завершены. Их отчёты в `logs/working/` — учесть при трактовке findings.

**Edge cases для явной сверки:**
