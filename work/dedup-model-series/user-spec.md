# User Spec: dedup-model-series — блок повторов по «машина + серия/тема» за 30 дней

## Что делаем

Добавляем в дедуп новое правило поверх существующего. Из каждой новой статьи, кроме
набора машин, извлекаем **серию/тему** каждого предмета и строим пары
**«машина + серия/тема»** (например `porsche 911 + k-pop demon hunters`,
`toyota supra + car culture`). Если хотя бы **одна** такая пара уже встречалась в
любой статье (опубликованной или в очереди) за последние **30 дней** — новая статья
считается дублем: **не переводим и не публикуем**, ссылка уходит в `processed_news`,
оператору приходит уведомление `[E015]` с деталями (что и с чем совпало).

«Серия/тема» понимается широко: линейки Hot Wheels (Car Culture, Boulevard, Team
Transport, Super Treasure Hunt, RLC, Zamac, Monster Trucks, Character Cars…),
**события** (San Diego Comic-Con) и **поп-культурные франшизы** (Stranger Things,
Top Gun, K-Pop Demon Hunters…). Для чисто поп-культурных вещей без узнаваемой модели
машины ключом служит сама тема/франшиза.

Правило работает по **любому источнику** — ловит и кросс-источниковые дубли, и
повторы одного и того же сайта («ещё фото…»). Если в статье серию/тему распознать не
удалось — откатываемся к **нынешнему** дедупу (пересечение наборов машин ≥50%, окно
7 дней), ничего в нём не меняя. При любом сбое механизма статья **всё равно
публикуется** (degraded mode).

## Зачем

Одна и та же машина/тема прилетает в канал ~**3 раза в месяц** — статьи разные, но
для подписчика это повтор. Нынешний дедуп их не ловит по двум причинам:
1. **Поп-культурные тай-ины** (Stranger Things, K-Pop Demon Hunters, Top Gun) — не
   узнаваемые модели машин → фингерпринт по машинам пустой → проверка пропускается.
2. Нынешний дедуп сравнивает только **разные** источники — повтор одного сайта
   («ещё фото…») не ловится вообще.

Реальный триплет, ради которого делаем (все три — про эксклюзивы SDCC 2026, должны
ловиться фильтром):
- t-hunted PT: [«Hot Wheels revela exclusivos da San Diego Comic-Con»](https://t-hunted.blogspot.com/2026/06/hot-wheels-revela-exclusivos-da-san.html)
- autoevolution EN: [«Hot Wheels San Diego Comic-Con releases … KPop Demon Hunters, Stranger Things, Top Gun»](https://www.autoevolution.com/news/hot-wheels-san-diego-comic-con-releases-are-about-kpop-demon-hunters-stranger-things-and-top-gun-271899.html)
- t-hunted PT (повтор того же сайта): [«Mais fotos do Porsche de K-Pop Demon Hunters»](https://t-hunted.blogspot.com/2026/06/mais-fotos-do-porsche-de-k-pop-demon.html)

## Как должно работать

### Сценарий 1 — повтор того же сайта («ещё фото»)
1. autoevolution публикует SDCC-подборку (в т.ч. Porsche K-Pop Demon Hunters). Бот
   публикует, сохраняет пары «машина+тема».
2. Через несколько дней t-hunted постит «ещё фото Porsche K-Pop Demon Hunters».
3. Бот извлекает пары новой статьи: `{porsche + k-pop demon hunters}`.
4. Пара уже была за 30 дней → **блок**. Ссылка → `processed_news`, в канал ничего,
   оператору `[E015]` с деталями.

### Сценарий 2 — кросс-источник, вся статья про то же
1. autoevolution публикует SDCC-подборку.
2. На следующий день t-hunted публикует PT-версию той же подборки (те же темы).
3. Пары новой статьи почти все уже были → **блок** (≥1 совпадения достаточно).

### Сценарий 3 — сборник с новым контентом, где повторяется одна пара
1. Вышел микс Car Culture (5 машин). Часть пар уже была за 30 дней.
2. Правило «≥1 совпадения → блок» → **вся статья блокируется**, даже если 4 машины
   новые. Это осознанный выбор оператора (агрессивный фильтр); митигация — `[E015]`
   уведомление, оператор видит блок. (См. Риски.)

### Сценарий 4 — серию/тему не распознали
1. Обычная новость «Nissan Skyline» без явной серии.
2. Пары не построились → **откат к нынешнему дедупу** (набор машин ≥50%, 7 дней).
   Поведение как сейчас, ничего не меняется.

### Сценарий 5 — ни машин, ни темы
1. «Mattel announces Q3 earnings» — ни машин, ни серии.
2. Оба фингерпринта пустые → проверка пропускается, статья публикуется как раньше.

### Сценарий 6 — сбой механизма
1. Экстрактор серий или сравнение падают с исключением.
2. В лог ERROR с трейсбеком, rate-limited `[E016]`, статья **всё равно публикуется**.

### Сценарий 7 — деплой
1. Оператор пересобирает контейнер на московском проде (`git pull && docker compose
   up -d --build`) **вне окна 10:00–20:00 МСК**.
2. Схема БД не меняется (серия кладётся в существующий JSON-фингерпринт).
3. Оператор разово запускает `python3 backfill_fingerprints.py --days 30` на проде
   (~5 мин) — окно за 30 дней сразу прогрето парами «машина+серия».

## Критерии приёмки

- [ ] **AC1.** Из тела новой статьи извлекаются пары «машина+серия/тема» и
  сохраняются в существующий `model_fingerprint` (новый ключ в JSON, БЕЗ новой
  колонки и БЕЗ миграции схемы).
- [ ] **AC2.** При публикации пары переезжают в `published_articles.model_fingerprint`
  вместе с остальным фингерпринтом.
- [ ] **AC3.** Блок: если ≥1 пара новой статьи совпала с любой статьёй (pending ИЛИ
  published) за **30 дней** и по **любому источнику** (в т.ч. тот же источник) —
  статья НЕ попадает в `pending_articles`, ссылка → `processed_news`, лог INFO,
  оператору `[E015]` с деталями (совпавшая пара + ссылка на прошлую статью).
- [ ] **AC4.** Мягкого флага (`[E014]`) для нового правила НЕТ — только блок либо
  проход. Ручной «всё-таки опубликовать» не делаем.
- [ ] **AC5.** Если серию/тему в статье не распознали — применяется существующий
  дедуп по набору машин (≥50%, 7 дней) без изменений.
- [ ] **AC6.** «Серия/тема» покрывает: линейки HW + события (SDCC) + поп-культурные
  франшизы (Stranger Things, Top Gun, K-Pop Demon Hunters). Для предмета без
  узнаваемой модели ключом служит тема/франшиза.
- [ ] **AC7.** Пустой фингерпринт (нет ни машин, ни темы) → проверка пропускается,
  статья публикуется. В БД пишем непустую структуру (не NULL — отличаем от
  необработанных строк).
- [ ] **AC8.** Degraded mode: любой сбой экстрактора/сравнения → ERROR в лог +
  rate-limited `[E016]`, статья **публикуется**. Канал не страдает от багов дедупа.
- [ ] **AC9.** `backfill_fingerprints.py --days 30` дозаполняет пары «машина+серия»
  статьям за 30 дней (в т.ч. тем, у кого старый фингерпринт уже был, но без пар).
  Идемпотентен; логирует сводку (обработано/пропущено/ошибки).
- [ ] **AC10.** Калибровочная фикстура включает **3 реальных SDCC-дубля** (t-hunted
  PT + autoevolution EN + повтор t-hunted «mais fotos») как настоящие дубли, плюс
  не-дубли (в т.ч. «та же машина в РАЗНОЙ серии» — не блок). Классификатор даёт
  ≥7/8 правильных решений (цель ≥95%).

## Ограничения

- **Без новых внешних зависимостей** и **без LLM** — regex + лексиконы (stdlib).
- **Без миграции схемы** — серия кладётся в существующий `model_fingerprint TEXT`.
- **Без нового top-level файла** — извлечение серий живёт в `model_extractor.py`
  (иначе повторится класс инцидента с рассинхроном FILES-списков деплоя).
- **Лексикон серий/тем** собирается эмпирически из реальных лент (сэмпл
  `published_articles`), англ. названия работают кросс-языково (PT/EN).
- **Backfill — разовый ручной шаг оператора** на проде после деплоя.
- Деплой — пересборка контейнера **вне окна 10:00–20:00 МСК**.

## Риски

- **Риск 1 — ложный блок (главный).** «≥1 совпадения → блок всей статьи» + широкие
  темы могут заблокировать легитимную новую статью, где совпала всего одна пара
  (напр. переизданный кастинг в том же миксе). Оператор **осознанно** выбрал
  агрессивный вариант. Митигация: уведомление `[E015]` (оператор видит блок);
  калибровочная фикстура с не-дублями; пары строятся по ПОЛНОЙ «машина+серия», не по
  одному бренду. Ложный блок для подписчиков «молчаливый» (статья не выходит), виден
  только по пингу — ручного восстановления нет by design.
- **Риск 2 — поп-культура без модели.** Мотивирующий SDCC-кейс не имеет узнаваемых
  машин — если экстракция не построит тему/франшизу-ключ, фича не поймает саму
  причину, ради которой делается. Митигация: калибровка на 3 реальных примерах —
  load-bearing.
- **Риск 3 — состояние прошлого backfill.** Если 14-дневный backfill уже прогонялся
  на проде, строки с непустым `model_fingerprint` могут пропуститься при дозаписи
  пар. Митигация: перед деплоем сверить состояние; при необходимости расширить
  выборку backfill (по отсутствию ключа пар, не по `IS NULL`).
- **Риск 4 — неполный лексикон серий/тем.** Новая серия/франшиза не извлечётся →
  дубль проскочит. Митигация: пополнение лексикона обычным PR при первом промахе.
- **Риск 5 — регрессия в пайплайне.** Митигация: degraded mode (AC8).

## Технические решения

- Мы решили **хранить пары в существующем `model_fingerprint` JSON** (новый ключ), а
  не в новой колонке — ноль миграций, ноль правок схема-пин тестов.
- Мы решили **извлекать серии/темы внутри `model_extractor.py`** (второй проход
  regex), а не отдельным модулем — чтобы не плодить top-level файл и не ловить
  рассинхрон FILES-списков деплоя.
- Мы решили **сначала применять новое парное правило** (30 дней, любой источник, блок
  по ≥1 совпадению), а при отсутствии серии — **откат к нынешнему** дедупу по набору
  машин (7 дней), не трогая его.
- Мы решили **не делать мягкий флаг и ручное восстановление** для нового правила —
  оператор хочет, чтобы дубли просто не попадали в канал; видимость даёт `[E015]`.
- Мы решили **собрать лексикон серий/тем эмпирически** из реальных статей, засеяв
  известными семействами (car-lines + события + франшизы).

## Тестирование

**Unit-тесты:** делаются всегда. `tests/test_model_extractor.py` — извлечение
серий/тем (линейки, события, франшизы; PT-текст с EN-названиями; предмет без машины
→ тема-ключ; нет серии → пусто).

**Интеграционные тесты:** делаем — трогаем критический путь публикации.
`tests/test_integration.py::TestCrossSourceDedup` — блок по паре (кросс-источник и
same-source), откат к набору при отсутствии серии, degraded при краше, пустой
фингерпринт → проход. Обновить `test_within_source_not_deduped` (нынешний
cross-source-only разворачивается на any-source для парного правила). Плюс
калибровочная фикстура: 3 реальных SDCC-дубля + не-дубли (в т.ч. «та же машина в
разной серии» = не блок), порог ≥7/8.

**E2E тесты:** не делаем — роль E2E играет 2-недельный мониторинг канала после деплоя.

## Как проверить

### Агент проверяет

| Шаг | Инструмент | Ожидаемый результат |
|-----|-----------|---------------------|
| 1. `pytest -q` | bash | Зелёный: новые + существующие тесты. |
| 2. `pytest tests/test_model_extractor.py -v` | bash | Извлечение серий/тем + пар. |
| 3. `pytest tests/test_integration.py::TestCrossSourceDedup -v` | bash | Блок/откат/degraded/проход. |
| 4. калибровочный тест | bash | ≥7/8; 3 реальных SDCC-пары помечены дублями. |
| 5. `backfill_fingerprints.py --days 30` на тестовой БД | bash | Сводка «обработано N…»; повторный запуск — no-op. |

### Пользователь проверяет
- **После деплоя** — запустить `python3 backfill_fingerprints.py --days 30` на проде.
- **Канал @myhwchannel, 2 недели** — нет повторов одной темы/машины+серии.
- **Пинги `[E015]` 2 недели** — спот-чек на ложные блоки (реально дубль или нет?).
- **SLA-ориентир:** 0 видимых дублей в канале; ≤1 ложный блок в месяц.
