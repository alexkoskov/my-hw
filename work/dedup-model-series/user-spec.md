# User Spec: dedup-model-series — дедуп по «машина + серия/тема» за 30 дней (тумблер + тиринг)

## Что делаем

Добавляем в дедуп новое **опциональное** правило поверх существующего. Из каждой
новой статьи, кроме набора машин, извлекаем **серию/тему** и строим пары
**«машина + серия/тема»** (например `porsche 911 + k-pop demon hunters`,
`toyota supra + car culture`). Если такая пара уже встречалась в любой статье
(опубликованной или в очереди) за последние **30 дней** — статья считается дублем.

Вердикт **двухуровневый (тиринг)**, чтобы не резать молча реальные новости:
- **Точная пара** (конкретная машина + конкретная франшиза/событие/лимитированная
  серия, напр. `porsche + k-pop demon hunters`) → **жёсткий блок**: не переводим и
  не публикуем, ссылка → `processed_news`, оператору `[E015]` с деталями.
- **Широкое совпадение** (только по теме без конкретной машины, напр. голое
  `stranger things`; либо частая рекуррентная линейка вроде Car Culture) →
  **мягкий флаг**: статья **публикуется**, оператору `[E014]` на ревью.

**Фейл-сейф (важно):** жёсткий блок — только для серий/тем, **явно помеченных как
«distinctive»** в лексиконе (конкретные франшизы/события/лимит-серии). Любая
неизвестная, новая или неоднозначная серия по умолчанию считается **широкой →
мягкий флаг**, никогда не жёсткий блок. Так новая серия не может молча зарезать
статью.

«Серия/тема» понимается широко: линейки Hot Wheels (Car Culture, Boulevard, Team
Transport, Super Treasure Hunt, RLC, Zamac…), **события** (San Diego Comic-Con) и
**поп-культурные франшизы** (Stranger Things, Top Gun, K-Pop Demon Hunters…).

Правило работает по **любому источнику** (в т.ч. повтор одного сайта) — **но только
когда серия/тема распознана**; простой репост без узнаваемой темы ловится (или нет)
существующим дедупом. Новое правило **основное, но отключаемое одним переключателем**
(env-переменная): выключено → работает только старый дедуп. При любом сбое механизма
статья **всё равно публикуется** (degraded mode).

**Композиция со старым дедупом (в дополнение, не вместо):** если новое правило НЕ
дало жёсткого блока (пара не совпала, или серии нет, или правило выключено) — далее
**всегда** отрабатывает существующий дедуп по набору машин (≥50%, 7 дней), как сейчас.

## Зачем

Одна и та же машина/тема прилетает в канал ~**3 раза в месяц** — статьи разные, но
для подписчика это повтор. Нынешний дедуп их не ловит: (1) поп-культурные тай-ины
(Stranger Things, K-Pop Demon Hunters, Top Gun) — не узнаваемые модели → фингерпринт
по машинам пустой → проверка пропускается; (2) повтор одного сайта («ещё фото…») по
серии/теме не отслеживается.

Реальный триплет (все три — про эксклюзивы SDCC 2026, должны ловиться фильтром):
- t-hunted PT: [«Hot Wheels revela exclusivos da San Diego Comic-Con»](https://t-hunted.blogspot.com/2026/06/hot-wheels-revela-exclusivos-da-san.html)
- autoevolution EN: [«… San Diego Comic-Con releases … KPop Demon Hunters, Stranger Things, Top Gun»](https://www.autoevolution.com/news/hot-wheels-san-diego-comic-con-releases-are-about-kpop-demon-hunters-stranger-things-and-top-gun-271899.html)
- t-hunted PT (повтор того же сайта): [«Mais fotos do Porsche de K-Pop Demon Hunters»](https://t-hunted.blogspot.com/2026/06/mais-fotos-do-porsche-de-k-pop-demon.html)

## Как должно работать

### Сценарий 1 — повтор того же сайта, точная пара → жёсткий блок
autoevolution публикует SDCC-подборку (в т.ч. Porsche K-Pop Demon Hunters). Через
дни t-hunted постит «ещё фото Porsche K-Pop Demon Hunters». Пара
`porsche + k-pop demon hunters` уже была за 30 дней → **жёсткий блок**, ссылка →
`processed_news`, оператору `[E015]`.

### Сценарий 2 — кросс-источник, та же подборка → жёсткий блок
autoevolution публикует SDCC-подборку; на следующий день t-hunted — PT-версию. Есть
общая точная пара → **жёсткий блок** (≥1 совпадения точных пар достаточно).

### Сценарий 3 — широкое совпадение по теме → мягкий флаг (не молчаливый блок)
Вышла мейнлайн-машинка Stranger Things. Позже — эксклюзив Stranger Things с Comic-Con
(другой продукт). Совпадение только по теме `stranger things`, без общей конкретной
машины → **мягкий флаг `[E014]`**: статья публикуется, оператору пинг на ревью.
(Так реальная новая новость не теряется молча — главное замечание валидатора.)

### Сценарий 4 — новое правило не заблокировало → добивает старый дедуп
Статья про Nissan Skyline: серию не распознали ИЛИ пара не совпала. Новое правило
проходит → **дальше всегда работает старый дедуп** (набор машин ≥50%, 7 дней). Ничего
в старом поведении не меняется.

### Сценарий 5 — правило выключено (тумблер)
Оператор выставил env-переменную «выкл». Новое правило полностью пропускается,
работает только старый дедуп. (Аварийный рубильник, если новое правило начнёт резать
лишнее — отключение одной переменной + рестарт, без правки кода.)

### Сценарий 6 — ни машин, ни темы → проход
«Mattel announces Q3 earnings»: оба фингерпринта пустые → проверка пропускается,
статья публикуется.

### Сценарий 7 — сбой механизма → degraded
Экстрактор/сравнение падают: ERROR в лог + rate-limited `[E016]`, статья публикуется.

### Сценарий 8 — деплой + прогрев
1. Пересборка контейнера на московском проде (`git pull && docker compose up -d
   --build`) **вне окна 10:00–20:00 МСК**. Схема БД не меняется.
2. Перед деплоем — проверка состояния прод-базы: `SELECT COUNT(*) FROM
   published_articles WHERE model_fingerprint IS NOT NULL` (ожидаем ~0 — базовый
   дедуп на текущем проде «холодный», база скопирована со старого NL до фичи).
3. После деплоя оператор разово запускает `python3 backfill_fingerprints.py
   --days 30` — прогревает **и старый фингерпринт по машинам, и новые пары** за 30
   дней (лечит холодную базу).
4. **Безопасная выкатка (рекомендуется):** сначала деплой с тумблером **выкл**,
   прогнать backfill, понаблюдать `[E014]`/логи пару дней на свежей базе, затем
   включить тумблер. (Тумблер по умолчанию on — это установившийся режим; для
   первого включения лучше «тёмный» деплой.)

## Критерии приёмки

- [ ] **AC1.** Из тела статьи извлекаются пары «машина+серия/тема» и сохраняются в
  существующий `model_fingerprint` (новый ключ в JSON, БЕЗ новой колонки и миграции).
- [ ] **AC2.** При публикации пары переезжают в `published_articles.model_fingerprint`.
- [ ] **AC3 (жёсткий блок).** Точная пара (конкретная машина + конкретная
  франшиза/событие/лимит-серия) совпала с любой статьёй (pending ИЛИ published) за
  **30 дней**, **любой источник** → статья НЕ в `pending`, ссылка → `processed_news`,
  лог INFO, оператору `[E015]` (совпавшая пара + ссылка на прошлую статью).
- [ ] **AC4 (мягкий флаг / тиринг).** Широкое совпадение (тема без конкретной машины,
  либо частая рекуррентная линейка) → статья **публикуется**, оператору `[E014]` на
  ревью (rate-limited как в текущей фиче). Никогда не жёсткий блок по широкому ключу.
- [ ] **AC5 (композиция «в дополнение»).** Если новое правило не дало жёсткого блока
  (нет совпадения / нет серии / выключено) → **всегда** отрабатывает существующий
  дедуп по набору машин (≥50%, 7 дней) без изменений.
- [ ] **AC6 (тумблер).** Env-переменная включает/выключает новое правило; по
  умолчанию **включено**. Выключено → правило полностью пропущено, только старый
  дедуп. Значение читается на старте (как `DB_FILE`/`TZ`).
- [ ] **AC7 (охват темы).** «Серия/тема» покрывает линейки HW + события (SDCC) +
  франшизы (Stranger Things, Top Gun, K-Pop Demon Hunters). Предмет без узнаваемой
  модели → тема-ключ (участвует только в мягком флаге, см. AC4). Проверяется
  калибровкой (AC11). Неизвестная/непомеченная серия → широкий тир (фейл-сейф).
- [ ] **AC8 (пустой фингерпринт).** Нет ни машин, ни темы → проверка пропускается,
  публикуется. В БД пишем непустую структуру (не NULL).
- [ ] **AC9 (degraded).** Любой сбой → ERROR + rate-limited `[E016]`, статья
  публикуется.
- [ ] **AC10 (backfill + предпроверка).** `backfill_fingerprints.py --days 30`
  дозаполняет пары «машина+серия» И базовый car-fingerprint за 30 дней (в т.ч. строки
  без ключа пар — выборка по отсутствию ключа, не только `IS NULL`). Идемпотентен,
  логирует сводку. Деплой-инструкция включает предпроверку `SELECT COUNT(*) … WHERE
  model_fingerprint IS NOT NULL` на проде.
- [ ] **AC11 (калибровка).** Фикстура включает: 3 реальных SDCC-дубля (t-hunted PT +
  autoevolution EN + повтор t-hunted) как жёсткие блоки; **не-дубли**: (а) та же
  машина в РАЗНОЙ серии → не блок; (б) same-source near-miss (разные машины, та же
  широкая линейка) → мягкий флаг, не жёсткий блок; (в) тема-only Stranger Things
  «мейнлайн vs SDCC» → мягкий флаг, не молчаливый блок. Классификатор ≥7/8.

## Ограничения

- Без новых внешних зависимостей и без LLM — regex + лексиконы (stdlib).
- Без миграции схемы — пары в существующем `model_fingerprint TEXT`.
- Без нового top-level файла — извлечение серий живёт в `model_extractor.py`.
- Лексикон серий/тем собирается эмпирически из реальных лент; нужен более частый
  апдейт, чем бренд-лексикон (франшизы — открытое, быстро растущее множество).
- Backfill — разовый ручной шаг оператора; деплой вне окна 10:00–20:00 МСК.

## Риски

- **Риск 1 — ложный блок.** Смягчён на трёх уровнях: **тиринг** (широкие темы →
  мягкий флаг, не блок), **тумблер** (мгновенное отключение при проблемах),
  калибровка с не-дублями. Остаточный: жёсткий блок точной пары теоретически может
  зарезать переиздание — виден по `[E015]`, отключаем тумблером.
- **Риск 2 — поп-культура без модели.** Митигация: тема-ключ + калибровка на 3
  реальных примерах (load-bearing).
- **Риск 3 — холодная прод-база (вероятно, backfill НЕ запускался).** Текущий прод
  поднят из `news.db` со старого NL (снимок до фичи дедупа), запуск backfill на нём
  не подтверждён. Митигация: предпроверка `SELECT COUNT` перед деплоем + обязательный
  `backfill --days 30` после (греет и базу, и новое правило).
- **Риск 4 — неполный лексикон.** Митигация: пополнение PR при первом промахе.
- **Риск 5 — регрессия.** Митигация: degraded mode (AC9) + тумблер.
- **Секвенирование.** Базовый cross-source-dedup доехал до прода лишь с переездом
  2026-07-06 (~дни соака). Новый слой опционален (тумблер) — можно включить после
  короткого наблюдения.

## Технические решения

- Пары — в существующий `model_fingerprint` JSON (новый ключ), без миграции.
- Извлечение серий/тем — внутри `model_extractor.py` (второй проход regex).
- Гейт: тумблер → новое парное правило (30 дней, любой источник, тиринг: точная пара
  = блок, широкая = флаг) → **всегда** старый set-overlap как добивающий бэкстоп.
- Тиринг «точная vs широкая» — по типу ключа (конкретная модель+франшиза/событие =
  точная; тема-only или частая линейка = широкая). Точную классификацию лексикона —
  в техспек.
- Пинги: `[E015]` (жёсткий блок, с деталями пары), `[E014]` (мягкий флаг, как в
  текущей фиче), `[E016]` (degraded).
- Backfill: `--days 30`, выборка по отсутствию ключа пар (не только `IS NULL`).

## Тестирование

**Unit** (`tests/test_model_extractor.py`): извлечение серий/тем + классификация
пары «точная/широкая»; предмет без машины → тема-ключ; нет серии → пусто.

**Интеграция** (`tests/test_integration.py::TestCrossSourceDedup`): жёсткий блок по
точной паре (кросс- и same-source); мягкий флаг по широкой теме (публикуется + E014);
композиция — при отсутствии блока добивает старый set-overlap; тумблер выкл → правило
пропущено; degraded; пустой фингерпринт → проход. Обновить `test_within_source_not_
deduped` (any-source для парного правила). Калибровочная фикстура (AC11), порог ≥7/8.

**E2E:** не делаем — роль E2E играет 2-недельный мониторинг канала после деплоя.

## Как проверить

### Агент проверяет
| Шаг | Инструмент | Ожидаемый результат |
|-----|-----------|---------------------|
| 1. `pytest -q` | bash | Зелёный: новые + существующие тесты. |
| 2. `pytest tests/test_model_extractor.py -v` | bash | Извлечение серий/тем + классификация пар. |
| 3. `pytest tests/test_integration.py::TestCrossSourceDedup -v` | bash | Блок/флаг/бэкстоп/тумблер/degraded/проход. |
| 4. калибровочный тест | bash | ≥7/8; 3 SDCC-пары = блок; not-dupe пробы = флаг/проход. |
| 5. `backfill_fingerprints.py --days 30` на тестовой БД | bash | Сводка; повтор — no-op; заполняет и пары, и car-fingerprint. |
| 6. тумблер выкл (env) → прогон гейта | bash | Новое правило пропущено, старый дедуп работает. |

### Пользователь проверяет
- **Перед деплоем** — `SELECT COUNT(*) … WHERE model_fingerprint IS NOT NULL` на проде.
- **После деплоя** — `python3 backfill_fingerprints.py --days 30` на проде.
- **Канал @myhwchannel, 2 недели** — спот-чек `[E015]` (ложные блоки?) и `[E014]`
  (реально дубль?). SLA-ориентир: по **жёсткому блоку** (distinctive) → 0 видимых
  дублей + ≤1 ложный блок/мес. По **широкому** тиру: статьи-дубли **публикуются** с
  флагом `[E014]` — это осознанный компромисс тиринга (не теряем новое ценой того,
  что широкий дубль может недолго повисеть); оператор при желании удаляет их вручную.
  Если ложных жёстких блоков много ИЛИ поток `[E014]` зашумлён — отключить тумблером
  и разобрать (в техспеке — не забыть про rate-limit широкого тира).
