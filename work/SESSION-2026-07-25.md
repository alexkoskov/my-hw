## Ключевые решения/грабли (для будущих сессий)

- Один бот-токен на прод+тест ⇒ getUpdates слушает ТОЛЬКО прод; флаг
  `REVIEW_BUTTONS_ENABLED` (default OFF, truthy `1/true/yes/on`) гейтит И
  слушатель, И отрисовку кнопок. Гейт fail-closed: нужен ещё непустой
  `TELEGRAM_BOT_TOKEN` и ЧИСЛОВОЙ `TELEGRAM_ADMIN_ID`.
- PTB 21.10: держать один `Bot` через несколько `asyncio.run` НЕЛЬЗЯ (httpx
  клиент привязан к создавшему event loop) — свежий Bot на каждый вызов, как в
  `send_admin_notification`.
- `sqlite3.connect` stdlib default timeout уже 5.0s — «bare connect падает
  мгновенно» было ложной предпосылкой; `timeout=5.0` теперь закреплён явно
  (тест-шпион), PRAGMA не добавляли (сдвинул бы execute-счётчик fault-injection
  теста).
- Инфраструктура субагентов дважды падала (401/403, session limit) — работа не
  теряется: код коммитится исполнителями, resume через SendMessage.

## Инцидент: «Connection closed» с NL — это fail2ban, сервер жив

Оператор не смог зайти на NL (`148.135.207.54`) ни root'ом, ни hwbot'ом —
«Connection closed by … port 22» до аутентификации. TCP-проба с другого адреса
показала: sshd на NL жив (и Москва жива) → **IP оператора забанен fail2ban**
(повторно; то же было ~2026-07-15 — см. отложенную S2-sudoers задачу «когда
fail2ban отпустит»). Документация серверов ВЕРНА: прод = Москва, тест-бот = NL.
Тест-проверку перед промоутом пропустили (гарантия «кнопки без флага спят» —
кодовая, закрыта QA). TODO оператору (не срочно): разбанить свой IP через
панель/консоль DeluxHost или дождаться истечения бана; альтернатива —
