# Session 2026-06-17 — Why 15:00 prod post missed + in-slot publish retry

Operator: "почему сегодня в 15:00 не опубликовалась новость на проде?" Diagnosed
from prod logs, then (operator request) added an **in-slot retry** so a transient
network blip on the publish side no longer costs the article its slot until the
next day. Change on `dev`, awaiting commit+push.

## Part 1 — Diagnosis of the missed 15:00 publish

**Facts from prod (`journalctl -u news_bot.service`, times МСК):**
- Process alive continuously since the 06-14 deploy (`Active: active (running) since
  2026-06-14`, PID 623966) — so NOT a crash / restart.
- 10:00 today: `[E008]` plan = queue 2, slots 10:00 + 15:00.
- 10:02: slot 1/2 published OK.
- 15:00:00: slot 2/2 picked `t-hunted …novos-prototipos…`, LLM translated fine.
- **15:00:27: `[slot 2/2] publish failed … api.telegra.ph … Read timed out (read
  timeout=15)`** → `[job] done. Published 1, carry-over 0, queue size now 1`.

**Root cause:** transient **Telegra.ph read-timeout** on the publish step (not the
LLM, not a crash, not the new hold-and-wait). The article was preserved (1 strike,
stayed pending). But because 15:00 was the LAST slot of the day (2 articles → 2
slots), the next retry was only the next 10:00 tick — so the post "skipped" 15:00.

This VPS has a recurring **flaky-network pattern** (DNS/`Temporary failure in name
resolution` on 06-09/06-10/06-15; Telegra.ph timeout today). See
[[incident_e011_can_be_server_dns]].

**Observability gap noted:** non-outage publish failures are logged but send NO
admin ping — operator only noticed by watching the channel. (Offered to add a
failure ping; operator chose the retry fix instead — see Part 2.)

**Schedule mechanics clarified:** the 3 slots (10:00/15:00/19:30) are NOT separate
cron triggers — one 10:00 `job()` run sleeps in-process until each slot. So a crash
between 10:00 and 15:00 would lose 15:00 (the 06-08 fragility). Today that was NOT
the cause (process stayed up), but it remains a latent risk.

## Part 2 — Fix shipped: in-slot publish retry (`dev`)

**Operator decision:** retry the same article in-slot after ~10 min (a couple of
tries) instead of waiting for the next day, so a one-off network timeout doesn't
eat the slot.

**Code (news_bot.py):**
- New constants `PUBLISH_RETRY_ATTEMPTS = 2`, `PUBLISH_RETRY_DELAY_SECONDS = 600`.
- New helper `_publish_with_retries(row, idx, n_slots) -> (outcome, last_error)`:
  - success → `'published'`
  - `ClaudeOutageError` → `'held'` immediately, **no retry** (hold-and-wait; a retry
    would re-translate/waste tokens)
  - `ClaudeTranscreationError` (per-article) → `'failed'` immediately, **no retry**
    (deterministic — same bad result)
  - any other Exception (Telegra.ph/Telegram/repo network) → retry up to 4× / 10 min
    apart, then `'failed'`
- Slot loop maps `'published'`→count, `'held'`→log, `'failed'`→existing 3-strike
  path (exactly one strike per slot, not per retry).

**Trade-offs / safety (confirmed in code review, approved):**
- Slots ≥90 min apart, so ≤40 min of retries (4×10 min) can't push into the next
  slot. Only edge: retries on the last slot (19:30) may finish ~20:10, past
  window-end — harmless (delays only the day's final post). Commented in code.
- A retried Telegra.ph failure re-runs the full publish incl. LLM re-translation
  (RU isn't persisted until Telegraph succeeds). Up to 4 extra LLM calls for a rare
  blip — acceptable; documented on the constant.

**Tests (tests/test_job_distributed_publish.py):**
- `TestPublishWithRetries`: transient-then-success → published (1 retry sleep);
  all-fail → failed + last_error + N+1 calls; `ClaudeOutageError` → held, no
  retry/sleep; `ClaudeTranscreationError` → failed, no retry.
- `TestSlotLoopTransientRetry`: recover-on-retry → no strike; exhausted retries →
  `increment_attempt` called EXACTLY once (regression guard vs per-retry striking).
- Existing strike/hold/per-article tests still green (retries are no-ops under the
  patched `time.sleep`).

**Review:** code-reviewer → approved_with_suggestions, no blockers. Applied both
minor suggestions (the exhausted-retries one-strike test + window-edge comment).

**Test count:** 1129 → **1135** (+6: helper/slot/per-article/regression tests).
Docs: architecture.md publish-loop section updated.
